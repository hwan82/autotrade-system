# 검토 점검표

검토자는 항목마다 **통과 / 실패 / 해당 없음** 중 하나로 답하고, 근거(파일:라인, 테스트 이름과 실행 결과, 문서 위치)를 붙인다. 근거 없이 "통과"라고 쓰지 않는다. 확인하지 못한 항목은 "확인 못 함"과 이유를 쓴다(통과로 치지 않는다).

판정: 실패가 하나라도 있으면 **수정 필요** 또는 **거부**. 확인 못 함이 있으면 **조건부 승인**이 아니라 **수정 필요**로 낸다.

## A. 실전 경로 PR (risk-ops, QA)
대상: 실전 주문 경로, RealTradingGuard, 블랙리스트·수동 보유 종목, 리스크 한도, 장애 대응, 증권사 주문 연동, 프로세스 격리, 보호 테스트 중 하나라도 건드리는 PR.

| # | 항목 |
|---|---|
| A1 | RealTradingGuard 기본값 OFF, 재기동 시 OFF가 유지된다. 이를 바꾸는 설정·코드·테스트 변경이 없다 |
| A2 | 실전 주문은 Guard 팩토리를 거친 출구로만 나간다(우회 경로 없음). ArchUnit 규칙이 그대로다 |
| A3 | 주문은 계좌의 증권사로만 간다. 다른 증권사로의 주문 전환(failover) 경로가 없다 |
| A4 | 타임아웃 시 재주문하지 않고 조회부터 한다. 미접수 확인 후에만 새 멱등 키로 1회 재전송한다 |
| A5 | 멱등 키 `{date}-{code}-{side}-{seq}`가 모든 주문에 붙고, 재기동 후에도 중복이 생기지 않는다 |
| A6 | 블랙리스트·수동 보유 종목은 어떤 경로(전략, 수동 명령, 청산, 재기동 복구)로도 자동 주문되지 않는다 |
| A7 | 계좌별 단일 직렬 큐와 토큰 버킷이 유지되고, 한 계좌의 장애·킬스위치가 다른 계좌에 영향을 주지 않는다 |
| A8 | 실전 엔진이 실험실·UI·게이트웨이 장애나 부하에 영향받지 않는다(프로세스 분리, 자원 부족 시 정지 순서) |
| A9 | 시세 단절·PC 장애 시 보유 종목 보호(보호 시세 경로, 서버 측 손절)가 약해지지 않는다 |
| A10 | API 키, 계좌번호, 토큰이 코드·로그·테스트 픽스처·커밋에 없다 |
| A11 | 보호 테스트가 삭제·비활성화·약화되지 않았다. 새 동작에는 실패하는 경우를 포함한 테스트가 있다 |
| A12 | 바뀐 동작이 장애 대응표(broker-and-fault-design.md 6장, 현재 17종, 해외 O1~O8)와 장애 테스트 8종의 전제를 깨지 않는다. 깨면 대응표와 테스트가 함께 바뀌었다 |
| A13 | 미국 시장 경로는 `MarketRules`로만 다르고, 시간은 거래소 현지 시간대, 금액은 계좌 통화로 계산한다 |
| A14 | 결정 로그와 기획서가 바뀐 동작과 일치한다(새 결정이 필요하면 기록되어 있다) |
