# 뉴스 건수 스냅샷 출처 조사 (Q-055)

- 작성: 2026-10-21, data-engineer
- 요청: 사용자 BAE "진행할 새 작업이 있는지 찾아주십시오"(2026-10-21) → [ADR-012](../adr/ADR-012-intraday-selection.md) 배치표 6번(뉴스 스냅샷 4.2, `news-count`·`news-surge`)의 선행 Q-055
- 범위: 뉴스 기사 건수를 날마다 쌓는 앞으로 전용 스냅샷의 출처. 약관상 저장·가공 범위, 개인 비상업 이용, 하루 호출 상한, 과금, 키 발급 조건
- 이 문서는 법률 자문이 아니다. 개인 PC의 비공개 실험(원자료 재배포 없음)에 맞춰 읽은 해석이다.

## 1. 결론
1. **네이버 검색 API(뉴스)는 지금 이 용도에 쓰지 않는다.** 2026-07-31부터 검색 API가 NAVER API HUB(네이버 클라우드 플랫폼)로 옮겨가 새 키는 클라우드 계정과 결제 수단 등록이 필요하고, 2026-09 시행 검색 API 개별 특약이 검색 데이터(가공·파생물 포함)의 복사·저장·캐싱을 금지하며 예외는 서버 이력 조회 목적 최대 21일이라고 여러 2차 자료가 정리한다 `[가정]`(원문 미확인, 2장). 8주 넘게 쌓아 다시 읽는 스냅샷은 건수만 남겨도 "파생물 저장"에 걸릴 수 있다 `[추론]`.
2. **대안 추천: 한국투자 "종합 시황/공시(제목)" 조회(`FHKST01011800`, `/uapi/domestic-stock/v1/quotations/news-title`).** 이미 쓰는 한투 키로 부르고 요금 항목이 없다(국내 시세 조회 무료, 사용자 확인 2026-10-09). 제목마다 관련 종목코드 `iscd1`~`iscd5`와 작성 일자·시각 `data_dt`·`data_tm`이 붙어 ADR-012 4.2가 걱정한 종목명 동명이인 오탐이 생기지 않는다 `[사실]` 3장.
3. 추천안은 한투 플러그인(`autotrade-broker-kis`, 보호 경로)의 읽기 전용 허용 목록에 1개를 더해야 해서 **실전 관련 PR**이 된다(risk-ops 검토, 독립 QA, 사용자 머지). 또 한투 약관의 저장 조항은 포털이 이 환경에서 열리지 않아 확인하지 못했다 `[가정]`. 그래서 지침 8장 2번(실전 영향)·6번(약관 해석)에 따라 **사용자 결정을 받는다**. 결정 전에는 수집 코드를 만들지 않는다.

### 2.2 이 용도에 맞는지
- ADR-012 4.2의 스냅샷은 날마다 받아 w거래일(20일 이상) 동안 남겨 두고, 녹화 실험 재현을 위해 스냅샷 ID로 다시 읽는다. 21일 예외를 넘고 "데이터베이스화"에 가깝다 `[추론]`.
- 건수만 남기면 덜 위험하다고 볼 수도 있지만 특약 요약이 "파생물 포함"이라 해석이 엇갈린다. 지침 8장 6번 대상이다.
- 결제 카드 등록은 무료 구간 안이라도 과금 가능성이 생기는 선택이라 지침 8장 1번 대상이다.

### 3.2 설계에 주는 영향
- 질의 규칙: 종목명 검색이 아니라 **종목코드 태그(`iscd1`~`iscd5`)로 센다.** ADR-012 4.2의 `news.query-rule`은 `kis-news-title-iscd@1` 같은 이름으로 manifest에 남긴다. 지주사·업종 기사처럼 본문 언급만으로 붙는 태그가 섞일 수 있어 상위 후보 손 확인 절차는 그대로 둔다 `[추론]`.
- 공시 제목이 섞인다(`news_lrdv_code`·`dorg`로 구분). 공시는 이미 `disclosure-count`(D-123)로 세므로 뉴스 건수에서는 공시 자료원을 빼야 이중 계산이 없다. 자료원 코드 값은 첫 수집 뒤 표로 고정한다 `[가정]`.
- 호출 방식은 두 안이다: (가) 하루 전체 목록을 날짜·시각 커서로 받아 종목코드로 나눔(호출 수가 종목 수와 무관), (나) 종목마다 `FID_INPUT_ISCD`로 조회(감시 100종목이면 하루 100회 이상). 한쪽 건수를 모르니 (가)를 먼저 시험하고 쪽 수가 너무 많으면 (나)로 바꾼다.
- 시각: `data_tm`이 있으므로 ADR-012 4.2의 "T 08:00 이전 기사만" 규칙을 그대로 쓴다.
- 앞으로 전용: 과거 일자 조회가 며칠만 되면 ADR-012 ⑥ 그대로(오늘부터 쌓음). 몇 달 거슬러 받을 수 있으면 백테스트 가능성이 생기지만, 그때도 과거 목록이 당시 그대로인지(삭제·정정) 알 수 없어 앞으로 전용 원칙은 유지한다 `[추론]`.

### 3.3 실전 경로와의 관계
- `KisRestClient`는 보호 경로 `autotrade-broker-*` 안에 있고 허용 목록이 고정이라, TR 하나를 더하면 실전 관련 PR이다(프로젝트 지침 11장, `scripts/ci/protected-paths.txt`).
- D-054 "조회 호출기 연결 PR 승인 조건"이 그대로 걸린다: 실전 계좌가 설정된 한투 키로는 조회 호출기를 만들지 않음(+시험), `rateLimited` 백오프, 재발급 60초 하한, risk-ops 검토.
- 토큰: 한투는 6시간 안에 다시 발급하면 같은 토큰을 돌려주고 발급마다 알림톡이 간다([한투 명세 요약](kis-open-api-spec.md) 3.1). 수집 명령이 하루 한두 번 토큰을 받는 것은 게이트웨이 실시간 접속키(별도 `Approval`)를 끊지 않는다 `[추론]`. 첫 실행 때 게이트웨이 녹화와 겹쳐 확인한다.
- 수집은 수집기 장 시간 보호 밖(장 마감 뒤, 장 전 08:00 전)에 돈다(기존 collector runbook 규칙).

## 5. 위험과 한계
- 2장 네이버 정보는 모두 2차 자료다. 공식 원문이 다르면(예: 건수만 저장은 허용) A의 판정이 바뀐다. 확인 방법: 사용자 브라우저로 NAVER API HUB 상품 페이지와 "검색 API 개별 특약" 2.4를 연다.
- B의 한쪽 건수, 거슬러 받는 기간, 자료원 코드는 모른다. 첫 호출로 확인하고 결과를 이 문서에 덧붙인다.
- 뉴스 건수는 앞으로 전용이라 w=20이면 수집 시작 뒤 20거래일이 지나야 지표가 계산된다. LIVE02(2026-12-21~) 전에 쓰려면 늦어도 2026-11-20쯤에는 수집을 시작해야 한다 `[추론]`(KRX 휴장일 반영 전 대략값).

## 6. 사용자 할 일(B를 고를 때)
- 한투 포털 이용약관에서 시세·뉴스 정보의 개인 저장 제한 조항이 있는지 확인(있으면 알려 주기).
- 한투 키가 실전 계좌용이면 조회 전용 앱키를 따로 발급받는 것을 권한다(D-054 risk-ops 조건). 키는 `secrets.json`의 `brokers.kis.app-key`·`app-secret` 자리에만 넣는다.
