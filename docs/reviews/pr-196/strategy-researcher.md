### M1. 구간 끝이 c라 c와 T 사이 휴장일 공시가 하루 늦게 세진다 (수정 필요)

- 현재 정의: 접수일 ∈ (c의 w거래일 첫날 앞 거래일, c]. "c 앞 휴장일 접수분은 c 구간에 든다" `[사실]`(D-123 6항, `Metric.DISCLOSURE_COUNT` 주석, 테스트 `휴장일_접수_공시는_다음_거래일_구간에_넣는다`)
- 그래서 **c 뒤·T 앞** 휴장일 공시는 T 선정에서 빠지고 다음 날(T+1) 선정에 들어간다 `[사실]`(정의에서 직접 따름). 예:
  - T = 2027-01-04(연초 첫 거래일 가정), c = 2026-12-30. 2026-12-31은 KRX 휴장이지만 DART 접수는 받는 날이라 `[추론]`, 연말 공시(주요사항보고 포함)가 몰리는 날인데 T에는 0건, 다음 거래일에야 1건 이상이 된다
  - 2026-05-01(금, KRX 휴장) 접수 공시는 T = 05-04(월)가 아니라 05-05 이후 첫 거래일에 세진다
  - 주말 접수분도 같다(건수는 적다 `[추론]`)
- 이 공시들은 T 장 시작 전에 이미 알 수 있으므로 T에 세도 미래 정보가 아니다. 지금 정의는 가설("전일 공시가 있었던 종목은 **다음 날** 정보 반영 거래")과 시점이 어긋나고, 반응이 이미 끝난 T+1에 종목을 뽑는다. 재무 지표는 이미 "접수일 < T"를 쓴다(selection-catalog "미래 정보 0건" 문단) `[사실]`라 두 공시 기반 지표의 시점 규칙도 달라진다
- 카탈로그 대안 표는 "거래일 접수분만"과 "T까지(장전 공시 포함)"만 비교했고, **"접수일 < T(달력일, T 당일 제외)"** 대안이 빠졌다. 이 대안은 장전 공시를 넣지 않고(T 07:30 수집 보장 문제 없음), `--to` 어제까지인 T 00:00~08:00 수집으로 그대로 덮이며, 주말·연휴 공시도 영영 빠지지 않는다
- 요청: 구간을 (c의 w거래일 첫날 앞 거래일, T−1일](= 접수일 < T)로 바꾸고, `checkDisclosures`의 덮기 확인과 `covered_through`도 T−1 기준으로, 카탈로그·D-123·ADR-012 정의와 대안 표, 휴장일 테스트(설 연휴 예시를 "c 뒤 휴장일 공시가 T에 세진다"로)를 맞춘다. 지금은 이 지표로 만든 결과가 하나도 없어 같은 키로 바꿀 수 있는 마지막 시점이다. 머지 뒤에 바꾸면 새 지표 키가 필요하다
- 버린 대안이 맞다고 판단하면(예: DART 접수가 휴장일에 실제로 0건이라는 근거) 그 근거를 `[사실]`로 적고 대안 표에 이 대안과 버린 이유를 넣는 것으로도 닫을 수 있다

### m1. 정정 머리말 규칙의 남는 위험 (문서)

`isCorrection`은 대괄호로 시작하는 보고서명을 모두 뺀다. `[연장결정]`·`[변경등록]`은 정정이 아니라 새 사건일 수 있다 `[추론]`. 첫 실제 스냅샷에서 B·I 유형 대괄호 머리말 종류별 건수를 품질 리포트에 남기면 규칙을 판단할 수 있다. 바꾼다면 카탈로그 대안 표대로 새 지표 키로 한다.

### m2. c 장중 공시와 장 마감 뒤 공시가 섞인다 (해석 한계, 문서)

접수일만 있어 c 장중 공시(이미 c 가격·거래량에 반영)와 c 장 마감 뒤 공시(T에 처음 반영)를 구분하지 못한다. 점수 `volume-spike`가 c 거래량 급증 순이라, 상위 20종목은 c 장중 공시로 이미 반응한 종목 쪽으로 기울 수 있다 `[추론]`. 가설 "다음 날 정보 반영 거래"를 해석할 때의 한계로 카탈로그 (라) 문단에 적는다. 접수번호(`rcept_no`)에는 시각이 없다는 점도 함께 적는다 `[가정]`(OpenDART 문서로 확인 필요).

### m3. 우선주는 늘 0건 (문서)

공시 `stock_code`는 보통주 코드라 `[추론]` 우선주는 공시 0건으로 늘 탈락한다. `filter.kinds: STOCK`에 우선주가 들어가는지에 따라 (라)는 사실상 보통주 전용이다. 카탈로그에 한 줄.
