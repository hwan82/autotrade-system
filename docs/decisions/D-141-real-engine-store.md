# D-141 실전 엔진 저장소: 엔진 전용 추가 기록 원장과 재기동 복구 순서 (ADR-015)

- 날짜: 2026-10-24
- 상태: 제안. 설계 항목은 **추천안 채택(자율, architect)**, 실전 경로 설계라 risk-ops 검토·독립 QA 뒤 사용자 머지. 기획서 RSK-12 "(DB)"와 다른 저장 수단 선택은 **Q-062로 사용자 확인**
- 근거: [ADR-015](../adr/ADR-015-real-engine-store.md), [7단계 준비 계획](../team/stage-7-readiness-plan.md) 2.3장 B0·3장 묶음 B
- 담당: architect(설계), risk-ops(검토·구현 B1~B7)

## 결정

1. 실전 엔진 상태의 원본은 `<설정 폴더>/engine-store/`의 엔진 전용 추가 기록 원장(JSON 줄, `FileChannel.force`, CRC32C, 원장별 일련번호, 날짜 파일 첫 줄 체크포인트)이다. PostgreSQL에 두는 실전 엔진 상태는 없다(Q-062 확인 대상).
2. 쓰기 주체는 한 번에 하나(`writer.lock`, 부팅 번호 검사). 다른 프로세스는 엔진이 내보낸 블랙리스트 스냅샷만 읽는다.
3. 주문 의도(멱등 키 포함)는 원장에 강제 기록된 뒤에만 보낸다. 재기동 뒤 첫 키는 원장 최대 `seq` + 1000 `[가정]`.
4. 복구는 제한하는 쪽으로만: 리스크 제한·블랙리스트·미확정 주문·보유 로트는 되살리고, Guard 상태·활성화 단계·2차 확인은 저장도 복구도 하지 않는다(ADR-002 A1 유지). 재기동 순서는 Guard OFF 생성 → 잠금 → 원장 검사 → 상태 재구성 → 기동 기록 → 명령 채널 → 활성화 때 대사 → 대사 통과 계좌만 OPEN.
5. 계좌별 원장·쓰기 스레드. 원장 손상은 그 계좌만 활성화를 막고, 블랙리스트 원장 손상은 모든 계좌를 막는다.
6. 쓰기 상한(값 `[가정]`, B1 실측): 올림 감사 2초(넘으면 전이 실패), 내림 감사는 기다리지 않음, 신규 진입 의도 0.5초(넘으면 진입 버림·보호 모드), 청산·손절 의도는 기록 실패여도 전송(D-023 공통 원칙 1).
7. 코드는 새 순수 모듈 `autotrade-real-store`(감시 긴급 경로와 공유). 실험실·게이트웨이·수집기·실험 명령은 의존 금지. 외부 jar·JDK 허용 목록(D-086)은 늘리지 않는다.
8. 원장 자동 삭제 없음.

## 대안과 버린 이유

PostgreSQL을 엔진 원본으로(DB 서비스 생존에 묶임, JDBC·`java.sql`을 실전 경로 허용 목록에 추가), 내장 DB(H2 외부 jar·리플렉션, SQLite 네이티브 적재), 상태 파일 통째 교체(전이 이력 없음), 메모리 매핑 큐(외부 jar·`Unsafe`)는 버렸다. 원장을 원본으로 두고 엔진 밖에서 PostgreSQL 읽기 전용 복사본을 만드는 안은 화면 요구가 생기면 연다. 자세한 비교는 ADR-015 3장.
