# 녹화 사전 검사 (`runRecordingPrecheck`)

[ADR-014](../adr/ADR-014-live02-judgement-roles-precheck.md) 5장(F4), [D-131](../decisions/D-131-live02-judgement-roles-precheck.md). LIVE02에 넣을 후보 조합을 게이트웨이 녹화 위에서 먼저 돌려 P0~P3을 보고, 대조군 품질과 LIVE02 대조군 시드 수 표를 만든다. **사전 검사 통과는 승격 근거가 아니다**(6단계 계획 4.2). LIVE02 등록 후보를 거르는 단계이고, 후보도 LIVE02 녹화 판정(`runLiveJudgement`)을 거친다. 이 결과는 투자 자문이 아니다.

## 1. 준비

1. `git pull`로 main을 받는다.
2. 등록 파일 `experiments/<실험ID>/experiment.yaml`을 쓰고 **실행 전에 커밋**한다(사전 등록). 모양은 ADR-014 5.1의 예시 그대로다.
   - `input: "recording-precheck"`. 녹화 실험 키(`profiles`·`boards`·`blacklist`·`selections`·`selection-input`·`parallelism` 등)를 모두 받는다. `selection-input`은 스냅샷 ID만 받는다(`latest` 거절).
   - `references`(참고 계좌, 판정하지 않음)·`group-null-seeds`(묶음별 대조군 시드 수). **대조군이 있는 모든 묶음에 `group-null-seeds`를 적어야 한다**(사전 검사는 21m − 1 기본값을 쓰지 않음).
   - `family-size`(m_pre, 빠진 조합도 셈), `alpha`(소수, 예 `"0.05"`), `min-round-trips`(P0), `p2`(P2를 판정할 계좌), `p3`(`"<판정 대상> vs <참고 계좌>"`), `p3-min-segments`(p3가 있으면 필수), `segments`(구간, 기간의 모든 거래일을 겹침 없이 덮어야 함. 양 끝은 거래일).
   - 기준선(`logic: buy-and-hold`)은 없어도 된다.
3. 녹화 폴더(기본 `<설정 폴더>\recordings`)에 기간의 게이트웨이 녹화가 있어야 한다. 녹화 실험과 같이 **녹화된 종목은 모두 `boards`에 있어야** 하고 주식 호가 단위가 아닌 가격(ETF 등)이 있으면 거절한다.
4. 장전 선정 조합이 있으면 수집 스냅샷 폴더(기본 `<설정 폴더>\snapshots`)에 등록한 일봉(·공시) 스냅샷이 있어야 한다.

## 2. 실행 (장 시간 보호 구간 밖, 긴 것은 토요일 아침)

```powershell
.\gradlew :autotrade-app-experiment:runRecordingPrecheck -Pexperiment=<실험ID>
```

옵션: `-PrecordingsDir=폴더`, `-PsnapshotsDir=폴더`, `-PverifyDeterminism`(레인을 한 묶음으로 다시 돌려 `precheck.md`가 바이트로 같은지 확인, 시간 두 배), `-PallowDuringSession`(실전 엔진과 게이트웨이를 모두 끈 날만), `-PmaxParallelRuns=N`, `-Pheap=4g`(기본 4g. 일봉 스냅샷이 크면 힙 검사가 늘릴 값을 알려 준다).

- 돌리는 것: BASE(등록 계좌 전부, 지연 0.5초) + 묶음마다 `group-null-seeds`의 N개 대조군 시드(시드 = 실험 시드 + i, 레인 ID는 녹화 판정과 같은 규칙). 변형·지연·녹화 대조 레인은 없다.
- 녹화는 날마다 다시 읽어 메모리가 기간과 상관없다. 레인을 묶음(병렬 상한·등록 파일 `parallelism`·4 중 작은 수)으로 나눠 묶음마다 녹화를 따로 읽는다. 묶음 수는 결과에 영향이 없다.
- 걸린 시간은 로그 끝 줄 `걸린 시간 hh:mm:ss`로 본다(결과 파일에는 쓰지 않음, 계획 4.3 "판정 시간").

## 3. 결과

등록 파일 옆에 쓴다. 끝까지 계산했을 때만 쓴다(멈추면 아무것도 쓰지 않음).

| 파일 | 커밋 | 내용 |
|---|---|---|
| `precheck.md` | 함 | 1 머리말, 2 판정 요약(계좌별 P0~P3과 결과), 3 항목별 근거, 4 구간 표(계좌 × 구간 순손익·왕복·왕복당, 경계 넘긴 왕복 수), 5 대조군 품질·LIVE02 시드 수 표, 6 구독 커버리지, 7 한도 도달·거절 사유, 8 선정 표 |
| `inputs.yaml` | 함 | 녹화 실험과 같은 모양(데이터셋 버전, 녹화일별 파일 SHA-256·줄 수·종료 상태·재기동 공백, 선정 입력·적용 기록 해시, BASE 상세 보고서 해시, 결정론 확인) |
| `selections/` | 안 함 | 녹화일별 선정 고정 파일·적용 기록(크다. 내용 해시는 `inputs.yaml`에 있다) |

결과 읽기: 판정 대상마다 걸린 P(P0·P1은 모두, P2는 `p2` 계좌, P3는 `p3` 왼쪽 계좌)가 모두 통과면 **통과(LIVE02 후보)**, 하나라도 탈락이면 **탈락**, 탈락 없이 판정 불가가 있으면 **판정 불가**. 5장 LIVE02 N 표가 LIVE02 등록의 `group-null-seeds` 값이다(x/N ≥ 0.5 묶음은 "묶음 빼기", 999를 넘으면 "999 초과").

종료 코드: 0 계산을 끝냄(탈락·판정 불가가 있어도 0), 1 입력 오류, 2 실패한 Run이나 결정론 불일치(파일은 씀, 녹화 실험과 같음), 3 실험실에서 취소, 4 장 시간 보호·정지 요청으로 멈춤.

## 4. 구현에서 정한 것 (추천안 채택(자율), ADR-014에 없는 세부)

| 항목 | 정한 것 | 대안과 버린 이유 | 되돌릴 조건 |
|---|---|---|---|
| 쓸 수 없는 시드 x | 왕복 0건 + 실패(P2 분포 N′ = N − x와 같은 기준) | 왕복 0건만 셈: 실패 시드도 LIVE02에서 L10 분포에 못 들어가므로 N 계획에서 빼면 낙관적 | strategy-researcher가 실패를 따로 다루자고 하면 |
| 커버리지 알림 "4구간 평균" | 구간 평균들의 평균 < 50%(구간 평균은 날별 비율의 평균, 선정 0종목·적용 못 한 날 제외) | 구간 하나라도 50% 미만: 짧은 구간 하루 결손에 민감 | 계획 4.3 문구가 다르게 확정되면 |
| 실패한 Run의 종료 코드 | 2(녹화 실험과 같음, 결과는 씀) | 0: ADR 5.4 "계산을 끝내면 0"을 글자 그대로. 실패한 Run은 결과를 판정에 쓰기 전에 사람이 봐야 해 2로 둠 | 사용자·QA가 0을 원하면 |
| 결정론 확인 | 레인 전체를 한 묶음으로 다시 돌려 `precheck.md` 바이트 비교, 결과는 `inputs.yaml`에만 | `precheck.md`에도 쓰기: 옵션에 따라 결과 파일이 달라져 "같은 입력이면 바이트로 같음"이 깨짐 | - |
| 녹화 종목 | 녹화 실험과 같이 모두 `boards`에 있어야 함 | boards 밖 종목을 걸러 읽기(주간 점검 방식): ADR 5.2가 녹화 실험과 같은 읽기로 정함 | 게이트웨이 녹화에 boards 밖 종목이 섞여 실제로 막히면 |
| 등록 파일 키 모양 | 최상위 키에 숫자 허용(`p2`·`p3`, `RegistrationYaml`). 모르는 키는 여전히 거절 | 키 이름 바꾸기: ADR 5.1이 정한 이름 | - |
