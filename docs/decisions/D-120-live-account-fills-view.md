# D-120 실시간 모의 계좌별 체결·거절 내역을 도는 중에 화면에서 본다

- 날짜: 2026-10-20
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 실험실(`autotrade-app-lab`)·화면(`autotrade-ui`)·`autotrade-sim` 읽기 전용 사본 메서드만 바꾼다. 실전 경로, RealTradingGuard, 블랙리스트, 리스크 한도, 보호 경로는 바꾸지 않는다. 계좌 결과·보고서·입력 기록 형식은 그대로다.
- 담당: ui-dev 결정·구현(sim-engine 읽기 메서드 2개 포함). 교차 검토: architect(코드)
- 근거: 사용자 질문(2026-10-20, LIVE00 운용 중 `#/live` 계좌 표를 보고 "모의 계좌별로 상세 거래 내역(체결내역)을 볼 수는 없습니까?"). 기획서 UI-08(실시간 모의 조회는 6단계로 이연, D-079).

## 문제

`[사실]` 실시간 모의 화면은 계좌별 체결 **건수**만 보였다(`RunStepper.Progress.fills`). 체결 원장은 계좌 메모리(`VirtualAccount.ledger()`)에만 있고, 세션을 **끝낸 뒤**에야 `experiments/<ID>/live-detail.txt`에 `fill` 줄로 남는다. 입력 기록(`journal/`)은 시세 이벤트이지 체결이 아니다. 그래서 도는 중에는 계좌별 체결 내역을 볼 방법이 없었다.

## 대안 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A(채택)** | 도는 세션의 계좌 메모리에서 체결·거절 사본을 읽는 API 두 개와 계좌 상세 화면 `#/live/runs/<계좌>`. 행 모양·표는 실험 계좌 상세(UI-02)와 같은 것을 씀 | 새 저장소·파일 없음. 재기동 뒤에도 입력 기록으로 되살린 계좌라 같은 체결이 보임. 결과·결정론에 영향 없음 | 세션이 없으면(끝낸 뒤) 볼 수 없음(live-detail.txt를 안내) |
| B | 체결마다 세션 폴더에 체결 파일을 따로 씀 | 세션 밖에서도 읽힘 | 쓰기 경로·실패 처리가 늘고 입력 기록과 두 원본이 됨(리플레이 일치 범위 밖 파일). 결과 DB 저장(UI-02 이연)과 겹침 |
| C | 끝낸 뒤 live-detail.txt를 화면에서 파싱 | 끝낸 세션도 봄 | 도는 중 질문에 답이 안 됨. 보고서 형식에 화면이 묶임 |

되돌릴 조건: 결과 DB 저장(UI-02 이연 항목)이 들어오면 B·C 대신 그 저장소를 읽게 바꾼다.

## 결정

1. `RunStepper.fillsSnapshot()`·`rejectionsSnapshot()`: 체결 원장과 거절·취소 기록의 불변 사본(화면용, 결과에 안 씀).
2. `LiveSession.activity(runId)` → `RunActivity(runId, fills, rejections)`: 세션 잠금 안에서 사본을 만든다. 실패로 멈춘 계좌는 멈추기 전까지의 기록을 돌려준다. 없는 계좌는 빈 값.
3. API(로컬 조회 전용 GET): `GET /api/live/runs/{runId}/fills?page&size`(체결, **최근 것부터**), `GET /api/live/runs/{runId}/rejections?stage&code&page&size`(거절, 최근 것부터, 사유별 건수는 거르기 전 전체). 행은 실험 계좌 상세와 같은 `FillRow`·`RejectionPage`. 세션이 없거나 되살리는 중이거나 없는 계좌면 404. 한 쪽 최대 200행(`Page.MAX_SIZE`).
4. 화면: `#/live` 계좌 표의 계좌 ID가 링크. 계좌 상세는 평가금액·현금·체결·거절 타일, 체결 내역 표(체결 시각·종목·구분·수량·체결가·수수료·세금·슬리피지·실현손익·멱등 키·신호→체결 순번), 거절 사유 분포와 로그. 쪽을 넘기는 중 표가 바뀌지 않게 자동 갱신은 하지 않고 "새로 읽기"로 다시 읽는다.
5. 종목명 표(`SymbolNames`)를 실험 카탈로그와 실시간 API가 같이 쓰도록 빈으로 나눴다(동작 같음).

## 위험과 한계

- 사본은 요청마다 원장 전체를 복사한다. 8주 세션 계좌당 수천 건 수준이라 무시할 만하다 `[추론]`. 세션 잠금을 잠깐 잡으므로 수신 경로와 경합하지만 복사는 마이크로초~밀리초 수준 `[추론]`.
- 끝낸 세션의 체결은 화면에서 보지 못한다(live-detail.txt를 읽어야 함). 결과 DB 저장(UI-02 이연)이 오면 메운다.
- 적용 시점: 실험실 재기동 때부터. LIVE00이 돌고 있는 사용자 PC는 이 변경 때문에 다시 띄울 필요가 없다.
