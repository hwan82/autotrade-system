## 수정 필요 항목

**M1. 예열 일수 ≥ 후보와 ±20% 변형이 쓰는 가장 긴 조회 기간을 시작 전에 검사할 것** (`WalkForwardStudy.candidates`, 또는 계획 3장·조합 실험 절차 6장 등록 규칙)
- `kr-52w-high-position@1`은 `signal.lookback-days: 250`이고 ±20% 변형은 200·300이다(`Perturbation.scale`은 `study.warmup-days`를 같이 늘리지 않는다). 계획 3장과 조합 실험 절차 6장의 등록 예시는 `warmup-days: "260"`이다. 그대로 등록하면 ×1.2 변형(300일)은 각 3년 학습 구간 앞 약 40거래일 동안 `closes.size() < lookback`이라 진입을 못 한다(`NearHigh.java:195`). 학습 구간 약 735거래일 중 5% 남짓이 빠져 ×1.2 변형 수익률이 낮게 나오고, C7 "원래의 50% 이상"이 엣지가 아니라 설정 때문에 떨어질 수 있다. 반대로 원래 프로필은 260 ≥ 250이라 영향이 없어, 두 변형이 같은 조건에서 비교되지 않는다.
- 지금 코드에는 `plan.warmupDays`와 프로필의 조회 기간을 맞춰 보는 곳이 없다(`grep study.warmup-days`: 합성 실험 `ScreeningCriteria`에서만 쓴다). 다른 후보는 문제가 없다(돌파 24 + 1, 반전 120, 이평 추세 60 × 1.2 = 72).
- 사전 등록 전인 지금 막아야 한다. 등록 뒤에 발견하면 같은 구간을 다시 평가하는 셈이 된다.
- 추천: 시작 전에 후보·변형마다 필요한 예열 거래일(로직별 조회 기간 키의 최댓값 + 1, 또는 `study.warmup-days`를 key-param과 같은 배율로 늘린 값)을 계산하고, `warmup-days`가 그보다 작으면 입력 오류(종료 코드 1)로 시작하지 않는다. 실패 테스트 1건(52주 후보 + 예열 260 → 거부)을 둔다. 대안: 문서만 고쳐 예시를 `warmup-days: "310"`으로 올리는 것(사람 실수를 막지 못해 버림). 대안을 고르더라도 계획 3장 예시 값은 고쳐야 한다.

**M2. 판정 수치를 손 계산 테스트로 고정할 것** (`WalkForwardJudgeTest`, 필요하면 `PooledTest`)
- 지금 판정 테스트는 3/4 올림, C10 표본 하한, p 동점, C3 경계, 합성 순서만 본다. `evaluate()`를 거치는 C1·C1w·C6·C7·C8·C9d 계산과 `Pooled.of`·`perTrip`의 이은 곡선·왕복당 손익은 통합 테스트에서 "결과 파일에 C1w 글자가 있다" 수준으로만 확인된다(`WalkForwardStudyTest.java:134`).
- 이 식들은 4단계 계획이 사전 등록한 판정식이고 단계 완료 판정과 승격 근거가 이 숫자에서 나온다. PR #78 M1에서 C6 식을 하나로 고정한 것도 구현이 그 식을 따르는지 시험으로 확인할 수 있어야 의미가 있다. 실데이터를 돌린 뒤 식 오류가 발견되면 등록 실험을 버리고 새 ID로 다시 돌려야 한다.
- 요청: 합성 `WindowRun` 2~3구간(평가금액·왕복을 손으로 지정)으로 다음 값을 기대값과 비교하는 테스트.
  - `Pooled`: 이은 곡선 값과 S_k, 이은 총수익률, 왕복 합, `perTrip` = (이은 최종 − 시드)/왕복 수
  - C1: 이은 수익률 − 이은 지수, 경계 0(같으면 탈락). C1w: 4구간 3승 통과, 2승 탈락
  - C6: 구간 첫날 시드 대비를 포함한 일수익률 평균 비, 학습 평균 0 → 탈락, 비 0.6 정확히 → 통과
  - C7: 학습 구간 평균 수익률 × 0.5 경계, 변형 PF 0.99/1.00 경계, 원래 학습 손실 → 탈락
  - C8: 최고 달을 빼면 0원 → 탈락(> 0이어야 통과)
  - C9d: PF null(손실 왕복 없음) + 수익 → 통과, 수익 0 → 탈락
  - C10: `evaluate()` 경로로 N = 199, m = 10에서 k = 0 통과·k = 1 탈락
- 코드 변경이 아니라 테스트 추가라 판정식을 바꾸지 않는다. 식이 계획과 다르게 구현된 것이 테스트로 드러나면 그때 고치는 것은 등록 전이라 허용된다.

**M3. 동시 신호 초과 시 종목 코드 순 진입을 측정하고 해석 한계로 사전 등록할 것** (`WalkForwardReport` 결과 파일, 계획 6장 위험, 조합 실험 절차 6장 6번)
- 일봉 이벤트는 거래일 → 시각 칸 → 종목 코드 순으로 정렬된다(`DailyBarMarketDataSet.java:53`). 일봉 로직은 하루 첫 체결에 신호를 내므로, 그날 조건을 만족한 종목이 `limits.max-entries-per-day`(4)나 빈 자리(`sizing.max-positions` 4·8)보다 많으면 **코드가 작은 종목부터** 들어가고 나머지는 거절된다.
- 새 후보 셋은 이 상한에 거의 매일 걸릴 것으로 본다 `[추론]`. 국내 유니버스 약 2,500종목에서 20일 종가 신고가(`kr-donchian-swing`)나 250일 최고 종가 95% 이내(`kr-52w-high-position`)는 보통 하루 수십~수백 종목이다. 선정이 `none`인 조합은 순위 기준이 없어, 이 후보들이 실제로 시험하는 것은 "조건을 만족한 종목 중 코드가 가장 작은 몇 개"가 된다. 국내 종목 코드는 대체로 오래 상장한 코스피 기업이 작아, 결과가 가설의 효과가 아니라 상장 연차·시장(코스피 쏠림)·규모 쏠림을 반영할 수 있다. 무작위 대조군(`random-daily`, 스윙 5% × 약 2,500 = 하루 약 125신호 대 한도 4)도 같은 구조로 쏠리므로 C10에서는 일부 상쇄되지만, C1·C1w(시총 지수 대비)와 결과 해석은 그대로 영향받는다.
- 스킬 4장 비교 지표의 "거래 제한 도달 빈도, 거절 사유 분포"가 이 쏠림을 보는 지표인데 results.md에 없다. 선정 쪽은 같은 문제를 알고 대응 조건을 적어 두었다(`selection-catalog.md` 91행 "상한에 걸리는 날이 잦으면 점수 지표를 넣은 새 버전"). 전략 진입 쪽에는 그런 기록이 없다.
- 요청(사전 등록 전에 이번 PR에서):
  1. results.md에 후보·검증 구간별로 "신호 수 / 실제 진입 수 / 한도 때문에 거절된 수 / 한도에 걸린 거래일 비율"을 내는 표를 더한다(대조군은 쌍별 중앙값). 거절 사유는 리스크 체인·계좌가 이미 남기는 사유 코드를 모으면 된다 `[추론]`.
  2. 계획 6장 위험과 조합 실험 절차 6장 6번 "해석 주의"에 "동시 신호가 한도를 넘으면 종목 코드 순으로 진입한다. 한도에 걸린 날 비율이 높으면 그 후보의 성과는 코드 순 표본에 대한 것"이라는 문장과, 해석 규칙(예: 한도에 걸린 거래일이 검증 거래일의 50%를 넘는 후보는 통과해도 승격 제안 전에 순서 무관 재현(같은 후보, 시드로 섞은 순서)을 요구)을 사전 등록 문구로 넣는다.

## 점검표 밖 발견 (권고, 막지 않음)

1. **C10이 진입 엣지만 보는 것은 아니다**: 대조군은 스타일마다 하나라 청산·보유 기간이 후보와 다르다. `kr-short-reversal-swing`(최대 5일, 손절 8%) 대 `kr-random-daily-swing`(최대 10일, 손절 5%), `kr-donchian-swing`(손절 7%·추적 6%) 대 같은 대조군, `kr-52w-high-position`(손절 15%, 로직 청산) 대 `kr-random-daily-position`(손절 10%). 왕복당 순손익(원)은 보유 기간이 길수록 상승장에서 커지므로, C10은 "진입 + 청산 묶음 대 무작위 진입 + 다른 청산"을 비교한다. 비중은 같아 원 단위 비교 자체는 공정하다. results.md 대조군 표에 후보와 대조군의 평균 보유 거래일을 같이 내고, `report.md`에서 C10 해석에 이 차이를 적기를 권한다. 후보별 청산을 맞춘 대조군(후보 프로필에서 진입만 `random-daily`로 바꾼 파생 프로필)은 다음 실험 후보로 둔다.
2. **리더보드 지표 보강**: 스킬 4장의 비용 비중(비용 ÷ 비용 전 손익), 평균 보유 기간, 회전율이 리더보드에 없다(비용은 원 금액만). 특히 `kr-short-reversal-swing`은 왕복 비용이 기대 반등폭과 같은 크기일 수 있어(PR #78 권고 6) 비용 비중이 해석의 핵심이다.
3. **`kr-short-reversal-swing`의 key-param**: ±20% 대상이 추세 필터 `signal.trend-days`(100 → 80·120)다. 가설의 핵심은 "K일 연속 하락"과 "X일 평균 회복"이라 `signal.down-days`(3 → 2·4) 쪽이 민감도 검사로 더 의미가 있다. v1은 이미 등록 전이라 바꿀 수 있지만, 바꾸면 새 해시가 되므로 등록 전에 정하기를 권한다. 그대로 두면 report.md에 "핵심 신호 파라미터의 민감도는 보지 않았다"를 한계로 적는다.
4. **지수의 일봉 공백 수익률**: `MarketIndex`는 전일 일봉이 직전 거래일과 같을 때만 그날 수익률을 넣는다. 거래정지로 일봉이 아예 빠진 기간이 있으면 재개일의 큰 등락이 지수에서 빠지는데 계좌는 그 손익을 그대로 받는다. 거래정지일에 거래량 0 일봉이 있으면 문제가 없다고 주석에 적혀 있으니, 이렇게 빠진 (종목, 날) 수를 `capExcluded`처럼 세어 결과 파일에 내기를 권한다.
5. **C7 PF 계산의 기간 인자**: `robust()`가 학습 Run을 `Pooled.of(seed, runs, from, to)`로 묶을 때 검증 기간 `from`·`to`를 넘기고, 학습 구간끼리 겹쳐 이은 곡선 날짜가 뒤로 돈다. C7은 PF(왕복 합)만 쓰므로 판정에는 영향이 없다. 혼동을 막으려면 PF만 왕복에서 직접 계산하거나 주석으로 "곡선 지표는 쓰지 않음"을 적는다.
6. **"52주 고가" 명칭**: 원 연구(George·Hwang 2004)는 장중 고가 기준이다. 이 프로필은 종가 기준 250거래일이라고 가설·README에 정확히 적혀 있어 문제는 없고, report.md에서 원 연구와 정의가 다르다는 점만 한 줄 적으면 된다.
7. **계산량**: 기준 규모 대조군 Run 6,400개는 실측 전 `[가정]`이다(ADR-009 4장). 첫 실데이터 실행에서 대조군 수를 줄여야 하면 N + 1 ≥ 20m(m = 10이면 N ≥ 199)을 지키는 선에서 줄이고, 그 변경은 새 실험 ID로 한다.
