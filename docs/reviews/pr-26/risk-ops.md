## 점검표 밖 발견
1. **[하] QA pr-25 발견 4(D-037 행의 결정 근거 혼재, D-023 문구를 좁힌 사실 미기록)는 이 PR에 등록되지 않음.** 커밋 메시지는 "지적 3건"이라 의도적 제외로 보이나 제외 이유가 어디에도 없다. 실전 동작에 영향은 없으므로 막지 않는다. pm-lead 후속으로 남기거나 제외 이유를 PR 본문에 적을 것을 권고.
2. **[하] ADR-006:203에 QA pr-25 발견 1(a)의 "판정은 ② 전에, 계좌·종목의 시장 단위로" 와 (c)의 "체결 확인 상한 시각"이 명시되지 않음.** "언제 읽는지 정한다", "마감 전에 다시 건다"로 정할 거리를 남겼고, 합격 테스트(마감 직전 PANIC에서 미체결 보유가 서버 측 손절 없이 마감을 넘기지 않음)가 결과로 이를 강제하므로 막지 않는다. 7단계 설계 때 판정 시점을 ② 전으로, 재설정 상한 시각을 RSK-11 "청산 외 주문 금지" 구간 시작 전으로 두는 것을 추천.
3. **[하] 마감 전 서버 측 손절 재설정은 새 주문 발생 경로다.** 7단계 구현 때 이 재설정 주문도 계좌 직렬 큐의 손절 우선순위, 멱등 키, 타임아웃 시 조회 우선(UNKNOWN → 조회) 규칙을 따라야 한다. 재설정 실패 시에는 긴급 표시와 보호 모드 유지(ADR-006 2.5 계약, PanicLiquidator.java:17-18)로 끝나야 한다. 합격 테스트에 "재설정 주문 타임아웃 → 재전송 없이 조회" 경우를 추가할 것을 권고.
4. **[하] 기획서 RSK-13 인수 조건(autotrade-spec.md:188)과 16장 risk-ops 후속(362행)에 ADR-006:203의 새 합격 테스트 2건이 없음.** ADR 후속 표가 단일 원본 기획서보다 엄격한 상태다. 7단계 구현 PR 전에 autotrade-spec-keeper로 RSK-13 인수 조건에 반영할 것을 권고(막지 않음).
5. 확인했지만 문제 아님: ADR-006:202가 인용한 `PanicLiquidator.java:11` 문구("장 외 시간에는 취소만 하고 매도하지 않는다")는 실제 코드와 일치. ADR-006:204가 인용한 risk-ops pr-25 원문의 VI·종목 단위 메모(61·96행)도 실재. "7단계 전 필수" 표기는 기존 202행 관례와 같다.
