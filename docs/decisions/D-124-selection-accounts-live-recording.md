# D-124 선정 조합 계좌를 녹화 실험·실시간 모의에 연결한다(ADR-012 배치표 4번)

- 날짜: 2026-10-20
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 실험실(`autotrade-app-lab`)·실험 명령(`autotrade-app-experiment`)·`autotrade-sim`·화면(`autotrade-ui`)만 바꾼다. 실전 경로, RealTradingGuard, 블랙리스트 규칙, 리스크 한도, 보호 경로는 바꾸지 않는다. 등록 파일에 `selections`가 없으면 계좌·시드·결과·기록 형식이 지금과 같다(LIVE00·LIVE01 불변, 회귀 시험).
- 담당: sim-engine(+ ui-dev 화면 표시). 교차 검토: architect(코드)
- 근거: [ADR-012](../adr/ADR-012-intraday-selection.md) 3.5·3.6·6장 4번, [D-121](D-121-intraday-selection.md) ④⑤, architect PR #191 검토 N1~N3. 번호: D-122(넓힌 watchlist)·D-123(공시 스냅샷)은 다른 열린 브랜치가 써서 D-124를 쓴다.

## 결정

1. **등록 키**(`RegisteredSelections`, 녹화 실험 `RecordingPlan`·실시간 모의 `LivePlan` 공통):
   ```yaml
   selections:
     - "kr-intraday-hot@1 x kr-random-control@1"   # 선정 x 전략, profiles 계좌 뒤에 이 순서로 계좌 번호
   selection-input:
     daily: "latest"        # 실시간만 latest. 녹화 실험은 스냅샷 ID(latest 거부)
     financials: "latest"   # 재무 조건이 있는 선정만
   ```
   ADR-012 3.5 예시의 겹친 목록 대신 조합 실험(`CombinationPlan`)과 같은 한 줄 `"선정 x 전략"`을 쓴다(등록 파일 YAML 읽기를 좁은 모양으로 지킴). `disclosures`는 공시 스냅샷 수집(배치표 3번) 전이라 알아보고 거절한다. 갱신 주기가 `PRE_OPEN_DAILY`가 아닌 선정도 거절한다.
2. **계좌 순서와 시드**: 선정 계좌는 `profiles` 계좌 뒤에 붙는다. 선정 없는 계좌는 `run-seed-v1` 그대로, 선정 계좌는 조합 해시·`run-seed-v2`(ADR-007). 그래서 선정 계좌를 더해도 앞 계좌의 결과는 같다.
3. **그날 후보** = 선정 결과 `selected` ∩ `boards`. `boards` 밖은 `NOT_SUBSCRIBED`, 등록 파일 `blacklist`는 `BLACKLISTED`로 빼고 다음 순위로 메우지 않는다. 후보 밖 종목의 신규 진입은 기존 "선정 밖 비보호 신호 차단"으로 막고 청산은 막지 않는다. 주문 직전 블랙리스트 검사는 리스크 체인이 그대로 다시 본다.
4. **고정 파일과 적용 기록**(`SessionSelections`): `<기준 폴더>/selections/<거래일>/<selection_hash>.json`(ADR-007 2.6 결과 + 만든 커밋·만든 시각, 내용 해시 검사), 못 만든 날은 `<hash>.problem.json`(사유). 날짜 전환 지점은 그날 첫 이벤트를 기록하기 **전에** `applied.json`(조합마다 적용한 결과의 내용 해시 또는 `SELECTION_MISSING`과 사유)을 임시 파일 → 원자적 이름 바꾸기로 쓴다(N3). 적용 기록이 있으면 그것만 따르고 늦게 온 결과는 무시한다. 기준 폴더는 실시간이면 `<설정 폴더>/live-sessions/<ID>/`, 녹화 실험이면 `experiments/<ID>/`.
5. **판정**: 적용 범위 = T 하루, 선정 해시 일치, 일봉 기준일 ≥ T의 직전 거래일(아니면 `STALE_INPUT`), 결과 없음 `MISSING`, 깨진 파일은 사유와 함께 `SELECTION_MISSING`. 실전용 `SelectionValidity`(ADR-007 2.6)가 들어오면 그것으로 바꾼다.
6. **적용 기록을 못 쓰면 세션을 멈춘다**(그날 이벤트를 기록하지 않음, `stopReason`). 기록 없이 계속하면 재기동·리플레이에서 다른 선정을 볼 수 있기 때문이다.
7. **준비 작업(N2)**: 실험실의 별도 낮은 우선순위 스레드가 장 시간 밖(거래소 현지 16:00 ~ 다음 날 08:30 `[가정]`)에 5분마다, 또는 `POST /api/live/selections/prepare`로 요청받을 때 다음 거래일 T의 결과를 만든다. 세션 처리 스레드에서는 계산하지 않는다. 준비는 정지 요청·세션 멈춤(디스크 하한 포함)을 관문으로 묻고(멈춰 있으면 시작하지 않고 단계 사이에도 멈춤), 일봉 행 수 × 1KB `[가정]`가 실험실 최대 힙의 절반을 넘으면 계산하지 않고 `PRODUCER_FAILED`로 남겨 실험실 밖 명령을 안내한다.
   - ADR-012 3.5의 "세션을 열 때 한 번"은 장중에 세션을 열면 이벤트와 같은 시간에 전체 일봉을 읽게 되어 뺐다. 장중에 연 세션은 화면의 "지금 준비"로 손으로 준비한다.
   - **실험실 밖 명령** `./gradlew :autotrade-app-experiment:runLiveSelectionPrepare -Pexperiment=<ID> -Pdate=YYYY-MM-DD [-Pheap=8g]`(`ExperimentMain live-prepare`): 날짜는 꼭 준다(명령 본체는 벽시계를 읽지 않음). 장 시간 보호·정지 요청 관문(D-063). 종료 코드 0 준비됨, 1 입력 오류, 2 못 만든 선정 있음, 3 취소, 4 정지.
8. **녹화 실험**: 녹화일마다 등록 파일의 스냅샷 ID로 장전 선정을 계산해 결과 폴더에 같은 구조로 쓴다. 만든 시각을 남기지 않아 다시 돌리면 고정 파일까지 바이트로 같다. 스냅샷 폴더는 `-PsnapshotsDir`(기본 `<설정 폴더>/snapshots`). `experiments/*/selections/`는 커밋하지 않는다(스냅샷으로 다시 만듦, 시장 전체 평가라 큼).
9. **리플레이 확인**(`runLiveReplayCheck`): 플랜 기간의 적용 기록과 가리키는 파일의 내용 해시를 먼저 확인하고(없거나 다르면 종료 코드 1). 입력 기록에 줄이 있는 날인데 적용 기록이 없으면 지웠거나 옮긴 것이므로 그날을 `SELECTION_MISSING`으로 보지 않고 실패한다(세션은 열지 않음, 리플레이 확인·주간 점검은 종료 코드 1, architect PR #197 N1). 다시 계산하지 않고 고정 파일로 리플레이한다. 입력 스냅샷이 PC에 남아 있고 힙이 되면 다시 계산해 내용 해시를 비교한다. 결과는 `inputs.yaml`의 `selection-recompute:` 줄("같음 X, 다름 Y, 재계산 생략 Z"). 다름이 있으면 실시간 경로 결함과 따로 `selectionsRecomputed=false`, 종료 코드 2. 주간 점검(`runLiveWeeklyCheck`)의 계좌 대조도 같은 고정 파일을 쓴다.
10. **녹화 판정**(`runLiveJudgement`)은 선정 계좌가 있는 등록을 아직 받지 않는다(입력 오류로 거절, 후속). → **[D-126](D-126-live-judgement-selection-accounts.md)으로 붙음**(세션 고정 파일로 모든 레인을 돌림).
11. **화면**: `#/live`에 "선정 조합 계좌" 구역. 그날 적용(선정, `APPLIED` 또는 `SELECTION_MISSING`·사유, 후보·구독 커버리지, 뺀 종목과 `NOT_SUBSCRIBED`·`BLACKLISTED`), 다음 거래일 준비 결과, "지금 준비" 버튼. 계좌 표에는 프로필 뒤에 조합 이름이 붙는다.

## 후속 반영(화면, ui-dev)

- 11번 화면 보강(실시간 화면 선정 결과 표시 PR): 적용 표에 후보 종목 코드와 `SELECTION_MISSING` 사유의 자세한 내용을 칸에 바로 보인다(전에는 마우스를 올려야 보임). "다음 거래일 준비"는 메모리의 마지막 준비 결과 대신 세션 폴더 파일 상태(`SessionSelections.prepared`, 읽기만)를 보여 실험실을 다시 띄워도 준비 사유 파일(D-126 입력 스냅샷 키 포함)이 보인다. 장중 순위 선정만 있는 세션은 장전 선정 표와 "지금 준비" 버튼을 숨긴다(`View.dailySelections`). 결정 내용(판정·후보 규칙)은 바꾸지 않는다.

## 대안 비교

| 쟁점 | 채택 | 버린 안과 이유 | 되돌릴 조건 |
|---|---|---|---|
| 계산 시점 | 장 시간 밖 준비 스레드 + 손 요청, 날짜 전환은 읽기만 | 날짜 전환 지점 계산: 처리 큐가 차서 이벤트를 버리고 입력 기록까지 흔듦(ADR-012 F1). 세션 열 때 한 번: 장중에 열면 같은 문제 | 실전용 선정 생산자(D-049 ⑨)가 생기면 그 결과 파일을 읽음 |
| 적용 기록 쓰기 실패 | 세션 멈춤 | 기록 없이 계속: 재기동에서 늦게 온 파일로 다른 선정을 볼 수 있음(결정론 깨짐) | 없음 |
| 힙 부족 | 계산 전에 행 수로 거절하고 밖 명령 안내 | 그냥 계산: 실험실 OOM은 선정 없는 계좌까지 멈춤(절대 규칙 6 정신) | 일봉 줄 단위 계산이 들어오면 |
| 등록 모양 | 한 줄 `"선정 x 전략"` | 겹친 목록: 등록 파일 YAML 읽기(`RegistrationYaml`)를 넓혀야 함 | 없음 |
| 재계산 다름 | 따로 표시(종료 코드 2) | 실시간 경로 결함으로 섞기: 원인이 다른데 같은 칸에 들어감 | 없음 |

## 위험과 한계

- 장 시간 밖 범위(16:00~08:30)와 행당 1KB는 `[가정]`이다. 실제 일봉 전체(약 2,500종목 × 수년)가 4g 실험실 힙에 들어가는지는 사용자 PC에서 처음 준비할 때 확인한다. 안 들어가면 밖 명령으로 준비한다.
- KRX 일봉 게시 시각(ADR-012 3.7, 배치표 1번)이 다음 날 08:00이면 1차 선정은 날마다 `STALE_INPUT`이다. 이 경우 화면·보고서에 그대로 보인다.
- 녹화 판정은 아직 선정 계좌를 받지 않는다. LIVE02 판정 전에 붙인다.
- 같은 PC에서 밖 명령과 실험실 준비가 같은 날 파일을 동시에 쓰면 먼저 놓은 쪽이 남는다(같은 입력이면 같은 내용). 결과 파일과 적용 기록은 하드 링크로 놓아 이미 있는 파일을 덮어쓰지 않는다(architect PR #197 R1). 하드 링크를 못 만드는 파일 시스템에서는 확인 뒤 이름 바꾸기라 좁은 경합이 남는다.
- 후속(architect PR #197 R2~R4, R2·R4는 [D-126](D-126-live-judgement-selection-accounts.md)에서 처리): 계산이 실패한 날은 장 밖 동안 5분마다 일봉 전체를 다시 읽는다(실패 뒤 물러서기). 준비 스레드는 `OutOfMemoryError`를 잡지 않고 행당 1KB는 실측 전이다. 녹화 실험 선정 준비에는 힙 검사가 없고 이전 실행의 `selections/<날짜>/`를 지우지 않는다(같은 입력이면 같은 파일이라 결과는 같음 `[추론]`).
- 적용 시점: 실험실 재기동 때부터. 지금 도는 LIVE00·LIVE01은 `selections`가 없어 동작이 같고 다시 띄울 필요가 없다.

## 검증

- `SessionSelectionsTest`: 결과 파일 왕복·변조 거절, 후보(boards·블랙리스트, 메우지 않음), 한 번 적용·늦은 결과 무시·재기동 같음, 문제 파일·`STALE_INPUT`, 적용 기록 확인 실패(바뀜·없음·깨짐), 준비(정지 요청, 이미 있음, 이미 적용).
- `LiveSelectionSessionTest`: 기록일의 적용 기록을 지우면 세션이 열리지 않음, 선정 계좌는 그날 후보만 사고 재기동·리플레이가 같음, 선정 없는 계좌는 선정 계좌를 더하지 않은 세션과 같음, 최신 스냅샷으로 준비·재계산 같음/생략/다름, 적용 파일이 바뀌면 세션이 열리지 않음, 적용 기록을 못 쓰면 멈춤, 등록 검증.
- `RecordingSelectionTest`: 녹화일마다 고정 파일, `STALE_INPUT`, 다시 돌리면 바이트로 같음, 선정 없는 계좌 결과 불변.
- `LiveLabServiceTest`: 계좌 이름 순서, 준비가 이벤트 스레드 밖에서 됨, 선정 없는 세션의 준비 요청 거절, 힙 검사. `ExperimentGateTest`: 준비 명령의 정지 요청·장 시간 보호·날짜 없음.
- 클라우드 컨테이너의 Maven 429 때문에 전체 빌드와 JUnit은 CI 결과로 확인한다(로컬은 javac 컴파일과 시험 장치 실행).
