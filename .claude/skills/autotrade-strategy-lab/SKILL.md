# 전략 실험실 (Strategy Lab)

실전 API로 받은 실시간 시세 위에서 자체 모의 계좌 여러 개로 매매 기법을 병렬 운용하고, 결과를 비교해 실전에 쓸 기법을 고르는 절차입니다.

## 용어
- **전략 프로필**: 시장(KR/US) + 종목 선정 + 매수 선별 + 진입 + 비중 + 거래 건수 제한 + 청산 + 리스크 한도를 묶은 매매 기법 1개. ID, 버전, 해시를 가진다.
- **실험**: 기간 × 시드머니(통화 포함) × 전략 프로필 N개 × 비용 모델 × 실행 방식(실시간 모의 또는 녹화 리플레이).
- **실행(Run)**: 실험 1회 결과. 계좌별 거래 내역, 자산 곡선, 지표.

## 1. 가설과 프로필 작성
1. 엣지 가설을 한 문장으로 쓴다: 시장·조건·보유 기간·기대 효과가 모두 들어가야 한다.
2. 가설 하나에 매매 스타일 하나(스윙과 단타를 섞지 않음). 국내와 미국 전략은 분리한다.
3. 프로필 YAML을 `strategies/<프로필ID>/v<버전>.yaml`에 쓴다. 필수 항목:
   - `market`: KR 또는 US, 통화
   - `universe`: 최소 시총, 최소 거래대금, 최소 주가, 제외 유형
   - `selection`: 자격 조건(Gate, AND) / 점수 지표와 가중치(합 100, 횡단면 백분위) / 상위 N / 섹터 상한
   - `entry`: 신호 종류, 유효 시간, 무효화 조건, 주문 방식(미국은 지정가 + 여유폭)
   - `sizing`: 거래당 리스크 %, 종목당 상한 %, 동시 보유 수, 현금 버퍼
   - `limits`: 일 최대 주문 수, 재진입 금지 기간, 일·주간 손실 한도, MDD 서킷, 연속 손절 정지
   - `exit`: 손절(ATR 배수 또는 %), 익절, 추적 손절, 시간 청산, 추세 이탈, 장 종료 처리
4. 기본값은 docs/team 자료(스크리너 기본 세트, 장중 신호 카탈로그)의 값을 쓰고, 바꾼 값만 표시한다.

## 2. 실험 설계
1. 질문을 정한다: "A와 B 중 어느 청산 규칙이 MDD를 줄이는가"처럼 비교 대상이 분명해야 한다.
2. 실행 방식을 고른다:
   - **실시간 모의**: 장중 실시간 시세로 여러 계좌 병렬 운용. 실제 기간이 그대로 걸린다.
   - **녹화 리플레이**: 녹화된 날짜들에 새 전략을 돌린다. 빠르게 반복 가능.
3. 기간 분할: 학습 구간과 검증 구간을 나눈다. 녹화 데이터가 쌓이면 워크포워드(최소 3구간).
4. 기준선 포함: 매수 후 보유, 지수(KOSPI/KOSDAQ 또는 S&P500/NASDAQ), 현재 최선 프로필.
5. 파라미터 그리드는 작게 시작(변수 1~2개, 3~5단계).
6. 고정 항목 명시: 시드머니와 통화, 비용 모델, 체결 규칙, 데이터 버전.
7. 실험 정의를 `experiments/<실험ID>/experiment.yaml`로 저장한다.

## 3. 실행
- 실행 기록: 커밋, 데이터 버전, 프로필 해시, 시작·종료 시각, 시세 공백 구간, 오류.
- 녹화 리플레이는 두 번 돌려 결과가 같은지 확인한다. 다르면 결과를 쓰지 않고 원인부터 찾는다.
- 시세 공백 구간이 있었던 실시간 모의 결과는 공백을 표시하고 해석에 반영한다.

## 4. 비교 지표 (모두 비용 차감 후)
| 지표 | 의미 |
|---|---|
| 총수익률, CAGR | 성장 |
| 벤치마크 대비 초과수익 | 알파 |
| MDD, 최장 회복 기간 | 감내 가능성 |
| 샤프 | 위험 대비 효율 |
| 승률, 평균 손익비, Profit Factor | 기대값 구조 |
| 거래 수, 평균 보유 기간, 회전율 | 통계 신뢰도와 비용 부담 |
| 비용 비중 | 비용이 수익을 얼마나 깎는지 |
| 거래 제한 도달 빈도, 거절 사유 분포 | 제한 조건의 영향 |

## 5. 선발 기준 (기본값, 결정 로그로 조정)
- 비용 차감 후 벤치마크 초과, Profit Factor ≥ 1.3, MDD ≤ 20%, 샤프 ≥ 1.0
- 검증 구간 거래 30건 이상
- 검증 구간 성과가 학습 구간의 60% 이상
- 주요 파라미터 ±20% 변경 시 성과 급락 없음
- 초과수익이 특정 기간 하나에 몰려 있지 않을 것
- 비교한 프로필 수가 많을수록 우연히 좋아 보일 가능성이 커진다는 점을 리포트에 적는다.

## 6. 리포트 (`experiments/<실험ID>/report.md`)
1. 요약: 질문, 결론, 추천 프로필(3줄)
2. 실험 조건: 실행 방식, 기간, 시드·통화, 비용, 데이터 버전, 커밋, 프로필 목록
3. 리더보드 표
4. 자산 곡선과 MDD 구간 해석
5. 과최적화 검사 결과
6. 실패·이상 사례와 원인 추정 [추론]
7. 다음 실험 제안

## 7. 승격
- 순서: 실시간 모의 최소 8주(선발 기준 통과, 주문 처리 오류 0건) → 녹화 리플레이로 표본 외 재검증 → 실전 소액(자산 10% 이하) → 확대.
- 승격 제안서는 pm-lead에게 결정 후보로 넘긴다. 실전 활성화는 사용자가 UI에서 직접 한다.

## 금지
- 비용 차감 전 성과로 결론 내기
- 검증 구간 결과를 보고 파라미터를 고친 뒤 같은 구간으로 재평가하기
- 미래 정보 사용(T 시점 신호를 T 시점 가격에 체결 등)
- 실패한 실험 기록 삭제
