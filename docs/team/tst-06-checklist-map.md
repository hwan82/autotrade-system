# TST-06 원본 체크리스트 대응표

- 작성일: 2026-10-26 · 작성: risk-ops · 기준 코드: main `53482a56`
- 대상 요구사항: [기획서](../spec/autotrade-spec.md) TST-06 "7단계 시작 전 원본 체크리스트 34항목을 요구사항 ID에 매핑한 표를 만들고, 미충족 항목을 실전 활성화 화면에 **경고**로 표시. 차단 조건은 TST-01만"
- 출처 항목: [7단계 준비 계획](stage-7-readiness-plan.md) 2.3 K9, 묶음 0(대응표). 화면 경고 구현은 묶음 H(ui-dev)이고 이 문서의 범위 밖이다.

## 1. 결론

1. [사실] 원본 34항목은 ChatGPT 설계서 2종(저장소 밖)의 표다. 장중 실시간 자동매매 설계서 표 10-1이 16항목, 주식 스크리너(일봉 스윙) 설계서 표 12-1이 18항목이다. 장중 16번 "모의투자 최소 8주 수행 계획"은 원문 표의 마지막 줄이다.
2. 처리: 채택 17, 대체 17, 미채택 0. 대체는 대부분 원본의 고정값(ATR 계수, 0.75%, 4주, 증권사 모의투자)을 **전략·선정 프로필 파라미터와 실험 비교**(기획서 0장 #4), **자체 실시간 모의 8주**(0장 #7·#8)로 바꾼 것이다.
3. 상태(main `53482a56`): 충족 4, 부분 24, 미충족 6, 해당 없음 0. 미충족 6개(신호 경과 상한, 유동성 검사, 슬리피지 상한, 5분 대사, 일·주간 손실 한도, MDD 서킷)는 모두 **실전 경로 코드가 아직 없어서**다. 규칙 자체는 기획서에 있다.
4. 화면 경고는 정적 경고 11개(시스템 준비 상태)와 계좌별 경고 5개로 묶었다(5장). 34항목 중 경고 대상이 아닌 것은 충족 4개와, TST-01 차단으로 표시되는 1개(장중 15번)다.
5. **차단은 TST-01(장애 테스트 8종 합격)뿐이다.** 이 표의 어떤 항목도 실전 활성화를 막지 않는다. RSK-01 활성화 단계(인증 → 주문 세션 → 첫 대사) 실패 때 OFF 유지, ENV-02 해외 차단 같은 기존 규칙은 TST-06과 별개이고 이 문서가 바꾸지 않는다 `[추론: TST-06 문구 "차단 조건은 TST-01만"은 이 체크리스트에서 나오는 차단을 한정한 것으로 읽음]`.

## 2. 판정 기준

**처리**(기획서 0장 "원본 문서 간 차이와 택한 쪽"의 방식을 따른다)

| 값 | 뜻 |
|---|---|
| 채택 | 원본 항목의 의도를 그대로 요구사항으로 둠. 수치는 `[가정]` 기본값이고 실전 값은 사용자 결정일 수 있음(Q-008) |
| 대체 | 같은 위험을 다른 방식으로 다룸(고정값 → 프로필 파라미터, 증권사 모의투자 → 자체 실시간 모의 등) |
| 미채택 | 이 시스템에서 다루지 않음 |

**상태**: 실전 활성화 관점에서 본다(실험실에서만 되는 것은 "부분").

| 값 | 뜻 |
|---|---|
| 충족 | 규칙이 확정되고, 실전 활성화에 필요한 구현·검증까지 끝남 |
| 부분 | 규칙 또는 일부 구현은 있으나 실전 경로 구현·실전 값·검증 중 하나 이상이 남음 |
| 미충족 | 규칙은 기획서에 있으나 실전 경로에 해당 코드가 없음 |
| 해당 없음 | 처리가 미채택이라 대응이 없음 |

**경고 대상 규칙**

1. 상태가 부분·미충족인 항목은 경고 대상이다(TST-06 "미충족 항목을 경고").
2. 다만 같은 원인을 가진 항목은 경고 하나로 묶는다(5장 경고 ID). 예: 손절 방식·종목 수·가중치처럼 **실험으로 고르는 전략 설계 항목**은 따로 띄우지 않고, 그 결과인 "실전 계좌 조합의 승격 상태" 경고(W-21) 하나로 보인다. 지정된 조합은 프로필 검증을 통과한 값만 쓰고, 구현되지 않은 프로필 키는 검증이 거부하므로(`SelectionCriteria.java:24-26` "모르는 키는 거부한다") 실전 계좌가 미구현 기능에 기대는 일은 없다 `[추론]`.
3. 장애 테스트 시행 결과에 해당하는 항목은 경고가 아니라 TST-01 차단 표시로 보인다(같은 사실을 경고와 차단으로 두 번 띄우지 않음).
4. 기존 요구사항이 이미 정한 활성화 화면 경고(ENV-02 점검 목록, ENV-03·RSK-06 "PC 장애 시 보호 수단 없음", D-045 8주 미완 예외 경고)는 다시 만들지 않고 같은 표시를 쓴다.

**표기**: `[사실]` 근거가 있는 내용, `[추론]` 근거에서 끌어낸 판단, `[가정]` 확인 전 값(지침 6장). 근거 열의 경로 약어: E = `autotrade-app-engine/src/main/java/com/autotrade/app/engine`, R = `autotrade-risk/src/main/java/com/autotrade/risk`, S = `autotrade-strategy/src/main/java/com/autotrade/strategy`, SEL = `autotrade-selection/src/main/java/com/autotrade/selection`.

## 5. 실전 활성화 화면 경고 목록 (묶음 H 입력)

모든 경고는 **활성화를 막지 않는다**. 화면은 ADR-006 2차 확인 대화상자 앞(활성화 버튼을 누르기 전 계좌 카드와 대화상자 머리)에 경고 목록을 보이고, 2차 확인 흐름(비밀번호 + 계좌 별칭)은 바꾸지 않는다. 경고를 확인했다는 별도 체크 단계도 넣지 않는다(새 확인 단계는 ADR-006 변경이라 이 문서 범위 밖). [추론, 권고] 활성화 명령의 감사 기록에 그때 보인 경고 ID 목록을 함께 남기면 나중에 "무엇을 알고 켰는지"를 추적할 수 있다. 감사 기록 형식은 묶음 B(B1)에서 정한다.

## 6. 갱신 규칙

- 7단계 묶음(A·B·C·D·E·F·G·H·I)의 PR이 머지될 때마다 risk-ops가 3·4장 상태와 5장 해제 여부를 갱신한다. 갱신은 문서 PR이다.
- 상태를 "충족"으로 바꿀 때는 근거 열에 실패 테스트 이름이나 결정 번호를 적는다. 근거 없이 상태만 바꾸지 않는다.
- 7단계 실전 활성화 결정 전 독립 QA(지침 11장)는 이 표를 TST-07 대응표(준비 계획 I2)와 함께 본다.
- 원본 체크리스트 문구는 저장소 밖 설계서에서 옮긴 것이다. 원문을 다시 확인해 다르면 원본 문구 열만 고치고 그 사실을 이 장에 적는다.

| B. 원인별 경고 16개 + 대응표 링크(이 문서) | 경고 ID마다 원본 항목을 묶고, 화면에서 이 표로 들어갈 수 있게 함 | **채택(추천안, 자율)**. TST-06 "미충족 항목을 경고"를 빠짐없이 덮으면서(모든 부분·미충족 항목이 어느 경고 ID에 걸림) 화면 경고 수를 줄인다 |
| C. 경고 없이 대응표만 | 문서로만 관리 | 버림. TST-06 인수 조건 "미충족 항목 경고 표시 테스트"를 만족하지 못한다 |

되돌릴 조건: 묶음 H 화면 시험이나 독립 QA에서 묶은 경고가 원인을 가린다고 판정되면, 그 경고 ID만 원본 항목 단위로 다시 나눈다.

**위험과 한계**

- [사실] 상태 판정은 main `53482a56`의 코드 검색 결과다. "검색 0건"은 이름이 다른 구현을 놓쳤을 수 있다(준비 계획 5장과 같은 한계). 묶음 머지 때 갱신으로 바로잡는다.
- [가정] 원본 34항목 문구는 저장소 밖 설계서에서 옮긴 사본으로 확인했다. 원본 판본이 여럿이면 번호가 다를 수 있다.
- [추론] 정적 경고는 문서와 화면이 따로 관리되면 낡을 수 있다. 묶음 H에서 화면의 경고 ID 목록이 이 문서 5장 ID와 같은지 확인하는 시험(문서 대조 시험)을 두기를 권한다(ui-dev·architect 변경 제안).
- 경고는 사용자가 무시하고 켤 수 있다. 실전 손실을 막는 것은 경고가 아니라 Guard 기본 OFF, 첫 대사, 장애 테스트 8종 차단, 서버 측 손절, 한도 구현이다. 이 문서는 그 어느 것도 약화하지 않는다.
- W-24의 30일과 W-20의 실전 몫 식은 `[가정]`이며 Q-060 결정과 묶음 H 설계 때 다시 본다.
