# D-062 실험실이 조합 실험 결과를 불러와 실험 화면(교차표·선정 결과)에 보이기

- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 실전 주문 경로·Guard·블랙리스트 코드·리스크 한도·장애 대응은 건드리지 않는다
- 담당: sim-engine(화면 쪽은 ui-dev 경계). 교차 검토: architect
- 근거: 기획서 UI-02, SIM-09·10, STR-15·17, [D-060](D-060-selection-ui.md)(결과 본문은 `ExperimentCatalog.register(spec, report, selectionResults)`로 받고 다시 계산하지 않음), [D-061](D-061-daily-replay-combination-runner.md)(조합 실험 실행 명령, 대안표 "실험실이 나중에 이 클래스를 부른다"), [ADR-001](../adr/ADR-001-module-structure.md) 실험실 힙 2GB, [ADR-005](../adr/ADR-005-ui-dashboard.md), PR #49·#50 후속 과제

## 결정

1. **실행 명령이 결과 묶음을 쓴다**: `runCombinationExperiment`는 기존 결과 파일에 더해 `experiments/<실험ID>/result-bundle.jsonl.gz`(`ResultBundle`, 스키마 1)를 쓴다. 실험 명세, 실행 결과 머리(코드 커밋·비용 표 해시·체결 모델), Run마다 요약·지표·조합(전략·선정 프로필 본문)·체결 원장·자산 곡선·왕복·거절·날짜별 선정 기록, 실험이 쓴 선정 결과 본문(`SelectionResult.canonicalJson()` 그대로)을 JSON Lines로 담는다. 금액·소수는 `toPlainString()` 문자열(자리수 보존), long은 문자열이다. 실행 시각 같은 메타가 없어 같은 입력이면 같은 내용이다. 임시 파일에 다 쓴 뒤 바꿔 넣는다.
2. **결과 묶음은 커밋하지 않는다**(`.gitignore`). 선정 결과 평가 행(거래일 × 유니버스 전 종목)이 커서다. 같은 명령으로 다시 돌리면 같은 결과로 다시 만들어진다(SIM-09).
3. **실험실은 실험을 다시 돌리지 않고 결과 묶음만 읽는다**(`ExperimentFolders`, 속성 `autotrade.lab.experiments-dir`, 기본 `experiments`). 화면 "실험" 아래 "실험 폴더"에 조합 실험 등록 파일이 있는 폴더를 보이고(상태: 불러올 수 있음·결과 묶음 없음·아직 실행 안 함·화면에 있음·등록 파일 오류. REST 계약은 ADR-005 5장 표), "불러오기"(`POST /api/experiment-folders/{id}/load`, CSRF 토큰 필요)로 올린다. 실험실을 다시 띄우면 다시 불러온다(결과 DB 저장 전, `InMemoryExperimentCatalog`).
4. **올리기 전 대조**: ① 폴더 이름 = 묶음의 실험 ID ② 묶음에서 되살린 결과를 `ReportWriter`로 다시 그린 글이 커밋된 `detail.txt`와 바이트까지 같음(코드 커밋 줄 포함) ③ 선정 결과마다 내용 해시를 다시 계산해 줄의 해시와 같음 ④ 묶음의 선정 결과 해시 집합 = `selection-days.tsv`의 `result_hash` 집합 ⑤ 프로필 본문에서 다시 계산한 프로필·선정 해시 = Run 요약의 해시 ⑥ Run마다 줄 수가 머리와 같음(잘린 파일). 하나라도 다르면 올리지 않고 사유를 폴더 목록에 보인다.

## 대안과 되돌릴 조건

| 선택 | 버린 대안 | 이유 | 되돌릴 조건 |
|---|---|---|---|
| 실행 명령이 쓴 결과 묶음을 읽음 | A. 실험실이 등록 파일로 실험을 다시 돌림(`CombinationExperiment.run`) | 선정 계산 입력이 스냅샷 전체를 올려 약 300만 행에 2GB를 쓴다(QA PR #39 실측). 실험실 힙 상한 2GB(ADR-001)를 넘고, 실험실 안에서 무거운 계산을 새로 돌리면 5.2 정지 순서 1번("시뮬레이션 실험의 신규 실행 중단") 대상이 생기는데 그 장치가 아직 없다(Q-049와 같은 문제) | 실험 생성·실행 화면을 만들 때(그때는 별도 프로세스로 돌리고 결과 묶음을 읽는 지금 경로를 그대로 쓴다) |
| 〃 | B. 기존 텍스트 결과(`detail.txt`·`runs.tsv`)를 파싱 | `detail.txt`에 체결 시각, 거절 상세, 선정 종목 목록, 계좌 ID가 없고 선정 결과 본문(평가 행)은 어디에도 없다. 형식을 넓히면 골든 파일과 결정론 비교 대상이 함께 바뀐다 | — |
| 〃 | C. 결과를 DB(ADR-004 4장 표)에 저장 | 실험실 DB 연결·저장소 구현이 아직 없다. 이 PR 범위를 넘는다 | DB 저장소가 생기면 같은 묶음을 DB로 옮기는 적재기로 쓰고, 화면은 DB를 읽는다 |
| JSON Lines + gzip, 커밋 안 함 | D. 한 JSON 문서 | 실험실이 줄 단위로 읽으며 오류 줄 번호를 줄 수 있다. 한 문서는 통째로 올려야 한다 | — |
| 〃 | E. 묶음도 커밋 | 다년 실험이면 평가 행이 수백 MB(gzip 뒤 수십 MB)일 수 있다 `[추론]`. 다시 만들 수 있는 산출물이다 | 실험 폴더를 다른 PC에서 그대로 열어야 할 필요가 생기면(그때는 Git LFS 등 과금 여부를 사용자에게 묻는다) |
| 쓰기는 sim(순수 모듈), 읽기는 실험실(Jackson) | F. 쓰기·읽기 모두 sim | 순수 모듈에는 JSON 읽기 라이브러리가 없고 직접 파서를 두면 코드가 커진다. 두 쪽이 어긋나는 위험은 실험실 테스트가 sim 쓰기로 만든 묶음을 되살려 같은지(명세·결과·선정 결과 equals, `ReportWriter` 글 일치) 보는 것과, 실제 불러오기 때 `detail.txt` 대조로 막는다 | 다른 프로세스(예: 실전 엔진)가 같은 묶음을 읽어야 하면 읽기를 공용 모듈로 옮긴다 |

선정 결과 파일 코덱(ADR-007 2.6, 실전 엔진이 읽는 결과 파일)은 이 결정이 정하지 않는다. 실험실의 선정 결과 되살리기는 같은 정규 JSON의 역이지만 실험실 안에서만 쓰고, 해시 대조로 확인한다.

## 위험과 한계

- **실험실 메모리**: 불러온 실험은 선정 결과 평가 행까지 실험실 메모리에 남는다. 다년·전 종목 실험은 힙 2GB에서 모자랄 수 있다 `[추론]`(아직 실측 없음). 모자라면 실험실만 멈추고 실전 엔진에는 영향이 없다(별도 프로세스, 지침 4장 6번). 첫 실제 조합 실험 때 힙 사용량을 재고, 모자라면 선정 결과 본문을 필요할 때 파일에서 읽는 방식(카탈로그의 질의 단위 메서드는 그대로)으로 바꾼다.
- **코드가 바뀐 뒤 다시 돌린 결과**: 묶음과 `detail.txt`를 한 실행이 함께 쓰므로, 다른 커밋으로 다시 돌리면 두 파일이 함께 바뀐다. 커밋된 `detail.txt`와 다른 결과를 막으려면 결과 파일을 커밋한 실행에서 나온 묶음이어야 한다(대조 ②가 커밋 줄까지 본다). 결과 파일을 고치지 않은 채 묶음만 다른 실행으로 바꾸면 불러오지 않는다.
- **`detail.txt` 대조가 보지 못하는 칸**: 체결 시각(신호·체결), 거절 상세 문구, 날짜별 선정 종목 목록, 계좌 ID는 `detail.txt`에 없어 바이트 대조로 확인되지 않는다. 이 칸은 묶음과 `detail.txt`를 같은 실행이 함께 쓰는 것과 줄 수·해시 대조에 기댄다. 선정 종목 목록은 선정 결과 본문(내용 해시 확인)에서 다시 얻을 수 있다(PR #51 architect F5).
- D-062 전에 돌린 조합 실험은 묶음이 없다("결과 묶음 없음"). 지금은 실제 조합 실험이 아직 없다.
- 실험실은 묶음 파일 크기 상한을 따로 두지 않는다(로컬 전용 화면, 사용자가 누를 때만 읽음).

## 검증

- `CombinationExperimentTest`: 실제 실행 경로에서 묶음을 쓰고 두 번 실행한 묶음이 바이트까지 같음, 임시 파일이 남지 않음, 묶음의 선정 결과 해시 집합 = `selection-days.tsv` 해시 집합 ⊇ 선정 기록이 가리키는 해시.
- `ResultBundleReaderTest`: 조합 실험·선정 없는 실험·실패 Run을 쓰고 읽으면 명세·결과·선정 결과가 equals, 잘린 파일·빠진 줄·바뀐 프로필 본문·바뀐 선정 결과·다른 스키마 거부.
- `ExperimentFoldersTest`, `ExperimentFolderControllerTest`: 목록 상태, 불러온 뒤 교차표·선정 결과 평가 행 API가 실제 값, 두 번 불러오기 409, CSRF 없는 요청 403, `detail.txt`·`selection-days.tsv`·폴더 이름 불일치 거부와 사유 표시, 조합 실험이 아닌 폴더 제외, 잘못된 ID.
