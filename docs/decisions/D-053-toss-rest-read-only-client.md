# D-053 토스 REST 명세 반영: 읽기 전용 조회 호출기와 현재가 폴링, 토큰 무효 처리

- 날짜: 2026-10-10
- 상태: 확정, **추천안 채택(자율)**(지침 8장). 증권사 연동을 건드려 risk-ops 검토 뒤 사용자 머지(지침 10장).
- 출처: 사용자 BAE가 2026-10-10 12:17Z 프로젝트 스레드에 토스증권 Open API REST 명세(OpenAPI 3.1.0, v1.2.24)를 올리고 "보완"을 요청했다. 요약은 [토스 명세 요약](../research/toss-openapi-spec.md).
- 담당: architect(결정·코드), risk-ops(검토)

## 결정
1. 새 모듈 `autotrade-broker-toss`를 둔다. 능력은 `POLLING_QUOTE`(현재가 `GET /api/v1/prices`, 소스 이름 `TOSS-POLL`, 한 번에 200종목)만 선언한다. 실시간(`REALTIME_QUOTE`)은 토큰 소유(Q-042)를 정하고 AsyncAPI 원문으로 필드를 확인한 뒤(규칙 요약은 명세 요약 5.1장), 주문·잔고는 7단계 risk-ops 작업으로 미룬다.
2. 조회 호출기(`TossRestClient`)는 계좌 없이 토큰만으로 부르는 GET 조회 경로(시세·종목 정보·시장 정보·랭킹·시장 지표·섹터) 허용 목록만 보낸다. 계좌·자산·주문·주문 내역·조건주문·주문 가능 정보 경로는 HTTP 요청 전에 거절한다. 목록을 넓히는 변경은 risk-ops 검토 대상이다.
3. 호출 한도(Client ID × 그룹 단위): 그룹마다 공식 한도(토스 개발자 문서 개요 표, 예 `MARKET_DATA` 15·`STOCK_ALL` 1·`MARKET_INFO` 3)와 초당 10회 중 작은 값으로 시작하고, 응답 `X-RateLimit-Limit`을 따르되 공식 한도를 넘지 않는다. `Remaining` 0이면 `Reset`초, 429면 `Retry-After`초(최대 60초) 쉰다. 429는 자동 재시도하지 않는다. 그룹마다 따로 기다리며 한 그룹의 대기가 다른 그룹을 막지 않는다. 현재가 폴링은 한도 대기가 1초를 넘으면 요청을 보내지 않고 바로 실패로 돌린다(보호 폴링 공백 방지, PR #41 검토). 토큰 재발급이 필요한 경우의 발급 그룹(`AUTH`) 대기에도 1초 상한을 둔다. 넘으면 발급하지 않고 실패하며 다음 발급은 60초 하한을 따른다(PR #41 독립 QA F1).
4. 토큰: 401 `expired-token`·`invalid-token`이면 토큰을 버리고 한 번만 다시 부른다. 401 `token-revoked`(같은 Client ID로 다른 곳이 새 토큰을 받음)면 곧바로 다시 받지 않고 10분 동안 호출을 막은 뒤 한 번 다시 받는다. 단, 끊긴 토큰이 이 호출기가 이미 새로 받아 바꾼 이전 토큰이면(동시 요청 중 자기 재발급) 쉬지 않고 새 토큰으로 한 번 다시 보낸다(PR #41 architect F4). 쉬는 동안에는 어떤 경로로도 새 토큰을 받지 않고, 같은 토큰으로 진행 중이던 다른 요청이 끊겨도 다시 보내지 않는다(F5). 그동안 플러그인은 DEGRADED다. 토큰 발급 거절(400·401·403)은 ADR-003 4장 인증 실패 규칙(60초 하한, 연속 3회 DEGRADED, 2분부터 두 배씩 30분)을 따른다. 403은 허용 IP 미등록으로 안내한다. 수명이 20분 미만인 토큰은 수명의 절반이 지난 뒤에만 다시 받는다(호출마다 재발급해 같은 Client ID의 다른 토큰을 끊는 일 방지, PR #41 risk-ops F2).
5. 이 플러그인은 어느 프로세스에도 아직 연결하지 않는다. 토큰이 Client ID당 1개라 토큰을 받을 프로세스를 정한 뒤(Q-042) 연결한다. `GatewayMain`이 토스를 건너뛰는 동작(D-039)은 그대로다.

## 대안 비교
| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 읽기 전용 플러그인만, 연결 없음(채택) | 실행 동작 변화 0, 토큰 충돌 0. 명세 기반 코드·테스트 확보 | 바로 쓰는 기능 없음 | 채택 |
| B. 게이트웨이에 토스 폴링·조회 명령 연결 | 키 넣으면 바로 시험 | 7단계 실전 엔진 토큰과 서로 끊음, 열린 PR #39·#40과 같은 빌드 파일 수정 | 버림(Q-042 뒤 재검토) |
| C. `token-revoked`도 즉시 재발급 | 단순 | 상대 프로세스 토큰을 계속 끊는 왕복 | 버림 |
| D. `token-revoked`면 사람이 풀 때까지 정지 | 상대를 절대 끊지 않음 | 무인 시 보호 폴링이 영영 멈춤 | 버림(7단계 엔진 쪽은 risk-ops가 다시 정함) |

## 영향과 남은 위험
- `[사실]` 지금 실행 중인 프로세스의 동작은 바뀌지 않는다(연결 없음).
- 한도 숫자는 개요 문서를 요약 도구로 읽은 값이라 첫 실호출 헤더로 다시 확인한다. 콤마 인코딩, 점 표기 미국 티커 형식은 `[가정]`(요약 9장).
- 토스 FAQ는 "모든 프로세스가 하나의 토큰을 쓰라"고 한다. 게이트웨이와 실전 엔진이 별도 프로세스인 우리 구조와 맞추는 방법은 Q-042로 남긴다.
- 주문 멱등 키 `clientOrderId`(36자, 점 불가, 10분 유효)와 우리 멱등 키 규칙의 차이는 7단계 risk-ops 입력으로 넘긴다(요약 6장).
- 되돌릴 조건: 실측 한도가 10회보다 작아 429가 반복되면 시작값을 낮춘다. 토스가 Client ID를 여러 개 허용하면 B안을 다시 본다.
