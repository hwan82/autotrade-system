# 수집 소스 라이선스·약관 조사: Python 수집기(Q-007)와 OpenDART 로컬 저장(Q-026)

- 작성: data-engineer · 확인일: 2026-10-10 (KST)
- 입력: [D-019](../decisions/D-019-python-collector.md), [D-038](../decisions/README.md)(2단계 일봉 범위), [D-041·D-042·D-043](../decisions/D-041-selection-x-signal-combinations.md), [기획서](../spec/autotrade-spec.md) MD-07·09·11, 14장 배치표 1번, [ADR-003](../adr/ADR-003-market-data.md) 2.6장
- 표기: `[사실]`(공식 출처 있음), `[추론]`, `[가정]`(확인 방법 함께 적음)
- 이 문서는 법률 자문이 아니다. 약관 문구를 읽고 이 프로젝트 용도(개인 PC의 비공개 실험, 원자료 재배포 없음)에 맞춰 해석한 것이다.

## 0. 결론

1. **일봉·상장주식수·종목 이력의 출처는 KRX Open API(`openapi.krx.co.kr`)로 정한다.** 한국거래소 공식 API이고, 약관이 비상업 목적 이용, 하루 10,000회, 제3자 제공 금지, 화면 출처 표시를 조건으로 건다. 개인 실험용 로컬 저장은 이 조건 안에 든다 `[추론]`. (2.1장)
2. **pykrx·FinanceDataReader 같은 스크래핑 라이브러리는 쓰지 않는다.** 라이브러리 코드는 MIT지만 데이터를 긁어 오는 KRX 정보데이터시스템(`data.krx.co.kr`) 약관이 2026-08-29 시행판에서 "자동화 수단을 이용하여 정보를 무단 수집·복제·배포하는 행위"를 금지한다. D-019가 예로 든 pykrx는 이 이유로 버린다. (2.2·2.3장)
3. **OpenDART 재무 데이터의 개인 실험용 로컬 저장은 허용된다고 본다(Q-026 닫음).** OpenDART 약관에는 저장·복제를 막는 조항이 없고, 제16조 ①의 금융감독원 저작권은 "오픈API 서비스 및 관련 프로그램"에 대한 것이다. 약관에 없는 저작권 사항은 제16조 ④에 따라 저작권법·공공데이터법을 따르는데, 공공데이터법 제3조 ④는 영리적 이용도 원칙적으로 막지 못하게 한다. 조건은 인증키 비공개, 호출량 준수, 원자료 재배포 안 함이다. (3장)
4. **사용자에게 물을 것 1건(Q-036)**: KRX Open API의 "비상업적인 목적" 조건이 7단계 실전 매매용 선정 결과(STR-19)에도 맞는지는 약관 문구만으로 판단하기 어렵다. 실험실(1~6단계)은 개인 비공개 연구라 문제없다고 보고 지금 진행하고, 실전용은 7단계 전에 사용자가 한국거래소에 문의하는 것을 추천한다. 결과가 부정적이면 실전용 선정 입력만 공공데이터포털 금융위원회 주식시세정보로 바꾼다. (4장)
5. **과금 없음.** 두 소스 모두 약관·서비스 목록에 요금 조항이 없고 인증키 발급만 필요하다. KRX Open API 무료는 2차 자료로만 확인해 `[가정]`으로 둔다. (2.1장)
6. **수집기 키는 `secrets.json`에 넣지 않고 수집기 전용 비밀 파일에 둔다.** 공식 REST만 쓰게 되어 Python 수집기를 유지할지 Java 일괄 명령으로 바꿀지(Q-037, 추천 Java)는 architect ADR로 정한다. D-038 되돌릴 조건은 걸리지만 수집기를 2단계에 넣지 않는다. (7장)

## 2. 일봉·상장주식수·종목 이력 소스 (Q-007)

### 2.1 KRX Open API — 채택

[사실] [KRX Open API 이용약관](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp), 부칙 "이 약관은 2025년 12월 26일부터 시행한다." 2026-10-10 확인.

| 조항 | 원문(발췌) | 우리 쪽 영향 |
|---|---|---|
| 제6조 | "API 이용자는 API 서비스를 비상업적인 목적으로만 이용할 수 있으며, API 서비스를 이용한 결과에 대한 대가를 제3자에게 청구해서는 아니된다." | 실험실 이용은 개인 비공개 연구라 비상업 목적 `[추론]`. 실전 매매 입력은 4장 Q-036 |
| 제6조 | 결과에 다른 내용을 삽입하거나 왜곡하는 것 금지, "API 서비스의 결과를 API 이용자가 왜곡한 경우 … 민사․형사적 필요한 조치" | 원시값을 그대로 스냅샷에 담고, 수정 계수는 별도 열로 둔다(ADR-003 형식 그대로). 품질 검사에서 뺀 행은 품질 리포트에 남긴다 |
| 제8조 | "하나의 키당 1일(매일 0시~24시) 10,000회 이하의 요청으로 제한하며, 이를 초과할 경우 서비스가 중지될 수 있다." | 수집기 일일 호출 상한을 10,000 아래로 설정(기본 8,000 추천). 날짜 하나에 API 하나를 1회 부르므로, 2010년 이후 전체 이력은 유가증권·코스닥(약 4,150거래일)과 코넥스(2013-07 이후 약 3,250거래일) 각각 일별매매정보와 종목기본정보를 날짜마다 받으면 약 23,000회다. 하루 8,000회면 사흘에 나눠 받는다. 종목기본정보를 날짜마다 받지 않고 상장 변동일에만 받으면 줄어든다 `[추론]` |
| 제8조 | "한국거래소에서 발급된 인증키는 12개월간 미사용시 사전 공지 없이 삭제될 수 있다." | 매일 증분 수집이 키를 살려 둔다 |
| 제10조 ① | "한국거래소가 제공하는 API 서비스 및 관련 프로그램의 저작권은 한국거래소가 보유한다." | — |
| 제10조 ③ | "API 이용자가 API 서비스를 이용한 결과를 사용하여 화면을 제작한 경우, 해당 화면에 "한국거래소 통계정보"를 사용한 결과임을 명시해야 한다." | 이 데이터로 만든 실험 화면·리포트에 출처 문구. ui-dev 변경 제안(6장) |
| 제11조 ② | "API 이용자는 한국거래소로부터 제공받은 정보를 제3자에게 제공할 수 없다." | 원시 스냅샷을 저장소·공유 폴더에 올리지 않는다(D-019가 이미 커밋 금지). 테스트 픽스처는 합성 데이터만 |
| 제11조 ③ | 이용계약 종료 후에는 제공받은 정보를 이용할 수 없다 | 키 만료·해지 시 그 키로 받은 스냅샷을 실험 입력으로 쓰지 않는다. manifest에 출처 약관과 수집 키 별칭을 남긴다 |

- [사실] 제공 범위([서비스 목록](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd), 2026-10-10 확인): 유가증권·코스닥 일별매매정보와 종목기본정보는 2010-01-04부터, 코넥스는 2013-07-01부터.
- [사실] 이용 절차: 인증키 발급 뒤 쓸 API마다 따로 이용 신청과 승인이 필요하다. 승인 전 호출은 `401 Unauthorized API Call`([2차 자료 예제 저장소](https://github.com/skkimjj/krx-openapi-examples)이므로 `[가정]`, 첫 호출에서 확인).
- [가정] 요금: 약관과 서비스 목록에 요금 조항이 없고, 2차 자료([seokhoonj/krx-openapi](https://github.com/seokhoonj/krx-openapi))가 "무료 인증키"라고 적는다. 확인 방법: 키 신청 화면에서 요금 안내 여부를 본다. 유료로 바뀌면 과금 멈춤 조건(지침 8장 1번)으로 사용자에게 묻는다.
- [가정] 응답 필드: 일별매매정보에 상장주식수(`LIST_SHRS`)·시가총액(`MKTCAP`)·소속부가 들어 있다고 본다. 2차 자료 예제가 상장주식수 변화로 액면분할을 감지하므로 상장주식수는 있을 가능성이 높다 `[추론]`. 확인 방법: 첫 호출 응답 필드 목록을 수집기 테스트 고정값으로 남긴다.
- [추론] 상장폐지 종목: 날짜별 조회가 "그날 상장된 전 종목"을 돌려주므로 날짜별 결과를 합치면 2010년 이후 상장 기간이 재현된다(생존편향 제거, 지침 5장). 2010년 이전 유니버스는 없다.
- [사실] 원시가: 2차 자료 예제가 2018-05-03 삼성전자 2,650,000원 → 2018-05-04 51,900원 사례로 수정주가가 아님을 보인다. 수정 계수는 따로 만든다(5장).

### 2.2 KRX 정보데이터시스템 직접 수집, pykrx — 버림

[사실] [KRX 정보데이터시스템 홈페이지 이용약관](https://data.krx.co.kr/contents/MDC/INFO/informationController/MDCINFO003.cmd), "이 약관은 2026년 8월 29일부터 시행한다." 2026-10-10 확인.

- 제10조(금지행위) ②: "자동화 수단을 이용하여 정보를 무단 수집·복제·배포하는 행위"
- 제12조 ②: "이용자는 당 사이트의 정보를 거래소의 사전 허락 없이 복사·복제·배포·전송·공중송신하여서는 아니 됩니다."
- 제12조의2: 마켓데이터 상품은 별도 「마켓데이터 상품 구매 및 이용약관」을 따른다(유료 상품 경로, 이번 범위 밖).

[사실] [pykrx](https://github.com/sharebook-kr/pykrx)는 코드 라이선스 MIT([PyPI](https://pypi.org/project/pykrx/), 최신 1.2.9, 2026-09-19)이고, README 면책 문구가 "본 라이브러리는 KRX(한국거래소) 및 Naver의 데이터를 스크래핑하며, 데이터의 저작권은 각 제공처에 있습니다.", "상업적 용도 사용 시 데이터 제공처의 약관을 준수해야 합니다."라고 쓴다. 지금은 일부 API에 KRX 회원 로그인(`KRX_ID`·`KRX_PW`)이 필요하다.

[추론] pykrx는 정보데이터시스템 화면용 엔드포인트를 프로그램으로 호출하므로 제10조 ②의 "자동화 수단을 이용한 무단 수집"에 해당한다. 같은 데이터를 공식 API(2.1)로 받을 수 있으니 약관 위반 위험을 질 이유가 없다. 또 회원 계정 ID·비밀번호를 수집기에 넣어야 해 비밀값 관리 부담이 생긴다.

### 2.3 FinanceDataReader — 버림

[사실] [FinanceDataReader](https://github.com/FinanceData/FinanceDataReader)는 MIT이고, 일봉 기본 출처가 Naver("지정하지 않은 경우 (NAVER에서 가져오며 2000년 이후 데이터)"), `KRX:` 접두어는 한국거래소 데이터다. [추론] KRX 쪽은 2.2와 같은 이유로, Naver 쪽은 포털 화면 데이터를 공식 API 없이 긁는 방식이라 같은 위험이 있다. Naver 약관 원문은 확인하지 않았다 `[가정]`. 쓰지 않으므로 확인은 하지 않는다.

### 2.4 공공데이터포털 금융위원회 주식시세정보 — 예비

[가정] 공공데이터법 제3조 ④는 다른 법률의 특별 규정이나 제28조 ① 사유가 없으면 공공기관이 공공데이터의 영리적 이용을 금지·제한하지 못하게 한다(법률 제21392호, 2026-08-28 시행. law.go.kr은 이 환경에서 접근이 막혀 [2차 사본](https://www.nepla.ai/law/공공데이터의-제공-및-이용-활성화에-관한-법률)으로 확인, 원문 대조 전이라 `[가정]`. 확인 방법: law.go.kr 원문).

[가정] 데이터셋 [금융위원회_주식시세정보](https://www.data.go.kr/data/15094808/openapi.do)는 이용허락범위 "제한 없음", 상장주식수·시가총액 포함, 영업일 하루 늦게 갱신, 수록 기간은 2020년 무렵부터라고 알고 있으나 포털이 자동 조회를 막아(robots) 확인하지 못했다. 확인 방법: 사용자 브라우저나 키 신청 화면에서 "이용허락범위"와 수록 시작일을 본다.

판단: 수록 기간이 짧아 다년 워크포워드(D-043 중기 선발)에 모자랄 수 있고 확인도 덜 됐다. 1순위로 두지 않고, Q-036 답이 부정적일 때 실전용 선정 입력의 대체 소스로 둔다.

### 2.5 대안 비교

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **A. KRX Open API** | 공식 API, 약관이 이용 조건을 명시, 2010년 이후, 상장주식수 포함 `[가정]` | 비상업 한정, 하루 10,000회, 제3자 제공 금지, 원시가만 | **채택** |
| B. pykrx(정보데이터시스템 스크래핑) | 구현 쉬움, 1990년대 이력 | 사이트 약관 제10조 ② 위반 소지, 회원 비밀번호 필요, 화면 변경에 깨짐 | 버림 |
| C. FinanceDataReader | 여러 출처 통합 | B와 같은 약관 위험 + Naver 약관 미확인 | 버림 |

## 4. 사용자에게 물을 것: Q-036

**질문**: KRX Open API 데이터를 7단계 실전 매매용 선정 결과(STR-19)의 입력으로도 써도 되는지, 7단계 전에 한국거래소에 문의할까요?

- 왜 묻나: KRX Open API 약관 제6조는 "비상업적인 목적으로만"이라고 하는데 "비상업"의 정의가 없다. 개인 비공개 실험(1~6단계)은 비상업으로 보는 것이 자연스럽다 `[추론]`. 개인 계좌의 실전 매매 판단에 쓰는 것은 제3자에게 대가를 받는 서비스는 아니지만 수익 목적의 이용이라 해석이 갈릴 수 있다. 지침 8장 6번(법적·규정상 우려)에 해당해 사용자 결정으로 둔다.
- 선택지
  1. **(추천) 실험실은 지금 KRX Open API로 진행하고, 7단계 전에 사용자가 한국거래소 Open API 문의 창구에 "개인 계좌 매매 판단용 이용이 비상업 목적에 드는지"를 묻는다.** 답이 부정적이면 실전용 선정 입력만 공공데이터포털(2.4)로 바꾼다. 실험실 데이터와 실전 입력이 갈리면 실전용 스냅샷도 같은 품질 검사를 통과해야 한다.
  2. 처음부터 실전·실험 모두 공공데이터포털로 간다. 약관 걱정이 적지만 수록 기간이 짧고(가정) 2010~2019 다년 워크포워드를 못 할 수 있다.
  3. 문의 없이 개인 이용이므로 비상업으로 보고 실전에도 쓴다. 가장 빠르지만 해석 위험을 그대로 진다.
- 막히는 것: 없음. 실전 계좌의 조합 지정은 7단계(배치표 5번)라 그 전까지 결정하면 된다. 그 전에는 1번으로 진행한다.

## 7. 수집기 키 보관, 수집기 언어, 2단계 범위 (PR #36 architect 검토 반영)

### 7.1 수집기 키는 `secrets.json`에 넣지 않는다
[사실] `secrets.json`에는 증권사 app-key·app-secret, 계좌번호, 운영자 비밀번호 해시가 함께 있다([config-keys.md](../config/config-keys.md) 예시). Python 수집기가 이 파일을 읽으면 D-019 3장 경계("증권사 API 키·토큰·계좌 정보를 다루지 않는다")를 어긴다. 또 architect 검토에 따르면 Java 설정 로더는 모르는 키가 있으면 파일 전체를 거부하므로, 사용자가 수집기 키를 넣으면 4개 프로세스가 증권사 키 없이 뜰 수 있다.

결정(D-050 ⑤): OpenDART·KRX Open API 키는 **수집기 전용 비밀 파일**에 둔다. 위치·형식은 architect 설정 ADR로 정한다(배치표 1번 시작 전). 그 전까지 사용자는 키 발급과 서비스 이용 신청만 하고 파일에는 넣지 않는다. D-041·Q-026 원문의 "`secrets.json` 등록" 표현은 이 결정으로 대체한다.

### 7.2 Python 수집기를 유지할지 (Q-037)
D-019가 Python을 허용한 이유는 국내 공개 라이브러리(pykrx 등)였다. 이번 조사로 그 라이브러리를 모두 버리고 공식 REST API 두 개(KRX Open API, OpenDART)로 정했으니 전제가 바뀌었다. D-019 되돌릴 조건("Java만으로 같은 데이터를 같은 품질로 확보할 수 있게 되면")에 가까워졌다 `[추론]`.

| 대안 | 장점 | 단점 |
|---|---|---|
| A. Python 수집기 유지 | 데이터 가공(pandas)이 쉬움, D-019 경계·CI 검사가 이미 있음 | 언어 2개, 키 파일을 Java와 따로 관리 |
| B. Java 일괄 명령(4개 프로세스 밖, D-042 실전용 선정 결과 생산자처럼) | 언어 1개, `SnapshotManifest` 등 기존 계약 재사용, 설정 로더 하나 | 일괄 명령도 실전 엔진과 격리해야 함(별도 실행, 같은 프로세스 금지) |

data-engineer 추천: **B**. 공식 REST 두 개는 Java로 충분하고 계약을 한 언어로 지킬 수 있다. 다만 모듈 배치와 설정 체계는 architect 경계라 Q-037로 남기고, 배치표 1번 시작 전 architect ADR에서 정한다. 7.1의 비밀 파일 위치도 이 결정과 같이 정한다.

### 7.3 D-038 되돌릴 조건 평가
D-038은 "Q-007이 2단계 재판정 전에 풀리면 수집기를 2단계에 넣는다"고 했고, 2단계는 아직 완료 판정 전이라 조건이 걸린다. **넣지 않는다**(D-050 ⑥).
- 수집기는 사용자 키 발급, KRX 서비스별 승인, 수집기 언어(Q-037)와 키 파일 결정이 먼저다. 2단계 완료는 이미 사용자 실녹화를 기다리는데, 여기에 이 선행 조건을 더하면 판정이 더 늦어진다.
- 수집기 결과가 필요한 때는 6단계 시작 전이다(D-038, D-041 3.4). 2단계에 넣어 얻는 것이 없다.
- 대안 "2단계에 넣기"는 버림. 되돌릴 조건: 2단계 QA 재판정이 일봉 실데이터를 완료 조건으로 요구하면 다시 본다.
