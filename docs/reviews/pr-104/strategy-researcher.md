## 권고 (막지 않음)

- R1. 후보 행은 `validationRuns` 전체(실패 구간 포함)를 더하고, 대조군 행만 "완료 시드 합"이라고 적었다. 후보 검증 Run이 전략 생성 뒤 실패하면 부분 왕복이 섞인다. 실패가 하나라도 있으면 종료 코드 2로 결과 자체를 쓰지 않으므로 실제 영향은 없지만, 표 머리 문구에 "후보는 검증 구간 합(실패 구간이 있으면 표를 쓰지 않음)"을 한 줄 넣으면 대조군 쪽 문구와 대칭이 된다.
- R2. 귀속 규칙의 한계 [추론]: 같은 종목에서 한 왕복의 청산 신호·체결과 다음 왕복의 진입·청산 신호가 같은 거래일에 모두 일어나면 같은 날 키를 덮어써 앞 왕복이 뒤 왕복의 사유를 받는다. 일봉 워크포워드(ADR-009)에서는 신호 다음 봉 체결과 재진입 금지 기간 때문에 생기지 않는다고 본다. 장중 리플레이에 이 표를 재사용할 때는 키를 (종목, 날짜)에서 (종목, 신호 시각)으로 바꾸거나 로트와 직접 잇는 것을 검토한다.
- R3. 해석 지침(report.md 작성 때): 이 표는 기술 통계다. 후보 비율과 대조군 비율의 차이에 검정을 붙이지 않았으므로 "후보의 손절 비중이 대조군보다 낮다" 같은 문장은 대조군 시드별 비율 분포(최소·중앙·최대) 없이 결론으로 쓰지 않는다. 필요하면 대조군 표처럼 시드별 분포를 후속으로 낸다. 후보 검증 왕복이 30건 근처면 비율 한 칸이 1건에 3%p씩 움직인다는 점도 같이 적는다.
- R4. "시간·최대 보유" 칸은 `timeExit`(시간 청산)과 `maxHoldDays`(최대 보유 거래일, STR-18)를 같은 `TIME_EXIT`로 센다. 4단계 후보는 스윙이라 실질적으로 최대 보유 쪽이지만, 단타 후보가 들어오면 두 사유를 나누는 편이 해석에 낫다(`ExitReason` 변경은 strategy 모듈 계약이라 architect 검토 대상).
- R5. PR #98 검토의 R3(`study-sha256` 직접 쓰기), R4(PR #79 권고 4·5·7)는 이 PR 범위 밖이며 그대로 유효하다.
