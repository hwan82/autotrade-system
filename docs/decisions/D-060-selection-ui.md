# D-060 선정 프로필 편집·조합 교차표·선정 결과 조회 화면 (배치표 4번)

- 날짜: 2026-10-11
- 상태: 확정 · **추천안 채택(자율)**(지침 8장)
- 담당: ui-dev. 교차 검토: architect(REST 계약·모듈 경계, 검토 원문 `docs/reviews/pr-<번호>/`)
- 근거: 기획서 UI-02·03·08, STR-02·15~17, MD-10, SIM-10, 14장 배치표 4번, [ADR-007](../adr/ADR-007-selection-combination.md) 2.1·2.2·2.3·2.6·5장(ui-dev 행), [ADR-005](../adr/ADR-005-ui-dashboard.md), [D-057](D-057-selection-catalog.md), [조합 실험 절차](../strategy/combination-experiments.md) 1장
- 범위: 실험실 화면과 실험실 REST만. 실전 계좌의 조합 지정·교체(배치표 5번), 실험 실행 명령·리플레이 연결(sim-engine 진행 중)은 건드리지 않는다. 실전 주문 경로·Guard·블랙리스트·리스크 한도 변경 없음

## 결정

1. **선정 프로필 저장**: 전략 프로필과 같은 불변 버전 파일 규칙·같은 YAML 모양으로 `<selections-dir>/<선정ID>/v<버전>.yaml`에 저장한다(Spring 속성 `autotrade.lab.selections-dir`, 기본 `selections`). 두 저장소의 파일 읽기·쓰기는 `VersionedProfileFiles` 하나로 공유하고(전략 프로필 저장소의 동작은 그대로이고, 오류 메시지 앞에 "전략 프로필"·"선정 프로필" 종류 이름이 붙는다. 예: "프로필이 없습니다" → "전략 프로필이 없습니다"), 화면에서 만든 파일은 실험 실행기의 순수 읽기 `SelectionProfileYaml`이 같은 선정 해시로 읽는다(테스트).
2. **저장 때 카탈로그 검사**: 예약 키(`SelectionProfile`: 가설·스타일별 갱신 주기·종목 수 상한)와 카탈로그(`SelectionCriteria.parse`: 모르는 키, 지표·연산·기간·재무 지표 시장)를 모두 통과해야 저장한다. 오타 키가 해시에만 섞이는 것을 막는다(D-057 1번과 같은 원칙). 읽을 때는 예약 키만 보고 카탈로그 문제는 `catalogProblem`으로 보여 준다(카탈로그가 바뀌어도 옛 버전 이력은 보이게).
3. **조건 행 편집기**(UI-03): 가설·갱신 주기·최대 종목 수, 하드 필터(상품 유형·최소 가격·최소 일봉 거래일), 자격 조건 행(지표·연산·기준값·기간, 화면 순서대로 `gate.01`부터 다시 번호), 선택 순위(`score.*`), 그 밖의 키(`notes.*`)로 나눈 폼이다. 선택지는 `GET /api/selection-catalog`(순수 모듈 enum)에서 받아 화면이 카탈로그를 복제하지 않는다. 갱신 주기 선택지는 스타일에 맞는 것만 보인다.
4. **조합 표시**(ADR-007 5장 ui-dev 행): 리더보드 "프로필" 열을 "조합(선정 × 전략)"으로 바꾸고 조합 해시를 함께 보인다. 선정이 없으면 "선정 없음". 계좌 상세 머리에 선정 프로필·전략 프로필·조합 해시, 자산 곡선 범례도 조합 이름이다. `format.js` `STYLE`에 `POSITION: '중기'`(ADR-007 2.3).
5. **교차표**(UI-02 "선정별·매매지표별 교차표, 칸마다 조합 해시와 대조군 대비 차이"): 행 = 선정(“선정 없음” 대조군 행은 맨 아래), 열 = 전략 프로필 버전, 칸 = 계좌 하나. 대조군 두 축(조합 실험 절차 1장 3번)을 모두 보인다: 같은 열의 선정 없음 칸 대비(선정 효과), 같은 행의 대조 열 대비(매매지표 효과). 차이는 서버가 `BigDecimal`로 빼서 문자열로 준다(화면은 계산하지 않는다, ADR-005 5장 공통 규칙). 행 대조 열은 화면이 ID에 `random`이 든 열을 기본으로 고르고 사용자가 바꿀 수 있다(화면 기본값일 뿐 판정 규칙이 아님). 교차표 아래에 다중 비교 주의 문구를 둔다.
6. **선정 결과 조회**(UI-03·08, MD-10): 계좌 화면에 날짜별 선정 기록(`run_selection_day`: 판정·사유, 선정 종목 수, 막은 신규 진입, 정정 대체 규칙 수), 날짜를 누르면 그날 쓴 결과(적용 범위, 입력 기준일, 선정 종목, 탈락 사유별 종목 수, 평가 행의 조건별 값). **정정 대체 규칙(MD-10 (2))** 은 결과 머리 경고 문구(편향 설명), 평가 행 "대체 규칙" 표시, 리더보드·날짜별 기록의 건수, "정정 대체 규칙 적용"만 거르기로 보인다. 결과 본문은 실험 등록 때 `ExperimentCatalog.register(spec, report, selectionResults)`로 함께 받고(실험실은 `CalculatedSelectionSource.results()`), 실험실이 선정을 다시 계산하지 않는다(조합 실험 절차 1장 7번). 본문 없이 등록된 결과는 기록만 보이고 "본문 없음"으로 표시한다. 실험 조합에 없는 선정의 결과는 등록을 거절한다.

## 대안과 되돌릴 조건

| 항목 | 고른 것 | 버린 것과 이유 | 되돌릴 조건 |
|---|---|---|---|
| 저장소 구현 | 공통 `VersionedProfileFiles` + 종류별 변환 | (a) 전략 프로필 저장소 복제: 같은 파일 규칙(append-only, 원자적 쓰기, 다시 읽어 해시 대조)이 두 벌로 갈라질 위험. (b) 순수 모듈에 쓰기 구현: 순수 모듈은 Jackson YAML 쓰기를 갖지 않고 쓰기는 실험실만 한다 | 두 종류의 파일 모양이 갈라지면(예: 선정에만 새 최상위 키) 변환 쪽에서 나눈다 |
| 저장 검사 범위 | 예약 키 + 카탈로그 | 예약 키만: 오타 키가 저장돼 실험 때 처음 실패 | 카탈로그 밖 실험 키가 필요해지면 `notes.*`처럼 예외 접두어를 카탈로그(strategy-researcher)에 더한다 |
| 편집기 | 구조화 폼(조건 행) | 키·값 행 편집기만(전략 프로필과 같음): UI-03 "조건 행(지표, 연산, 기준값, 기간)"을 채우지 못하고 오타가 잦음 | 카탈로그 문법이 바뀌면 폼을 같이 고친다(선택지는 서버에서 와서 지표 추가는 자동) |
| 차이 계산 위치 | 서버(`BigDecimal`) | 화면 JS(`Number`): 금액·비율을 화면에서 계산하지 않는 ADR-005 원칙 위반, 부동소수 오차 | 없음 |
| 선정 결과 본문 출처 | 실험 등록 때 함께 받음 | (a) 실험실이 조회 때 다시 계산: 같은 값을 두 번 계산하고 데이터 스냅샷 연결이 필요. (b) 결과 파일 읽기: 결과 파일 코덱은 실전 관련 별도 PR(D-057 6번) | 실험 결과 DB 저장 때 `run_selection_day`와 결과 메타 표로 옮긴다(ADR-007 2.5 V2 스키마) |

## 위험과 한계

- **실험 없이 하는 선정 미리보기는 아직 없다.** UI-03의 "날짜별 선정 결과·탈락 사유 미리보기"는 프로필 편집 화면에서 데이터 스냅샷으로 바로 계산하는 기능인데, 스냅샷 연결은 일봉 리플레이 연결 작업(sim-engine, 진행 중)이 정한다. 지금은 실험을 돌린 뒤 결과 조회 화면으로 본다. 후속 과제로 남긴다.
- 실험 생성 화면이 없어 "시장·스타일이 다른 조합은 화면에서 만들 수 없음"(UI-03)은 선정 프로필 화면의 "조합할 수 있는 전략 프로필" 목록(같은 시장·스타일만)과 `Combination` 생성자 검사로만 지킨다. 실험 생성 화면 작업 때 선택지를 같은 규칙으로 거른다.
- 실험 목록은 메모리뿐이다(ADR-005 8장). 지금 실험 실행 명령은 실험실 카탈로그에 등록하지 않으므로 교차표·선정 결과 화면은 샘플(`bootTestRun`)로만 확인했다. 실행 명령이 등록할 때 `register(spec, report, selectionResults)`를 쓰면 된다.
- 교차표는 같은 실험 안 칸끼리만 뺀다(지침 5장). 칸이 많으면 우연히 좋아 보이는 칸이 생기므로 판단은 조합 실험 절차의 다중 비교 기준을 따른다고 화면에 적었다. 화면 자체는 유의성을 판정하지 않는다.
