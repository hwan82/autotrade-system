# D-129 녹화 판정이 장중 순위 선정 계좌를 받는다: 입력 기록 레인마다 추적기를 따로 돌린다(D-127 후속)

- 날짜: 2026-10-20
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). `autotrade-sim`과 `autotrade-selection`(시각 범위 표 정리)만 바꾼다. 실전 경로, RealTradingGuard, 블랙리스트 규칙, 리스크 한도, 게이트웨이, 보호 경로는 바꾸지 않는다. 등록 파일에 장중 순위 선정이 없으면 판정·녹화 실험 결과 파일이 지금과 바이트로 같다(선정 없는 등록, `PRE_OPEN_DAILY` 선정만 있는 등록 모두 main과 `cmp`로 확인).
- 담당: sim-engine. 교차 검토: architect(코드), strategy-researcher(판정 해석)
- 근거: [D-127](D-127-intraday-at-selection.md) 7·12번(녹화 판정 후속), [D-126](D-126-live-judgement-selection-accounts.md)(선정 계좌 판정), [D-116](D-116-stage-6-recording-judgement.md)(녹화 판정), [ADR-012](../adr/ADR-012-intraday-selection.md) 3.3·5.2, architect PR #200 R1·R2·R3·R5·R6·n1, architect PR #199 R3·R4, strategy-researcher PR #199 R5. 번호: 열린 브랜치 전부의 결정 로그 최대가 D-127이라 D-129을 쓴다.

## 결정

1. **녹화 판정(`runLiveJudgement`)이 장중 순위 선정(`INTRADAY_AT`) 계좌가 있는 등록을 받는다.** 장전 선정(D-126)과 한 등록에 섞여도 된다.
2. **입력 기록 레인마다 추적기를 따로 둔다**(architect PR #200 R6). 실행기의 레인 경로(`runLanes`)는 레인마다 그 레인 명세의 장중 선정으로 `IntradayTracker`를 새로 만들고, 첫 번째 읽기에서 같은 이벤트를 같은 순서로 준다. 레인끼리 나눠 쓰는 것이 없어 레인 결과는 그 레인 하나만 돈 결과와 같다(시험으로 확인). 입력 기록 레인(BASE·PERTURB·지연 0/1.5/2초·대조군 시드)은 모두 같은 기록을 읽으므로 같은 날 같은 후보를 같은 적용 시작 순번부터 산다. 주문 지연은 이벤트를 바꾸지 않으므로 순위에 영향이 없다.
3. **대조군**: 지금 규칙 그대로다. 대조군은 선정 묶음(선정 프로필마다)마다 하나이고, 장중 순위 선정 판정 대상에는 같은 장중 선정 + `kr-random-control` 대조군이 있어야 한다. 시드 레인은 `<ID>-S<k>-NULL<i>`(k는 장전·장중을 합친 선정 묶음 순서), m은 모든 묶음의 판정 대상 수, 묶음마다 N = 21m − 1이다.
4. **녹화 리플레이(L11)는 녹화 이벤트로 따로 순위를 매긴다.** 적용 시작 순번은 기록마다 순번이 달라 입력 기록 순위를 옮길 수 없다. L11은 "녹화만으로 같은 등록을 돌렸을 때"와의 차이라서 순위 차이도 그 안에 들어가는 것이 맞다. 대신 순위가 같은지를 `judgement.md`에 날짜·선정마다 적는다(아래 5번).
5. **`judgement.md`에 장중 순위 표**: 장전 선정 표(9장)가 있으면 10장, 없으면 9장 "장중 순위 선정(D-127)". 입력 기록이 있는 거래일 × 장중 선정마다 순위 시각, 선정 수, 후보, BLACKLISTED, 적용 시작 순번, 막힌 신규 진입(BASE), 녹화(L11) 후보가 같은지. 그날 순위 시각 전에 기록이 끝나면 "순위 없음"이다. 표에 쓸 순위는 같은 추적기를 입력 기록에 한 번 더 돌려 만든다(순수 계산이라 레인과 같은 값). 머리말에 장중 계좌 설명 한 줄이 더해지고, 6장 소제목은 장중 선정 묶음에도 붙는다.
6. **조합 실험(일봉, `runCombination`)은 `INTRADAY_AT`을 계속 거절한다**(D-127 12번 그대로). 일봉 리플레이에는 09:30 전 체결이 없어 순위를 매길 수 없다. 장중 선정 × 매매지표 조합은 녹화 실험(D-127)과 실시간 모의·녹화 판정(이 결정)으로 본다.
7. **함께 정리한 것**(판정 결과에 영향 없음)
   - 실행기 장중 입력 범위를 생성 뒤 바뀌는 필드에서 새 실행기를 돌려주는 `withIntradayUniverse`로 바꿈(architect PR #200 R5).
   - 순번 없이 묻는 `SelectionDay.allowsEntry(Symbol)` 삭제. 순위 시각 전 진입을 열 수 있어서다(R1).
   - `at` 허용 범위를 `SelectionProfile.AT_RANGES` 표 한 곳에 두고, 시작이 거래소 캘린더 정규장 시작 + 1분, 끝이 정규장 끝 30분보다 앞인지 시험으로 묶음(R2). 범위 값은 그대로(KRX 09:01~14:30, 미국 09:31~15:00).
   - 공백 끝이 정확히 09:00:00(정규장 첫 순간)이면 `SESSION_GAP`으로 둔다(n1). 잃은 체결이 없을 수도 있지만 표본만 빠지는 보수적 동작이라 그대로 두고 시험으로 고정한다. 08:59:59에 끝난 공백은 표시하지 않는다.
   - 일봉 스냅샷 폴더 이름 `"krx-daily"`를 `SnapshotHeap.KRX_DAILY` 한 곳에 둠(architect PR #199 R4).
   - 녹화 실험이 일봉 스냅샷을 읽기 전에 힙 검사를 부르는지 시험(최대 힙 주입, architect PR #199 R3).
   - L10 줄의 N이 그 계좌 선정 묶음 분포의 N인지 시험(strategy-researcher PR #199 R5).
   - 장전 + 장중 섞인 등록의 끝단 시험: 녹화 실험(`inputs.yaml`에 `selection-input`·`intraday-selections` 둘 다, 장전 계좌는 장전 선정만 있는 실험과 같은 체결)과 실시간 → 리플레이 확인 → 녹화 판정(architect PR #200 R3).

## 대안 비교

| 쟁점 | 채택 | 버린 안과 이유 | 되돌릴 조건 |
|---|---|---|---|
| 레인 순위 | 레인마다 추적기 | 레인 0 추적기를 모든 레인이 나눠 씀(PR #200 방식): 지금은 같은 이벤트라 값이 같지만, 레인이 서로 다른 입력을 읽는 날 조용히 틀린 순위를 씀. 레인 독립 원칙(D-116 "레인끼리 공유하는 것 없음")과도 어긋남 | 레인 수 × 장중 선정 수가 커져 추적기 메모리·첫 읽기 시간이 측정으로 문제가 되면 같은 입력 레인끼리만 나눠 쓰기 |
| L11 녹화 순위 | 녹화 이벤트로 따로 | 입력 기록 순위를 녹화에 옮김: 적용 시작 순번이 기록마다 달라 시각으로 바꾸는 새 규칙이 필요하고, 녹화만으로 돌린 결과와 달라짐 | 녹화와 입력 기록의 순위 차이가 잦아 L11이 순위 차이로만 탈락하는 것이 확인되면 L11 판정에서 순위 다른 날을 빼는 규칙(사전 등록 전) |
| 보고서 순위 | 입력 기록에 추적기를 한 번 더 | 실행기 결과에 순위를 실어 보냄: 모든 실행 경로의 보고서 형식이 바뀜 | 판정 시간이 문제가 되면 |
| 조합 실험 | 거절 유지 | 일봉으로 근사(시가·고가로 순위): 09:30 전 정보가 아닌 하루 전체 값이라 미래 정보 | 장중 분봉 스냅샷이 생기면 |

## 위험과 한계

- 판정이 장중 선정이 있으면 입력 기록과 녹화를 한 번씩 더 읽는다(순위 표용). LIVE01 규모에서 판정 시간이 몇 % 늘어난다 `[추론]`. 대조군 레인은 선정 묶음마다 N개라 장중 선정 하나를 더하면 대조군 Run이 21m − 1개 늘어난다(D-126 위험과 같음).
- 녹화(L11) 순위가 입력 기록과 다르면 그날 L11 차이에 순위 차이가 섞인다. 10장 "녹화(L11) 후보" 칸이 **다름**인 날이 있으면 L11 결과를 그 점과 함께 읽는다.
- 장중 선정의 순위는 boards 안 순위다(D-127 위험 그대로). 판정 결과를 시장 전체 장중 순위 성과로 읽지 않는다.
- (마) `kr-intraday-open-momentum`은 녹화 실험 사전 검사(D-127 11번) 통과 전에는 LIVE02에 등록하지 않는다. 이 결정은 판정 도구만 준비한다.
