# D-133 KRX 실제 거래대금(`ACC_TRDVAL`) 수집: 일봉 스냅샷 선택 파일 `daily_turnover.csv`

- 날짜: 2026-10-20
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 담당 data-engineer. 교차 검토: architect(코드), strategy-researcher(지표·프로필 적용 시점 상담).
- 근거: [ADR-012](../adr/ADR-012-intraday-selection.md) 3.2(49행)·6장 후속 F1, PR #193 strategy-researcher R2(`docs/reviews/pr-193/strategy-researcher.md` 53행: `avg-turnover` 근사 c 종가 × 거래량은 고가 마감 쪽으로 기운다), [ADR-008](../adr/ADR-008-collector.md) 2.3·2.4
- 번호: D-132는 녹화 입력 기록 순서 고정 스레드(`claude/project-thread-astsat`)가 써서 D-133을 쓴다.
- 실전 경로, RealTradingGuard, 블랙리스트, 리스크 한도, 게이트웨이, 보호 경로(`autotrade-marketdata` 포함)는 바꾸지 않는다. 바뀌는 코드는 `autotrade-app-collector`뿐이다.

## 결정

1. **수집**: `KrxOpenApiClient`가 일별매매정보 응답의 `ACC_TRDVAL`(원)을 읽는다. 칸이 없거나 비거나 `-`면 값 없음(`null`)으로 두고 일봉 수집은 멈추지 않는다. 음수·소수면 원자료 이상이라 멈춘다. 필드 이름은 다른 필드처럼 `[가정]`이고 첫 실행 품질 리포트로 확인한다(runbook 3.8). 원문 캐시를 그대로 다시 읽으므로 **다시 받지 않는다**(API 호출 없음).
2. **형식**: `krx-daily` 스냅샷에 선택 파일 `daily_turnover.csv`(`market,code,date,turnover`)를 더한다. 일봉을 쓴 행 중 값이 있는 행만, KRX 값 그대로(원가격 기준 금액이라 수정 계수를 곱하지 않음). 거래정지일 0원도 그대로 둔다. `daily_bars.csv`·`instrument_history.csv`·`listed_shares.csv` 형식과 내용, `DailyBar`, manifest 스키마 버전(1)은 그대로다. 이 파일이 있는 스냅샷이 "형식 v2"이고, 없는 스냅샷(D-133 전 전부)은 "거래대금 없음"이다.
3. **ID**: 거래대금 파일을 쓰면 ID 해시 기준이 `daily_bars.csv`와 `daily_turnover.csv` 둘이다(`<이름>:<SHA-256>\n` 줄들의 SHA-256, 공시 스냅샷 D-123과 같은 규칙). 같은 캐시라도 D-133 전과 **다른 ID**가 나온다. 일봉 해시만 쓰면 같은 ID의 옛 폴더가 이미 있어 새 파일이 버려진다(`SnapshotWriter`는 같은 ID 폴더를 덮어쓰지 않음).
4. **옛 ID 재현**: `krx-daily --without-turnover`는 거래대금 파일 없이 일봉만 해시해 D-133 전과 같은 형식·같은 ID를 만든다(테스트: 일봉 파일 바이트 동일, ID = 일봉 해시). 실험이 고정한 옛 스냅샷(예: EDGE01 `krx-daily-2026-10-16-a6df4719`, 4단계 사전 등록)을 지운 뒤 다시 만들어야 할 때 쓴다. 옛 스냅샷과 그 결과는 이 결정으로 바뀌지 않는다.
5. **품질 검사(경고만)**: 거래대금이 저가 × 거래량 ~ 고가 × 거래량(원가격) 밖인 행을 세고 앞 20건을 품질 리포트 "실제 거래대금" 칸과 콘솔 한 줄에 적는다. 거래량이 있는데 0원, 거래량 0인데 금액이 있는 행도 여기 걸린다. KRX 하루 거래대금에는 시간외 거래·대량매매가 들어갈 수 있어 정상 거래도 걸릴 수 있으므로 오류로 막지 않는다 `[추론]`. 비율이 크면 단위·필드 착오를 의심한다. 응답에 값이 하나도 없으면 크게 알린다.
6. **이번에 하지 않는 것**(strategy-researcher 상담, 다음 PR):
   - 선정 지표 `turnover`(c에서 끝나는 w거래일 `ACC_TRDVAL` 단순 평균, 수정 안 함, 기존 `avg-turnover`는 그대로 두어 해시 불변)와 읽는 쪽 `SnapshotTurnover`(selection 모듈). 필드 존재를 첫 실행으로 확인한 뒤 넣는다. 결측 규칙 제안: 스냅샷에 파일 없음 → 계산 전체 실패(근사로 조용히 대체 금지), 파일 범위가 c 미만 → `STALE_INPUT`, 그날 행만 없음 → `NO_DATA`, 거래정지 0원 → 0으로 평균.
   - 프로필 v2(`kr-watchlist-turnover`, (다)·(라)·(라) 대조): 지금 만들지 않는다. EDGE01과 LIVE02 후보 C1~C3은 v1에 고정이고 엣지 검사를 다시 돌려야 하므로, LIVE02 등록 뒤 새 EDGE 실험(새 ID)으로 돌리고 v1과의 선정 겹침을 기술 통계로 남긴다. 감시 종목 목록(D-122)은 LIVE01·LIVE02 진행 중에 바꾸지 않고 다음 목록 갱신 때 바꾼다.

## 대안

| 안 | 내용 | 판단 |
|---|---|---|
| A. `daily_bars.csv`에 `turnover` 열 추가, manifest 스키마 버전 2 | 한 파일에 같이 | 버림. `SnapshotDailyBarSource`·`SnapshotFiles`(정확히 1만 받음)·`DailyBar`(브로커 일봉 차트도 만듦)가 있는 `autotrade-marketdata`는 보호 경로라 실전 관련 PR이 되고, 버전을 올리면 지금 실험실·선정 코드가 새 스냅샷을 못 읽는다. 일봉 해시가 바뀌어 옛 ID 재현 경로도 없어진다 |
| **B. 선택 파일 + 두 파일 해시 ID + `--without-turnover`** | 이번 결정 | 채택. 읽는 쪽 무변경(선택 파일은 무시), 옛 형식·옛 ID 재현 가능, 보호 경로 밖 |
| C. 선택 파일, ID는 일봉 해시만 | ID 불변 | 버림. 같은 ID 폴더가 있으면 새 파일이 버려지고, 거래대금 값이 달라도 ID가 같아 결정론이 깨진다 |

**되돌릴 조건**: 첫 실행에서 `ACC_TRDVAL`이 없으면(리포트 "응답에 ACC_TRDVAL이 없습니다") 필드 이름을 원문으로 확인해 고치거나, 제공하지 않으면 거래대금 파일 쓰기를 기본 끔으로 되돌리는 새 결정을 낸다.

## 위험

- `ACC_TRDVAL` 존재와 단위(원)는 `[가정]`이다. 범위 검사와 콘솔 줄이 첫 실행에서 드러낸다.
- 당일 거래대금은 시간외 단일가가 끝난 뒤 확정된다 `[가정]`. 수집기는 서울 18:00 전이면 기본 `--to`를 어제로 두고 오늘 응답은 캐시하지 않는다(ADR-008 2.3). 18:00 직후 실행은 최근 날 값이 덜 집계됐을 수 있어 runbook대로 18:30 이후에 돌린다.
- 매일 운영에서 새 ID가 생기므로 같은 날 이 변경 전후 스냅샷 ID가 다르다. 실험·선정 결과는 ID로 입력을 고정하므로 비교는 같은 ID끼리만 한다. 근사(`avg-turnover`)와 실제(`turnover`) 결과를 비교할 때도 같은 스냅샷 ID·같은 기간끼리만 하고 어느 지표를 썼는지 적는다.
- 디스크: 거래대금 파일은 약 970만 행, 한 줄 약 35바이트로 일봉 파일의 약 60% 크기 `[추론]`.
