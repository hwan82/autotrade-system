# D-076 실시간 시세 전달(게이트웨이 → 실험실)과 실시간 모의 세션

- 날짜: 2026-10-14
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 실전 주문 경로·RealTradingGuard·블랙리스트·리스크 한도·장애 대응 규칙은 바꾸지 않는다. 다만 게이트웨이(7단계에 실전 엔진과 함께 쓰는 프로세스)에 출구가 생기므로 risk-ops 검토를 받고, 검토 판정에 따라 머지 권한(지침 10장)을 정한다
- 담당: architect(설계), data-engineer(전달·입력 기록), sim-engine(실행기 공통부·세션·리플레이 확인). 교차 검토: architect, risk-ops
- 근거: 6단계(실시간 모의 운영) 선행 과제, ADR-003 5장 "실시간 전달(IPC): 녹화까지만" 행, SIM-03·SIM-13, 지침 4장 6번·5장
- 상세: [ADR-010](../adr/ADR-010-live-feed-and-session.md)

## 결정

1. **전달**: 게이트웨이가 설정 폴더 아래 Unix 도메인 소켓 `run/market-feed.sock`(폴더 700·소켓 600)으로, 녹화하는 줄과 같은 줄을 같은 순서로 실험실에 넘긴다. 형식은 녹화 줄(`RecordingCodec`) 그대로, 구독 줄·인사 줄만 더한다. 못 열면 경고만 남기고 녹화만 한다.
2. **게이트웨이는 기다리지 않는다**: 받는 쪽마다 큐 50,000줄, 차면 버리고 `DataGap(CONSUMER_OVERFLOW)`, 30초 동안 못 보내면 끊음, 받는 쪽 최대 4개. 수신·녹화는 전달 때문에 멈추지 않는다(절대 규칙 6).
3. **실시간 모의 세션**: 실험실이 등록 파일(`input: "live"`)로 세션을 열고 계좌(프로필) N개를 리플레이 실행기와 같은 코드(`RunStepper`)로 움직인다. 한 번에 한 세션, API `/api/live`.
4. **결정론**: 받은 이벤트를 먼저 입력 기록(설정 폴더 `live-sessions/<ID>/journal/`, 녹화 형식)에 쓰고, 쓴 줄을 계좌에 준다. 재기동하면 기록을 다시 돌려 계좌를 되살리고, 끊긴 구간은 공백으로 남긴다.
5. **합격선(SIM-13)**: 끝낸 세션의 상세 보고서와 입력 기록 리플레이 결과가 바이트로 같아야 한다(`runLiveReplayCheck`, 다르면 종료 코드 2). 이 명령은 D-063 장 시간 보호·정지 요청을 그대로 받는다.
6. **자원 양보**: 세션 처리 스레드는 최저 우선순위, 1초마다 감시 정지 요청 파일을 보고 멈춘다. 실시간 세션에는 D-063 장 시간 보호를 걸지 않는다(장중 운용이 목적, 증권사 호출 없음).

## 대안

| 대안 | 판단 |
|---|---|
| A. 로컬 소켓 + 녹화 줄 형식 + 버림·공백(채택) | ADR-006과 같은 로컬 채널, 형식 하나, 게이트웨이 무영향 |
| B. TCP 루프백 | 다른 프로세스 접근 차단에 인증이 더 필요. 버림 |
| C. 실험실이 녹화 파일을 따라 읽기 | flush 지연·파일 회전·재기동 공백 처리가 까다롭다. 소켓이 Windows에서 안 되면 되돌릴 안 |
| D. 실험실이 증권사에서 직접 수신 | 키·구독 한도를 나눠 써야 하고 D-013 분리와 어긋남. 버림 |
| E. 무손실(게이트웨이가 기다림) | 절대 규칙 6 위반. 버림 |
| F. 입력 기록 없이 바로 계좌에 | 재기동 복구·리플레이 확인 불가. 버림 |

되돌릴 조건: 사용자 PC(Windows)에서 소켓을 열 수 없으면 C안. 몇 주 분량 재기동이 받는 큐를 넘길 만큼 느리면 계좌 상태 스냅샷(ADR-010 대안 G).

## 위험과 한계

- 입력 기록이 녹화와 비슷한 디스크를 한 번 더 쓴다(6단계 주간 점검에서 디스크 여유 확인).
- 재기동 시간은 운용 기간에 비례(미측정 `[가정]`).
- 멈춤·끝냄 때 받는 큐에 남은 이벤트는 버린다(다시 시작하면 재기동 공백으로 덮임).
- 실험실 입력은 전달 버림·끊김만큼 게이트웨이 녹화보다 적을 수 있다. 공백으로 남고, 녹화와의 차이 측정은 6단계 주간 점검.
- Windows 소켓 권한·경로 길이 `[가정]`.

## 검증

ADR-010 6장. 실시간 세션(중간 재기동·끊김 공백 포함) 결과와 입력 기록 리플레이 결과가 상세 보고서 바이트까지 같다(`LiveSessionTest`). 게이트웨이 녹화 줄과 실험실 수신 줄이 같다(`GatewayFeedTest`). 느린 받는 쪽에도 `publish`가 기다리지 않는다(`FeedServerTest`).

## 후속

실시간 모의 화면(ui-dev), 사용자 PC 첫 운용일 확인(절차서 [stage-6-live-session](../runbooks/stage-6-live-session.md)), 실시간 대 게이트웨이 녹화 차이 주간 측정(strategy-researcher), 실전 엔진 전달(7단계).
