## 결정

1. **화면.** 실험 목록(`#/experiments`) 맨 위에 "실행 중인 실험"을 둔다. 실행 중·응답 없음 작업을 기본으로 보이고, 끝난 작업(완료·확인 필요·입력 오류·취소됨·정지 요청으로 멈춤·실패)은 버튼으로 펼친다. 줄마다 실행 명령 종류, 상태 배지, 진행률 막대(`permille`), Run 끝·실패·진행 중 수, 거래일 진행, 병렬 상한, 시작·갱신 시각(KST), 메시지를 보인다. 응답 없음(60초 넘게 갱신 없음)은 줄 배경과 문구로 따로 표시한다.
2. **취소.** 실행 중이고 아직 취소 요청이 없는 작업에만 "취소" 버튼을 둔다. 확인 창을 거쳐 `POST /api/experiment-jobs/{id}/cancel`(CSRF 토큰)을 보내고, 줄에 "취소 요청됨(다음 확인 지점에서 끝남)"을 표시한다. 화면은 이 요청 말고 아무것도 쓰거나 멈추지 않는다(D-089 그대로).
3. **SSE `GET /api/experiment-jobs/stream`.** 이벤트 이름 `jobs`, 본문은 목록 API 첫 페이지(`page=0&size=50`)와 같은 모양 `{items, page, size, total, unreadable, truncated}`. 실험실이 연결이 하나라도 열려 있을 때만 2초마다 작업 폴더를 다시 읽고, 첫 페이지가 바뀌었을 때만 보낸다(실행 중 명령은 5초마다 상태 파일을 고쳐 쓰므로 실행 중에는 그 주기로 감). 새 연결에는 바로 한 번 읽어 지금 상태를 보낸다. 바뀐 것이 없으면 15초마다 주석 줄을 보내 떠난 브라우저의 연결을 치운다. 연결은 8개까지, 수명 30분, 넘치거나 종료 중이면 본문 없는 409(모니터링 SSE와 같은 규칙). 읽기·보내기는 우선순위가 가장 낮은 데몬 스레드 하나다(SIM-14: 실험실은 자원 부족 때 먼저 멈춘다).
4. **종료.** 실험실 종료 때 `SmartLifecycle`이 웹 서버 graceful shutdown보다 먼저 열린 진행 상태 SSE를 닫는다(D-091 2번과 같은 이유: 실전 운영 화면을 싣는 실험실 재기동이 30초 늦어지지 않게).
5. **연결이 안 될 때.** 브라우저가 409를 받거나 연결이 닫히면 화면은 5초 주기 조회(`GET /api/experiment-jobs?page=0&size=50`)로 바꾸고, 상단에 "실시간 연결"·"주기 조회(5초)"를 표시한다. 다른 화면으로 가면 연결과 조회를 바로 멈춘다.

UI-01의 "실시간 갱신은 SSE"는 이 결정으로 모니터링(D-090)과 실험 진행 상태 두 화면에 적용된다. 실시간 모의 화면(3초 조회, D-076)과 상단 모드 띠(실전 엔진 스냅샷 5초 조회, UI-05·UI-06)는 그대로 조회한다. 모드 띠는 실전 엔진 명령 채널을 읽는 경로라 바꾸려면 risk-ops 검토가 필요하고, 실시간 모의 화면은 실험실 안 상태라 SSE로 바꿀 이득이 작다.

## 대안

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 3-A. 연결이 있을 때만 실험실이 작업 폴더를 주기적으로 읽어 바뀐 것만 보냄 | 실행 명령·상태 파일 변경 없음. D-089의 "실험실은 읽기만" 유지. 연결이 없으면 읽지 않음 | 최대 2초 늦음. 폴더를 주기마다 다시 읽음(상한 500개, D-089) | **채택** |
| 3-B. `WatchService`로 폴더 변경 알림 | 늦음 없음 | Windows·네트워크 드라이브에서 동작 차이, 이벤트 넘침(OVERFLOW) 처리 필요, 응답 없음(시간 경과)은 어차피 주기 확인이 필요 | 버림 |
| 3-C. 실행 명령이 실험실에 소켓으로 알려 줌 | 바로 반영 | 실행 명령이 실험실 프로세스에 기대게 됨(D-062·D-089는 실험실 없이도 도는 명령), 계약과 보호 규칙이 늘어남 | 버림 |
| 3-D. SSE 없이 화면이 5초마다 조회만 | 서버 코드 없음 | UI-01(SSE) 미충족. 창을 여러 개 열면 창마다 폴더를 읽음 | 버림(연결 실패 때 대체 경로로만 씀) |
| 1-A. 실험 목록 화면 위에 진행 영역 | 결과 불러오기(실험 폴더)와 한 화면에서 이어짐 | 목록 화면이 길어짐 | **채택** |
| 1-B. 별도 메뉴 "진행 상태" | 화면이 단순 | 끝난 뒤 결과를 불러오려면 화면을 옮겨야 함 | 버림 |

되돌릴 조건: 작업 폴더가 커져 2초 주기 읽기가 실험실 CPU·디스크 지표(MON-05)에 보이면 주기를 늘리거나 3-B를 다시 본다. 결과 DB 저장(ADR-005 9장) 뒤 화면 실행이 들어오면 진행 상태도 같은 저장소에서 읽도록 바꾼다.

## 위험과 한계

- 진행 상태는 상태 파일을 쓰는 실행 명령에만 나온다(D-089 대상: 조합·녹화·합성 시세 비교·워크포워드·실시간 모의 점검·주간 점검). 워크포워드 전체 진행률은 D-089 후속 그대로 아직 없다(구간마다 진행률).
- SSE는 첫 페이지(최근 50개)만 보낸다. 화면도 그 50개만 보이고 "최근 50개만" 문구를 띄운다.
- 화면 JS(배지, 진행 막대, 409 뒤 조회 전환)는 자동 시험이 없다. 화면 Playwright CI(5단계 QA 권고 R3)가 들어올 때 넣는다. 이 PR에서는 샘플 데이터 실행(`bootTestRun`)과 브라우저로 확인한 결과를 PR 본문에 남긴다.
- 취소 버튼은 상태 파일이 "실행 중"이고 응답이 있는 작업에만 효과가 있다. 화면이 갱신되기 전에 명령이 이미 끝났으면 409를 받고 그 문구를 화면에 보인다.

## 검증

- `ExperimentJobStreamTest` 6건: 바뀌었을 때만 보내고 새 연결에는 지금 상태, 갱신 멈춤이 응답 없음으로 바뀌어 감, 조용하면 주석 줄, 보내기 실패 연결 제거, 연결 상한과 종료 뒤 거절, 첫 페이지 50개.
- `ExperimentJobControllerTest` 추가 1건: SSE가 비동기로 열리고 루프백이 아닌 Host는 403.
- `ExperimentJobStreamShutdownTest` 1건: 실제 웹 서버에서 첫 `jobs` 이벤트를 바로 받고, 연결을 연 채 실험실을 닫아도 10초 안에 끝남.
