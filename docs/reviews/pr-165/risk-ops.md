## 점검표 밖 발견
- [참고] D-107 결정 3번 본문(D-107:17)은 옛 괄호 문구를 그대로 인용한다. 같은 파일 아래 후속 반영 절이 새 문구를 적어 기록상 모순은 아니지만, 문구만 찾는 사람은 옛 문구를 볼 수 있다. 결정 본문을 고치지 않는 관례라면 그대로 둬도 된다.
- [참고] 감시(`WatchdogMain.java:194`, `:210`)도 첫머리가 괄호로 끝나고 표준 오류 줄이 다시 "(감시 없이 실전·실험을 돌리지 마세요)"를 붙여 `)(`가 생긴다. 이 PR 범위 밖이고 판정·종료 코드와 무관한 표시 문제다. 다음 감시 변경 PR에서 같이 맞추길 권고.
- [참고] Q1 시험의 로그 처리기는 `ArrayList`에 기록을 모은다. 엔진 로거 `com.autotrade.engine`에는 알림 큐 스레드 등 다른 스레드가 쓰지 않음을 확인했다(NotificationQueue·Guard 감사·명령 감사는 다른 로거 이름). 지금은 경합 위험이 없으나, 엔진 로거를 다른 스레드가 쓰게 되면 `hasSize(3)`가 흔들릴 수 있다.
- [참고] 같은 작업 폴더에서 검토자들이 Gradle을 동시에 돌리면 시험 결과 파일 충돌로 빌드가 거짓 실패한다. 이번에는 clone 폴더에서 다시 돌려 확인했다.
