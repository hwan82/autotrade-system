- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 실험 명령 쪽(`autotrade-sim`, `autotrade-app-experiment`)만 바꾼다. 실전 경로, 보호 경로(marketdata 포함), 장 시간 보호·정지 요청 관문(D-063)의 동작은 바꾸지 않는다. 판정 기준 수치는 바꾸지 않는다(D-114 그대로).
- 담당: sim-engine 결정·구현. 교차 검토: architect(코드), strategy-researcher(판정 기준 계산)
- 근거: [6단계 계획](../strategy/stage-6-plan.md) 4.2(L1~L11)·5장 T2, [D-114](D-114-intraday-live-promotion-criteria.md)(사용자 확정 기준), [D-115](D-115-stream-recordings-in-live-checks.md)(줄 단위 읽기), [D-027](D-027-strategy-lab-protocol.md)(C7 변형 규칙·C10 대조군), [D-071](D-071-stage-4-plan.md) 5번(본페로니 p), D-066 4번(거래 단위 괴리), STR-13(지연 0·1.5·2초)

## 문제

실시간 세션은 등록된 계좌 8개만 돌린다 `[사실]`(`LiveSession`, ADR-010 2.4). L1~L6·L8·L11은 그 결과(와 주간 점검)로 계산할 수 있지만, L7(±20% 변형), L9(지연 2초), L10(대조군 분포, N + 1 ≥ 20m = 120)은 다른 계좌가 더 필요하다. 계산하는 명령이 없으면 LIVE01이 끝나도(12-18) 판정 리포트를 쓸 수 없다.

## 결정

1. **명령** `./gradlew :autotrade-app-experiment:runLiveJudgement -Pexperiment=<실험ID> [-PsessionsDir] [-PrecordingsDir] [-PallowDuringSession] [-PmaxParallelRuns=N] [-Pheap=4g]`. 끝낸 세션(잠금 없음)의 입력 기록과 `live-detail.txt`를 읽어 `experiments/<ID>/judgement.md`를 쓴다. 종료 코드 0 판정함(후보 0개 포함), 1 입력 오류, 2 무사고 I1~I3이 깨짐(파일은 씀), 3 취소, 4 장 시간 보호·정지 요청(파일 없음). `ExperimentMain`의 작업 잠금·진행 상태·병렬 상한을 그대로 쓴다.
2. **입력은 입력 기록**(실시간 결과와 같은 입력). 원래 성과 = 입력 기록 리플레이(= 실시간 결과, D-076 합격선)이므로 변형·지연·대조군과의 차이가 파라미터·지연·시드에서만 나온다. 같은 실행에서 그 리플레이가 `live-detail.txt`와 바이트로 같은지(I3)도 본다.
3. **돌리는 것**(레인, 모두 같은 기간·비용·체결 규칙):

   | 레인 | 내용 | 판정 |
   |---|---|---|
   | BASE | 등록 파일 그대로, 지연 0.5초 | L1~L6, L8, L10(값), L11(실시간 쪽), I1~I3 |
   | PERTURB | 판정 대상마다 `study.key-param` ×0.8·×1.2(4단계 C7과 같은 `Perturbation.scale`, 범위 밖이면 판정 불가) | L7 |
   | L0·L1500·L2000 | 판정 대상을 지연 0·1.5·2초로(STR-13) | L9(2초), 나머지는 참고 표 |
   | NULL1~NULL(20m−1) | 대조군(`logic: random`)을 시드 = 실험 시드 + i로 | L10 분포 |
   | REC | 등록 파일 그대로 같은 날 게이트웨이 녹화(boards·운용 기간)로. 주간 점검 계좌 대조와 같은 입력·버전 | L11(녹화 쪽) |

   LIVE01(m = 6)이면 입력 기록 레인 124개, Run 157개(8 + 12 + 18 + 119)다.
4. **판정 역할**: 등록 프로필 중 `logic: buy-and-hold` 하나가 기준선, `logic: random` 하나가 대조군, 나머지가 판정 대상(m = 그 수)이다. 둘 중 하나라도 없거나 둘 이상이면 입력 오류다. 기준선·대조군도 같은 기준으로 참고 판정을 낸다(6단계 계획 4.2: 대조군이 L1~L6을 통과하면 기준이 느슨하다는 신호).
5. **판정 규칙**(수치는 D-114·`ScreeningThresholds.defaults()` 그대로):
   - L4: 관측 20거래일 미만이면 판정 불가(D-069 `MIN_SHARPE_DAYS`).
   - L5 미달은 **탈락**이다(D-114 "C5 수치 그대로", 4단계 1차 선별 `ScreeningCriteria` C5와 같음). 4단계 워크포워드(D-071)의 "C5 미달 → 보류"는 따르지 않았다. 대부분 미달이면 기준을 낮추지 않고 등록을 늘리는 안을 사용자에게 묻는다(6단계 계획 4.2 되돌릴 조건). `[가정]` strategy-researcher 확인 대상.
   - L6: 운용 시작일 + 28일 전 거래일이 앞 4주, 그 뒤가 뒤 4주. 순손익은 일별 평가금액 차. 한쪽에 거래일이 없으면 판정 불가.
   - L7: 원래 총수익률이 0 이하면 탈락(C7과 같음).
   - L10: p = (k+1)/(N+1), k = 후보 값 이상인 대조군 수, N = 왕복 1건 이상으로 끝난 대조군 수. N + 1 < 20m이면 판정 불가(D-071 5번과 같은 식). 시드 수는 판정이 가능한 가장 작은 20m − 1이다.
   - L11: |총수익률 차| ≤ 2%p이고 |체결 수 차| ≤ 실시간 체결 수 × 10%(경계 포함). 같은 날 녹화가 하나라도 없거나 녹화에 호가 단위 위반 가격이 있으면 판정 불가.
   - 결과: 탈락이 하나라도 있으면 탈락, 아니면 판정 불가가 있으면 보류, 모두 통과면 후보.
6. **함께 적는 것**(6단계 계획 4.2 리포트 항목): 벤치마크 매수 후 보유 수익률, 장중 노출(거래일마다 09:00~15:30 동안 든 매입 금액 × 시간 ÷ (시드머니 × 장 시간), 체결 시각 기준 `[가정]` 정규장 시각 고정), 마감 노출, 왕복당 순손익, 블랙리스트 거절 수, 지연 민감도 표, 대조군 분포 요약, 거래 단위 괴리(진입 (종목, 거래일) 일치율·첫 진입 체결가 괴리 평균, D-066 4번 정의를 장중에 옮긴 참고값. 판정에는 쓰지 않음).
7. **실행기 레인 경로** `SimulationExperimentRunner.runLanes`: 기간이 같은 실험 여러 개(`Lane` = 명세 + 체결 설정)를 D-115의 목록이 아닌 입력 방식으로 함께 돈다. 입력은 레인 수와 상관없이 두 번만 읽는다. 레인마다 결과는 따로 돈 `runDetailed`와 바이트로 같다. D-115의 단일 실험 경로는 레인 하나짜리 레인 경로로 바꿨다(동작 같음, 기존 시험 그대로 통과).
8. **묶음 병렬**: 레인을 Run 수가 고르게 묶음으로 나누고(정해진 순서), 묶음마다 스레드 하나가 입력 기록을 따로 읽는다. 묶음 수 = min(병렬 Run 상한, 4). 레인끼리 공유하는 것이 없어 결과는 묶음 수와 상관없다(시험: 1·2·4묶음 결과 파일 같음).

## 대안

| 대안 | 판단 |
|---|---|
| ① 입력 기록 + 레인 경로 + 묶음 병렬(채택) | 원래 성과가 실시간 결과와 같은 입력이라 차이의 원인이 하나다. 기록을 묶음 수만큼만 푼다 |
| ② 게이트웨이 녹화로 모든 레인 | 계획 5장 문구("운용 기간 녹화로")에 가깝지만, 원래 성과가 실시간 결과와 달라져(L11 괴리만큼) L7·L9·L10의 비교 기준이 둘이 된다. 버림. 녹화는 L11에만 쓴다 |
| ③ 레인마다 실행기를 따로(D-115 경로 157번) | 코드 변경이 없지만 기록을 300번 넘게 푼다(LIVE01 한 번 읽기 약 15분 `[추론]`이면 70시간 넘음). 버림 |
| ④ 대조군을 한 실험 안 여러 계좌로 | Run 시드가 (실험 시드, 프로필 해시)에서만 나와(`RunSeeds`) 같은 프로필 계좌는 같은 난수열이다. 시드를 바꾸려면 실험이 따로여야 한다. 레인으로 해결 |
| ⑤ 묶음 없이 한 스레드 | 결과는 같지만 4코어에서 약 3배 느리다(아래 실측). 버림, 상한 1로 돌리면 같은 동작 |
| L5 미달 = 보류(4단계 워크포워드처럼) | D-114가 "C5 수치 그대로"라 1차 선별(D-027) C5의 탈락을 따랐다. 보류로 바꾸면 L5 미달 프로필이 "후보가 될 수도 있음"으로 읽힌다. strategy-researcher 검토에서 다르면 이 결정을 고친다 |

되돌릴 조건: 사용자 PC에서 LIVE01 판정이 하룻밤(약 12시간)을 넘으면 대조군 레인을 따로 저장해 다시 쓰거나 묶음 수 상한을 올린다. 거래 단위 괴리를 판정에 넣기로 하면(D-114 다음 결정) 7장 표의 값을 그대로 쓴다.

## 위험과 한계

- **시간**: 컨테이너(4코어) 실측, 2종목 5일 이벤트 27.7만 건, Run 157개: 1묶음 73초, 4묶음 23초, 힙 사용 약 110MB. Run 한 걸음 약 1.7µs(1묶음, 풀기 포함) `[사실]`(개발 쪽 직접 실행, 시험 코드에서 잼). LIVE01 10종목 40일 약 7천만 건 `[추론]`(D-115 추정)이면 1묶음 약 5시간, 4묶음 약 1.5~2시간 `[추론]`. 합성 시세라 신호 수가 실제와 다르고 사용자 PC 코어 수에 따른다. LIVE00(4일) 판정으로 먼저 재서 고친다.
- **메모리**: Run 수에 비례하고 기간과는 체결·자산 곡선 크기만큼만 는다. 기본 힙 4GB.
- **진행 상태 표시**: 묶음마다 진행 보고를 따로 내서 상태 파일의 "지금 실험"이 묶음 사이를 오간다(결과에는 영향 없음). 명령 전체 진행률은 묶음 수 + 1로 알린다(D-098).
- **역할 식별이 `logic` 값에 기댄다**: 기준선·대조군 로직 이름이 바뀌면 이 명령도 바꿔야 한다. 등록 파일에 역할을 적는 방식은 후속(등록 형식 변경이라 strategy-researcher 몫).
- **장중 노출**은 정규장 09:00~15:30 고정이라 수능일(10:00~16:30) 같은 날은 조금 틀린다 `[가정]`. 참고 표시라 판정에는 영향이 없다.
- **L11 진입 일치**는 (종목, 거래일) 첫 진입만 맞춘다. 하루에 같은 종목을 여러 번 드나드는 프로필은 일치율이 실제보다 높게 나올 수 있다(참고값).
- I4(주간 점검 8회 종료 코드)·I5(유효 운용일)는 계산하지 않는다. 주간 점검 결과 파일로 본다.
- 이 결과는 투자 자문이 아니며, 후보도 표본 외 재검증 뒤 실전 적용은 사용자가 정한다.

## 검증

- `SimulationExperimentRunnerTest`: 지연·시드·프로필이 다른 레인 셋을 한 번에 돌려도 레인마다 따로 돈 보고서와 바이트 일치, 입력은 두 번만 읽음, 한 레인의 실패 계좌는 다른 레인에 영향 없음, 기간·데이터 버전이 다르면 아무 Run도 시작하지 않음, 진행 보고는 레인 Run 합계. D-115 골든·격리·정지 시험은 그대로 통과.
- `LiveJudgeCriteriaTest`: L6(4주 경계), L7, L8(최고 주), L9, L10(p = 1/120 경계 통과, 2/120 탈락, N = 118 판정 불가, m = 2이면 N = 39), L11(2%p·10% 경계), 판정 순서, 실패 Run, 기준선 자기 비교, 거래 단위 괴리, 장중·마감 노출을 손 계산과 비교.
- `LiveJudgementTest`: 실험실 세션을 끝까지 돌린 입력 기록으로 판정 → I3 같음, 레인 44개·Run 53개(m = 2), 1·2·4묶음 결과 파일 같음, 2초 레인이 따로 돈 실험과 바이트 일치, 대조군 시드 = 실험 시드 + i, 실시간 보고서를 바꾸면 I3 다름(사고), 녹화가 없으면 L11 판정 불가, 기준선·대조군 없으면 입력 오류, 세션이 열려 있으면 거부, 정지 확인에서 멈추면 파일 없음.
- `./gradlew build`(ArchUnit·순수 모듈 검사 포함).
