# D-123 공시 스냅샷 수집(dart-disclosures)·지표 disclosure-count·프로필 (라)

- 날짜: 2026-10-20
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 6번 시점 규칙은 **D-121 ③ "접수일 ≤ 기준 데이터일"을 대체**한다(확정 결정을 바꾸므로 지침 8장 4번에 따라 사용자에게 물었고, **사용자가 "T 전날까지"로 확인함**(2026-10-20)). 실전 주문 경로·RealTradingGuard·블랙리스트·리스크 한도·보호 경로(`autotrade-marketdata`·`autotrade-domain`·`autotrade-config`·아키텍처 시험)는 바꾸지 않는다.
- 담당: data-engineer(수집), strategy-researcher(지표·프로필). 교차 검토: architect, strategy-researcher
- 근거: [ADR-012](../adr/ADR-012-intraday-selection.md) 3.1·3.2·3.3·3.4, 배치표 3번, [D-121](D-121-intraday-selection.md) ②③, 수집 라이선스 D-050·D-055([결정 로그](README.md)), 카탈로그 [selection-catalog.md](../strategy/selection-catalog.md)

## 결정

1. **수집 명령** `dart-disclosures [--from 2010-01-01] [--to 어제] [--types B,I] [--max-calls 2000] [--krx-snapshot ID]`. OpenDART `list.json`을 회사 코드 없이 유형(`pblntf_ty`)·달력 달 창·쪽(100건) 단위로, 최근 달부터 거꾸로 부른다. 지난 창은 캐시하고 다시 부르지 않는다. `--to`는 어제까지만 받는다(당일은 아직 접수 중).
2. **하루 상한은 몫으로 나눠 센다**(ADR-012 3.4 "재무 상한 안에서"를 바꿈). 같은 키의 호출 기록에 몫(`main`=재무, `disclosures`=공시)을 남기고, 공시 몫 기본 2,000회(최대 10,000), 재무 몫 기본 10,000회(그대로), 두 몫 합 20,000회(OpenDART 가이드 "일반적으로 20,000건" `[가정]`)를 넘지 않는다. 사용자가 재무 전체 수집을 하루 10,000회씩 돌리는 중이라 공시가 재무 몫을 깎지 않게 한다. 공시 최대 10,000은 어느 쪽을 먼저 돌려도 재무 기본 몫이 남는 값이다. 020(한도 초과) 응답은 두 몫 모두 그날 멈춘다. 몫 기록이 없는 예전 호출은 재무 몫으로 센다.
3. **순서**: 매일 `krx-daily` → `dart-financials` → `dart-disclosures`(재무 신선도가 먼저, ADR-012 architect F6). T 전날까지 공시를 담으려면 공시 수집은 T 00:00 뒤 08:00 전(장 시간 보호 전)에 돌린다.
4. **스냅샷** `snapshots/dart-disclosures/dart-disclosures-<마지막 날짜>-<해시8>/`: `disclosures.csv`(`market,code,code_source,corp_code,corp_cls,pblntf_ty,rcept_no,rcept_dt,report_nm`)와 `disclosure_types.csv`(`pblntf_ty,from,to`, 유형별 수집 구간) 두 파일 모두 manifest에 SHA-256·행 수, 스냅샷 ID 해시는 두 파일 해시로 만든다. manifest 형식은 그대로(보호 경로)라 받은 유형 목록은 manifest 필드가 아니라 `disclosure_types.csv`에 둔다. 원문·본문은 받지 않는다. 받다가 상한에 걸리면 다 받은 창까지로 스냅샷을 만들고 종료 코드 3. 스냅샷에는 훑은 구간(`state.json`) 안의 창 파일만 넣는다. 창을 쓰고 훑은 구간을 적기 전에 끝난 실행이 남긴 파일은 다음 실행이 지우고 다시 받으며, 창끼리 날짜가 겹치거나 같은 접수번호가 두 번 나오면 스냅샷을 만들지 않고 실패한다(같은 공시를 두 번 세지 않음, PR #196 architect F1).
5. **종목 코드 붙이기**: 공시의 `stock_code`(DART) → 같은 회사 고유번호의 다른 공시 코드(CORP, 그 날짜를 덮는 구간 또는 가장 가까운 구간) → KRX 종목 이력 이름 대조(NAME, 그날 유일할 때만). 못 붙이면 코드 빈칸으로 남기고 품질 리포트에 유형·법인 구분별 건수를 적는다.
6. **지표** `disclosure-count`(공시, window w, 자격 조건에만, KRX만): `gate.<nn>.types` 유형 공시 중 접수일이 [c에서 끝나는 w거래일의 첫날, T−1](달력일)인 건수. 재무 규칙 "접수일 < T"와 같고, c·T 사이 휴장일 접수분이 T 선정에 들며 날마다 선정하면 각 접수일이 한 번만 세진다(PR #196 strategy-researcher M1. 처음 안 (앞 거래일, c]은 휴장일 접수분을 하루 늦게 셌다). 정정·첨부(대괄호 머리말 보고서명)와 코드 없는 공시는 세지 않는다. 0건은 정상값 0.
7. **입력 확인**: 공시 입력이 없거나 조건 구간을 수집 구간이 못 덮으면 `STALE_INPUT`, 조건 유형을 스냅샷이 받지 않았으면 `INPUT_TYPE_MISSING`으로 계산 전체를 멈춘다(결측 탈락으로 0종목 결과를 내지 않음).
8. **결과·실험 입력**: 공시 조건이 있는 선정 결과만 `inputs.disclosures`(스냅샷 ID·SHA-256·`covered_through`)를 가진다. 없는 결과는 키가 없어 기존 내용 해시가 그대로다. 조합 실험·워크포워드 등록 파일에 선택 키 `disclosures-snapshot`을 더한다. 실험 생성 화면의 공시 스냅샷 칸은 후속이라, 화면은 공시 조건 선정 프로필이 든 조합을 거절하고 등록 파일에 직접 쓰라고 안내한다.
9. **프로필 (라)** `selections/kr-intraday-news/v1.yaml`(ADR-012 3.3): 전일 공시(B·I) ≥ 1, 전일 거래대금 ≥ 50억, `STOCK`, 종가 ≥ 1,000원, 21거래일 일봉, 거래량 급증 순 20종목. 수치는 `[가정]` 출발값이고 선정 엣지 일봉 사전 검사(배치표 2b)를 거쳐야 LIVE02에 들어간다.
10. 라이선스: OpenDART 기존 키·조건(D-050 ③ 키 비공개·호출 상한·원자료 재배포 없음) 그대로, 새 키·과금 없음. D-050 ③은 재무 데이터를 두고 쓴 판단이지만 같은 약관·같은 API의 공시 목록에도 그대로 적용된다고 본다 `[추론]`. 이름 대조에 쓰는 KRX 종목 이력은 D-055 조건(7단계 실전 선정에 쓰기 전 KRX 문의)을 따른다. 스냅샷은 저장소 밖. `--keep-snapshots`를 주면 일봉처럼 최근 K개와 실험 기록이 참조하는 것만 남긴다(지운 공시 스냅샷은 같은 ID로 다시 만들 수 있다는 보장이 없다).

## 대안

| 선택 | 채택 | 버린 대안과 이유 | 되돌릴 조건 |
|---|---|---|---|
| 공시 건수 시점 | 접수일 < T | 접수일 ≤ c(D-121 ③ 원안): c·T 사이 휴장일 접수분이 T+1로 밀려 가설 시점과 어긋남. T 당일 포함: 장전 수집 보장이 없어 입력이 날마다 흔들림 | 장전 공시를 T 07:30 수집 보장과 함께 쓰는 새 지표 키 |
| 하루 상한 | 몫 분리 + 키 합 20,000 | 재무 10,000 안에서 나눠 쓰기(ADR 원안): 사용자 재무 전체 수집이 하루 2,000회만큼 늦어짐. 몫 없이 합만: 먼저 돈 쪽이 다른 쪽을 굶김 | 공식 한도가 20,000보다 작다고 확인되면 키 합 상한을 그 값으로(공시 몫을 먼저 줄임) |
| 유형 목록 위치 | `disclosure_types.csv`(manifest 해시) | manifest 필드 추가: 보호 경로 변경이라 실전 관련 PR이 됨 | manifest 형식을 다른 이유로 바꿀 때 합칠 수 있음 |
| 정정 판정 | 읽는 쪽이 보고서명 머리말로 | 수집기가 정정 칸을 씀: 규칙이 두 곳에 생기고 규칙 바꿀 때 스냅샷을 다시 만들어야 함 | 머리말로 못 거르는 정정 유형이 나오면 새 지표 키 |
| 창 단위 | 달력 달 | 3개월(API 최대): 호출은 조금 적지만 쪽 넘김 중 total_count가 바뀔 확률이 커지고 재시작 비용이 큼 | 호출 수가 모자라면 3개월 창 |
| 구간 끝 | 어제까지 | 오늘까지: 같은 날 다시 돌리면 결과가 바뀌어 결정론이 깨짐 | 없음 |

## 위험과 한계

- 하루 20,000회는 2차 자료(가이드 문구) `[가정]`. 020이 일찍 오면 두 몫 모두 멈추므로 재무 수집이 그날 덜 진행될 수 있다(공시는 재무 뒤에 돌아 영향이 작다).
- 유형 I(거래소공시)는 하루 건수가 많아 (라)의 1차 조건이 넓을 수 있다 `[추론]`. 첫 실제 스냅샷 품질 리포트로 확인한다.
- **생존편향 미확인**(PR #196 strategy-researcher M2): OpenDART 목록의 종목 정보가 지금 회사 기준이면 상장폐지 회사 공시가 0건이 된다 `[추론]`. 품질 리포트에 "상장폐지 종목 공시 확인"(수집 구간 안 폐지 종목 중 상장 기간 안 공시가 붙은 비율, 종목 코드·날짜 단위, 상장 유지 종목 비율을 기준선으로 함께, PR #196 strategy-researcher N1)·접수 연도별 못 붙인 행·머리말별 건수를 넣었고, runbook 4장에 손 확인 절차를 두었다. 확인 전에는 (라) 과거 구간 결과를 선정 엣지 근거로 쓰지 않는다.
- 이름 대조는 같은 날 같은 이름이 하나일 때만 붙인다. 상장폐지·이름 변경 종목의 옛 공시가 빠질 수 있다 `[추론]`.
- 실제 OpenDART로 받은 결과는 아직 없다. 합성 응답 시험으로만 검증했다.
