# 키움 REST API 명세 요약 (2026-10-10 사용자 제공 명세 JSON)

- 작성: architect · 확인일: 2026-10-10 (KST)
- 입력: 사용자(BAE)가 올린 키움 REST API 명세 JSON(약 2.5MB, API 351개 + 오류 코드 목록). 원본은 저장소에 넣지 않았다(키움 배포물이고 크기가 커서). 같은 내용은 키움 공식 저장소 [Kiwoom-Securities/Kiwoom-REST-API](https://github.com/Kiwoom-Securities/Kiwoom-REST-API)와 키움 REST API 포털에서 받을 수 있다.
- 관련: [ADR-003 시세](../adr/ADR-003-market-data.md) 5장, [시세 사전 조사](market-data-limits.md) 1장, [실녹화 확인 절차](../runbooks/stage-2-real-recording.md)
- 표기: `[사실]`(명세 JSON 또는 공식 저장소 근거), `[추론]`, `[가정]`

## 0. 결론

1. **실시간 WebSocket 경로가 기존 조사와 다르다.** 명세의 실시간 항목 31개는 모두 `wss://api.kiwoom.com:10000/api/websocket`이다 `[사실]`. 2026-10-08 조사와 코드는 `/api/dostk/websocket`(미국 `/api/us/websocket`)이었다. 키 없이 어느 쪽이 열리는지 확인할 수 없어, 코드는 명세 경로를 먼저 쓰고 접속이 안 되면 예전 경로를 번갈아 시도하다가 LOGIN이 성공한 경로로 고정한다(추천안 채택(자율), 4.1). 첫 실접속 로그로 한 경로만 남긴다.
2. **오류 코드 37개가 공개돼 있다.** 지금까지는 `return_code`가 0이 아니면 모두 "키 거절"로 봤다. 이제 키·IP·투자구분 문제(8001·8050·8030 등), 토큰 만료(8005·8031·8103), 호출 한도(1700~1702)를 나눠 처리한다(3장). 특히 **8050 "IP가 등록되지 않았습니다"**는 키 신청 직후 가장 흔할 실패라 로그에 조치 방법을 같이 남긴다.
3. **REST 조회 TR을 쓸 수 있는 기반을 넣었다.** 읽기 전용 호출기(`KiwoomRestClient`)와 정규장 일봉(ka11081)이다. 녹화일 원본 대조(runbook 8번)를 HTS 화면 대신 `kiwoomDaily` 명령으로 할 수 있다. 주문·계좌·환전 경로는 호출기가 보내기 전에 거절한다(6장).
4. **주문 API(kt10000~, ust20000~)와 체결·잔고 통보(00, 04)는 범위 밖이다.** 실전 관련(지침 10장)이라 7단계 risk-ops 작업으로 남긴다(7장).

## 2. 공통 규약 `[사실]`

- **토큰 발급** `au10001` `POST /oauth2/token`: 본문 `grant_type=client_credentials`, `appkey`, `secretkey`. 응답 `token`, `token_type`(bearer), `expires_dt`(yyyyMMddHHmmss), `return_code`, `return_msg`. 폐기는 `au10002` `POST /oauth2/revoke`(appkey, secretkey, token).
- **조회 TR 헤더**: `api-id`(TR 코드), `authorization: Bearer <토큰>`. 연속조회는 응답 헤더 `cont-yn`이 `Y`일 때 다음 요청에 `cont-yn: Y`, `next-key: <응답 헤더 값>`을 넣는다.
- **종목코드**: 6자리는 KRX, `_NX` 접미사는 NXT(넥스트레이드), `_AL`은 통합(SOR). 예 `039490`, `039490_NX`, `039490_AL`. 우리 2단계는 KRX 단독 시세만 다룬다(runbook 8번이 KRX 단독 정규장 일봉과 대조).
- **결과 코드**: 응답 본문 `return_code`(0 정상). 값은 숫자 또는 숫자 문자열이다(실시간 등록 응답은 문자열). 공식 저장소 `kiwoom/core/errors.py`는 최상위 코드가 일반 코드(예: 3)이고 구체 코드가 `return_msg` 안에 `[8005:…]`(REST)나 `CODE=8005`(WebSocket)로 들어오는 경우를 처리한다(2026-10-10 확인).
- **호출 한도**: 명세에는 숫자가 없고 초과 코드만 있다. 숫자는 포털 공지 기준 국내 조회·주문 TR 각각 토큰별 초당 5회(시세 사전 조사 K1).

### 4.1 접속 경로 (기존 조사와 충돌)

대안 비교
- A(채택): 명세 경로 우선, 접속 실패 시 예전 경로와 번갈아 시도, LOGIN 성공 경로로 고정. 어느 쪽이 맞아도 첫 녹화가 열린다. 비용은 틀린 경로 한 번당 재접속 대기 한 번.
- B: 명세 경로만. 명세가 최신이면 가장 단순하지만, 틀리면 사용자가 장중에 녹화를 못 하고 코드 수정을 기다려야 한다.
- C: 설정 키로 경로 지정. 설정 계약(config-keys.md)을 늘리고 사용자가 값을 알아야 한다. 실측 한 번으로 끝날 문제에 비해 무겁다.
- 되돌릴 조건: 첫 실접속 로그(`시세 배분`과 LOGIN 성공)에서 경로가 확인되면 다른 경로를 지우고 B로 줄인다.

### 4.2 메시지 형식 `[사실]`

- 접속 뒤 `{"trnm":"LOGIN","token":…}`, 응답 `trnm=LOGIN`의 `return_code` 0. 서버 `PING`은 그대로 돌려준다.
- 등록 `{"trnm":"REG","grp_no":"1","refresh":"1","data":[{"item":[…],"type":[…]}]}`, 해지 `REMOVE`. `refresh` 0은 그룹 전체 해지 후 등록, 1은 추가.
- 수신 `{"trnm":"REAL","data":[{"type","name","item","values":{…}}]}`. 값은 모두 문자열이고 가격 앞 `+`/`-`는 전일 대비 방향이다.
- `0B` 주식체결: 20 체결시간(HHmmss), 10 현재가, 15 거래량(+매수/-매도 체결), 27·28 최우선 매도·매수호가, 290 장구분(1 장전 시간외, 2 장중, 3 장후 시간외), **9081 거래소구분(KRX/NXT)**. 코드는 9081이 있고 KRX가 아니면 버린다(NXT 체결이 KRX 녹화에 섞이지 않게).
- `0D` 주식호가잔량: 21 호가시간, 41~50 매도호가, 61~70 매도잔량, 51~60 매수호가, 71~80 매수잔량, 121·125 총잔량, 23·24 예상체결가·수량, 6044~6087 KRX·NXT별 잔량, 6100~ 중간가. 명세 예시(6자리 등록)에서 6044 이후는 0이라 61~80이 등록한 거래소 기준이라고 본다 `[추론]`.
- `0s` 장시작시간: 215 장운영구분(0 장시작전 알림 8:40부터 1분마다, 2 장마감전 알림 15:20부터, 3 장시작, 4 장마감, 8 정규장마감), 20 시각, 214 장시작 예상 잔여시간. `item: [""]`로 등록.
- `1h` VI발동/해제: 전 종목 수신(`item: [""]`). 9001 종목코드, 9068 VI발동구분(1 정적, 2 동적, 3 동적+정적, 4 VI연장), 1221 발동가격, 1223 발동시각, 1224 해제시각, 1225 적용구분, 9069 발동방향(1 상승, 2 하락).
- `FE` 미국 체결가: 등록 item이 `{"jmcode":"NVDA","stex_tp":"ND"}`(ND 나스닥, NY NYSE, NA AMEX). 20·51020 시각은 **미국시간(ET) HHmmss**, 22 체결일자 YYYYMMDD, 290 장구분(0 정규장, 1 프리, 2 애프터, 4 주간거래). ADR-003 5장의 "시간 필드 의미(현지/한국) 확인"은 명세상 ET로 답이 나왔다 `[사실]`(실측으로 재확인).

## 6. 조회 TR 허용 범위 (이 PR)

`KiwoomRestClient`는 아래 경로와 `ka`·`usa` TR만 보낸다. 그 밖은 HTTP 요청(토큰 발급 포함) 전에 `IllegalArgumentException`으로 거절하고 테스트가 지킨다(`KiwoomRestClientTest`).

- 허용: `/api/dostk/{stkinfo, mrkcond, chart, sect, rkinfo, frgnistt, elw, etf, thme, shsa, slb}`, `/api/us/{stkinfo, mrkcond, chart, sect, rkinfo, invtinfo}`
- 거절: 주문 `/api/dostk/ordr`·`crdordr`·`/api/us/ordr`, 계좌 `acnt`(ka로 시작하는 계좌 조회 포함), 환전 `/api/us/exchange`(환전 신청 ust31302 포함), 관심종목 `watchlist`, `kt`·`ust` TR 전부.
- 다음에 쓸 만한 조회 TR(제안, 이 PR 범위 밖): `ka10099` 종목정보 리스트(상장주식수·NXT 가능 여부·투자유의, 종목 마스터 보강), `ka10081`/`ka11081` 일봉(수집기 대체·검증용), `ka10054` VI 발동 종목, `usa10099` 미국 종목 리스트, `usa06012` 미국 일봉, `ust31301` 환율(경로가 `/api/us/exchange`라 허용하려면 TR 단위 허용으로 바꾸고 risk-ops 검토).

## 7. 범위 밖: 주문·계좌 (7단계, risk-ops)

명세에는 국내 주문 `kt10000`(매수)·`kt10001`(매도)·`kt10002`(정정)·`kt10003`(취소)와 신용주문, 미국 주문 `ust20000~`, 계좌 조회 `kt00001~`, 체결·잔고 실시간 통보 `00`·`04`가 있다. 이것들은 실전 주문 경로라 이 PR에서 코드로 옮기지 않았다. 7단계에서 키움 `OrderGateway`를 만들 때 risk-ops가 이 명세를 입력으로 쓴다. 그때 볼 것: 주문 응답의 주문번호 필드, 타임아웃 뒤 조회 TR(미체결·체결 조회), 체결 통보 `00`의 상태값, 멱등 키를 실을 수 있는 필드가 있는지(없으면 우리 쪽 원장으로만 관리).
