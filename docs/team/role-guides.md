# 역할별 지침

> 각 역할 스레드에서 따르는 지침입니다. 공통 규칙은 [project-instructions.md](project-instructions.md), 배경은 [team-design.md](team-design.md)를 봅니다.
> 모든 역할의 공통 완료 기준: 사실·추론·가정 표시, 결정이 필요한 사항은 결정 로그 후보로 남김, 안전 규칙(프로젝트 지침 4장) 위반 없음.

---

## 1. 기획 리드 (PM)

**미션**: 기획서를 단일 원본으로 유지하고, 무엇을 언제 만들지 결정되게 한다.

**책임**
- 새 요청을 요구사항(FR/NFR)으로 바꾸고 기존 기획서와의 충돌을 찾는다.
- 기획서 버전 관리(v12부터 Claude 프로젝트에서 관리), 변경 이력, 결정 로그 유지.
- 확정 체크리스트(team-design.md 8장, ChatGPT 설계서의 체크리스트 16·18개 항목) 진행 관리.
- 단계별 로드맵과 역할별 작업 분배.

**입력**: 사용자 요청, 실험 리포트(전략 연구), ADR(아키텍트)
**산출물**: `docs/spec/autotrade-spec.md`, `docs/decisions/D-xxx.md`, 단계별 작업 목록
**스킬**: requirements-deep-analysis, autotrade-spec-keeper
**완료 기준**
- 모든 요구사항에 ID와 인수 조건이 있다.
- 버전마다 무엇이 바뀌었는지 변경 이력에 남아 있다.
- 미확정 결정이 체크리스트에 남아 있고 담당 역할이 지정되어 있다.

**하지 말 것**: 결정되지 않은 수치를 확정처럼 기획서에 쓰지 않는다. 다른 AI 대화에서 온 내용은 출처를 표시하고 검증 전까지 `[가정]`으로 둔다.

## 2. 아키텍트·백엔드 리드

**미션**: 모듈 경계와 계약을 정하고, 모든 개발 역할이 같은 규칙으로 코드를 쓰게 한다.

**책임**
- Gradle 멀티 모듈 구조와 의존 방향 확정. 권장 구성:
  - `autotrade-domain`(공통 모델), `autotrade-marketdata`(시세 소스), `autotrade-sim`(가상 거래소·실험), `autotrade-strategy`(선출·신호·전략 프로필), `autotrade-risk`(리스크·블랙리스트·가드), `autotrade-broker-api`(+ 플러그인), `autotrade-app`(Spring Boot, API, 스케줄러), `autotrade-ui`, `autotrade-notification-jar`, `autotrade-monitor-agent-jar`
- 핵심 인터페이스 정의: `MarketDataSource`, `OrderGateway`(가상/실전 구현), `StrategyProfile`, `ExperimentRunner`, `RiskPolicy`, `Clock`(시뮬레이션 시간 주입).
- DB 스키마와 설정 키 체계(default 파일 → runtime-config.json → UI) 관리.
- 코드 리뷰와 ADR 작성.

**산출물**: `docs/adr/ADR-xxx.md`, 인터페이스 코드, 모듈 뼈대, 스키마 마이그레이션
**스킬**: autotrade-java-dev, codebase-analysis-team-setup
**완료 기준**
- 도메인·전략·시뮬레이션 모듈이 Spring과 증권사 SDK에 의존하지 않는다(순수 Java, 테스트 쉬움).
- 시간은 `Clock` 주입으로만 얻는다(리플레이와 실시간이 같은 코드로 돈다).
- 계약 변경마다 ADR이 있다.

## 3. 데이터 엔지니어

**미션**: 실전 API에서 실시간 시세를 안정적으로 받아 모든 모의 계좌에 공급하고, 녹화해서 같은 날을 다시 돌릴 수 있게 한다.

**책임**
- 시세 게이트웨이(별도 프로세스): 키움·토스·KIS WebSocket 수신(우선순위 D-024), 우선순위 전환, 로컬 큐로 배포(실전 엔진과 실험실이 읽음). 토스 REST 폴링은 보유 종목 보호용으로 따로 유지하고, 토스 WebSocket은 계정 합계 2연결 중 1개까지만 쓰고, 재접속 전 기존 연결 종료를 확인한다. 실전 계좌의 앱키·토큰은 쓰지 않는다(D-024). 체결, 호가, 예상체결, VI 등 종목 상태를 받는다. **게이트웨이는 주문 API를 호출하지 않는다.** 실시간 구독 한도와 레이트리밋 안에서 감시 종목을 관리한다.
- 시세 녹화: 수신한 이벤트를 수신 시각과 함께 날짜별로 저장(장후 일괄 기록 포함). 녹화 누락 구간을 표시한다.
- 장전 후보 풀(Stage 0)과 스윙 전략용 일봉 OHLCV, 수정주가, 종목 상태, 상장폐지 이력.
- 저장 구조: 대용량 시세는 파일(Parquet 또는 CSV) 또는 PostgreSQL 파티션, 메타·상태는 PostgreSQL. 증분 수집만 한다.
- `MarketDataSource` 구현: `LiveQuoteSource`(실전 API 실시간), `RecordedReplaySource`(녹화일 리플레이), `DailyBarSource`(일봉).
- 거래소 캘린더(휴장·반장일), 호가 단위 테이블.
- 데이터 품질 검사: 결측, 0원, 거래량 0, 액면분할 반영 여부, 시점(look-ahead) 위반.

**산출물**: 실시간 수신기, 녹화 저장소, 리플레이 소스, 데이터 품질 리포트(`experiments/_data-quality/`)
**스킬**: autotrade-java-dev (Python 수집기를 쓰는 경우 같은 원칙 적용)
**완료 기준**
- 특정 날짜의 유니버스를 "그날 상장돼 있던 종목"으로 재현할 수 있다.
- 같은 녹화일을 두 번 리플레이하면 이벤트 순서와 값이 완전히 같다.
- 수신 끊김을 감지하고 재연결 후 누락 구간을 기록한다(해당 구간은 실험 결과에 표시).
- 데이터 출처와 라이선스, 수집 시각이 메타데이터로 남는다.

## 4. 시뮬레이션 엔진 개발

**미션**: 여러 매매 기법을 같은 시세 위에서 독립 계좌로 병렬 운용하는 가상 거래소를 만든다.

**책임**
- `VirtualExchange`: 시세 이벤트를 받아 계좌별 주문을 체결. 체결 규칙은 데이터 해상도별로 정의(일봉: 다음 날 시가, 분봉: 다음 봉 시가, 호가: 잔량 소멸).
- 비용 모델: 수수료, 거래세, 슬리피지(고정 % 또는 유동성 기반), 호가 단위 반올림, 상하한가 체결 불가 처리.
- `VirtualAccount`: 시드머니, 현금, 포지션, 미체결, 일일 거래 건수, 일일·주간 손실 누적.
- `ExperimentRunner`: 실험(기간 × 시드 × 전략 프로필 N개)을 받아 병렬 실행, Run 결과 저장.
- 성과 지표 계산: 총수익률, CAGR, MDD, 샤프, 승률, 손익비(Profit Factor), 평균 보유일, 거래 수, 회전율, 비용 비중, 벤치마크 대비 초과수익.
- 주문 상태머신, 멱등 키, 리스크 검증, 블랙리스트를 실전과 같은 코드로 통과시킨다.

**산출물**: `autotrade-sim` 모듈, 실험 결과 테이블(experiment, experiment_run, virtual_account, virtual_trade_log, equity_curve)
**스킬**: autotrade-java-dev
**완료 기준**
- 골든 테스트: 고정 데이터와 고정 프로필로 거래 내역과 지표가 기대값과 정확히 일치.
- 계좌 간 격리: 한 계좌의 상태가 다른 계좌에 영향 없음(테스트로 증명).
- 실험 1건 결과에 데이터 버전, 프로필 해시, 비용 모델, 코드 버전(커밋)이 기록된다.

## 5. 전략 연구 (퀀트)

**미션**: 실험으로 실전에 쓸 매매 기법을 찾고, 왜 그 기법인지 근거를 남긴다.

**책임**
- 전략 프로필 카탈로그 관리: 종목 선정(스크리너 점수·자격 조건), 매수 선별, 진입 신호, 비중, 거래 건수 제한, 청산, 리스크 한도.
- 엣지 가설을 한 문장으로 쓰고, 가설마다 프로필을 만든다(스타일 혼합 금지).
- 실험 설계: 기간 분할(학습/검증), 파라미터 그리드는 작게 시작, 기준 전략(매수 후 보유, 지수) 포함.
- 결과 비교와 과최적화 검사(워크포워드, ±20% 민감도, 최소 거래 수, 특정 기간 쏠림).
- 승격 제안: 선발 기준 통과 프로필을 PM에게 결정 후보로 제출.

**산출물**: `strategies/<프로필ID>/v<버전>.yaml`, `experiments/<실험ID>/report.md`, 승격 제안서
**스킬**: autotrade-strategy-lab, data-inference-ideation
**완료 기준**
- 모든 리포트에 기간, 시드, 비용 모델, 데이터 버전, 비교 대상이 명시되어 있다.
- 선발 근거가 표본 외 구간 성과를 포함한다.
- 실패한 실험도 기록한다(같은 실험 반복 방지).

**하지 말 것**: 비용 차감 전 성과로 결론 내지 않는다. 결과를 보고 파라미터를 고친 뒤 같은 구간으로 다시 평가하지 않는다.

## 6. 리스크·운영

**미션**: 어떤 오류가 나도 계좌가 훼손되지 않게 한다.

**책임**
- RealTradingGuard를 **실전 계좌별로** 운용(기본 OFF, UI 2차 확인, 세션·대사 통과 후 OPEN), 실전/가상 라우팅.
- 증권사 플러그인 상태(NOT_CONFIGURED/CONFIGURED/ACTIVE/DEGRADED)와 기능별 우선순위, 시세 소스 전환(FAILOVER/SHARDED). 주문은 증권사 간 대체 금지.
- 프로세스 4개 격리(실전 엔진, 시세 게이트웨이, 실험실, 감시)와 자원 부족 시 정지 순서, 서버 측 손절 주문.
- 기준 문서: [broker-and-fault-design.md](broker-and-fault-design.md)
- 주문 무결성 9대 원칙과 타임아웃 시 조회 우선 로직.
- 블랙리스트(UI 지정 + 수동 보유 자동 감지)와 파이프라인 최우선 필터.
- 계좌 한도와 킬스위치(일일·주간 손실, MDD 서킷, 연속 손절, API 오류 누적).
- 3단계 서킷브레이커와 monitor-agent-jar 연동, 거래소 시간 구간 통제.
- 알림(긴급 Slack, 정보성 카카오톡), 카오스 테스트 시나리오(연결 끊기, 응답 지연, 재시작).

**산출물**: `autotrade-risk` 모듈, 안전 테스트 모음, 장애 대응표, 운영 체크리스트
**스킬**: autotrade-java-dev
**완료 기준**
- 안전 규칙마다 실패해야 하는 테스트(위반 시 차단되는지)가 있다.
- 장애 매트릭스 14종이 감지 방법과 함께 구현되고, 장애 테스트 8종(broker-and-fault-design.md 7장)을 통과한다.
- 실험실·UI·게이트웨이를 강제 종료하거나 부하를 걸어도 실전 엔진의 지연 목표가 유지된다.
- 실전 경로를 건드리는 모든 PR에 이 역할의 검토 기록이 있다.

## 7. UI 개발

**미션**: 사용자가 실험을 만들고 비교하고, 시스템을 안전하게 통제할 수 있게 한다.

**책임**
- 실험 화면: 기간·시드·전략 프로필 선택으로 실험 생성, 진행 상태, 결과 리더보드, 자산 곡선 겹쳐 보기, 거래 내역 드릴다운, 추천-선별 거절 사유 로그.
- 전략 프로필 편집: 파라미터 폼, 프로필 복제·버전 관리.
- 설정 화면: default 값 표시, 변경 즉시 반영, API Key 마스킹 입력.
- 운영 화면: 모드 표시(가상 탐색 중/실전 가동 중), 실전 활성화 2차 확인, PANIC SELL, 블랙리스트 관리, 추천 종목·보유 잔고·거래 내역 조회, 모니터링 지표(SSE).

**산출물**: `autotrade-ui`, 화면 명세, API 연동
**스킬**: autotrade-java-dev
**완료 기준**
- 실전 관련 버튼은 확인 절차 없이 동작하지 않는다.
- 같은 실험의 계좌들을 한 화면에서 비교할 수 있다.
- 비밀값은 화면·네트워크 응답·로그에 평문으로 나오지 않는다.

## 8. 역할별 전문성 기준
공통 기준은 [project-instructions.md](project-instructions.md) 9장. 아래는 역할별로 추가로 갖춰야 할 깊이입니다.

| 역할 | 전문가 수준으로 갖출 것 |
|---|---|
| 기획 리드 | 요구사항마다 ID, 근거 원문 위치, 측정 가능한 인수 조건. 요구사항 간 충돌·누락 분석표. 단계별 범위와 완료 기준. 원본 문서 간 차이는 어느 쪽을 택했는지 이유와 함께 기록 |
| 아키텍트 | 모듈 의존 방향과 금지 의존을 빌드로 강제(예: ArchUnit). 인터페이스마다 계약(사전·사후 조건, 예외, 스레드 안전성). ADR마다 대안 2개 이상과 트레이드오프. 성능·메모리 예산과 측정 방법 |
| 데이터 엔지니어 | 증권사 문서의 원문 근거(링크, 버전, 확인 날짜). 시세 지연·누락·순서 뒤바뀜 처리와 품질 지표(지연 분포, 누락률). 녹화 형식의 스키마 버전과 리플레이 정확성 검증 |
| 시뮬레이션 엔진 | 체결 모델의 가정(호가 깊이, 부분 체결, 슬리피지)을 명시하고 실제 체결 기록과 비교해 오차를 측정. 결정론 보장(같은 입력 같은 결과) 골든 테스트. 비용 모델 출처 |
| 전략 연구 | 가설, 사전 등록한 평가 지표, 표본 외 검증(IS/OOS, 워크포워드), 다중 비교 보정, 파라미터 민감도(±20%), 비용 차감 후 성과, 생존편향·미래정보 점검표. 성과가 좋을수록 더 의심하고 원인을 설명 |

| UI 개발 | 실전·모의 상태를 착각할 수 없는 화면(색, 문구, 2차 확인). 위험 동작은 되돌릴 수 없음을 명시. 비밀값 마스킹. 접근성과 장시간 모니터링 피로도 고려 |
