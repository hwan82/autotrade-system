# D-126 녹화 판정이 선정 조합 계좌를 세션의 고정 선정 파일로 판정한다(D-124 후속)

- 날짜: 2026-10-20
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). `autotrade-sim`만 바꾼다. 실전 경로, RealTradingGuard, 블랙리스트 규칙, 리스크 한도, 보호 경로는 바꾸지 않는다. 등록 파일에 `selections`가 없으면 레인·결과 파일이 지금과 바이트로 같다(LIVE00·LIVE01 불변, 시험으로 확인).
- 담당: sim-engine. 교차 검토: architect(코드)
- 근거: [D-116](D-116-stage-6-recording-judgement.md)(녹화 판정), [D-124](D-124-selection-accounts-live-recording.md) 10번(녹화 판정은 후속), [ADR-012](../adr/ADR-012-intraday-selection.md) 3.3(대조군 "같은 선정 + 무작위 진입")·3.6(고정 파일), architect PR #197 R2·R4. 번호: D-125는 열린 브랜치(선정 엣지 일봉 사전 검사)가 써서 D-126을 쓴다.

## 결정

1. **녹화 판정(`runLiveJudgement`)이 선정 조합 계좌를 받는다.** 판정의 모든 레인(BASE·PERTURB·지연 0/1.5/2초·대조군 시드·REC 녹화)이 실시간 세션이 남긴 같은 적용 기록과 결과 파일(`<설정 폴더>/live-sessions/<ID>/selections/<날짜>/`)을 읽는다. 판정 때 선정을 다시 계산하지 않는다. 그래서 변형·지연·대조군 계좌도 실시간 계좌와 같은 날 같은 후보로만 새로 사고, 쓰는 선정은 그날 장 시작 전에 정해진 것뿐이다(미래 정보 없음).
2. **고정 파일 확인은 리플레이 확인과 같다**: 기간의 적용 기록이 가리키는 결과 파일이 없거나 내용 해시가 다르면, 또는 입력 기록에 줄이 있는 날의 적용 기록이 없으면 판정하지 않고 입력 오류(종료 코드 1)로 멈춘다.
3. **역할**: 기준선(`buy-and-hold`)은 선정과 상관없이 하나. 대조군(`random`)은 선정 묶음(선정 없음, 선정 프로필마다)마다 하나까지이고, 판정 대상이 있는 묶음에는 같은 묶음의 대조군이 있어야 한다. 선정 판정 대상에 같은 선정의 대조군이 없으면 입력 오류다(ADR-012 3.3 "같은 선정 + 무작위 진입").
4. **L10 대조군 분포는 묶음마다 따로**: 판정 대상이 있는 묶음의 대조군을 시드 = 실험 시드 + i로 N개씩 돌리고, 계좌의 L10은 같은 묶음 분포로 본다. N = 21m − 1, m은 묶음을 합친 판정 대상 수(본페로니 0.05/m도 전체 m). 레인 ID는 선정 없음 `<ID>-NULL<i>`(지금과 같음), 선정 묶음 `<ID>-S<k>-NULL<i>`(k는 판정 대상이 있는 선정 묶음의 계좌 순서).
5. **변형·지연**: 판정 대상의 ±20% 변형과 지연 레인 계좌는 원래 계좌의 선정을 그대로 쓴다. 변형 Run은 프로필 ID가 아니라 레인 안 순서로 찾는다(같은 전략이 선정 없음·선정 묶음 양쪽에서 판정될 수 있음).
6. **결과 파일**: 계좌 이름에 `선정@버전 x 전략@버전`을 쓰고, 선정이 있을 때만 머리 설명 한 줄, 6장 대조군 분포를 묶음별 소제목으로 나누고, 9장 "선정(D-124)"(날짜·선정마다 상태·후보·`NOT_SUBSCRIBED`·`BLACKLISTED`·커버리지·막힌 신규 진입, 녹화 실험 results.md와 같은 표)을 더한다. 선정이 없으면 아무것도 바뀌지 않는다.
7. **준비 작업이 같은 입력으로 실패한 날 다시 읽지 않는다(architect PR #197 R2)**: 계산이 실패하면 사유 파일(`<hash>.problem.json`)에 입력 스냅샷 키(`daily=<ID>;financials=<ID>`)를 남긴다. 결과가 없는 선정이 모두 같은 키로 이미 실패했으면 준비 작업은 스냅샷을 읽지 않고 남긴 사유를 돌려준다. 새 스냅샷이 나오면(키가 다르면) 다시 계산한다. 적용 기록(`applied.json`)에는 키가 들어가지 않는다(형식 불변).
8. **녹화 실험 선정 준비(architect PR #197 R4)**: 일봉 스냅샷을 읽기 전에 힙을 본다(행 수 × 1KB `[가정]`이 최대 힙의 절반을 넘으면 읽지 않고 `-Pheap=<N>g`를 안내하는 입력 오류). 다시 돌리면 이전 실행이 남긴 `experiments/<ID>/selections/` 파일 중 이번 결과에 없는 것과 빈 폴더를 지운다(커밋하지 않는 생성 파일). 힙 추정은 `SnapshotHeap` 한 곳에 둔다.

## 대안 비교

| 쟁점 | 채택 | 버린 안과 이유 | 되돌릴 조건 |
|---|---|---|---|
| 판정 레인의 선정 | 세션 고정 파일 읽기 | 판정 때 다시 계산: 스냅샷·계산 코드가 바뀌면 실시간 계좌와 다른 후보로 돌고, 재계산 확인은 리플레이 확인이 이미 함 | 없음 |
| 선정 계좌의 L10 | 같은 선정 대조군 분포(묶음별) | 선정 없는 대조군 하나로 모두 비교: 선정 효과와 진입 효과가 섞여 "진입 규칙이 무작위보다 나은가"를 못 봄(ADR-012 3.3) | 선정 효과만 따로 볼 축이 필요해지면 대조군 축 2(같은 지표 + 선정 없음)를 판정 항목으로 더함 |
| 선정 계좌 판정 거절 유지 | 붙임 | LIVE02 판정 때 손으로 따로 계산: 결과 재현이 안 됨 | 없음 |
| m과 N | 전체 m, 묶음마다 N = 21m − 1 | 묶음별 m: 다중 비교 보정이 약해짐 | strategy-researcher가 묶음별 보정을 정하면 |
| 실패일 재시도 | 같은 입력 키면 건너뜀 | 시간 물러서기: 같은 입력이면 몇 번을 다시 해도 같은 실패이고 시각 의존이 생김 | 계산이 입력 밖 요인(시각 등)에 의존하게 되면 |
| 녹화 실험 힙 | 읽기 전 검사 + 안내 | OOM 뒤 안내: 명령이 오래 돈 뒤 죽고 원인을 사람이 찾아야 함 | 행당 바이트 실측(architect R3)으로 추정이 크게 틀리면 값만 바꿈 |

## 위험과 한계

- 대조군 시드를 묶음마다 돌려 Run 수가 늘어난다(판정 대상 m, 선정 묶음 g면 대조군 Run이 약 (1 + g) × (21m − 1)). LIVE02 등록 전에 판정 시간을 다시 잰다 `[추론]`.
- 행당 1KB는 실측 전 `[가정]`이다(architect PR #197 R3). 녹화 실험이 필요 없이 멈추면 `-Pheap`을 올려 다시 돌린다.
- 판정 대상이 없는 선정 묶음의 대조군은 참고로만 표에 나오고 L10은 판정 불가로 남는다.
- 같은 입력 키로 건너뛰는 것은 계산이 입력 스냅샷만으로 정해진다는 계약(SelectionSource)에 기댄다. 계산 코드를 고친 뒤 같은 날을 다시 준비하려면 사유 파일을 지운다(실험실을 다시 띄워도 사유 파일은 남는다). runbook stage-6-live-session에 적었다.
