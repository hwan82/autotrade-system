## 1. ORD-06 지연 초과 신호 폐기

- 원본: 총 지연 목표 1.5초 초과 신호는 주문하지 않고 폐기(chatgpt-주식매매 4장).
- 추천 요구사항: 신호 생성 시각(근거 시세 이벤트 시각)부터 발주 직전까지 경과가 `order.max-signal-age`(기본 1.5초 `[가정]`, MON-04 목표와 같은 값)를 넘으면 **신규 진입 신호만** 폐기하고 사유 `STALE_SIGNAL`로 기록한다. 청산·손절·취소는 나이와 무관하게 실행한다.
- 인수 조건: 지연 주입 시 신규 진입 0건·사유 로그 존재, 같은 조건에서 손절 매도는 실행됨. 가상 체결도 같은 규칙(SIM-12).
- 대안: (a) 원본 그대로 모든 신호 폐기 → 손절 매도가 늦을수록 버려져 위험, 버림. (b) 폐기 없음, 지연만 기록 → 오래된 가격으로 진입해 성과 왜곡, 버림. (c) 채택안.
- 되돌릴 조건: 6단계 실측 p95가 목표를 자주 넘어 폐기율이 높으면 값을 실측 기반으로 재조정(값 변경은 실전 한도라 사용자 결정).
- 위험: 시계 기준이 다르면 오판. 경과는 같은 프로세스 단조 시계로 재고, 거래소 시각은 기록만 한다.

## 2. ORD-07 주문 상태머신과 재시작 복구

- 추천: 채택. 상태 집합 `NEW → SUBMITTING → ACCEPTED → PARTIALLY_FILLED → FILLED`, 분기 `REJECTED`, `CANCEL_REQUESTED → CANCELED`, `EXPIRED`, `UNKNOWN`(타임아웃·응답 유실). 허용 전이표 밖 전이는 예외로 막고 경보. 전이마다 시각·멱등 키·응답 원문(비밀값 마스킹) 기록.
- 재시작 복구: 미완료(종결 상태 아님) 주문은 기동 시 전부 `UNKNOWN`으로 보고 조회 → 증권사 기준으로 확정. 확정 전에는 해당 계좌 Guard OPEN 불가(RSK-01 활성화 절차의 "첫 대사"에 포함).
- 인수 조건: 전이표 전체 단위 테스트, 금지 전이 실패 테스트, 미완료 주문을 둔 채 강제 종료 후 재기동 시 중복 주문 0건(TST-01 #3과 같은 시나리오).
- 대안: 상태를 DB에만 두고 전이 규칙 없이 갱신 → 중복 매도 원인 추적 불가, 버림.
- 위험: 증권사별 상태 코드 매핑 누락. 매핑 못 한 코드는 `UNKNOWN`으로 보내고 조회로 확정.

## 3. ORD-08 9대 원칙 판정 기준

- 원본 수치 `[가정]`: 최우선 잔량 < 주문 수량 1.5배 또는 스프레드 > 0.3%면 발주 취소, 슬리피지 상한 0.5%, 주문 실패 3회면 정지, 실측 슬리피지 괴리 종목은 당일 제외, 킬스위치·서킷 자동 해제 금지.
- 추천: 수정 채택.
  - 유동성·스프레드·슬리피지 상한은 **신규 진입에만** 적용. 청산·손절은 막지 않고 overseas-design.md O5처럼 여유폭을 단계적으로 넓혀 재시도한다.
  - 주문 실패 3회 정지는 **해당 계좌·해당 API 그룹 단위**(ORD-04와 같은 단위). 다른 계좌 영향 없음(RSK-09).
  - 괴리 종목 당일 제외는 신규 진입만, 보유분 청산은 허용.
  - 자동 해제 금지 채택.
  - 수치는 설정 키 기본값으로 두고 실전 값은 Q-008에 편입.
- 대안: 원본 그대로 → 급락 시 스프레드가 벌어지면 손절이 막힘, 버림.

## 4. RSK-01 보강: Guard 활성화 절차와 OFF 전환

- 추천: 채택.
  - Guard OFF 계좌는 **주문용** 세션·토큰을 만들지 않는다(시세용은 별개). 주문 API 클라이언트 생성 자체가 OPEN 이후에만 가능하도록 구조로 막는다.
  - 활성화 순서: 인증 → 주문 세션 → 첫 대사(잔고·미체결·ORD-07 복구 확정) 통과 → OPEN. 중간 실패 시 OFF 유지와 사유 표시.
  - 2차 확인: 로컬 비밀번호 재입력(해시만 저장, 비밀 저장소 CFG-03) + 계좌 표시명 확인. `[추론]` 브라우저 클릭 두 번은 실수로 통과할 수 있어 지식 요소를 넣는다.
- OFF 전환 시 보유 처리(**질문 1**):
  - A **보호 모드(추천)**: 신규 진입 중단, 미체결 매수 취소, 보유분은 손절·익절 매도와 서버 측 손절(RSK-06)만 계속. 보유 0이 되면 주문 세션 종료.
  - B 즉시 정지: 미체결 전부 취소하고 엔진 매도도 멈춤. 보유분은 서버 측 손절만 남고, 서버 측 손절 미지원 계좌는 보호 수단 없음.
  - C 전량 청산: OFF가 곧 PANIC SELL. 실수로 끄면 원치 않는 손실 확정.
  - 재기동 시는 규칙대로 모든 계좌 OFF로 시작한다. 보유가 있으면 Slack 긴급 알림으로 알리고, 사용자가 2차 확인을 거쳐 보호 모드나 OPEN을 고른다. **재기동 후 자동 보호 모드 진입은 하지 않는다**(지침 4장 1번 "재기동 시 OFF"를 약화하지 않기 위해). 그 사이 보호는 서버 측 손절 주문이 맡는다.
- 인수 조건: OFF 계좌에서 주문 클라이언트 생성 시도 실패 테스트, 활성화 단계별 실패 주입 시 OFF 유지, 선택한 OFF 처리 규칙 테스트.

## 5. RSK-04 보강: 서킷 3단계

- 추천: 채택. RSK-07 정지 순서와 같은 말로 맞춘다.
  - 1단계: 해당 계좌 신규 매수 차단. 보유 관리 계속.
  - 2단계: 엔진 잠금. 신규 주문 중단, 미체결 매수 취소, 보호 모드(손절·익절 매도만), 연결 재수립과 대사.
  - 3단계: 청산·종료. 아래 질문 3.
  - 단계 진입 조건(손실 한도, 연속 손절, API 오류 누적, MDD)의 값은 Q-008. 단계는 올라갈 때 자동, **내려갈 때와 해제는 수동**(2차 확인, 감사 로그).
- 3단계 동작(**질문 3**):
  - A **자동 PANIC OFF(추천, 원본안)**: 3단계는 신규 주문 전면 중단 + 긴급 알림 + 사용자 PANIC SELL 확인 대기. 서버 측 손절과 보호 모드 매도는 유지.
  - B 자동 청산: 3단계 진입 즉시 자동 매매 포지션 전량 청산. 오탐(예: 시세 오류로 MDD 오계산)이면 손실 확정.
- 인수 조건: 단계별 발동·해제 테스트, 자동 하향 해제가 일어나지 않는 실패 테스트.

## 8. RSK-12 블랙리스트 영속화와 해제

- 추천: 수정 채택.
  - DB 영속화, 항목: 종목, 시장, 유형(`MANUAL` 사용자 지정 / `AUTO_ASSET` 수동 보유 자동 감지), 사유, 등록 시각·주체, 범위.
  - 감지 시점: 장전 + 매 5분 대사(BRK-05). 수동 보유 판정은 "시스템 주문 원장에 없는 보유".
  - **보유 중 AUTO_ASSET은 해제 불가**(원본은 2차 확인 후 해제). `[추론]` 보유 중 해제하면 시스템이 사용자의 수동 포지션을 손절·청산 대상으로 잡을 수 있어 지침 4장 3번을 사실상 약화한다. 사용자가 매도해 보유가 0이 된 뒤 해제 제안을 띄우고, 해제는 사용자 클릭 + 2차 확인.
  - MANUAL 해제는 2차 확인 + 감사 로그.
  - 차단 시마다 감사 로그(경로, 계좌, 종목, 규칙).
  - 실험실: 실시간 모의는 현재 블랙리스트 적용, 리플레이·백테스트는 실험 시작 시 블랙리스트 스냅샷을 실험 메타에 기록해 결정론 유지(SIM-09·10).
- 적용 범위(**질문 2**):
  - A **전역(추천)**: MANUAL·AUTO_ASSET 모두 모든 실전 계좌와 실시간 모의 계좌에 적용. 한 계좌의 수동 보유 종목을 다른 계좌가 자동 매매하는 일도 막는다.
  - B 계좌별: 등록한 계좌에만 적용. 유연하지만 한 종목에 수동 보유와 자동 매매가 동시에 걸려 합산 노출이 의도보다 커질 수 있음.

## 9. RSK-13 PANIC SELL

- 추천: 채택.
  - 범위: 계좌별 버튼과 전체 버튼 모두. 둘 다 2차 확인.
  - 대상: 자동 매매 포지션만. 블랙리스트·수동 보유 제외(지침 4장 3번).
  - 순서: Guard를 보호 모드로 고정(신규 주문 즉시 차단) → 미체결 전부 취소 확인 → 서버 측 손절 주문 취소 확인(이중 매도 방지, RSK-06) → 매도 → 체결 확인 → Guard OFF.
  - 장 외 시간: 미체결 취소와 Guard OFF만 하고, 매도는 다음 개장 후 사용자가 다시 누른다(예약 매도 자동 실행 안 함).
  - 실전 엔진이 죽어 있으면 감시 프로세스의 긴급 경로(MON-02, 매도·취소만)로 같은 순서.
- 국내 매도 방식(**질문 4**):
  - A **시장가(추천)**: 정규장에서 즉시 체결 우선. 미국은 시장가 매도도 가능하나 엔진 공통 규칙(OVS-06)대로 지정가+여유폭.
  - B 국내도 지정가+여유폭: 시장·엔진 규칙이 하나로 같아지지만 급락 중 미체결이 남을 수 있음.
- 인수 조건: 블랙리스트 종목 미매도 테스트, 서버 측 손절 취소 확인 전 매도 금지 테스트, 엔진 종료 상태에서 감시 프로세스 PANIC 테스트.

## 10. CFG-05 운영 중 API Key·증권사 교체

- 추천: 수정 채택. 원본은 "미체결 0건 또는 Guard OFF"로 하나였으나 둘을 나눈다.
  - **API Key 교체**: 해당 계좌 미체결 0건일 때만, 교체 중 신규 진입 일시 중단과 DEGRADED 표시, 교체 후 첫 대사 통과 시 자동 재개(재개는 원래 상태 복귀일 뿐 OPEN 승격이 아님).
  - **증권사 교체**: 계좌의 증권사가 바뀌는 것은 새 계좌로 본다(지침 4장 7번 "주문은 계좌의 증권사로만"). Guard OFF + 보유 0 + 미체결 0일 때만 허용.
- 대안: 원본 그대로 → 미체결 0이면 증권사도 바꿀 수 있어, 보유가 남은 채 주문 경로가 다른 증권사로 바뀌는 일이 생김. 버림.

## 12. STR-05 보강 승격 단계

- 원본 `[가정]`: 모의 중 사고 1건이면 8주 재시작, 실전 소액 4주(목표 대비 괴리 30% 이내), 확대 3개월(자산 30%).
