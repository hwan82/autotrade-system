# 기획서 관리 (Spec Keeper)

## 파일
- 기획서: `docs/spec/autotrade-spec.md`
- 결정 로그: `docs/decisions/README.md` (확정 표 + 미확정 표)
- 아키텍처 결정: `docs/adr/`

## 기획서 구조 (장 번호 고정)
0. 문서 정보(버전, 갱신일, 변경 이력 표)
1. 목적과 범위
2. 운영 환경 (개인 PC, 가용성 대책)
3. 아키텍처와 모듈, 프로세스 구조
4. 시세 데이터와 증권사 연동
5. 시뮬레이션 실험실
6. 종목 선출과 전략 프로필
7. 리스크 관리와 실전 가드
8. 주문 실행 무결성
9. 설정 체계 (default → runtime-config → UI)
10. UI
11. 모니터링과 알림
12. 해외(미국)주식
13. 테스트와 검증 단계, 장애 테스트
14. 로드맵
15. 확정 필요 결정

## 갱신 절차
1. **요청 분해**: 요구사항 단위로 나누고 ID를 붙인다(예: SIM-06, BRK-03, OVS-04).
2. **충돌 확인**: 기존 장과 docs/decisions 확정 표와 비교해 충돌·중복·대체 관계를 표로 정리한다. 확정 결정과 충돌하면 사용자에게 묻고, 답 전에는 "미확정"으로 둔다.
3. **반영**: 해당 장만 고친다. 다른 장의 내용을 복사하지 않고 장 번호로 참조한다.
4. **버전**: 내용 추가·변경은 부 버전(v12.1 → v12.2), 범위·구조 변경은 주 버전(v12 → v13). 변경 이력 표에 날짜, 버전, 요약, 요구사항 ID.
5. **결정 기록**: 사용자가 확정한 사항은 결정 로그 확정 표에 새 번호로 추가한다. 뒤집을 때는 기존 행을 고치지 않고 "D-xxx 대체"로 새 행을 쓴다.
6. **영향 통보**: 영향을 받는 역할(pm-lead, architect, data-engineer, sim-engine, strategy-researcher, risk-ops, ui-dev)과 할 일을 목록으로 만든다.
7. **미확정 갱신**: 새 미확정 항목을 결정 로그 미확정 표에 담당 역할과 함께 추가한다.

## 외부 자료 반영 규칙
- 다른 AI 대화, 블로그, 예시 문서에서 온 내용은 출처를 적고 [가정]으로 표시한다.
- 증권사 API 기능·주소·레이트리밋·구독 한도, 세율, 수수료는 공식 자료로 확인 전에는 확정하지 않는다.
- 예시 코드는 기획서에 넣지 않는다. 필요하면 인터페이스 시그니처와 동작 규칙만 쓴다.

## 출력
- 채팅에는 요약만: 바뀐 장, 새 버전, 사용자가 결정할 항목(선택지와 추천안), 영향받는 역할.
