## 대안과 버린 이유

- ① D-037 행 자체를 고쳐 근거를 나눔: 결정 로그는 기존 행을 고치지 않는 규칙(결정 로그 머리말)이라 버림. D-037 상세 파일을 새로 만들고 D-037 행에 링크를 다는 방법도 행 수정이라 버림. 보충 번호를 쓰는 방식은 D-095("D-092 4번 보충")와 같다.
- ② Q-047에 새 결정 번호를 붙임: 결정 내용은 PR #47·D-059 기록과 broker-and-fault-design.md 7.1에 이미 있고 바뀐 것이 없어, 닫힌 미확정 표의 다른 행(예: Q-009 "D-077 ⑧로 닫음")처럼 닫은 사유만 적었다.
- ⑤ #13 행을 그대로 두고 RSK-13에만 맡김: 장애 매트릭스를 먼저 읽는 구현자가 "보유분 유지"를 PANIC 매도 금지로 읽을 수 있어(architect 참고 2) 한 줄을 넣는 쪽을 골랐다. 묶음 E까지 미루는 안도 있었으나 문서만의 변경이라 지금 넣는다.
- ⑥ 그대로 둠: 두 인수 조건이 함께 있어 해석 충돌은 없지만(risk-ops 권고 3), 묶음 E 실패 테스트를 쓸 때 OFF 계좌에도 "보호 모드 고정" 테스트를 만들면 D-140 ①(확인 없이 올리지 않음)과 반대가 된다. 한정하는 쪽이 안전하다.

## 위험과 한계

- ③④는 문서다. TST-06의 화면 경고(묶음 H)와 K10 추천안의 코드 변경(있다면)은 따로 실전 관련 PR로 한다.
- 대응표 상태(충족·미충족)는 2026-10-26 main 기준이라, 7단계 묶음이 머지될 때마다 risk-ops가 갱신해야 한다.
- 이 기록은 RealTradingGuard·주문 경로·블랙리스트·리스크 한도·장애 대응 규칙을 바꾸지 않는다. ⑤는 D-140 ④의 문구를 옮긴 것이다.
