## 남은 권고 (막지 않음)

- R1. 휴장일 제외 분기(`KrxDailyCollector.java:111`의 `&& !calendarSaysHoliday(d)`)를 시험이 실제로 밟지 않는다. 새 시험 `여러_시장_중_최근_날_한_시장만_빈_목록이면...`은 10-05(시험 캘린더 휴장일)를 "최근이어도 게시 전 목록에 넣지 않는다"고 주석을 달았지만, 그 시험의 가짜 응답은 10-05에 두 시장 모두 자료를 주므로(`kospi && !d.isBefore(tue)`만 빈 목록) `empty`가 거짓이라 휴장일 조건과 무관하게 목록에 안 들어간다. 조건을 지워도 시험이 통과할 것으로 본다 `[추론]`. 영향은 최근 휴장일에 거짓 "게시 전" 한 줄이 나오는 콘솔 잡음뿐이라 데이터 오염은 없다. 10-05에 빈 목록을 주는 단언 하나를 넣고 주석을 맞추기를 data-engineer에 권한다.
- R2. 모든 시장이 빈 날은 "빠지는 시장"으로 적지 않는다(의도대로). 이 날은 `KrxDailySnapshotBuilder.java:117`에서 빈 평일로 분류돼 거래일에서 빠지므로, 그 실행의 스냅샷은 앞 거래일에서 끝난다 `[사실]`. 6단계 매일 운영에서 "스냅샷의 마지막 거래일"로 선정 결과를 내면 하루 묵은 자료로 그날 선정을 하게 된다 `[추론]`. runbook 문구를 "이 한 줄이 보이면(부분이든 전체든) 그날 선정에는 다시 수집한 스냅샷을 쓴다"로 넓히는 것을 권한다.
- R3. `CollectorMain.java`에서 새 메서드가 기존 `uncachedDates`의 Javadoc(`/** 이번 실행에서 캐시하지 않은 응답의 날짜... */`) 바로 아래에 끼어, 그 주석이 새 메서드 위에 떠 있고 `uncachedDates`는 설명을 잃었다. Java 21 툴체인의 `-Xlint:all`에는 dangling doc 경고가 없어 빌드는 통과하지만(JDK 23+로 올리면 `-Werror`에 걸릴 수 있음 `[추론]`), 주석을 `uncachedDates` 위로 옮기기를 권한다.
- R4(실험 기록). 이 한 줄은 콘솔에만 남는다. 6단계에서 날마다 만든 스냅샷을 실험 입력으로 쓸 때는 스냅샷 품질 리포트의 `PENDING`(PR #141) 칸이 비었는지를 실행 기록에 남겨, 부분 시장 날이 든 스냅샷이 실험에 쓰이지 않았음을 확인할 수 있게 한다. strategy-researcher가 사전 등록 절차에 반영한다(PR #141 R2와 같은 자리).
