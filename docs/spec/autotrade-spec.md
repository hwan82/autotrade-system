## 1. 목적과 범위

**목적**: 증권사 모의투자 API를 쓰지 않고, 실전 API로 받은 실시간 시세 위에서 자체 시드머니 모의 계좌 여러 개로 매매 기법을 병렬 운용·비교해 실전에 쓸 기법을 찾는다. 실전 매매는 검증을 통과한 기법에 한해 사용자가 UI에서 켤 때만 동작한다.

| 범위 | 포함 | 제외 |
|---|---|---|
| 시장 | 국내(KRX 코스피·코스닥), 미국 정규장(NYSE·NASDAQ·AMEX) | 미국 외 해외시장(D-014), 미국 프리·애프터·주간거래(D-015) |
| 증권사 | 토스·키움·한국투자, 설정되고 정상인 곳만(D-007) | 증권사 모의투자 API(D-003) |
| 매매 스타일 | 장중 단타, 일봉 스윙(D-006) | 파생상품, 소수점 매매(D-015) |
| 실행 환경 | 개인 PC(D-001) | 클라우드 서버 |

| ID | 요구사항 | 인수 조건 | 근거 |
|---|---|---|---|
| SIM-01 | 모의 단계에서 실전 API는 시세 수신에만 쓰고 주문 API는 호출하지 않는다. 모의 주문은 자체 가상 거래소에서 체결한다 | 모의 모드 전체 실행 중 증권사 주문 API 호출 0건(호출 계측 테스트로 증명) | D-003, team-design.md 2.2 |
| SIM-02 | 실험은 자체 시드머니로 시작한다 | 실험 설정에 시드머니가 기록되고 기본값은 D-021 | D-021 |
| SIM-03 | 매매 조건별로 여러 모의 계좌를 같은 시세 위에서 동시에 운용한다 | 한 실험에서 계좌 N개(N ≥ 2)가 같은 이벤트 스트림을 받아 독립 체결 | D-004 |
| SIM-04 | 기간을 정해 여러 매매 기법을 테스트한다 | 실험 = 기간 × 시드 × 전략 프로필 N개 × 비용 모델로 정의되어 저장 | team-design.md 3장 |
| SIM-05 | 결과를 비교해 실전 후보를 고른다 | 같은 실험의 계좌들이 리더보드로 비교되고 선발 기준(6장 STR-04) 통과 여부가 표시 | team-design.md 3장 |

## 7. 리스크 관리와 실전 가드

상세: [broker-and-fault-design.md](../team/broker-and-fault-design.md) 3.3·5·6장. 이 장의 요구사항을 바꾸는 변경은 risk-ops 검토 후 사용자가 결정한다(지침 8장 2번, 10장).

**7·8장 공통 원칙(D-023)**
1. 새 차단 규칙은 **신규 진입만** 막는다. 손절·청산·취소 같은 보호 동작은 어떤 차단 규칙으로도 막지 않는다. **예외: 블랙리스트·수동 보유(RSK-02)** 는 시스템이 보유한 수량의 손절·청산도 막는다(D-035). 그래서 보유 중인 종목이 블랙리스트에 오르면 경고한다(RSK-12).
2. 자동 해제 없음. 킬스위치·서킷·블랙리스트·Guard는 내려갈 때 자동, 다시 열 때는 사람(2차 확인, 감사 로그).
3. 모든 규칙은 하나의 검증 체인에 있고 가상 엔진도 같은 규칙으로 돈다(SIM-12).
4. 수치는 설정 키 기본값 `[가정]`이며, 실전 값은 Q-008에서 사용자가 정한다.

| RSK-13 | PANIC SELL: 계좌별·전체 버튼. 대상은 자동 매매 포지션만(블랙리스트·수동 보유 제외). 순서: ① 보호 모드 고정(신규 주문 즉시 차단). **2차 확인 전에** 하며 확인 실패·잠금·비밀번호 미설정이어도 수행한다. 전체 PANIC은 모든 계좌를 먼저 고정한다 → 2차 확인(RSK-01, 확인 문구는 계좌 별칭, 전체는 `전체 청산`. 실패하면 ①에서 멈춤) → ② 미체결 전부 취소 확인 → ③ 서버 측 손절 주문 취소 확인 → ④ 매도 → ⑤ 체결 확인 → ⑥ Guard OFF. 앞 단계가 끝나지 않으면 뒤 단계를 하지 않는다. **Guard OFF는 ②~⑤가 모두 끝났을 때만** 하고, 아니면 보호 모드를 유지한다(서버 측 손절을 취소한 뒤 매도·체결 확인이 실패하면 남은 보유에 서버 측 손절을 다시 걸거나 실패를 긴급 표시). 매도 방식: **국내 시장가**, 미국 지정가+여유폭(OVS-06, 미체결 시 여유폭 단계 확대). 장 외 시간에는 매도를 내지 않고 매도는 개장 후 사용자가 다시 실행한다. **매도를 낼 수 없으면(장 외 시간, 거래정지·VI·LULD 정지 등) ③ 서버 측 손절 취소를 하지 않고 ②는 미체결 매수만 취소한다**(서버 측 손절은 마지막 방어선, broker-and-fault-design.md 6.1). 이 규칙은 Q-017 결정 전에도 적용한다. 장 외 시간에 Guard를 끌지는 Q-017(추천: 보호 모드 유지)이며 결정 전 구현은 보호 모드를 유지한다. 재기동 직후 OFF 계좌는 ②~⑥을 건너뛴다(Q-016). 실전 엔진이 죽어 있으면 감시 프로세스 긴급 경로(MON-02, 매도·취소만)로 같은 순서. 명령 채널·2차 확인·단계별 처리 기준은 [ADR-006](../adr/ADR-006-real-control-channel.md) 2.3~2.5 | 블랙리스트·수동 보유 종목 미매도 테스트, 서버 측 손절 취소 확인 전 매도 금지 테스트, 엔진 종료 상태에서 감시 프로세스 PANIC 테스트, 장 외 시간 매도 미발주 테스트, 2차 확인 실패·잠금·비밀번호 미설정에서도 보호 모드 고정·청산 미수행 테스트, ②~⑤ 중 하나라도 끝나지 않으면 Guard OFF가 일어나지 않는 테스트, 장 외 시간·거래정지 종목 PANIC에서 서버 측 손절 취소와 미체결 매도 취소가 일어나지 않는 테스트 | D-023, D-037, 원본 v6·v11 |
