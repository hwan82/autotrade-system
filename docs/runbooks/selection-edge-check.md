# 선정 엣지 일봉 사전 검사 실행 절차 (사용자 PC)

[D-125](../decisions/D-125-selection-edge-precheck.md), [ADR-012](../adr/ADR-012-intraday-selection.md) 배치표 2b. 단타 선정 프로필이 고른 종목을 선정일 T 시가에 사서 T 종가에 판 결과를, 같은 날 같은 수를 무작위로 고른 대조군 999개와 비교한다. 판정을 통과한 선정만 녹화 실험(배치표 5번)과 실시간 모의 LIVE02 등록 후보가 된다. 일봉 원자료는 PC 밖으로 내보내지 않고, 저장소에는 등록 파일과 집계 결과만 들어간다(D-050).

## 순서 한눈에

| 단계 | 누가 | 무엇 |
|---|---|---|
| 1 | Claude | 등록 파일 `experiments/EXP-20261020-EDGE01/edge.yaml` 커밋(끝남, 결과를 본 뒤 고치지 않음) |
| 2 | 사용자 | `git pull` 뒤 EDGE01 실행(2장) |
| 3 | 사용자 → 스레드 | 결과 파일 다섯 개를 올린다(3장) |
| 4 | Claude | 결과 커밋, 판정 정리 |
| 5 | 사용자 | 공시 전체 수집과 품질 리포트 확인(4장). 끝나면 스냅샷 ID를 알려 준다 |
| 6 | Claude | EDGE02 (라)·EDGE03 공시 대조 등록 파일을 결과 전에 커밋 |
| 7 | 사용자 → 스레드 | EDGE02·EDGE03 실행과 결과 업로드(2·3장과 같음) |

## 1. 실행 시각(장 시간 보호)

실험 명령은 장 시간 보호 구간에는 시작하지 않고, 돌던 중이면 종료 코드 4로 멈춘다([실행 매뉴얼](README.md) 2장). 보호 구간은 국내 08:00~16:00, 미국 21:30~05:30(2026-11-02부터 22:30~06:30)이다(서울 시각).

- **추천: 토요일 07:00에 시작**. 토요일 07:00부터 월요일 07:30까지는 보호 구간이 없다. 걸리는 시간은 아직 모른다 `[가정]`(합성 시험만 돌렸다). 결정론 확인을 붙이면 두 번 돈다.
- 평일이면 16:30에 시작해 21:00(2026-11-02부터 22:00) 전에 끝나야 한다. 처음 한 번은 주말에 돌려 걸린 시간을 확인한다.
- 실전 엔진과 게이트웨이를 끈 날이라도 `-PallowDuringSession`은 붙이지 않는다(필요 없다).

## 2. 실행

PowerShell을 열고 아래를 그대로 붙여 넣는다.

```
chcp 65001
cd C:\2.Code\myproject\autotrade-system
git pull
.\gradlew.bat :autotrade-app-experiment:runSelectionEdgeCheck -Pexperiment=EXP-20261020-EDGE01 -PverifyDeterminism
```

- `chcp 65001`은 한글 출력이 깨지지 않게 한다.
- 일봉 스냅샷 `krx-daily-2026-10-16-a6df4719`가 기본 위치(`<설정 폴더>\snapshots\`)에 있어야 한다. 다른 폴더에 두었으면 `-PsnapshotsDir=D:\폴더`를 붙인다.
- 진행 상황(거래일 20일마다)은 실험실 진행 화면에 "선정 엣지 검사"로 보인다. 실험실에서 취소하면 종료 코드 3, 결과 파일은 쓰지 않는다.
- 메모리 기본 8GB. `OutOfMemoryError`가 나면 `-Pheap=12g`처럼 올리고, 그래도 안 되면 메시지를 스레드에 붙인다.

종료 코드(출력 마지막 `finished with non-zero exit value N`의 N, 없으면 0):

| 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 끝남. 판정이 탈락·판정 불가여도 0 | 3장 |
| 1 | 입력 오류(스냅샷 없음, 등록 파일 오류, 같은 실험이 이미 실행 중 등) | 출력 마지막 20줄을 스레드에 붙인다 |
| 2 | 결정론 불일치. 결과를 쓰지 않는다 | 출력 마지막 20줄을 스레드에 붙인다 |
| 3 | 실험실에서 취소 | 다시 실행 |
| 4 | 장 시간 보호·정지 요청 파일로 멈춤 | 보호 구간이 끝난 뒤 같은 명령 다시 |

## 3. 스레드에 올릴 것

`experiments\EXP-20261020-EDGE01\` 안의 다섯 파일:

- `results.md`(판정, 구간별, 선정 기술 통계, 해석 한계)
- `windows.tsv`, `days.tsv`, `null.tsv`(집계값만, 종목별 가격 없음)
- `inputs.yaml`(스냅샷 ID·해시, 커밋, 결정론 확인 결과 `same`)

`inputs.yaml`의 `code-dirty`가 `true`면 저장소에 커밋하지 않은 변경이 있었던 것이다. `git status`를 보고 변경을 되돌린 뒤 다시 돌린다.

## 4. (라)·공시 대조(EDGE02·EDGE03) 준비

(라) `kr-intraday-news@1`은 공시 스냅샷이 필요하다. 아래가 끝나야 Claude가 등록 파일을 커밋한다.

1. [수집기](collector.md) 3장대로 공시 전체 수집: `.\gradlew.bat :autotrade-app-collector:run --args="dart-disclosures --from 2010-01-01"`. 하루 몫 2,000회에서 멈추면(종료 코드 3) 다음 날 같은 명령을 다시 돌린다. `--max-calls 10000`을 붙이면 하루 10,000회까지 받는다(재무 몫과 별도).
2. 스냅샷이 **2014-01-01 이전부터 2026-03-31 이후까지** B·I를 덮어야 한다(품질 리포트의 구간 표). 최근 달부터 거꾸로 받으므로 2014년 이전까지 내려가야 한다.
3. [수집기](collector.md) 4장 끝의 공시 품질 리포트 확인 네 가지(종목 코드 표, 상장폐지 종목 공시 확인, 연도별 못 붙인 행, 손 확인 3종목)를 스레드에 붙인다. 공시 유형을 좁힐지는 이 리포트만 보고 등록 전에 정한다(D-125 3장).
4. 공시 스냅샷 ID를 알려 준다.

검사 명령도 같은 공시 스냅샷으로 상장폐지 종목과 상장 유지 종목의 연 단위 공시 덮임률을 비교한다. 폐지 종목 평균이 유지 종목의 0.8배 미만이거나 셀 수 있는 폐지 종목이 30개 미만이면 그 선정은 "판정 불가(생존편향 미확인)"다(D-125 2장 5번).
