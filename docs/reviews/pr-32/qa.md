## 점검표 밖 발견
시나리오 시도(잘못된 주문·중복 주문·보호 공백). 모두 7단계 `PanicLiquidator` 구현 계약의 문제이며 지금 main에서 실행되는 경로는 없다.

1. **[중] ③ 직전 재판정의 반대 방향(불가 → 가능)이 정해지지 않음 → 미체결 매도가 남은 채 서버 측 손절 취소.** 순서: ② 직전 판정이 "매도 불가"(예: VI·LULD 정지, 장 시작 전) → ②는 미체결 **매수만** 취소(ADR-006:99), 기존 미체결 **매도**(익절 지정가 등)는 남음 → ②가 끝난 뒤 정지가 풀림 → ③ 직전 재판정(ADR-006:203 (다))이 "매도 가능" → ③에서 서버 측 손절 취소 → ④ 전량 매도가 남은 미체결 매도 수량만큼 매도 가능 수량 부족으로 거절되거나 일부만 접수 `[추론, 증권사별 처리 미확인]` → 서버 측 손절 없이 보유가 남음. (다)는 "②~③ 사이에 정지가 걸리면 ③을 하지 않는다"만 적고, 계약 주석 PanicLiquidator.java:17은 "앞 단계가 DONE이 아니면"만 막는데 "매수만 취소"한 ②의 결과 값이 정해져 있지 않다(결과 값은 DONE·SKIPPED·NOT_AVAILABLE·FAILED뿐, PanicSteps.java:17-20). 요청: ADR-006:203 (다)와 PanicLiquidator.java 계약에 "② 직전 판정이 매도 불가면 그 PANIC 실행에서는 ③~⑤를 하지 않는다(재판정이 가능으로 바뀌어도 ②부터 다시 실행해야 함)"와 "매도 불가 모드의 ②는 DONE으로 보고하지 않는다(또는 ③~⑤ SKIPPED로 끝나 Guard OFF 없음)"를 적고, 합격 테스트에 "② 시점 매도 불가 → ③ 시점 매도 가능이어도 ③ 미수행"을 추가할 것. 역할 검토 원문 두 개 모두 이 방향을 다루지 않음(`grep` 결과 없음).
2. [하] 계좌 안 일부 종목만 매도 불가일 때 ③의 범위가 계약에 없음. 새 주석 PanicLiquidator.java:11-12는 "매도를 낼 수 없으면 서버 측 손절을 취소하지 않는다"고 계좌 단위로 읽히고, ADR-006:99는 종목만 건너뛸지 계좌 전체를 멈출지를 7단계로 미룬다. "종목만 건너뜀"을 고르면 ③은 매도 가능 종목의 서버 측 손절만 취소해야 하는데, 이 조건이 :205 결정 항목에 같이 적혀 있지 않다. :205에 "종목 단위로 건너뛰면 ②(매도 취소)·③은 매도 가능 종목에만 적용"을 함께 적을 것.
3. [하] RSK-11·RSK-13 기획서 반영 추적이 새 항목을 덮지 않음. ADR-006:203에서 "이 테스트들은 기획서 RSK-13 인수 조건에도 올린다(pm-lead…)"는 문장이 "보강할 것" (가)~(다) **앞**에 있어, 새로 추가된 합격 테스트 4건과 (나)의 RSK-11 "일괄 취소는 서버 측 손절을 지우지 않는다"가 기획서 반영 대상인지 불분명하다. 기획서 RSK-11(:189)에는 여전히 일괄 취소 대상 정의가 없다. 또 (나)는 "일괄 취소 대상에 서버 측 손절이 들어가는지 정하고"로 열어 두었는데, 들어가는 쪽을 고르면 PANIC과 상관없이 매일 모든 보유의 서버 측 손절이 지워지는 실전 영향이므로 사용자 결정 대상(지침 8장 2번)임을 적을 것.
4. 확인했지만 문제 아님: (a) 주석 첫 줄 "미체결 취소 확인(매도 불가면 매수만)"과 11-12행은 서로 모순 없음. (b) 역할 검토 원문은 메인이 고치지 않음(`git log` 상 원문 파일 변경 커밋은 원문 추가·덧붙임 커밋뿐). (c) QA pr-26 발견 3의 합격 테스트 문구 수정 요구("넘기지 않거나, 넘기면 긴급 FAILED")가 ADR-006:203에 반영됨. (d) QA pr-26 발견 5(주석 수정 시점)는 이 PR로 해소, :202 상태 칸 갱신.
