# 2단계 실녹화 두 번 리플레이 확인: 2026-10-12 (KRX)

절차: [실녹화 절차](../../docs/runbooks/stage-2-real-recording.md). 녹화 파일 자체는 올리지 않는다(외부 공유 금지, ADR-003).

## 결론

- [사실] 두 번 리플레이 결과가 같다. 528,156건, SHA-256 `b85109ab…c4bf4c4f` 두 번 일치. 판정 **동일** (아래 원문 1).
- [사실] 녹화는 정상 종료됐다(`complete=true`, 녹화기 누락 0, eventsSha256 파일과 일치).
- [사실] 원본 대조(G-1, **조건부**): 세 종목 모두 시가·고가·저가·종가가 키움 ka11081 KRX 단독 정규장 일봉과 한 자리도 다르지 않다(아래 대조표). 다만 두 값 모두 키움에서 왔고 같은 부호 해석 코드(`KiwoomStreamProtocol.unsigned`)를 거치므로, 첫 실녹화에 요구되는 HTS 일봉과의 부호·단위 확인이 끝나야 G-1 통과로 본다(후속 과제 4).
- [사실] 체결 수량 합은 일봉 거래량의 83.9~88.8%다. 원인은 13:05:41~14:19:47 KST 게이트웨이 창이 닫혀 녹화가 비었던 74분이다(meta.json 구간 2개).
- [사실] 키움 실시간 접속 경로 확인: `wss://api.kiwoom.com:10000/api/websocket` (게이트웨이 로그, PR #40 후속).

## 녹화 환경

- 녹화 PC: 사용자 Windows PC, Java 21, 저장소 main `4a87f60`(PR #52)에서 `installDist`로 만든 게이트웨이.
- 시세 증권사: 키움 REST(실전 키, 시세 수신만. 주문 API 호출 없음). 시세 배분 FAILOVER, KIWOOM 3종목.
- 종목(watchlist.json 후보): KRX:005930, KRX:000660, KRX:035420.

- [사실] 가격 자릿수, 첫 체결(09:00:03~09:00:24), 마지막 체결(15:30:09~15:30:22)이 정상 범위다. 수신 해석 오류 징후 없음.
- [추론] 74분 공백에도 고가·저가가 일치한 것은 그날 고가·저가가 공백 밖에서 났기 때문이다. 다른 날에는 공백이 있으면 고가·저가가 어긋날 수 있다.
- [추론] 거래량 차이는 대부분 74분 공백이다. 공백 없는 날의 녹화 비율(키움이 보내지 않는 체결 비중)은 이 녹화로는 따로 잴 수 없다.
- [사실] 처음 한 번 HTS 일봉과의 부호·단위 확인은 아직 하지 않았다(kiwoomDaily만 사용). 녹화 쪽(`KiwoomStreamProtocol`)과 kiwoomDaily 쪽(`KiwoomDailyChart`)이 같은 `KiwoomStreamProtocol.unsigned`를 쓰고 출처도 같아, 공통 해석 오류는 이 대조로 잡히지 않는다(architect 검토 F2).
- [사실] 005930 "정규장 밖" 18건 / 5,040주, 000660 5건 / 44주는 모두 15:40:00~15:43:27 체결이다. [추론] 장 마감 뒤 시간외 종가 매매(15:40~16:00)이며, 게이트웨이를 15:43에 멈춰 그 뒤는 녹화되지 않았다.

## 후속 과제

1. **재기동 공백이 GAP 이벤트로 남지 않는다.** 13:05~14:19 공백은 meta.json `segments`에만 있고 이벤트 흐름에는 GAP이 없다(GAP 6건은 모두 재접속 끊김). 리플레이를 읽는 쪽(시뮬레이션·지표)이 구간 사이를 끊김으로 다루는지 data-engineer가 확인한다. [추론] 다루지 않으면 74분을 "체결 없음"으로 읽는다. → [D-065](../../docs/decisions/D-065-recorder-restart-gap.md)로 처리(2026-10-12): 확인해 보니 리플레이는 구간을 읽지 않았고 시뮬레이션은 아직 녹화를 읽지 않는다. 이후 녹화부터는 녹화기가 재기동 공백을 `GAP`(`RECORDER_RESTART`)으로 남기고, 이 녹화는 고치지 않고 `replayCheck` 보고서에 표시 없는 경계로 적힌다.
2. **콘솔 한글 깨짐.** Windows에서 `kiwoomDaily` 등 Gradle 실행 명령의 한글 출력이 깨졌다. 이 PR에서 게이트웨이 모듈 JavaExec 작업에 `-Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8`을 붙였다(실험 명령과 같은 방식). 사용자 PC에서 다시 확인이 필요하다.
3. **녹화 창 닫힘 예방.** 장중 창이 닫혀 74분이 빠졌다. 절차서에 "창 최소화, 닫기 금지"를 더 눈에 띄게 둘지 검토한다.
4. **HTS 부호·단위 확인(G-1 조건).** 사용자가 HTS(영웅문) 2026-10-12 KRX 단독 정규장 일봉에서 1~2종목의 시가·고가·저가·종가를 위 대조표와 비교해 이 문서에 적는다. 같으면 G-1 조건을 푼다.
