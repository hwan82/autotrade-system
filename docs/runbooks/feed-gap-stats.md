# 시세 수신 간격 측정(feedGaps, ADR-016 G0)

실전 엔진이 "이 종목 시세가 조용하다"(T_quiet)와 "소스가 멈췄다"(접속 매매 3초)를 판단할 기준의 근거를 녹화로 잰다. 결정: [D-147](../decisions/D-147-feed-gap-stats.md). 값은 이 결과로 risk-ops가 정한다(ADR-016 2.6).

녹화 파일만 읽는다. 시세·주문 API, 게이트웨이·실험실 동작에는 손대지 않는다.

## 언제

- **장 시간 보호 구간 밖**(평일 저녁 늦게나 주말). 구간 안이면 명령이 시작하지 않는다(리플레이 점검과 같은 관문, D-085). 실전 엔진이 없는 지금도 이 관문은 그대로 둔다.
- 감시가 만든 정지 요청 파일(`<설정 폴더>/experiment-state/stop-request`)이 있으면 시작하지 않는다.
- 오늘 날짜 녹화는 아직 쓰이는 중이라 넣지 않는다(정상 종료 안 된 날은 보고서에 표시되고 종료 코드 3).
- 워크포워드 실행(EXP-20261027-WF01)과 같은 때 돌려도 되지만, PC가 느리면 하나씩 돌린다. 이 명령은 녹화를 한 번씩 줄 단위로 읽어 메모리를 적게 쓴다.

## 명령

저장소 폴더(`C:\2.Code\myproject\autotrade-system`)에서 `git pull` 뒤:

```
.\gradlew.bat :autotrade-app-gateway:feedGaps --args="2026-10-26..2026-10-30 --out=feed-gaps-2026-10-26_2026-10-30.md"
```

- 인자: 날짜(`2026-10-26`), 범위(`2026-10-26..2026-10-30`, 범위 안 KRX 거래일), 녹화일 폴더 경로. 여러 개 줄 수 있다. 녹화 폴더가 없는 거래일은 보고서에 적고 건너뛴다.
- `--out=파일`: 보고서를 그 파일에도 쓴다(상대 경로는 저장소 폴더 기준). 화면에도 같은 내용이 나온다.
- 종료 코드 0: 보고서 만듦, 2: 입력 오류·녹화 없음·읽기 실패, 3: 만들었지만 정상 종료 안 됐거나 잘린 녹화일이 있음, 4: 장 시간 보호·정지 요청으로 멈춤(보고서 안 씀).

## 결과 보내기

보고서 파일(종목 코드·이름·시각·통계만 있고 키·계좌는 없음)을 Claude에 올리거나 저장소 `experiments/stage-7-feed-gaps/`에 넣는다. 녹화 원본은 올리지 않는다(ADR-003 4장).

## 보고서 읽는 법

- **소스 단위 접속 매매 행의 `>3s`**: 0이 아니면 지금 감시 종목 구성에서 소스 3초 기준이 오탐을 낸다. "소스 단위 날짜별" 표로 어느 날인지 본다.
- **소스 단위 단일가 행**: 시가·종가 단일가 구간에 짧은 기준(예: 10~30초)을 둘 수 있는지(risk-ops PR #245 N3).
- **T_quiet 후보별 조용함 발생**: 후보값마다 하루 한 종목에 몇 번 보호 폴링으로 넘어가는지. 30초(지금 기본값)와 그보다 짧은 값의 차이를 본다.
- **종목별**: 거래가 드문 종목이 따로 튀면 종목마다 다른 값을 둘지 본다.
- 백분위는 `≤`(칸 위 경계로 올림), 최대와 `>Ns` 횟수는 정확한 값이다. 측정 방법은 보고서 맨 아래 절.
