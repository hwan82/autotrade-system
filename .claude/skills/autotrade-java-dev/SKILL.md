# 자동매매 시스템 개발 규칙

## 작업 절차
1. 기획서(`docs/spec/autotrade-spec.md`)와 결정 로그(`docs/decisions/README.md`)에서 관련 요구사항 ID와 결정을 찾는다. 없으면 pm-lead 확인 요청을 남기고, 진행 가능한 범위는 가정을 명시하고 진행한다.
2. 모듈 간 계약(인터페이스, DB 스키마, 설정 키, REST API)을 바꾸면 ADR 초안(`docs/adr/`)을 먼저 쓴다.
3. 실패하는 테스트부터 쓰고 구현한다.
4. 자기 검토 체크리스트 확인 후 PR을 만든다. 실전 경로를 건드리면 risk-ops 검토를 요청한다.

## 모듈 경계
- `autotrade-domain`, `autotrade-strategy`, `autotrade-sim`, `autotrade-risk`는 순수 Java. Spring, 증권사 SDK, DB 드라이버 의존 금지.
- Spring 연결, 스케줄러, REST, SSE는 실험실 프로세스 `autotrade-app-lab`에만 둔다. 실전 엔진·시세 게이트웨이·감시 프로세스(`autotrade-app-{engine,gateway,watchdog}`)는 순수 Java다(ADR-001).
- 증권사 연동은 `autotrade-broker-api` 인터페이스 뒤 플러그인(kis, kiwoom, toss)으로만. 플러그인끼리 참조 금지. 각 플러그인은 능력(REALTIME_QUOTE, POLLING_QUOTE, ORDER, BALANCE, SERVER_SIDE_STOP)과 상태(NOT_CONFIGURED, CONFIGURED, ACTIVE, DEGRADED)를 선언한다.
- 시장별 차이(거래 시간, 통화, 가격 단위, 주문 유형, 비용)는 `MarketRules`로만 다룬다. 엔진 코드에 시장 분기를 흩뿌리지 않는다.
- `autotrade-notification-jar`, `autotrade-monitor-agent-jar`는 자동매매 도메인을 몰라야 한다.
- 프로세스는 실전 엔진, 시세 게이트웨이, 실험실, 감시 4개. 실전 엔진은 다른 프로세스가 죽거나 느려져도 계속 동작해야 한다.

## 시간, 금액, 결정론
- 현재 시각은 주입된 `Clock`으로만 얻는다. 비즈니스 로직에서 `now()` 직접 호출 금지.
- 시간 계산은 거래소 현지 시간대(Asia/Seoul, America/New_York) 기준. 서머타임·휴장일은 캘린더 데이터로.
- 금액은 `BigDecimal` 또는 최소 통화 단위 `long`과 통화 코드를 함께. `double` 금액 계산 금지. 가격 단위 반올림 규칙을 코드로 명시.
- 난수는 시드 고정 가능한 주입 객체로만. 결과에 영향을 주는 순회는 정렬 기준을 명시.
- 병렬 모의 계좌 간 공유 가변 상태 금지. 시세는 불변 이벤트로 전달.

## 안전 불변식 (위반 시 PR 불가)
1. RealTradingGuard는 실전 계좌별, 기본 OFF, 재기동 시 OFF. 설정 파일 로딩이 이 값을 true로 만들 수 없다.
2. 실전 주문은 OrderGateway 실전 구현을 통해서만, Guard 확인 후에만, **계좌의 증권사로만** 나간다. 증권사 간 주문 대체 금지.
3. 주문마다 멱등 키 `{date}-{code}-{side}-{seq}`. 같은 키 재전송 차단.
4. 타임아웃 시 재주문 금지 → UNKNOWN → 조회 → 미접수일 때만 새 키로 1회 재발주.
5. 주문은 계좌별 단일 직렬 큐, 레이트리밋은 계좌·API 그룹별 토큰 버킷. 손절 주문이 우선.
6. 블랙리스트·수동 보유 종목 필터는 파이프라인 최우선, 청산 로직에도 적용.
7. 가상과 실전은 리스크 검증, 상태머신, 블랙리스트 코드를 공유한다.
8. 시세 게이트웨이는 주문 API를 호출하지 않는다.
9. 비밀값(API Key, 계좌번호, 토큰)은 코드·로그·예외 메시지·커밋에 남기지 않는다.

## 테스트 기준
- 도메인·전략·시뮬레이션: 단위 테스트 필수. 체결 규칙, 비용, 지표는 손 계산 기대값과 비교.
- 시뮬레이션 골든 테스트: 고정 녹화 데이터 + 고정 프로필 → 거래 내역·지표 스냅샷 일치.
- 안전 불변식마다 "위반 시도가 차단되는지" 테스트.
- 장애 경로 테스트: 연결 끊김, 응답 지연, 부분 체결, 중복 체결, 재시작 복구, 증권사 DEGRADED 전환, 실험실 부하 중 실전 지연 유지.
- 테스트를 끄거나 지워서 통과시키지 않는다.

## 설정
- 기동 순서: 내장 default → 외부 `runtime-config.json` → 외부 `secrets.json`(비밀값만). 없거나 깨진 파일은 빼고 기동.
- 실시간 변경 대상은 RuntimeConfigHolder로만 읽는다. 매 틱 참조.
- 증권사 키 변경은 미체결·보유 확인 → 세션 종료 → 재연결 순서.
- 새 설정 키는 기본값, 범위, 실시간 변경 가능 여부를 문서화.
