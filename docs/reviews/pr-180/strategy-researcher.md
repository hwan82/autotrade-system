## M1 (수정 필요) L11 녹화 리플레이가 실시간 세션이 없던 날의 녹화도 돌아 "같은 날" 비교가 아니다

[사실] `LiveJudgement.recording`(358~365행)은 `plan.from()`부터 마지막 입력 기록일까지 **녹화 파일이 있는 모든 날**을 `dirs`에 넣는다. 입력 기록은 있는데 녹화가 없는 날만 `missing`으로 판정 불가 처리하고, 반대(녹화는 있는데 입력 기록이 없는 날)는 그대로 녹화 리플레이에 들어간다. 주간 점검 계좌 대조(`LiveWeeklyCheck.compareDay`가 녹화 있는 날마다 `replay.startDay`)도 같은 동작이고, D-116은 이 일치를 근거로 들었다.

## M2 (수정 필요, D-116 확인 요청에 대한 답) L5 미달은 "판정 불가"로 두어 보류가 되게 한다

D-116은 L5 미달을 탈락으로 두고 이 검토에서 확인하라고 했다(5번, 대안 표 마지막 행). 결론: **L5 미달을 탈락이 아니라 판정 불가(NOT_AVAILABLE)로 두고, 합성은 지금 규칙(탈락 하나라도 → 탈락, 아니면 판정 불가 → 보류) 그대로** 쓰기를 권한다.

근거:
1. [사실] 후보 집합은 어느 쪽이든 같다. 후보 = L1~L11 전부 통과(D-114 5번)이고 L5 미달은 둘 다 후보가 아니다. 바뀌는 것은 이름과 다음 행동뿐이다. 그래서 사용자 확정 기준(D-114)을 바꾸지 않는 표기 결정이고, D-114 "C5 수치 그대로"는 30건이라는 수치를 말할 뿐 미달의 합성은 정하지 않았다.
2. [사실] 표본 부족을 "판정하지 않음"으로 두는 것이 이 프로젝트의 확정 방침이다: D-066 2번(사용자 결정, "못 미치면 판정하지 않는다, 통과도 탈락도 아님"), D-072 2번·`WalkForwardJudge`(C5 미달 보류). 6단계 계획 4.1도 I5(운용일 부족)를 보류로 둔다. 30건 미만은 "엣지가 없음"이 아니라 "아직 판정할 표본이 없음"이다. 1차 선별(D-027) C5가 FAIL인 것은 같은 프로필을 다음 단계에서 다시 보는 구조라 문제가 없었지만, 8주 판정은 이 등록의 마지막 판정이다.
3. [사실] 계획 4.2 되돌릴 조건("대부분 L5 미달이면 기준을 낮추지 않고 boards를 늘린 새 등록으로 기간을 늘리는 안을 사용자에게 묻는다")은 표본 부족 프로필을 다시 재는 것을 전제로 한다. 탈락으로 남기면 "실패한 실험 기록"으로 읽혀 같은 프로필 재등록이 "탈락 프로필 재시험(결과 보고 다시 고르기)"처럼 보인다.
4. 4단계 워크포워드처럼 "C5 미달이면 다른 항목과 무관하게 보류"(C5 우선)로 하지 않는 이유: 표본이 작아도 L3(MDD 20% 초과)·L9(지연 2초 손실)·L1 같은 탈락은 그 프로필을 표본만 늘려 다시 볼 이유를 약하게 만든다. 판정 불가로 두면 다른 탈락이 있으면 탈락, L5만 걸리면 보류로 나뉘어, 되돌릴 조건에서 "다시 잴 프로필"이 바로 보인다. D-116 대안 표가 걱정한 "보류 = 후보가 될 수도 있음" 오독은 상세 줄에 "왕복 N건(표본 부족, 기준 낮추지 않음)"을 적어 막는다.

고칠 곳: `LiveJudgeCriteria.evaluate` L5 줄(128~129행) FAIL → NOT_AVAILABLE, 클래스 주석 45~47행, D-116 5번·대안 표·README 요약 줄("L5 미달은 탈락"), 시험(L5 29건 → 판정 불가·다른 탈락 없으면 보류, 29건 + L3 탈락 → 탈락, 30건 통과 경계). 지금 L1~L5 개별 시험이 없으므로 이번에 L4(19일 판정 불가·20일 계산)와 함께 더한다.

## 권고 (막지 않음)

- **R1 L10 대조군 수의 여유.** 시드를 판정 가능한 최소 N = 20m − 1 = 119로 돌리므로, 대조군 Run 하나가 실패하거나 왕복 0건이면 N = 118이 되어 **판정 대상 6개 모두 L10 판정 불가 → 보류**다. 그때 시드를 더 돌리면 결과를 본 뒤 표본을 늘리는 모양이 된다. 지금(결과 전에) 정해 두기를 권한다: (a) 시드를 20m − 1 + 여유(예 +6 = 125)로 돌린다. N = 125면 문턱이 (k+1)·120 ≤ 126 → k = 0으로 같고(조금 더 엄격), 실패 6개까지 견딘다. 또는 (b) "N < 20m − 1이면 시드 20m, 20m+1…을 N이 찰 때까지 더 돈다"를 D-116에 사전 규칙으로 적는다. 어느 쪽이든 판정 수치(0.05/m)는 그대로다. N = 119에서 L10은 "119개 대조군 모두를 넘어야 통과"라는 점도 리포트 머리에 한 줄 적으면 읽는 사람이 엄격함을 안다.
- **R2 대조군 느슨함 신호 자동 표시.** 계획 4.2는 "A02가 L1~L6을 통과하면 기준이 느슨하다는 신호로 리포트에 적고 사용자에게 묻는다"고 한다. 지금은 표의 참고 행을 사람이 읽어야 한다. `judgement.md` 2장에 대조군 L1~L6이 모두 ○이면 굵은 한 줄을 내도록 권한다.
- **R3 역할 식별(D-116 후속 질문에 대한 답).** LIVE00·LIVE01 등록은 운용 중 고칠 수 없으므로 지금 등록 형식에 역할 필드를 더할 필요는 없다. `logic` 값 식별로 충분하고, 기준선·대조군이 하나씩이 아니면 입력 오류로 막는 지금 방식이 맞다. 다음 장중 등록(새 실험 ID)에서 같은 로직의 기준선을 둘 이상 쓰고 싶어질 때 역할 필드를 strategy-researcher가 제안한다.
- **R4 거래 단위 괴리(참고)의 한계 표기.** 첫 진입만 맞추므로 하루 여러 번 드나드는 프로필은 일치율이 높게 나온다는 D-116 위험 항목을 `judgement.md` 7장 주석에도 한 줄 넣는다(D-114 다음 결정에서 이 값을 판정에 넣을지 볼 때 필요).
