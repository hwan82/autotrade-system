# D-068 녹화 어댑터(녹화 → 실험 입력)와 시세 공백 처리 `BOOK-V2`

- 날짜: 2026-10-13
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 실전 주문 경로·Guard·블랙리스트 코드·리스크 한도·장애 대응은 건드리지 않는다
- 담당: sim-engine. 교차 검토: architect
- 근거: 로드맵 3단계 완료 기준 "녹화 데이터로 골든 테스트 통과"([team-design.md](../team/team-design.md) 6장, TST-02), [ADR-004](../adr/ADR-004-simulation-engine.md) 4장 "녹화 형식 어댑터"·"DataGap 처리" 행, [D-065](D-065-recorder-restart-gap.md) sim-engine 변경 제안, [ADR-003](../adr/ADR-003-market-data.md) 2.2~2.4
- 범위: 실험실 리플레이(`SimulationExperimentRunner`)의 입력과 가상 거래소. 녹화 형식·녹화기·리플레이 소스(data-engineer)는 바꾸지 않는다

## 배경

- [사실] 2단계 녹화는 `<root>/<시장>/<날짜>/events.jsonl.gz` + `meta.json`이고 녹화 순번은 날마다 1부터 다시 시작한다(`RecordingLayout`, `DayWriter`).
- [사실] 실험 입력 `MarketDataSet`은 sequence가 엄격히 늘어야 하고(`InMemoryMarketDataSet`, `SimulationExperimentRunner.validateAndSlice`), 가상 거래소도 같은 조건을 확인한다(`VirtualExchange.onEvent`). 그래서 여러 날 녹화를 그대로 이을 수 없다.
- [사실] 가상 거래소는 `DataGap`을 받아도 아무것도 하지 않았다(BOOK-V1, "그 밖의 이벤트는 체결에 쓰지 않는다"). 공백 뒤에도 공백 전 호가로 시장가 매수 예약 현금을 잡고, 대기 지정가의 앞선 잔량을 공백 전 값으로 계속 깎았다.
- [사실] 2026-10-12 실녹화는 공백 표시가 없는 구간 경계가 하나 있다(seq 410641, D-065 3번). D-065는 녹화 파일을 고치지 않고 어댑터가 그 경계를 끊김으로 다루도록 제안했다.

## 결정

1. **녹화 어댑터 `RecordedMarketDataSet`(autotrade-sim, `com.autotrade.sim.recording`)**: `open(layout, market, from, to)`가 기간 안 녹화일 폴더를 날짜 오름차순으로 읽어 하나의 `MarketDataSet`으로 만든다. 녹화가 없는 날은 건너뛴다.
   - **sequence = 데이터셋 안 위치(1부터)**. 녹화일 오름차순 → 녹화 순번 순이다. `origin(sequence)`가 (녹화일, 녹화 순번)을 돌려준다(끼워 넣은 줄은 0). 리플레이 소스의 "sequence = 녹화 순번" 계약(ADR-003 2.4)은 그대로이고, 이 번호는 실험 입력 안에서만 쓴다.
   - **재기동 공백**: 녹화기가 남긴 `DataGap(RECORDER_RESTART)`은 그대로 옮긴다. `RecordedDay.unmarkedRestarts()`가 비어 있지 않은 이전 녹화는 그 경계 바로 앞에 **녹화기(`DayWriter`)와 같은 규칙**으로 공백을 끼워 넣는다: 경계 앞에 나온 종목마다 종목 정렬 순으로, 시작 = 앞 구간 끝과 경계 직전 줄 수신 시각 중 늦은 쪽, 끝 = 경계 첫 줄 수신 시각, 시작이 끝보다 늦으면 끝에 맞춘다. 줄 없이 끝난 구간이 끼어 같은 줄 앞에 경계가 여럿이면 한 번만 넣고 마지막 경계 직전 구간(줄 없는 구간)의 끝으로 시작을 잡는다(녹화기는 이벤트를 받은 기동에서만 공백을 쓴다). 녹화 파일은 고치지 않는다.
   - **버전** `REC-<시장>-<첫 날>..<끝 날>-<해시 16자>`: 해시는 `REC-ADAPTER-V1`, 시장, 날짜별 events 파일 SHA-256을 이은 것이다. 읽기 전후 파일 해시가 다르면(녹화 중) 열지 않는다.
   - 날짜별 기록 `DayInfo`(파일 해시, 줄 수, 정상 종료 여부, 잘린 줄 여부, 구간 수, 표시 없는 경계, 끼워 넣은 공백 수)를 남긴다.
2. **가상 거래소 시세 공백 처리, 체결 규칙 `BOOK-V2`**: `DataGap`(원인 무관, RECORDER_RESTART 포함)을 받으면 그 종목의 마지막 호가 스냅샷을 체결·시장가 매수 예약에 쓰지 않고(평가에는 계속 씀), 그 종목 대기 지정가의 앞선 잔량을 "모름"으로 되돌린다. 공백 자체로는 체결하지 않는다. 그래서 다음 호가 스냅샷 전까지 그 종목 시장가는 체결되지 않고(호가 있는 종목은 원래 스냅샷으로만 체결), 새 시장가 매수는 마지막 체결가로 예약하며, 대기 지정가는 지정가보다 유리한 체결로만 체결된다. 새 스냅샷이 오면 앞선 잔량을 그 스냅샷 같은 가격 잔량으로 다시 잡는다. 평가 가격(마지막 체결가, 없으면 마지막 스냅샷 최우선 매수 호가)과 거래 상태는 그대로 둔다. ADR-004 2.2 11번.
3. **실험 보고서에 공백을 남긴다**: `SimulationReport.dataGaps()`(실험 기간 입력의 공백 표시, 모든 Run 공통)와 정규 보고서 머리 `data-gap seq=… <종목> <원인> <시작>..<끝>` 줄. 공백이 없는 실험의 보고서는 이전과 같다(체결 모델 줄의 버전만 바뀜).
4. **3단계 완료 기준 테스트**: 손으로 만든 이틀치 골든(`fixtures/krx-golden.events`)을 2단계 녹화기(`MarketEventRecorder`)로 실제 녹화 형식에 쓰고 어댑터로 읽어 돌리면 같은 골든(`golden/krx-golden.report`)과 바이트까지 같다(`SimulationExperimentRunnerTest.녹화_형식으로_다시_돌려도_같은_골든과_일치한다`).

## 위험과 한계

- 공백 동안 일어난 체결은 모른다. 그동안 대기 지정가가 실제로 체결됐을 수 있고(과소), 공백 뒤 첫 호가로 앞선 잔량을 다시 잡으면 공백 동안 뒤에 줄 선 주문까지 앞에 둔다(보수적) `[추론]`.
- 공백 동안 VI·정지가 시작되거나 끝났을 수 있다. 거래 상태는 마지막으로 받은 값을 그대로 쓴다 `[가정]`. 녹화기는 상태 변화를 시세 이벤트로 받으므로 재연결 뒤 상태가 다시 오면 고쳐진다.
- 이전 BOOK-V1 결과(`experiments/EXP-20261008-STR01` 등)와 새 결과는 체결 모델 ID가 달라 같은 비교 묶음에 들어가지 않는다. 그 실험들의 입력(합성 시세, 일봉)에는 `DataGap`이 없어 다시 돌리면 같은 숫자가 나온다 `[추론]`(이 PR의 골든은 그대로임을 확인).
- 입력 품질(`DayInfo`의 정상 종료 여부·잘린 줄)은 데이터셋에만 있고 실험 보고서에는 아직 나오지 않는다. 비정상 종료로 끝난 날은 끝부분 시세가 공백 표시 없이 빠질 수 있다. 실험 명령에 녹화 입력을 붙일 때 보고서·`inputs.yaml`에 함께 남긴다(architect 검토 R2). 녹화 중 판정은 읽기 전후 파일 해시 비교 하나다.
- 전략은 `DataGap`을 받아도 자기 상태(호가 기반 지표)를 고치지 않는다. 체결은 가상 거래소가 보수적으로 막지만, 공백을 다루는 전략 규칙은 strategy-researcher 후속 후보다(architect 검토 R5).
- 녹화일 전부를 메모리에 올린다. 2026-10-12(3종목) 52만 건이 하루다. 감시 종목이 수백 개로 늘면 날짜별로 읽는 목록으로 바꿔야 한다(후속).
- 실녹화로 실험하기 전에 남은 것(ADR-004 4장): 장 시작·마감 단일가 구간 처리, 실제 `KrxMarketRules`로의 녹화 실험, 공백이 있는 거래일을 거래일 판정·지표에서 다루는 방법, 실험 명령(`runCombinationExperiment`)에서 녹화를 입력으로 고르는 옵션, 실험실 결과 묶음(D-062)에 공백 표시. 이 결정은 시뮬레이션이 공백을 **보고 보수적으로 체결하게** 만들 뿐이다.

## 검증

- `RecordedMarketDataSetTest`: 이틀치 녹화 → 손으로 만든 이벤트와 같음(sequence 1~17)·`origin()`, 같은 녹화는 같은 버전, 녹화기가 남긴 재기동 공백 그대로, **이전 형식 녹화(공백 줄을 뺀 사본)에 끼워 넣은 공백이 지금 녹화기 결과와 같음**, 줄 없는 구간이 낀 경계는 한 번만 넣고 그 구간 끝(경계 직전 줄보다 늦음)부터 잡음, 녹화 없음·다른 시장·날짜 역순 거부.
- `VirtualExchangeTest`: 공백 뒤 시장가 매수 기준 가격 없음(호가를 예약에 안 씀)·평가는 공백 전 최우선 매수 호가 그대로, 공백 뒤 같은 가격 체결로는 대기 지정가가 체결되지 않고 다음 호가로 앞선 잔량을 다시 잡음, 다른 종목 공백은 영향 없음.
- `SimulationExperimentRunnerTest`: 녹화 형식 골든 바이트 일치(3단계 완료 기준), 공백이 보고서에 남고 손 계산대로 첫 체결이 seq 6 → seq 11(40주)로 바뀜. 기존 골든은 체결 모델 줄만 `BOOK-V2`로 바뀜.
- 실녹화 확인(2026-10-13, PR #71 머지 `6a1719b` 코드): 사용자 PC의 2026-10-12 녹화(events 파일 SHA-256 `860da4e7…eeeb64`, meta와 일치)를 클라우드 작업 공간에 잠시 복사해 `RecordedMarketDataSet.open`으로 읽었다(확인 뒤 복사본 삭제, 저장소에는 넣지 않음). 결과 `[사실]`:
  - 녹화 528,156줄 → 데이터셋 528,159건(끼워 넣은 공백 3), sequence 1부터 빈틈없음, 두 번 열면 버전과 이벤트가 같음. 버전 `REC-KRX-2026-10-12..2026-10-12-e973fb9fc953d6eb`.
  - 표시 없는 경계 `[410641]`에 `RECORDER_RESTART` 공백 3건(000660, 005930, 035420 순), 구간 04:05:41.66Z~05:19:47.35Z = 13:05:41~14:19:47 KST(실녹화 보고서의 74분 공백과 같음). 데이터셋 seq 410641~410643, `origin` 녹화 순번 0.
  - 녹화기가 남긴 `DISCONNECTED` 6건은 그대로 옮겨졌다(녹화 순번 411738~411740, 528148~528150).
- 검증하지 못한 것: 실녹화로 실험(전략 체결)을 돌린 결과. 실험 명령에 녹화 입력 옵션이 생기고 단일가 구간 처리가 들어간 뒤 확인한다.
