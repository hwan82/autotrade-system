## 1. LIVE02가 묻는 것

"장전·장중 선정으로 그날 종목을 고른 단타 조합 계좌가 8주(40거래일) 실시간 시세에서 사고 없이 돌고, 비용 차감 후 D-114 L1~L11을 모두 통과하는가."

LIVE01(선정 없는 장중 프로필 6개, 10종목)과 다른 점은 세 가지다.

1. 계좌가 선정 × 전략 조합이다(D-124). 그날 후보 = 선정 결과 ∩ `boards` − `blacklist`.
2. `boards`가 D-122 감시 종목 100개다(선정이 고른 종목을 받으려면 넓어야 한다).
3. L10 대조군이 "같은 선정 + 무작위 진입"이다(D-126). 선정 자체의 효과는 판정에 넣지 않고 참고 칸(7.1)으로 본다.

## 3. 후보 조합(판정 대상 m ≤ 4)

### 3.1 짝짓기(결과 보기 전에 고정)

가설에 맞는 매매지표를 지금 고른다. LIVE00·LIVE01·녹화 결과를 보고 고르면 표본 안 선택이 되므로, 아래 짝은 이후 바꾸지 않는다(바꾸려면 새 실험 ID와 새 사전 검사).

| 조합 | 선정 | 매매지표 | 왜 이 짝인가 | 들어가는 조건 |
|---|---|---|---|---|
| C1 | (다) `kr-intraday-hot@1` | `kr-orb-30@1` | (다) 가설은 "다음 날 장중 변동성·유동성"(EDGE01 주 통계 RANGE). 변동성이 크면 장 초반 30분 범위 돌파가 날 여지가 크다 `[추론]` | EDGE01 통과 + 4장 P0·P1 |
| C2 | (다) `kr-intraday-hot@1` | `kr-volume-surge@1` | 같은 가설의 "유동성" 쪽. 5분 거래량 급증 진입이 거래가 몰리는 종목에서 신호를 낸다 `[추론]` | EDGE01 통과 + 4장 P0·P1 |
| C3 | (라) `kr-intraday-news@1` 또는 공시 대조 `kr-intraday-news-nodisc@1`(D-125 4장 규칙으로 하나) | `kr-orb-30@1` | (라) 가설은 "정보 반영 장중 방향성". 방향이 생긴 날 범위 돌파가 이어진다 `[추론]` | EDGE02(또는 규칙상 EDGE03) 통과 + 4장 P0·P1 |
| C4 | (마) `kr-intraday-open-momentum@1` | `kr-orb-30@1` | (마)는 09:00~09:30 거래대금·수익률로 고르고, `kr-orb-30`은 바로 그 30분 범위 고가 돌파를 09:30부터 산다. "장 초반 추세가 이어진다"는 두 가설이 같은 구간을 본다 | 4장 P0~P3(일봉 사전 검사가 없어서, D-127 11번) |

- `[사실]` 선정 계좌도 전략은 그날 모든 이벤트를 받고, 막히는 것은 후보 밖 신규 진입 신호뿐이다(`RunStepper.java` 142~148행). 그래서 C4의 `kr-orb-30`은 09:30 전 30분 범위를 그대로 만든다. 다만 후보 밖 종목에서 막힌 신호가 전략 안의 "그날 이미 신호 냄" 상태를 쓰는지는 전략마다 다를 수 있다 `[추론]`. 4장 사전 검사 결과의 막힌 신규 진입 수로 확인한다.
- m은 실제로 들어간 판정 대상 수다(최대 4). **빠진 조합 자리는 다른 조합으로 메우지 않는다.** 메우면 사전 검사 결과를 보고 고르는 것이 된다. m이 줄면 L10 문턱이 느슨해지는 대신 사전에 정한 가족만 남는다.
- 4개 모두 빠지면 LIVE02를 등록하지 않고 그 결과(사전 검사 탈락)를 리포트로 남긴다. 기준을 낮춰 넣지 않는다.

### 3.2 m ≤ 4를 지키는 이유

ADR-012 3.3 "조합 수 m ≤ 4로 시작". L10 대조군 Run 수가 (1 + g) × (21m − 1)로 늘고(D-126 위험, g = 선정 묶음 수), 100종목 입력이라 Run 하나도 LIVE01보다 무겁다(11장). C1~C4면 g = 3, 대조군 Run 4 × 83 = 332개다.

### 3.3 `PRE_OPEN_DAILY_LAG1`이 필요해지면

10-21 확인에서 KRX가 다음 날 08:00에 게시한다고 나오면 (다)(라)는 실시간에서 c 일봉을 장 전에 받을 수 없다(ADR-012 3.7). 그때 실시간에 쓰는 것은 `LAG1` 판인데 EDGE01은 c = T의 직전 거래일 판을 검사했다. 그래서 `LAG1` 판 선정은 **같은 `edge.yaml` 키로 새 실험 ID의 일봉 사전 검사를 통과해야** C1~C3에 들어간다. 원래 판의 EDGE 통과를 근거로 쓰지 않는다. (마)는 일봉을 쓰지 않아 영향이 없다.

### 4.3 사전 검사에서 함께 재서 LIVE02 등록에 쓰는 값

- **q̂(묶음별 왕복 0건 대조군 비율, PR #199 R4)**: 묶음마다 83시드 중 왕복 0건인 시드 비율. 6.2의 N 식에 들어간다.
- **구독 커버리지**: 날마다 선정 종목 중 `boards` 안 비율(`NOT_SUBSCRIBED` 수). (다)(라)는 시장 전체에서 고르므로 이 값이 낮을 수 있다. 4구간 평균이 50% 미만이면 ADR-012 7장 되돌릴 조건(Q-054 안 1 재검토)을 사용자에게 알린다 `[가정]`. LIVE02 등록은 그대로 한다(커버리지는 판정 기준이 아님).
- **한도 도달·거절 사유(PR #200 m1)**: C4와 대조 선정 계좌의 동시 보유 상한·하루 진입 상한 도달 날 수, 거절 사유별 건수. 대조 선정(boards 전 종목)이 한도에 자주 걸리면 P3 차이에 "한도 때문에 못 산 종목"이 섞인다.

### 5.1 기준선을 v3로 두는 이유

`[사실]` `buy-and-hold`는 첫 호가가 온 종목부터 `sizing.slots`개까지 한 번씩 사고, 종목당 금액은 (첫 현금 × 99%) ÷ slots다(`BuyAndHold.java` 37~49행, PR #175 때와 같은 코드). v2(slots 10)를 100종목 boards에 쓰면 먼저 호가가 온 10종목만 사서 바구니가 도착 순서로 정해진다(PR #175 M1과 같은 문제). v3(slots 100)는 모든 종목을 한 번씩 시도해 바구니가 도착 순서와 무관하다.

`[추론]` 종목당 약 99,000원이라 1주 가격이 그보다 비싼 종목은 0주가 되어 빠지고 035720은 거절된다. 그래서 기준선은 "boards 중 1주 10만 원 미만 종목의 동일 금액 바구니 + 현금"이다. 빠지는 종목 수는 watchlist를 확정한 뒤(10-24~25) 세어 등록 파일 주석과 판정 리포트에 적는다.

| **v3 slots 100, 시드머니 1,000만 원(채택)** | L1 정의(같은 세션 매수 후 보유, D-114)를 그대로 두고 바구니만 사전 등록으로 고정한다 |

## 6. 판정 기준 적용(PR #199 R1)

### 6.1 L1~L11

D-114 L1~L11의 수치와 계산을 바꾸지 않고 선정 조합 판정 대상에 적용한다. 바뀌는 것은 "어느 계좌와 비교하나"뿐이다.

| 번호 | LIVE02 적용 |
|---|---|
| L1 | 판정 대상 총수익률 > A01(v3) 총수익률 |
| L2~L5 | 그대로(PF ≥ 1.3, MDD ≤ 20%, 샤프 ≥ 1.0·관측 20거래일 이상, 왕복 ≥ 30·미달은 판정 불가) |
| L6 | 그대로: 시작일 + 28일(2027-01-18) 앞뒤 각각 순손익 > 0. 휴장일 때문에 앞 17거래일·뒤 23거래일로 갈린다 `[사실]`(캘린더로 셈). D-114 정의대로 두고 리포트에 적는다 |
| L7 | 그대로: 전략 `study.key-param` ±20%(선정은 흔들지 않음, D-126 5번). C1·C3·C4는 `signal.range-minutes`, C2는 `signal.surge-ratio` |
| L8·L9 | 그대로 |
| L10 | p = (k+1)/(N′+1) ≤ 0.05/m, **m = LIVE02 판정 대상 수(C1~C4 중 들어간 것, 묶음 합)**, 대조군 = **같은 선정 묶음의 무작위 진입**(D-126 4번), N′ = 왕복 1건 이상인 시드 수, N′ + 1 < 20m이면 판정 불가. 시드 수 N은 6.2 |
| L11 | 그대로: 입력 기록이 있는 날의 같은 날 게이트웨이 녹화(100종목) 리플레이와 총수익률 차 ≤ 2%p, 체결 수 차 ≤ 10% |

- 판정 규칙(D-116): 탈락 하나면 탈락, 아니면 판정 불가가 있으면 보류, 모두 통과면 후보. 후보는 STR-05 다음 단계(녹화 표본 외 재검증)로 가고 실전 활성화는 그 뒤에도 사용자 결정이다.
- 기준선·대조군·참고 계좌(R1~R3)도 같은 표로 내되 판정하지 않는다. 대조군(S1~S3-대조)이 L1~L6을 통과하면 기준이 느슨하다는 신호로 리포트에 적고 사용자에게 묻는다(6단계 계획 4.2와 같음).
- D-114는 "EXP-20261026-LIVE01"의 기준이다(D-114 결정 문단). LIVE02에 같은 기준을 쓰는 것은 승격 기준의 범위를 새 실험·새 계좌 종류로 넓히는 일이라 사용자 확인 항목으로 올린다(9장 Q-056 ①).

### 6.2 대조군 시드 수 N(PR #199 R4)

`[사실]` 지금 `runLiveJudgement`는 N = 21m − 1로 고정하고(`LiveJudgement.java` 164~167행), 왕복 0건 시드는 L10 분포에서 빠진다(`LiveJudgeCriteria.Evidence.nullPerTrip` "완료·왕복 1건 이상만"). 여유는 m개뿐이라 왕복 0건 시드가 m개를 넘으면 그 묶음 판정 대상 모두 L10 판정 불가(보류)다.

등록 때 묶음마다 아래로 N을 정해 등록 파일에 적는다(8장 F3). 늘리는 쪽만 있어 보수적이고, 결과를 보기 전(사전 검사 q̂만 보고)에 정한다.

N_k = max(21m − 1, ⌈21m ÷ (1 − q̂_k)⌉ − 1)

- q̂_k = 4.3의 묶음 k 왕복 0건 시드 비율(사전 검사 83시드). 사전 검사도 40거래일이라 같은 길이의 추정치다.
- 예: m = 4, q̂ = 0이면 N = 83, q̂ = 0.1이면 ⌈84 ÷ 0.9⌉ − 1 = 93.
- q̂_k ≥ 0.5이면 그 묶음 대조군이 사실상 거래하지 않는 것이라 N을 늘리지 않고 그 묶음 판정 대상을 빼고 등록한다(m도 줄어듦). 결과가 아니라 대조군 성질만 보고 정하는 것이다.

### 9.1 사용자에게 묻는 항목

**Q-056 ① LIVE02 선정 조합 계좌를 D-114 L1~L11로 판정할까요?** (6.1, PR #199 strategy-researcher R1)

(나) L10 대조군이 같은 선정 + 무작위 진입(D-126)이고 m은 실제 판정 대상 수(≤ 4)라서 계좌별 문턱이 0.05/6에서 0.05/m(m = 4면 0.0125)이 된다. 가족 전체 오류율 5%는 같다. (다) 선정 효과는 참고 칸이다(7.1). `[추론]` 문턱 숫자는 같지만 승격 기준의 적용 범위를 새 실험·새 계좌 종류로 넓히고 m 문구를 바꾸므로, 사용자가 정한 승격 기준 방향을 바꾸는 경우(8장 5번)로 본다. 6단계 계획에서도 판정 기준 확인을 사용자 일(T3)로 두었다.
