## 점검표 밖 발견

1. **(수정 필요) RSK-13 인수 조건 좁힘이 PROTECTIVE 계좌를 빠뜨렸다.**
   - 바뀌기 전: "2차 확인 실패·잠금·비밀번호 미설정에서도 보호 모드 고정·청산 미수행 테스트" — 계좌 상태를 가리지 않아 PROTECTIVE 계좌(보유가 남은 채 이미 보호 모드)도 "확인 실패면 청산하지 않는다"가 시험 대상이었다.
   - 바뀐 뒤(`docs/spec/autotrade-spec.md` RSK-13 인수 조건): "2차 확인 실패·잠금·비밀번호 미설정에서도 **OPEN·ACTIVATING 계좌는** ① 고정(…)·청산 미수행 테스트(OFF 계좌는 아래 "OFF이고 허가 0건" 테스트가 다룬다)". OPEN·ACTIVATING은 이 문장이, OFF는 "허가 0건"(주문 자체 불가)이 다루지만 **PROTECTIVE 계좌의 청산 미수행은 어느 인수 조건에도 없다.**
   - [사실] 지금 엔진 시험도 이 경우를 따로 고정하지 않는다: `EngineCommandHandlerTest`의 확인 실패 PANIC 시험(`PANIC은_2차_확인이_틀려도_보호_모드_고정은_하고_청산은_하지_않는다`:310, `잠긴_상태에서도_…`:333, `비밀번호가_없어도_PANIC은_열린_계좌를_…`:348)은 이름과 단언으로 보아 열린(OPEN) 계좌에서 시작한다. PROTECTIVE에서 시작하는 확인 실패 PANIC 시험은 찾지 못했다(이름 검색).
   - 영향 `[추론]`: 묶음 E에서 실패 테스트를 인수 조건 목록대로 쓰면, "확인 없이 청산을 시작하지 않는다"는 핵심 보호(2차 확인, RSK-01)가 PROTECTIVE 계좌에서 시험되지 않은 채 지나갈 수 있다. 지금 구현이 틀렸다는 뜻은 아니다(1단계에서 멈추는 구조, ADR-006 2.5 `:100`).
   - 고칠 것: 인수 조건을 예를 들어 "2차 확인 실패·잠금·비밀번호 미설정 PANIC에서 **모든 계좌 청산 미수행**, OPEN·ACTIVATING 계좌는 ① 고정(…), PROTECTIVE 계좌는 PROTECTIVE 유지, OFF 계좌는 아래 'OFF이고 허가 0건'"처럼 청산 미수행을 계좌 상태와 떼어 놓는다. D-144 ⑥ 설명도 같이 맞춘다. 이 변경은 PR #237 risk-ops 권고 3을 따른 것인데, 권고 3 자체가 PROTECTIVE를 짚지 못했다(그 검토의 누락).
