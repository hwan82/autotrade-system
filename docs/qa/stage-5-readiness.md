## 3. 5단계에 묶인 요구사항 중 이 단계에서 끝나지 않는 것

기획서 진행표(5. UI 행)는 UI-01~08과 MON-05를 관련 요구사항으로 적는다. 아래는 데이터를 만드는 쪽이 아직 없어 화면만 먼저 만들 수 없는 항목이다. 이 표를 5단계 판정 범위에서 뺄지는 판정 범위 결정이다(사용자 확인 대상, 지침 8장 5번).

| 요구사항 | 지금 상태 | 막는 것 | 이어서 할 단계 |
|---|---|---|---|
| UI-02 진행 상태 | 실행은 터미널 실행 명령(진행 로그는 터미널) | 실행기 진행 보고·취소(ADR-004 4장), 결과 DB 저장 | 6단계 전 |
| UI-05 블랙리스트 관리·추천 종목·잔고·거래 내역 | 운영 화면 1차(Guard 상태·활성화·내리기·PANIC)까지 | 실전 엔진 스냅샷의 해당 필드(실전 경로, 사용자 머지) | 7단계 |
| UI-07 미국 화면(USD, KST·ET 병기) | 시각 표시 함수는 시장별 병기(`format.js`), 미국 실험·계좌는 없음 | 미국 조합 실험 실행 명령, 미국 계좌 | 해외 단계 |
| UI-08 조회 화면 필드(추천 종목·잔고·거래 내역, 대사 상태) | 실험 쪽 체결·보유·비용은 있음. 실전·실시간 모의 계좌 조회는 없음 | 실시간 모의 운영(6단계)·실전 엔진 스냅샷(7단계) | 6·7단계 |
| MON-05 모니터링 화면 | `autotrade-monitor-agent-jar`가 아직 빈 모듈 | 모니터 에이전트 구현 | 6단계 운영 전 |

## 4. 남은 위험

- 실험 결과는 실험실 메모리에만 올라간다(재기동하면 다시 불러옴, D-062).
- 화면 JS는 자동 테스트가 없다(빌드 도구 없는 정적 프런트, D-026). 손 확인은 PR마다 Chromium으로 한다.
- 실제 KRX 전체 스냅샷으로 등록·실행·불러오기를 한 적은 아직 없다(4단계 사용자 PC 수집 뒤 첫 조합 실험이 첫 실사용).
