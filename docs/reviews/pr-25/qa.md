## 점검표 밖 발견
시나리오 시도(잘못된 주문·중복 주문·보호 공백):

1. **[중] "매도를 낼 수 있는가" 판정 기준과 시점이 정의되지 않음 → 판정이 "가능"인데 실제 매도가 안 되면 서버 측 손절이 취소된 채 밤을 넘길 수 있음.** 예: 국내 15:20~15:30 종가 단일가 구간이나 RSK-11 "일괄 취소" 구간 직전에 PANIC → "장중"으로 판정해 ③ 서버 측 손절 취소 → ④ 시장가가 체결되지 않거나(하한가 잔량, 단일가 미체결) 마감 → 보유가 서버 측 손절 없이 남음. 미국도 지정가+여유폭이 마감 전에 다 못 채우면 같다. ADR-006 2.5 계약("다시 걸거나 FAILED로 알린다")은 있으나, 장 마감 뒤에는 다시 걸기 자체가 안 될 수 있다 `[추론]`. 7단계 전에 정할 것: (a) 판정은 ② 전에, 계좌·종목의 시장 MarketRules 세션 구간으로 하고 "청산 외 주문 금지" 구간 시작부터 일정 여유 이전까지만 "매도 가능"으로 본다, (b) 상태를 모르면(거래정지 여부 조회 실패 등) "매도 불가"로 본다(fail-closed), (c) 체결 확인 상한 시각을 두고 넘으면 서버 측 손절을 마감 전에 다시 건다. RSK-13 인수 조건에 "마감 직전 PANIC에서 미체결 시 서버 측 손절 복구" 테스트 추가 권고.
2. **[하] "매도를 낼 수 없음" 예시에 VI가 들어 있음.** KRX VI 발동 중에는 2분 단일가 매매로 바뀔 뿐 주문 접수는 된다 `[추론, 공식 자료 미대조]`. 미국 LULD 정지 중 주문 접수도 거래소·증권사마다 다를 수 있다 `[추론]`. VI를 "매도 불가"로 분류하면 서버 측 손절은 남으니 보호 공백은 아니지만, 사용자가 원한 청산이 안 된다. 분류는 고정 목록이 아니라 MarketRules와 증권사 거절 응답으로 정하고, 7단계 구현 때 KRX·증권사 공식 자료로 확인할 것. 또 전체 PANIC에서 국내 장 외·미국 장중처럼 계좌마다 판정이 다를 수 있으니 판정 단위(계좌의 시장, 종목)를 RSK-13에 명시할 것(A13 관련).
3. **[하] 코드 계약 주석이 새 규칙을 담지 않음.** PanicLiquidator.java:11 "장 외 시간에는 취소만 하고 매도하지 않는다"는 "취소"가 서버 측 손절 취소(③)를 포함하는지 분명하지 않아, 7단계 구현자가 주석만 보면 장 외에 서버 측 손절을 지울 수 있다 `[추론]`. risk-ops 1차 검토가 이 주석 갱신을 요청했고(risk-ops.md 수정 요청 1), 이 PR은 ADR-006 6장에 "7단계 전 필수" 후속으로 미뤘다. RSK-13 인수 조건(장 외·거래정지 PANIC에서 서버 측 손절 취소 없음)과 TST-07 (7) A9가 7단계에서 이를 잡으므로 이번 머지를 막지는 않지만, 저장소 안에 덜 엄격한 계약 문구가 남는다. 다음 코드 PR에서 바로 고칠 것.
4. **[하] D-037 행의 결정 근거가 섞여 있음.** 행 끝은 "사용자 결정(PR #18 머지)"인데, 그 안의 매도 불가 규칙은 "이 PR(#25) 사용자 머지로 결정"이다. 나중에 읽는 사람이 이 규칙도 PR #18에서 정해진 것으로 볼 수 있다. 또 D-023 RSK-13 "장 외 시간은 매도 안 함"은 그대로 지키지만, v13 문구의 "장 외 시간에는 미체결 (전부) 취소"를 "미체결 매수만 취소"로 바꾼 것이 D-023 문구를 좁힌 것이라는 점이 D-037에 적혀 있지 않다. 의미상 보호를 강화하는 변경이라 확정 결정 충돌은 아니라고 본다 `[추론]`.
5. 확인했지만 문제 아님: (a) 장 외 PANIC 뒤 미체결 매도(전략 청산 지정가)와 서버 측 손절이 함께 남아 개장 후 이중 매도가 되는가 → 이 조합은 PANIC 전에도 같았고, 매도 가능 수량을 넘는 매도는 증권사가 거절한다 `[추론]`. 새 위험 아님. (b) 장 외 PANIC 후 개장 때 다시 PANIC → 계좌가 PROTECTIVE라 1단계 SKIPPED 후 2차 확인, 증권사 단계 진행(EngineCommandHandler.java:232-260). 문서와 일치. (c) D-036 건너뜀은 PR #23 예약. 현재 main과 충돌 없음(merge-tree).
