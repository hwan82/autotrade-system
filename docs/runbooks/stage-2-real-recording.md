# 2단계 완료 확인: 실제 KRX 하루 녹화와 두 번 리플레이

2단계 완료 기준 "하루 녹화분을 두 번 리플레이해 결과 동일"(team-design.md 6장, 기획서 MD-06)을 실제 증권사 시세로 확인하는 절차다. QA 2단계 재판정의 C1과 G-1(원본 대조)에 대응한다. 증권사 키가 필요해 사용자가 직접 한다. 요금은 무료로 확인됐다([시세 조사](../research/market-data-limits.md) 1.5절).

## 준비 (장 시작 전)
1. 키움 또는 한국투자 Open API 사용 신청을 하고 App Key·Secret을 받는다. 키움은 포털에서 접속할 PC의 IP를 등록한다.
2. 설정 폴더(`AUTOTRADE_CONFIG_DIR`, 기본 `~/.autotrade/`)의 `secrets.json`에 키를 넣는다. 키는 저장소·채팅에 올리지 않는다.
   ```json
   { "brokers": { "kiwoom": { "app-key": "<KIWOOM_APP_KEY>", "app-secret": "<KIWOOM_SECRET_KEY>" } } }
   ```
   한국투자는 `"kis": { "app-key": "<KIS_APP_KEY>", "app-secret": "<KIS_APP_SECRET>" }`.
3. 그 증권사로 실전 계좌(`real-trading.accounts`와 계좌번호)를 설정해 두었다면 게이트웨이가 그 키를 쓰지 않는다(D-024). 녹화할 증권사는 실전 계좌가 없는 쪽이어야 한다.
4. 같은 폴더에 `watchlist.json`을 만든다. 대조하기 쉬운 대형주 몇 개면 충분하다.
   ```json
   { "held": [], "candidates": ["KRX:005930", "KRX:000660", "KRX:035420"] }
   ```

## 녹화 (08:40 전 시작, 15:40 뒤 종료)
5. 저장소 루트에서 `./gradlew :autotrade-app-gateway:installDist`로 설치한 뒤 `autotrade-app-gateway/build/install/autotrade-gateway/bin/autotrade-gateway`로 실행한다(`gradlew run`은 Ctrl+C 때 정상 종료 처리가 돌지 않을 수 있다). 로그에 `시세 배분` 줄이 나오고 장이 열린 뒤 녹화 폴더의 `events.jsonl.gz` 크기가 늘면 정상이다. 키가 3번 거절되면 ERROR 로그가 남고 재시도 간격이 늘어나니, 키와 IP 등록을 확인한 뒤 다시 실행한다. 키움은 거절 사유를 `키움 토큰 발급 실패(HTTP …): return_code …` 줄로 남긴다(8050 IP 미등록, 8030 실전/모의 키 혼동, 8001·8002 키 오류, 1700~1702 호출 한도: [키움 명세 요약](../research/kiwoom-rest-api-spec.md) 3장). 키움은 처음 LOGIN에 성공하면 `키움 실시간 접속 경로 확인: wss://…` 줄이 나온다. 이 줄을 9번 보고 때 같이 올린다(접속 경로 확정용).
6. 장 마감(15:30 종가 단일가) 뒤 15:40 이후에 Ctrl+C로 끈다. 정상 종료해야 메타(`meta.json`)에 정상 종료 표시와 `eventsSha256`이 남는다. 녹화는 `~/.autotrade/recordings/KRX/<날짜>/`에 생긴다.

## 확인
7. `./gradlew :autotrade-app-gateway:replayCheck --args="<날짜> replay-<날짜>.md"`를 실행한다(예: `2026-10-12`). 녹화를 디스크에서 두 번 따로 읽어 리플레이하고, 두 결과의 SHA-256과 메타·파일 해시를 비교한다. 보고서는 저장소 루트에 생긴다. 종료 코드 0이면 동일(녹화도 정상 종료·잘림 없음), 1이면 다름, 2면 녹화를 읽지 못한 것, 3이면 두 회차는 같지만 녹화가 불완전(비정상 종료·마지막 줄 잘림·0건)해 완료 증거로 쓸 수 없다는 뜻이다. 3이면 다른 날 다시 녹화한다. 장 시간 보호 구간(국내·미국 정규장 60분 전~폐장 30분 뒤)에는 시작하지 않는다(관문 판정 전에 Gradle 컴파일이 먼저 돌아 부하가 생긴다). 4면 장 시간 보호 구간이거나 감시의 정지 요청 파일(`<설정 폴더>/experiment-state/stop-request`)이 있어 멈춘 것이다(D-085, 보고서를 쓰지 않음). 장 마감 뒤(서울 16:00 이후, 미국장 보호 전)에 다시 돌린다. 실전 엔진을 끈 날에만 `-PallowDuringSession`을 붙여 장 시간 보호를 풀 수 있다(정지 요청 파일은 풀리지 않음).
8. 원본 대조(G-1): 보고서의 종목별 시가·고가·저가·종가를 HTS(영웅문·eFriend) 그날 **KRX 단독 정규장** 일봉과 비교한다. NXT 통합이나 시간외가 섞인 값과는 비교하지 않는다. 도구는 정규장(캘린더 구간, 종가 단일가 체결을 위해 마감 뒤 1분 포함 `[가정]`) 체결만 시가~종가에 넣고, 그 밖의 체결은 "정규장 밖" 칸에 따로 적는다. 가격 자릿수나 첫·마지막 체결 시각이 크게 다르면 수신 해석 오류다. 체결 수량 합은 일봉 거래량과 비교해 차이를 적는다(끊김, 녹화 시작 지연, 증권사가 보내지 않는 체결 때문에 다를 수 있다). 대조 결과를 보고서 끝에 한두 줄 적는다. 키움 키가 있으면 HTS 대신 게이트웨이를 끈 상태에서 `./gradlew :autotrade-app-gateway:kiwoomDaily --args="<날짜> kiwoom-daily-<날짜>.md"`로 같은 종목(`watchlist.json`)의 KRX 단독 정규장 일봉 표를 받을 수 있다(조회 TR ka11081만 쓰고 주문·계좌 API는 부르지 않는다. 키움 실전 계좌가 설정돼 있으면 실행하지 않는다). 처음 한 번은 몇 종목을 HTS 일봉과도 비교해 부호·단위 해석을 확인한다.
9. 보고서 파일을 프로젝트 스레드에 올린다. data-engineer가 `experiments/stage-2-replay/<날짜>.md`로 커밋하고 QA에 2단계 완료 재판정을 요청한다. 녹화 파일 자체는 올리지 않는다(외부 공유 금지, ADR-003).

## 실패했을 때
- 연결은 되는데 이벤트가 0건: 구독 거절일 수 있다(ADR-003 5장). 게이트웨이 로그를 스레드에 올린다(키·토큰 값이 보이면 지운다).
- 키움 연결 실패가 계속되고 `접속 실패` 경고만 반복됨: 실시간 경로 문제일 수 있다. 게이트웨이 로그를 올리면 경로를 고친다(두 경로를 번갈아 시도하므로 보통은 저절로 붙는다).
- 가격이 10배·100배 다름, 시각이 9시간 어긋남: 필드 해석 `[가정]`이 틀린 것이다(Q-015). 보고서를 올리면 수정 PR을 만든다.
- 장중 게이트웨이 창이 닫히거나 PC가 꺼졌다: 같은 날 다시 실행하면 이어서 녹화한다. 그날 녹화 폴더에 `events.jsonl.gz.before-segment-<번호>` 보관본이 생긴다(재기동 직전 원본, 리플레이는 읽지 않음). `replayCheck`가 종료 코드 3(불완전)이 아니고 보고서 이벤트 수가 예상과 맞으면 보관본은 지워도 된다. 수가 이상하면 지우지 말고 스레드에 알린다(PR #66).
