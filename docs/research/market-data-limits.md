## 0. 결론

1. **미국 실시간 시세는 키움·한국투자는 무료가 공식 확인됐고, 토스도 추가 비용이 없는 것으로 보인다(`[추론]`, 요금 조항 미확인).** 무료 소스가 두 곳 확정이므로 과금 멈춤 조건에 해당하지 않는다. 다만 키움(나스닥 토탈뷰)과 토스(일부 거래소, NBBO 아님)는 미국 통합 시세가 아니고, 한국투자는 원천 거래소가 공개되지 않았다. (2장)
2. **실시간 구독 한도는 키움 200종목, 토스 200건(연결 2개 × 100), 한국투자 41건**이다. D-008 잠정안대로 키움을 1순위로 확정할 근거가 생겼다. 단, 키움(토큰당 세션 1개)과 토스(계정당 연결 2개)는 연결 수가 작아 프로세스 분리(D-013)와 함께 연결 배분 원칙이 필요하다. (1장, 3장)
3. **토스증권 Open API에 실시간 WebSocket이 생겼다.** 기존 설계 문서의 "토스는 REST만, 실시간 없음"은 지금 공식 문서와 다르다. 그래서 D-008을 대체해 토스를 실시간 2순위로 올리는 결정을 제안한다(4장). 보유 종목 보호 폴링 경로는 그대로 둔다. 확정 결정과 충돌하고 장애 대응 경로와 맞닿아 있어 사용자 확인과 risk-ops 검토 대상이다.

## 3. 대안 비교: 시세 1·2·3순위

### 3.1 연결 배분 제약 (D-013 프로세스 분리와의 관계)
- 키움은 계좌별(토큰별) WebSocket 세션 1개다 `[사실]` K1. 시세 게이트웨이와 실전 엔진(주문 체결 통보 실시간 `00`)이 같은 토큰으로 각자 접속하면 서로의 세션을 밀어낼 수 있다 `[추론]`. 따라서 프로세스마다 별도 토큰(별도 앱키 또는 계좌)을 쓰거나, 실전 엔진의 체결 확인을 REST 조회로 두어야 한다. 한 계좌에 토큰을 여러 개 받을 수 있는지는 `[가정]`(5장).
- 토스는 계정당 연결 2개이고, 3번째 연결이 들어오면 **가장 오래된 연결이 끊긴다** `[사실]` T2. 실전 엔진이 주문 이벤트(`personal:order`)용으로 1개를 쓰면 게이트웨이는 1개(100건)만 쓸 수 있다. 어떤 프로세스도 2개를 넘겨 연결하면 안 되고, 연결 수는 설정으로 고정해 감시 프로세스가 점검해야 한다(절대 규칙 6, risk-ops 검토 대상).
- 아래 용량은 이 배분(토스는 게이트웨이 1연결, 키움은 게이트웨이 전용 토큰)을 전제로 한 체결+호가 기준 종목 수다. 키움의 종목 단위 계산은 `[가정]`.

### 3.2 안 비교

| 안 | 국내·미국 순서 | 두 소스 SHARDED 용량(체결+호가) | 장점 | 단점 |
|---|---|---|---|---|
| A (추천) | 키움 1, 토스 2, 한국투자 3 | 키움 200 + 토스 50 = 약 250종목 | 실시간 소스 3곳으로 장애 대비 여유가 커짐. 토스는 미국 전 세션 푸시. 한국투자는 41건이라 3순위 예비로 충분 | 토스 WebSocket은 AsyncAPI 1.2.x로 신생이라 안정성 실적이 적음. 시세 채널이 LOSSY. 토스 연결 배분 규칙이 추가로 필요 |
| B (D-008 유지) | 키움 1, 한국투자 2, 토스 폴링 | 키움 200 + 한국투자 20 = 약 220종목 | 기존 결정 그대로, 연결 배분 규칙이 단순 | 실시간 소스가 2곳뿐. 토스 실시간을 버림 |
| C | 토스 1, 키움 2, 한국투자 3 | A와 같음 | 토스 연결 2개를 모두 시세에 쓰면 용량 증가 | 공식 실적이 가장 짧은 소스를 주력으로 씀. 실전 주문 이벤트 연결과 충돌 위험이 가장 큼 |

- 세 곳 모두 쓰면(D-009 범위 밖) 약 270종목이다. 용량 차이(250 대 220)는 크지 않고, A의 실익은 **용량보다 실시간 소스가 하나 더 생기는 것**이다 `[추론]`.
- 모든 안에서 **토스 보유 종목 보호 폴링(`toss-polling-scope: HELD_ONLY`, broker-and-fault-design.md 3.3·5.1·6장)은 그대로 유지한다.** A안은 실시간 순위만 추가하고, 실전 엔진의 보호 시세 경로를 대체하지 않는다.

A를 고른 이유: 1순위는 구독 한도가 같은 키움·토스 중 이미 잠정 1순위이고 10호가를 주는 키움으로 둔다(broker-and-fault-design.md 4.1의 "한도가 큰 쪽이 1순위" 원칙과 맞음). 토스를 2순위로 올리면 실시간 장애 대비 소스가 하나 늘고, 미국 시세를 모든 세션에서 받을 수 있다.
B를 버린 이유: 근거였던 "토스는 실시간 없음"이 공식 문서와 다르다. 다만 A의 이득이 크지 않으므로, 사용자가 단순함을 원하면 B도 합리적이다.
되돌릴 조건: 2단계 시세 구현 후 장중 녹화에서 토스 소스의 누락률이나 지연(p99)이 키움보다 눈에 띄게 나쁘면 B로 돌아간다. 기준 수치는 data-engineer가 2단계 품질 지표 설계 때 정한다.

## 4. 결정 로그 변경 제안 (pm-lead 반영 요청)

> 2026-10-08 갱신: 사용자가 A안을 골라 D-024(D-008 대체)로 기록했다.
> risk-ops 검토로 연결 배분(계정 합계 2연결), 실전 엔진 REST 확정, 종목별 수신 공백 감시, 장애표 17번을 broker-and-fault-design.md에 넣었다. 키움 다중 토큰 가능 여부와 토큰 발급 시 다른 토큰 무효화 여부는 **실전 활성화 전 필수 확인** 항목이다. 7장 장애 테스트 1번에 "게이트웨이가 토스 3번째 연결이나 키움 동일 토큰 재접속을 시도해도 실전 엔진의 주문 상태 확인에 공백이 없음"을 합격 기준으로 넣는 안은 사용자 결정 대상이다.

data-engineer는 결정 로그와 다른 역할 문서를 직접 고치지 않는다(지침 3장). 결정 로그는 기존 행을 고치지 않고 새 번호로 대체하므로, 사용자 선택에 따라 아래 한 줄을 그대로 쓴다.

- **A안 승인 시**: `D-0xx (D-008 대체) | 실시간 시세 우선순위는 국내·미국 모두 키움 1, 토스 2, 한국투자 3. 토스 보유 종목 보호 폴링(HELD_ONLY)은 유지. 토스 WebSocket은 계정당 2연결 중 게이트웨이 1개, 실전 엔진 1개로 배분 | docs/research/market-data-limits.md 3장`
- **B안 선택 시**: `D-0xx (D-008 확정) | 실시간 시세 우선순위는 키움 1, 한국투자 2 확정(공식 한도 키움 200종목, 한국투자 41건). 토스는 보유 종목 보호용 폴링 유지 | docs/research/market-data-limits.md 1장`
- **Q-001 닫기**: 1장 표로 답함. 남은 `[가정]`은 5장 확인 목록으로 넘김.
- **Q-003 닫기**: 키움·한국투자 미국 실시간 무료 공식 확인, 토스는 `[추론]`.

## 5. 위험과 남은 확인 항목

| 항목 | 상태 | 확인 방법 | 틀렸을 때 영향 |
|---|---|---|---|
| 한국투자 WebSocket 동시 세션 수(appkey당 1개?) | `[가정]` | KIS Developers 포털 공지·FAQ 확인, 또는 2단계에서 두 번째 연결 시도 | 1개보다 많으면 용량 증가(좋은 쪽) |
| 한국투자 41건이 국내·해외 합산인지 | `[가정]` 합산 | 국내 30건 + 해외 15건 등록 시험 | 합산이 아니면 미국용 여유 증가 |

| 키움 국내·미국 WebSocket이 같은 세션 한도를 나누는지 | `[가정]` 나눠 씀 | 두 URL 동시 접속 시험 | 별도면 용량 증가 |
| 토스 `trade`·`orderbook` 구독이 100건을 각각 차지하는지 | `[가정]` 각각 | 같은 종목 두 채널 구독 후 `too-many-topics` 경계 확인 | — |
| 키움 한 계좌에 토큰(세션)을 여러 개 받을 수 있는지 | `[가정]` | 키움 포털 문의, 2단계에서 두 토큰 동시 접속 시험 | 안 되면 실전 엔진은 키움 WebSocket 대신 REST 조회로 체결 확인 |
| 토스 미국 실시간 시세 요금 | `[추론]` 무료. 2026-10-09 재확인 실패(공식 페이지가 스크립트 렌더링이라 문구를 읽지 못함, 2차 자료만 있음). 확인 전에는 기본 꺼짐(D-033), 확인은 Q-020 | 토스 Open API 이용약관·FAQ 요금 조항 확인, 또는 개발자 콘솔 신청 화면의 요금 안내 | 유료면 과금 멈춤 조건, 사용자 확인. 대체 수단: 키움·한국투자만으로 운용(둘 다 미국 실시간 무료 공식 확인) |
| 한국투자·키움 미국 실시간 무료 문구 | 공식 저장소 명세·샘플 근거, 포털 원문 미확인 | KIS·키움 포털 해외 시세 안내 확인 | 바뀌었으면 Q-003 재오픈 |
| 한국투자 REST 초당 20건 | 공식 샘플 주석 근거, 포털 원문 미확인 | 포털 "API 호출 유량 안내" 확인 | 작으면 REST 보정 속도 하향 |

설계 반영 제안 `[추론]`: 한도 수치는 코드에 박지 말고 증권사별 설정 키로 두고(예: `broker.<id>.realtime.max-subscriptions`, `broker.<id>.rest.<group>.tps`), 토스는 응답 헤더 값을 우선한다. 설정 키 이름은 architect 소관이므로 제안으로만 남긴다.

검증하지 못한 것: 위 수치는 모두 문서 기준이다. 실제 계정으로 접속해 측정하지 않았다(API 키 없음). 2단계에서 계정을 연결한 뒤 5장 항목을 실측으로 확인한다.
