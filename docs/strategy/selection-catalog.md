# 선정 조건 카탈로그 (STR-15·16)

- 담당: strategy-researcher. 날짜: 2026-10-10. 결정: [D-057](../decisions/D-057-selection-catalog.md)(추천안 채택(자율))
- 근거: 기획서 STR-10·11·15·16, MD-07·10·11, [D-041·D-042·D-043](../decisions/D-041-selection-x-signal-combinations.md) 4장, [ADR-007](../adr/ADR-007-selection-combination.md) 2.1·2.6
- 코드: `autotrade-selection` 패키지 `com.autotrade.selection.calc`(`SelectionCriteria` 문법, `Metric` 지표, `SelectionCalculator` 계산, `FinancialsAt` 재무 시점 규칙), `selection.result.SelectionResult`(결과 모델·내용 해시)
- 프로필 파일: `selections/<선정ID>/v<버전>.yaml`([selections/README.md](../../selections/README.md))

## 1. 계산 순서

선정 기준일 **T** = 결과를 처음 적용하는 거래일(`apply_from`). 기준 데이터일 **c** = T의 직전 거래일.

0. **입력 확인**(ADR-007 2.6 `STALE_INPUT`의 생산 쪽, PR #45 architect F1): 일봉 스냅샷 manifest `coverage.lastTradingDate`가 c 이상이어야 한다. 시가총액 조건이 있으면 상장주식수 입력이 있고 `coverage.sharesAsOf` ≥ c, 재무 조건이 있으면 재무 입력이 있고 `coverage.lastCollectedAt`의 거래소 현지 날짜 ≥ c여야 한다. 공시 조건(`disclosure-count`)이 있으면 공시 입력이 있고, 조건이 쓰는 유형마다 공시 스냅샷의 수집 유형 목록(`disclosure_types.csv`)에 그 유형이 있어야 하며(없으면 `INPUT_TYPE_MISSING`), 그 유형의 수집 구간 하나가 조건의 접수일 구간(3장)을 통째로 덮어야 한다(아니면 `STALE_INPUT`)(D-122). 하나라도 어기거나 기준일을 모르면 계산하지 않고 실패한다(결측 탈락으로 "0종목" 결과를 내지 않는다). 결과 `inputs`의 기준일은 계산 기준일이 아니라 이 manifest 값이다. 재무 조건은 엔진 판정의 지연 상한(기본 5거래일)보다 엄격하지만, 실험실 리플레이는 보통 나중에 수집한 스냅샷을 써서 걸리지 않는다.
1. **유니버스**: c에 상장돼 있던 종목 전부(나중에 상장폐지된 종목 포함, MD-07). c 전에 폐지된 종목은 빠진다.
2. **하드 필터**(STR-10): `filter.kinds` → `filter.min-price` → `filter.min-bar-days` 순. 걸리면 자격 조건을 보지 않고 사유 하나로 탈락.
3. **자격 조건**(Gate, 모두 AND): 조건마다 값을 계산하고 비교한다. 한 조건에서 떨어져도 나머지 조건 값을 모두 남긴다(탈락 사유 분석용).
4. **순위**: 통과 종목을 `score.*` 순(같으면 종목 코드 순), 점수가 없으면 종목 코드 순으로 세워 `max-symbols`까지 선정. 넘친 종목은 `RANK_CUTOFF`.
5. **결과**: 선정 종목(순위), 전 종목 평가(통과·탈락 사유, 조건별 값, 정정 대체 규칙 표시), 입력 데이터 기준(일봉 스냅샷·수록 마지막 거래일, 상장주식수 기준일, 재무 스냅샷·수집 시각, 공시 조건이 있을 때만 공시 스냅샷 ID·SHA-256·`covered_through`(쓴 유형들 수집 구간 끝날 중 가장 이른 날)), 내용 해시(ADR-007 2.6 정규 JSON의 SHA-256).

**적용 범위**: `POST_CLOSE_DAILY`·`PRE_OPEN_DAILY`는 T 하루. `POST_CLOSE_WEEKLY`는 T가 그 ISO 주(월~일)의 첫 거래일이어야 하고 그 주 마지막 거래일까지. 실험실은 주중에 시작해도 그 주 첫 거래일 결과를 쓴다.

**미래 정보 0건**: 일봉·상장주식수는 c까지만, 재무는 접수일이 T보다 앞선 공시만, 공시 건수는 접수일 ≤ c인 공시만 읽는다(T 당일 장전 공시도 쓰지 않음, ADR-012 3.1). T가 거래일이므로 "접수일 < T"는 "접수일 다음 거래일 ≤ T"와 같다(MD-10). 테스트: `SelectionCalculatorTest#기준일_당일_이후_일봉은_쓰지_않는다`, `#가_재무_4조건_골든_T1`(T1 당일 접수 공시 미사용).

## 3. 지표

| 키 | 입력 | 기간 | 정의 | 결측·특수 사유 |
|---|---|---|---|---|

| `volume-ratio` | 일봉 | window w | c에서 끝나는 w거래일 **수정 거래량** 합 ÷ 그 앞 w거래일 합(길이가 같아 평균의 비와 같음) | 2w거래일 중 하루라도 일봉 없음, 앞 구간 합 0 → `NO_DATA` |
| `return` | 일봉 | window w | c 수정 종가 ÷ (c에서 w거래일 앞 날 수정 종가) − 1. w+1개 종가 | 하루라도 없음 `NO_DATA` |
| `avg-turnover` | 일봉 | window w | w거래일 평균(원가격 종가 × 거래량) | 같음 |
| `day-range` | 일봉 | — | (c 수정 고가 − c 수정 저가) ÷ c−1 수정 종가. 단타(ADR-012 3.2) | c 또는 c−1 일봉 없음, c−1 종가 ≤ 0 → `NO_DATA` |
| `close-strength` | 일봉 | — | (c 종가 − c 저가) ÷ (c 고가 − c 저가). 1이면 고가 마감, 0이면 저가 마감. 같은 날 세 가격이라 수정 계수가 약분돼 원가격으로 계산. 단타(ADR-012 3.2) | c 일봉 없음, 고가 = 저가(상·하한가 고정, 거래 1건 등) → `NO_DATA`(고저 모순 행은 품질 검사가 먼저 뺌) |
| `disclosure-count` | 공시 | window w | `gate.<nn>.types` 유형 공시 중 접수일이 **(c에서 끝나는 w거래일의 첫날 앞 거래일) 다음 날 ~ c**인 건수. w1이면 c−1 다음 날 ~ c라 c 앞 휴장일(주말·공휴일) 접수분이 c 구간에 든다. 정정·첨부 공시(보고서명이 `[기재정정]`·`[첨부정정]`·`[첨부추가]`·`[변경등록]`·`[연장결정]`처럼 대괄호 머리말로 시작)는 세지 않는다. 종목 코드를 못 붙인 공시도 세지 않는다. **자격 조건에만** 쓴다(`score`에 쓰면 거부). KRX 선정만. 공시 스냅샷(ADR-012 3.4, D-122) | 결측 없음: 공시 0건은 정상값 `0`. 스냅샷이 구간을 못 덮으면 계산 전체를 멈춘다(1장 0번) |
| `volume-spike` | 일봉 | window w | c **수정 거래량** ÷ (c 앞 w거래일 수정 거래량 평균). `volume-ratio`(w일 합 ÷ 앞 w일 합)와 달리 c 하루를 본다. w+1개 일봉(w20이면 c 포함 21거래일). 단타(ADR-012 3.2) | w+1거래일 중 하루라도 일봉 없음 또는 **거래량 0 이하인 날**(거래정지일은 거래량 0 일봉으로 저장, ADR-008) → `NO_DATA`. 정지일이 평균에 들어가면 배율이 부풀기 때문이다(PR #193 strategy-researcher M1) |

- **수정 거래량** = 거래량 ÷ `adj_factor`. 수정 계수는 가격에 곱하는 누적 계수(ADR-008 "수정 계수")라, 2:1 분할 전 거래량은 2배로 바뀐다. 계수는 스냅샷 시점 기준이지만 비율 지표는 상수배에 불변이라 미래 정보가 아니다. 테스트: `000040`(분할 낀 창, 원거래량이면 4배 → 수정 2배로 탈락).
- **사유 코드**: 조건 탈락 `GATE_<nn>`, 결측 `GATE_<nn>_NO_DATA`, 적자 `GATE_<nn>_DEFICIT`, 자본잠식 `GATE_<nn>_CAPITAL_IMPAIRED`, 필터 `FILTER_KIND`·`FILTER_MIN_PRICE`·`FILTER_MIN_BAR_DAYS`, 점수 결측 `SCORE_NO_DATA`, 순위 밖 `RANK_CUTOFF`.
- **값 표기**: `BigDecimal`(`MathContext.DECIMAL64`) 계산 뒤. 모든 중간 계산(수정 거래량·수정 종가, 합, 영업이익률, 나눗셈)은 `DECIMAL128`로 하고 결과 값만 마지막에 한 번 `DECIMAL64`로 줄인다. 반올림 오차가 쌓여 경계(정확히 3배, 정확히 3%, 정확히 1.5배)가 2.999…·0.0299…·0.4999…로 떨어지지 않게 하려는 것이다(PR #45 architect F2·F2b, 테스트 `#거래량_비율_경계는_수정_계수가_1이_아니어도_정확하다`, `#수익률_경계는_수정_계수가_1이_아니어도_정확하다`, `#영업이익률_증가율_경계는_반올림에_흔들리지_않는다`). 그 뒤 `stripTrailingZeros().toPlainString()`(예: `0.5`, `300000000000`).
- 재무·공시 지표는 OpenDART(국내) 출처라 KRX 선정에만 쓸 수 있다(D-041 5장).
- **공시 건수의 정정 규칙**: OpenDART 공시 목록에는 원공시를 가리키는 필드가 없어 정정 공시를 원공시로 묶지 않고 머리말로만 거른다. 같은 사건의 원공시와 기재정정이 같은 구간에 있으면 1건, 원공시는 구간 밖이고 정정만 구간 안이면 0건이다. 머리말 없는 다른 보고서명(예 `주요사항보고서(자기주식취득결정)`)은 모두 센다.
- 단타 지표(ADR-012, D-121 ②): 전일 거래대금은 `avg-turnover`의 `window: 1`(c 종가 × 거래량 근사, 실제 거래대금 `ACC_TRDVAL`은 수집 전, ADR-012 후속 F1), 전일 등락률은 `return`의 `window: 1`로 쓴다. 공시 건수는 `disclosure-count`(공시 스냅샷 수집과 함께, ADR-012 배치표 3번, D-122).

## 4. 재무 시점 규칙 (MD-10, D-042 4번)

사업보고서(보고서 코드 11011)만 쓴다. 한 사업연도에 원 공시와 정정 공시가 각각 한 행이다(ADR-008 2.5).

| 경우 | T 시점에 쓰는 값 | 표시 |
|---|---|---|
| 기본 규칙: 그 연도에서 T 전에 접수된 가장 늦은 공시의 값이 있음 | 그 공시 값(원 공시 → 정정 접수일 다음 거래일부터 정정 값) | 없음 |
| 대체 규칙: 가장 늦은 공시의 값을 모름(OpenDART가 정정 반영 값만 줘서 원 공시 값 없음) | 그 연도는 아직 없는 것으로 보고 **직전 사업연도**를 최근 사업보고서로 씀. 비교 기준 연도도 한 해 앞당겨짐 | `restatement_fallback = true`, 결과 `restatement_fallback_count` |
| 비교 기준 연도(k년 전)의 값을 모름 | 대체하지 않음 | `NO_DATA` |

"최근 사업보고서" = T 전에 접수된 사업보고서가 있는 가장 늦은 사업연도. 연결·개별 선택은 수집기가 공시마다 정한다(연결 우선, ADR-008 2.5). 두 해의 구분이 다를 수 있는 것은 남은 한계다(6장).

## 6. 대안과 한계

| 선택 | 채택 | 버린 대안과 이유 | 되돌릴 조건 |
|---|---|---|---|
| 조건 문법 | 평평한 `gate.<nn>.{metric,op,value,window,years}` | 식 문자열(`"volume-ratio(20) >= 3"`): 파서가 필요하고 해시가 공백·표기에 흔들림. 지표별 전용 키(`gate.volume-ratio-20`): 같은 지표를 다른 기간으로 두 번 쓸 수 없음 | 조건 사이 OR가 필요해지면 새 키 `gate.<nn>.any-of`를 더하는 ADR |
| 일봉 결측 | 결측 종목은 그 조건 `NO_DATA`(보간 없음) | 앞 값 채우기: 거래정지 종목이 "거래량 0"처럼 보여 비율이 왜곡됨 | 결측 탈락이 유니버스의 5% 이상 `[가정]`이면 data-engineer와 거래정지 표시 칸 검토 |
| 점수 없을 때 자르기 | 종목 코드 순 | 무작위(시드): 결과 해시가 시드에 묶여 선정 결과 공유가 계좌 시드와 얽힘 | 상한에 걸리는 날이 잦으면 점수 지표를 넣은 새 버전 |
| 공시 건수 구간 | 접수일 (w거래일 첫날 앞 거래일, c] (달력일) | 거래일 접수분만: 주말·연휴 공시가 영영 안 세짐. 기준일 T까지: 장전 공시가 들어가지만 T 08:00 전 수집이 보장되지 않아 날마다 입력이 달라짐(ADR-012 3.7) | 장전 공시 효과가 크다는 근거가 나오면 T 07:30 수집 보장을 전제로 새 지표 키 |
| 정정 공시 | 대괄호 머리말이면 세지 않음 | 원공시에 묶기: 목록에 원공시 필드가 없음. 모두 세기: 정정이 많은 회사가 "공시 많음"으로 뽑힘 | 정정 판정이 틀린 사례가 품질 리포트에서 보이면 규칙 보강(새 지표 키) |
| 재무 대체 규칙 단위 | (종목, 사업연도) 하나를 직전 연도로 | 대체 없이 결측: 정정이 잦은 기업이 체계적으로 빠지는 다른 편향 | 대체 적용이 재무 선정 종목의 5% 이상 `[가정]`(D-042 되돌릴 조건) |

**남은 한계**
- `volume-ratio`((나) 프로필)는 거래정지일(거래량 0 일봉)을 그대로 합에 넣는다. `volume-spike`처럼 결측으로 바꾸면 이미 돈 실험 결과가 달라지므로 이 카탈로그에서는 바꾸지 않고, 바꾸려면 새 지표 키나 새 결정으로 한다(PR #193 strategy-researcher 후속).
- 관리종목·투자경고·거래정지·정리매매·우선주 구분(STR-10 일부)은 지금 스냅샷(`instrument_history.csv`)에 없어 필터를 만들지 못했다. data-engineer 변경 제안: 종목 이력에 시점별 상태 칸(관리·경고·정지)과 주식 종류(보통·우선) 칸 추가.
- 연결·개별 구분이 두 사업연도에서 다르면 증가율이 섞인 기준으로 계산된다 `[추론]`. 첫 실수집 품질 리포트에서 건수를 본 뒤 "같은 구분만 비교" 옵션을 정한다.
- 재무 조건 선정의 백테스트는 2019년 4월 무렵부터 가능하다(D-041 5장, OpenDART 2015년~ × 3년 증가율).
- 공시 종목 코드는 공시 자체의 `stock_code` → 같은 회사 고유번호 → KRX 종목 이력 이름 대조 순으로 붙인다(D-122). 셋 다 실패한 공시는 세지 않으므로, 상장폐지·이름 변경 종목의 옛 공시가 빠질 수 있다 `[추론]`. 건수는 수집 품질 리포트(`dart-disclosures-*.md`의 "코드 못 붙인 행")에서 본다.
- 실제 KRX·OpenDART 스냅샷으로 돌린 결과는 아직 없다(키 발급 대기). 합성 골든 테스트로만 검증했다.
