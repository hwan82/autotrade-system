- 상태: 채택 (추천안 채택(자율), data-engineer · 교차 검토 architect, risk-ops)
- 날짜: 2026-10-08
- 단계: 로드맵 2단계 시세 (docs/team/team-design.md 6장)
- 기획서: [v12](../spec/autotrade-spec.md) MD-01~09, BRK-02·03·06, OVS-01(시장 코드)
- 근거 결정: D-003, D-004, D-007~D-010, D-013, D-014, D-019
- 입력: [시세 사전 조사](../research/market-data-limits.md)(Q-001·Q-003), [ADR-001](ADR-001-module-structure.md)
- 결정 로그: D-028(구조). 2단계 완료 기록은 독립 QA 승인 뒤에 한다(지침 11장, D-031)

## 1. 배경

[사실] 1단계 뼈대(PR #7)는 `MarketDataSource`, `MarketEvent`, `BrokerPlugin` 계약만 있고 구현이 없었다. 2단계 완료 기준은 "하루 녹화분을 두 번 리플레이해 결과 동일"(team-design.md 6장, MD-06)이다.

[사실] 실전 증권사 키가 아직 없다. 그래서 프로토콜은 증권사 공식 저장소의 명세·샘플 코드(키움 `kiwoom-rest-api` 문서, 한국투자 `open-trading-api` 샘플)를 기준으로 구현하고, 모든 테스트는 가짜 전송 계층과 녹화 형식 데이터로 돌린다. 실제 접속 검증은 키가 들어온 뒤 5장 확인 목록으로 한다.

[사실] 이 작업 중에 사용자 결정 D-024가 D-008을 대체했다. 실시간 우선순위는 키움 1, 토스 2, 한국투자 3이고, 토스 보유 종목 보호 폴링은 유지한다. 이 ADR의 구현은 키움·한국투자 WebSocket과 토스 폴링까지다. 토스 WebSocket은 같은 공통 엔진에 `TossStreamProtocol` 하나를 더하는 후속 작업이다(2.1, 5장). 그전까지 게이트웨이는 `market-data.priority`에서 실시간을 구현한 소스만 고르므로 키움·한국투자로 돈다.

## 2. 결정

### 2.1 실시간 소스와 증권사 플러그인

```
 autotrade-app-gateway ──► autotrade-broker-kiwoom ─┐
                       └─► autotrade-broker-kis ────┤──► autotrade-broker-api ──► autotrade-marketdata ──► domain
   autotrade-broker-toss (폴링, 게이트웨이는 안 씀) ─┘
```

- **공통 엔진 하나, 프로토콜만 증권사별.** `StreamingMarketDataSource`(marketdata.live)가 접속, 로그인 대기, 구독 등록, 재연결(1초부터 두 배씩 최대 30초), 무응답 감시, 끊긴 구간 표시를 맡는다. 플러그인은 `StreamProtocol`(엔드포인트, 열기 메시지, 구독·해지 메시지, 해석)만 구현한다. 토스 WebSocket을 붙이게 되면 `TossStreamProtocol` 하나와 플러그인 능력 선언만 추가하면 된다(BRK-06).
- **`LiveMarketDataSource`** = `MarketDataSource` + `start()`, `state()`, 상태 알림, `close()`. 상태는 `NEW → CONNECTING → CONNECTED ⇄ DISCONNECTED → CLOSED`.
- **플러그인 상태(BRK-02)**는 `BrokerStatuses.fromConnection`으로 연결 상태에서 정한다. 키 없음 NOT_CONFIGURED, 연결 전·재접속 시도 중 CONFIGURED, 연결됨 ACTIVE, 끊김 DEGRADED.
- **능력 선언(BRK-03)**: 키움·한투는 `REALTIME_QUOTE`만, 토스는 `POLLING_QUOTE`만 선언한다. 세 플러그인 모두 `orderGateway`는 항상 빈 값이고 주문 코드가 없다(MD-01). 플러그인끼리 참조하지 않는 것은 ArchUnit `증권사_플러그인끼리_참조하지_않는다`가 검사한다.
- **수신 스레드 분리.** 소켓 콜백은 해석까지만 하고 이벤트는 소스 전용 `SerialDispatcher`(크기 제한 큐)로 넘긴다. 큐가 차면 버리고 나중에 `CONSUMER_OVERFLOW` 공백을 남긴다. 느린 수신자가 소켓을 막지 않는다(broker-and-fault-design.md 5장).
- **토큰.** `TokenCache`가 만료 여유를 두고 재발급하고, 로그인 거절이면 버리고 재발급한다. 토큰 값은 `toString`에서 가리고 로그·예외 메시지에 넣지 않는다(안전 불변식 9).

| 항목 | 키움 | 한국투자 | 토스 |
|---|---|---|---|
| 방식 | WebSocket `wss://api.kiwoom.com:10000/api/dostk/websocket` | WebSocket `ws://ops.koreainvestment.com:21000/tryitout` | REST 폴링 `GET /api/v1/prices` |
| 인증 | 접근 토큰(`au10001`) → `LOGIN` 응답 대기 | 접속키(`/oauth2/Approval`, 24시간) → 구독 메시지 헤더 | 접근 토큰(client credentials) |
| 실시간 항목 | `0B` 체결, `0D` 호가 | `H0STCNT0` 체결, `H0STASP0` 호가 | 현재가 |
| 소스 한도 | 200종목 (그룹 등록 1회 100종목씩) | 20종목 (41건, 종목당 체결+호가 2건) | 호출당 200종목, 초당 15회 |
| 소스 이름 | `KIWOOM-WS` | `KIS-WS` | `TOSS-POLL` |

근거: [시세 사전 조사](../research/market-data-limits.md) 1장. 실시간 필드 번호와 메시지 형식은 각 플러그인 클래스 주석에 출처와 함께 적었다.

**토스 폴링 위치.** `TossPricePoller`는 `BrokerPlugin.pollingQuotes()`로 노출하지만 게이트웨이는 쓰지 않는다. D-008·D-024의 "보유 종목 보호 폴링"은 실시간이 모두 끊겼을 때 실전 엔진이 손절 감시에 쓰는 경로이고, 그 연결은 7단계 risk-ops 작업이다. 폴러는 GCRA(최소 간격 150ms, 연속 4회)로 초당 15회 한도 아래에 머물고, 429면 `Retry-After`까지 막고, 401이면 토큰을 버린다.

### 2.2 소스 배분, 장애 전환, 공백 표시 (MD-03·04·05)

`SourcePlanner`는 순수 함수다. `market-data.priority` 순서에서 쓸 수 있는(실시간 능력 있음, DEGRADED 아님, 끊긴 뒤 아직 재연결 안 됨이 아님) 소스를 고른다.

1. AUTO는 쓸 수 있는 소스가 둘 이상이면 SHARDED, 하나면 FAILOVER(D-009). SHARDED를 지정해도 하나뿐이면 FAILOVER로 돈다. 세 곳 SHARDED는 D-009 범위 밖이라 앞의 두 곳만 쓴다.
2. 종목 순서는 보유 먼저, 그다음 후보 순서. 1순위 소스 한도까지 채우고 남으면 2순위로.
3. 한도를 넘는 후보는 뒤에서부터 뺀다. **보유 종목은 빼지 않는다.** 활성 소스가 차면 FAILOVER라도 쓸 수 있는 다음 소스로 넘긴다. 그래도 받을 곳이 없는 보유 종목은 `unservedHeld`로 ERROR 로그를 남긴다(알림 연결은 7단계).

`MarketHub`(시장마다 하나)는 소스 상태가 바뀌면 그 자리에서 다시 배분한다. 옮기는 순서는 (1) 빠지거나 다른 소스로 가는 종목을 먼저 빼고 (2) 새로 맡는 종목을 더한다. 같은 종목이 두 소스에서 동시에 녹화되지 않고, 새 구독이 증권사 한도를 넘지 않는다. 소스가 바뀐 종목마다 `DataGap(SOURCE_SWITCH)`를 녹화한다. 시작은 옛 소스에서 마지막으로 메시지를 받은 시각이라, 무응답으로 늦게 알아챈 구간도 공백에 들어간다. 받을 소스를 잃은 종목은 구독이 닫혀 소스가 재연결 때 내는 공백을 받을 곳이 없으므로, 게이트웨이가 잃은 시각을 기억했다가 다시 배정될 때(또는 종료 때) 공백을 남긴다.

끊긴 소스는 다시 CONNECTED가 될 때까지 쓰지 않는다. 기동 직후 첫 접속 실패도 끊김으로 알린다. 상태 알림은 여러 스레드에서 오므로 허브는 알림의 값 대신 소스의 현재 상태를 다시 읽는다. 재접속 시도(CONNECTING) 중에 종목을 되돌리면 아직 못 받는 소스로 옮기는 셈이라서다. 다시 연결되면 우선순위 배분으로 돌아간다.

**공백 표시(`DataGap`, 도메인 `MarketEvent`에 추가).** 원인은 4가지다.

| 원인 | 누가 남기나 | 구간 |
|---|---|---|
| `DISCONNECTED` | 실시간 소스, 재로그인 후 종목마다 | 마지막 수신 시각 ~ 재연결 시각 |
| `CONSUMER_OVERFLOW` | 실시간 소스, 디스패처 큐가 찼을 때 | 처음 버린 시각 ~ 다시 받은 시각 |
| `RECORDER_OVERFLOW` | 녹화기, 쓰기 큐가 찼을 때 | 처음 버린 시각 ~ 다시 받은 시각 |
| `SOURCE_SWITCH` | 게이트웨이, 소스를 옮긴 종목마다 | 옛 소스에서 마지막으로 받은 시각(`lastReceivedAt`, 끊김이 원인일 때) 또는 옮긴 시각 ~ 옮긴 시각 |
| `DISCONNECTED`(게이트웨이) | 게이트웨이, 받을 소스를 잃었던 종목(전 소스 장애, 한도 밖) | 옛 소스에서 마지막으로 받은 시각 ~ 다시 배정된 시각, 끝까지 없으면 게이트웨이 종료 시각 |

**MD-03 "3초 내 전환".** [추론] 끊김을 알아챈 뒤 재배분까지는 같은 호출 안에서 끝나므로 지연이 없다. 남는 시간은 끊김을 알아채는 시간이다. 소켓이 닫히면 바로 알고, 조용히 멈춘 경우는 무응답 판단 시간(키움·한투 90초)이 걸린다. 장중에 90초 무수신은 정상일 수도 있어(거래 없는 종목만 구독) 이 값을 줄이려면 PING 주기 확인이 먼저다(5장). TST-01 #1(한쪽 차단 시 3초 내 전환)은 소켓 종료 기준으로 만족하고, 무응답 감지는 7단계 장애 테스트에서 값을 정한다.

**감시 종목.** 2단계는 설정 폴더의 `watchlist.json`을 기동 때 읽는다. `{"held":["KRX:005930"],"candidates":["KRX:000660"]}`. 보유 종목을 실전 엔진에서, 후보를 장전 후보 풀(STR-08 Stage 0)에서 받는 연결은 3·7단계 작업이다.

### 2.3 녹화 형식과 순번 (MD-05)

- 경로: `<녹화 폴더>/<MARKET>/<yyyy-MM-dd>/events.jsonl.gz` + `meta.json`. 날짜는 **수신 시각의 거래소 현지 날짜**다.
- 한 줄에 이벤트 하나(JSON). 키: `seq`(그날 녹화 순번, 1부터 빈틈 없이), `src`(소스 이름), `srcSeq`(소스 순번), `t`(TRADE·BOOK·STATUS·GAP), `sym`, `ex`(거래소 시각), `rx`(수신 시각), 종류별 값. 가격은 문자열 소수(`BigDecimal`), 형식 버전은 `meta.json`의 `formatVersion`(현재 1).
- **순번은 녹화기가 매긴다.** 여러 소스에서 들어오는 이벤트를 쓰기 스레드 하나가 큐 순서대로 받으며 `seq`를 붙인다. 리플레이는 이 `seq` 순서 그대로 재생하므로 같은 파일이면 같은 순서다.
- **중단 후 이어 쓰기.** 같은 날 다시 기동하면 기존 파일에서 온전한 줄만 읽어 닫힌 gzip 묶음으로 다시 쓰고 그 뒤에 이어 쓴다. 비정상 종료로 꼬리가 깨진 파일도 이어 쓸 수 있고, `seq`는 이어서 매기고 `meta.json`의 `segments`가 하나 늘어난다.
- `meta.json`: 시장, 날짜, 시간대, 소스별 범위, 이용 조건 메모, 구간 수, 마지막 순번, 이벤트 수, 공백 수, 녹화기가 버린 수, 정상 종료 여부, 정상 종료 시 파일 SHA-256. 메타는 임시 파일에 쓰고 원자적으로 바꾼다.
- 녹화기는 수신 스레드를 막지 않는다. 큐가 차면 버리고 `RECORDER_OVERFLOW` 공백을 남긴다. 1초마다 flush.
- 녹화 데이터는 저장소에 커밋하지 않는다(4장 이용 조건).

### 2.4 리플레이 (MD-06)

- `RecordedDay.open(dir)`은 정상 종료 파일이면 SHA-256을 확인하고, `seq`가 1부터 빈틈 없는지 검사한다. 정상 종료가 아니면 깨진 꼬리만 버리고 연다.
- `RecordedReplaySource`는 `MarketDataSource`를 구현한다. 구독 후 `replay()`가 호출 스레드에서 `seq` 순서로 동기 재생한다. 시계는 사용하지 않는다(재생 속도 조절은 3단계 실험 실행기 몫).
- **완료 기준 테스트**: `RecordingReplayTest`가 녹화기로 하루치를 기록하고, 같은 녹화일을 두 번 리플레이해 이벤트 순서와 값이 완전히 같음을 확인한다. 중단 후 이어 쓰기, 깨진 꼬리, 공백 기록, 종목 필터도 같이 검사한다.

### 2.5 거래소 캘린더와 시장 규칙 (MD-08)

- `ExchangeCalendar.bundled(KRX|US)`: 리소스 JSON(`calendar/krx.json`, `calendar/us.json`)에서 휴장일, 특수 개장(지연 개장, 조기 폐장)을 읽는다. 범위 밖 날짜는 `CalendarCoverageException`으로 거절한다(조용히 평일로 보지 않음).
- 범위: KRX 2026년, 미국 2026~2028년(NYSE 공식 휴장·조기 폐장표).
- 항목마다 출처를 남기고, 원문으로 확인 못 한 날은 `verified:false`로 둔다. `unverifiedDates()`로 꺼낼 수 있다.
- `KrxMarketRules`, `UsMarketRules`가 도메인 `MarketRules`를 구현한다. 정규장 판단은 캘린더 기준, 호가 단위는 아래 표.

| 시장 | 호가 단위 | 근거 |
|---|---|---|
| KRX 주식 | 2천 원 미만 1, 5천 미만 5, 2만 미만 10, 5만 미만 50, 20만 미만 100, 50만 미만 500, 그 이상 1,000 | KRX 유가증권·코스닥 업무규정(2023-01-25 개편) |
| KRX ETF·ETN | 5원 | 같은 규정 |
| 미국 | 1달러 이상 0.01, 미만 0.0001 | SEC Rule 612 |

### 2.6 일봉 스냅샷과 품질 검사 (MD-07·09)

- D-019대로 과거 일봉은 Python 수집기가 **버전 스냅샷 파일**로 넘긴다. 2단계는 Java 쪽 읽기와 검사만 만든다(수집기는 Q-007 이후).
- 스냅샷 폴더: `manifest.json`(스키마 1, 스냅샷 ID, 기준일, 출처·라이선스·수집 시각, 파일별 SHA-256·행 수), `daily_bars.csv`(원시 OHLCV + 수정 계수), `instrument_history.csv`(종목 기간: 이름, 종류, 소속부, 상장일, 폐지일).
- `SnapshotDailyBarSource.load`가 해시·행 수를 확인한다. **그날의 유니버스는 그날 상장돼 있던 종목**이다(상장폐지 포함, 생존편향 제거). 소속부 이력도 기간으로 들어 있어 Q-012 형식을 정한다(데이터 채우기는 수집기 작업).
- 품질 규칙. 오류 행은 읽을 때 뺀다.

| 규칙 | 수준 | 내용 |
|---|---|---|
| NON_POSITIVE_PRICE | 오류 | 0원 이하 가격 |
| OHLC_INCONSISTENT | 오류 | 고가 < 저가, 시가·종가가 고저 밖 |

## 4. 위험과 한계

- **한국투자 실시간은 평문 `ws://`다.** [사실] 공식 샘플의 실전 주소가 `ws://ops.koreainvestment.com:21000`이다. 접속키가 평문으로 나간다. 접속키는 시세 전용이고 24시간 뒤 만료되지만, 공용 와이파이에서는 쓰지 않는 것을 운영 수칙으로 둔다. 주문 경로(REST, HTTPS)와는 별개다.
- **토스 토큰은 클라이언트당 하나만 유효하다** `[사실]`(시세 사전 조사 T1). 실전 엔진(주문)과 다른 프로세스가 같은 키로 토큰을 받으면 먼저 받은 쪽이 끊긴다. 2단계는 게이트웨이에서 토스를 쓰지 않아 충돌이 없다. 7단계에서 토스 토큰 보유 프로세스를 하나로 정해야 한다(risk-ops).
- **증권사 키 공유(키움·한국투자).** [사실] 게이트웨이는 `brokers.kiwoom`·`brokers.kis` 키로 토큰을 받는데, 설정 구조상 같은 증권사 실전 계좌도 이 키를 쓴다(`RuntimeConfig.Brokers`). [추론] 7단계에서 같은 키로 실전 계좌를 켜면 게이트웨이의 토큰 재발급이 실전 엔진의 토큰·세션을 밀어낼 수 있다(키움은 토큰당 세션 1개). D-024는 실전 계좌의 키·토큰을 엔진 전용으로 두고, 키움 별도 토큰은 서로 무효화하지 않는다는 실측 뒤에만 허용한다. 그래서 **계좌번호까지 설정된 실전 계좌가 있는 증권사는 게이트웨이가 실시간을 띄우지 않고 경고만 남긴다**(`GatewayMain.reservedForRealTrading`, 테스트 있음). 실측(Q-015)으로 안전이 확인되면 이 규칙을 풀지 정한다(risk-ops 검토).
- **실제 서버로 검증하지 못했다.** 프로토콜은 공식 명세·샘플 기준이고, 테스트는 가짜 전송 계층이다. 필드 번호나 부호 처리가 다르면 첫 접속에서 해석 오류가 난다. 해석 실패 메시지는 버리고 경고 로그(본문 제외)와 `stats().malformed`만 남기므로 연결과 프로세스는 멈추지 않는다.
- **무응답 감지 90초.** 조용한 끊김은 MD-03 3초 기준보다 늦게 잡힌다(2.2).
- **KRX 2026 휴장일 일부는 2차 자료다.** KRX 공지 원문을 못 받아 언론 보도로 채운 날은 `verified:false`다. 2026-11-19 수능일 개장 시각(10:00 가정)도 미확인이다.
- **캘린더 범위.** KRX는 2026년만 있다. 2027년 1월 1일 전에 추가하지 않으면 그날부터 캘린더 조회가 예외로 실패한다(조용히 틀리지 않고 멈춘다).
- **녹화 데이터 이용 조건.** 증권사 시세는 개인 연구용으로만 저장하고 재배포하지 않는다. 녹화 폴더는 저장소 밖(설정 폴더 아래)에 둔다.
- **녹화기 큐 10만 건.** [추론] 키움 200종목 × 초당 수십 건을 몇 초 버틴다. 디스크가 막히면 버리고 공백을 남긴다. 실전 엔진에는 영향이 없다(별도 프로세스).

## 6. 다른 역할에 대한 변경 제안

계약 변경은 이 PR에 함께 넣었다(코드가 그 계약을 쓰므로). 설정 키는 아직 추가하지 않고 제안만 한다.

**이 PR에 포함한 계약 변경 (architect 검토)**
- domain: `MarketEvent`에 `DataGap` 추가.
- marketdata: `LiveMarketDataSource`, `ConnectionState`, `SourceStateListener`, 패키지 `live`·`recording`·`calendar`·`rules`·`daily`·`polling`.
- broker-api: `BrokerCredentials`, `BrokerStatuses`, `BrokerPlugin.pollingQuotes()`(기본 빈 값, 기존 구현 영향 없음).
- 새 모듈 `autotrade-broker-{kiwoom,kis,toss}`, ArchUnit 규칙 `증권사_플러그인끼리_참조하지_않는다`.

| 키 | 형식 | 기본값 | 실시간 변경 | 설명 |
|---|---|---|---|---|

**risk-ops 7단계 요구 사항(검토 결과)**
- 토스 토큰은 실전 엔진 한 프로세스만 받고 이를 설정 검사나 테스트로 강제한다. 401 뒤 재발급에 속도 제한·백오프를 두고 되풀이되면 DEGRADED. 보호 폴링과 주문은 같은 토큰 캐시를 쓴다.
- 계좌 정보가 담긴 실시간 데이터(체결 통보)는 평문 `ws://`로 받지 않는다.
- `pollingQuotes()`를 실전 엔진에 연결하는 PR은 실전 관련으로 분류해 사용자가 머지한다.
- 키움·한국투자 키 공유: 계좌번호가 설정된 실전 계좌의 증권사는 게이트웨이가 쓰지 않는다(이 PR에 구현). 풀려면 Q-015 실측과 risk-ops 검토가 먼저다.
- 7단계 전 필수(검토 R4~R8): 보호 시세 경로가 토스 폴링 하나뿐인 문제(키움·한투 폴링 추가), `PollingQuoteSource` 계약에 `priceTime`으로 오래된 가격 판정과 레이트리밋 시 앞선 결과 폐기를 명시, 캘린더 범위 밖 예외가 손절을 막지 않게 처리하고 범위 끝나기 전 경보, 한국투자 평문 접속키로 체결 통보까지 구독할 수 있는지 확인, 플러그인이 주문 출구를 직접 만드는 우회 차단 ArchUnit 규칙을 플러그인 주문 코드 첫 PR보다 먼저.

**risk-ops 확인 요청(이 PR)**
- 4장 토스 토큰 단일 보유 문제와 7단계 토스 토큰 소유 프로세스.
- 보유 종목을 받을 실시간 소스가 없을 때(`unservedHeld`) 알림 수준.
