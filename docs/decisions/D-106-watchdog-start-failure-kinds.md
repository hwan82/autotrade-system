# D-106 감시 기동 실패를 설정 오류와 프로그램 오류로 나눠 표시(PR #144 독립 QA R1)

- 날짜: 2026-10-17
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 감시 프로세스(`autotrade-app-watchdog`, 보호 경로)의 기동 실패 표시와 종료 코드만 바꾼다. 감시 설정 검사 규칙(D-092·PR #115 risk-ops K2), 기동 거부 조건(D-095 4번), 알림 채널 구성(D-100·D-103), RealTradingGuard·주문 경로는 바꾸지 않는다. 보호 경로라 사용자 머지로 확정한다.
- 담당: risk-ops 결정·구현. 교차 검토: architect(코드), risk-ops(실전 관련)
- 근거: [PR #144 독립 QA](../reviews/pr-144/qa.md) R1, [D-092](D-092-watchdog-heartbeat-and-stop-requests.md), [D-103](D-103-settings-notification-test-send.md) 2026-10-17 반영 기록(채널 이름 코드 실수는 기동 예외)

## 문제

`WatchdogMain.main`은 기동 중 `IllegalArgumentException`을 모두 "감시 설정이 틀려 기동하지 않습니다"로 표시하고 종료 코드 2로 끝냈다. PR #144부터 알림 채널 이름이 어긋나는 코드 실수도 `IllegalArgumentException`으로 이 catch에 들어온다. 메시지 뒤에 실제 원인이 붙어 숨지는 않지만, 운영자는 첫머리 문구를 보고 `watchdog.properties`부터 고치려 든다(수집기 runbook 3.5가 이 문구로 찾게 한다). 감시가 뜨지 않는 동안은 하트비트·드라이브·자원 감시가 모두 없으므로 원인을 바로 짚는 것이 중요하다. 또 `IllegalArgumentException`이 아닌 기동 예외(감시 객체 생성·시작 실패)는 잡히지 않아 JVM 기본 스택 출력으로만 끝났다.

## 결정

1. **거부 종류를 따로 둔다**: 사람이 PC·설정을 고쳐야 하는 기동 거부만 `WatchdogRefusal`(패키지 전용, `IllegalArgumentException`을 이음)로 던진다. 감시 설정 파일을 못 읽음·값이 틀림(`WatchdogSettings`)은 첫머리 "감시 설정이 틀려 기동하지 않습니다"(예전 문구 그대로), 이 JVM이 PC CPU·메모리를 못 줌(D-095 4번)은 "이 JVM에서는 감시가 기동하지 않습니다". 둘 다 종료 코드 **2** 그대로다.
2. **나머지는 프로그램 오류**: `WatchdogRefusal`이 아닌 `RuntimeException`(알림 채널 이름 검사 실패 같은 `IllegalArgumentException` 포함)은 "감시가 기동 중 프로그램 오류로 멈췄습니다(설정 파일 문제가 아닙니다. 로그의 예외를 개발 쪽에 알려 주세요)"로 표시하고 종료 코드 **1**(`EXIT_START_FAILED`)로 끝낸다. 로그(ERROR)에는 예외 흐름도 남긴다. (2026-10-18 문구를 괄호 없이 바꿈, 아래 후속 반영) 1은 JVM이 처리되지 않은 예외로 끝낼 때와 같은 값이라 예약 작업·스크립트가 보던 "0이 아니면 실패"는 그대로다.
3. 두 경우 모두 표준 오류 한 줄에 "(감시 없이 실전·실험을 돌리지 마세요)"와 실제 원인(프로그램 오류면 예외 종류와 메시지)을 남긴다. 판정은 `WatchdogMain.StartFailure.of`, 출력은 `report`가 한다.
4. **설정 폴더 경로도 설정 오류**(2026-10-17, PR #148 architect N1·risk-ops R1 반영): `autotrade.config-dir`·`AUTOTRADE_CONFIG_DIR` 값이 경로 형식이 아니면(예: Windows에서 따옴표를 넣음) "설정 폴더 경로가 틀렸습니다"로 `WatchdogRefusal`(종료 코드 2)이다. 진입점 절차는 `WatchdogMain.launch`로 빼서 시험이 종료 코드를 직접 본다(risk-ops R2 변이 M4·M6).
5. 기동 점검(`WatchdogMain.run`)은 `WatchdogRefusal`만 종료 코드 2로 바꾸고, 그 밖의 예외는 그대로 던진다(시험에서 코드 실수가 설정 오류로 바뀌지 않게).

## 대안

| 대안 | 판단 |
|---|---|
| A. 거부 전용 예외 종류로 나눔(채택) | 설정 검사·JVM 검사가 던지는 곳에서 종류가 정해져, 다른 곳의 `IllegalArgumentException`이 설정 오류로 섞일 수 없다. 기존 문구·종료 코드 2와 CI 단계(틀린 감시 설정 → 2)를 그대로 둔다 |
| B. `startNotifications` 호출만 try로 감싸 따로 표시 | 알림 쪽만 고치고 감시 객체 생성·시작 등 다른 코드 실수는 여전히 섞이거나 스택만 남는다. 다음에 기동 단계를 더할 때마다 같은 실수를 반복하기 쉽다. 버림 |
| C. 문구만 "감시 설정 또는 프로그램 오류로 기동하지 않습니다"로 바꿈 | 가장 작지만 운영자가 무엇부터 볼지 여전히 고를 수 없고, runbook 검색 문구가 바뀐다. 버림 |
| D. 프로그램 오류에 새 종료 코드 3 | 예약 작업이 코드별로 나눠 보지 않고, 3은 다른 일괄 명령에서 "잠금 못 잡음" 뜻으로 쓴다(ADR-007). JVM 기본과 같은 1이 덜 헷갈린다. 버림 |

되돌릴 조건: 감시를 자동 재기동하는 체계(D-092 범위 밖)가 생겨 종료 코드로 재시도 여부를 고르게 되면, 설정 오류(재시도 무의미)와 프로그램 오류의 코드 구분을 그 체계 기준으로 다시 정한다.

## 위험과 한계

- 기동 거부 조건을 새로 더하는 사람이 `WatchdogRefusal` 대신 `IllegalArgumentException`을 던지면 프로그램 오류(종료 코드 1)로 보인다. 기동은 똑같이 막히므로 보호가 약해지지는 않고, 문구만 덜 정확하다. 클래스 설명에 규칙을 적었다.
- 기동 중 폴더 쓰기 권한 같은 I/O 실패(`UncheckedIOException` 등)는 사람이 고칠 환경 문제여도 프로그램 오류(종료 코드 1)로 표시된다(architect N1 예 2). 원인 줄에 예외 종류와 경로가 보이고 감시가 뜨지 않는 것은 같아 보호는 약해지지 않는다. 자주 보이면 그 예외를 거부 종류로 옮긴다.
- 엔진 쪽 같은 문제(`EngineMain.main`은 `IOException`만 잡아 알림 코드 실수가 JVM 기본 스택으로 끝남, PR #144 QA R2)는 이 결정 범위 밖이다. 원인 문구는 그대로 보여 막지 않는다.

## 검증

- 시험(`WatchdogMainTest`): `#감시_설정이_틀리면_기동을_거부한다`(거부 종류·종료 코드 2·runbook 문구), `#설정_파일을_못_읽어도_설정_오류로_거부한다`, `#PC_CPU_메모리를_줄_수_없는_JVM이면_기동을_거부한다`(JVM 문구), `#알림_채널_코드_실수_같은_예외는_설정_오류로_표시하지_않는다`(종료 코드 1, 첫머리에 "설정이 틀려" 없음), `#그_밖의_기동_예외도_프로그램_오류로_종료_코드_1이다`, `#기동_실패는_표준_오류에_첫머리_문구와_원인을_한_줄로_남긴다`, `#진입점은_설정_오류면_종료_코드_2로_끝내고_감시를_돌려주지_않는다`, `#진입점은_설정_폴더_경로가_틀리면_설정_오류로_거부한다`, `#진입점은_설정_오류가_아닌_기동_예외를_종료_코드_1로_끝낸다`, `#기동_점검은_설정_오류가_아닌_예외를_종료_코드로_바꾸지_않고_던진다`. 프로그램 오류 로그에 예외 흐름을 남기는지(risk-ops R2 변이 M7)는 시험하지 않는다(로그 처리기 교체가 필요하고 표준 오류 한 줄에 원인이 남는다).
- 함께 고친 것: `:autotrade-notification-jar:javadoc`이 main에서도 실패하던 문제(`NotificationSetup.ExternalChannel` 레코드 설명의 `@throws`, javadoc "invalid use of @throws")를 압축 생성자 설명으로 옮겨 고쳤다. 동작은 바뀌지 않는다.

## 후속 반영(2026-10-18, PR #166·D-110, PR #165 검토 권고)

판정·종료 코드는 그대로다. 2번 프로그램 오류 첫머리를 괄호 없이 "감시가 기동 중 프로그램 오류로 멈췄습니다. 설정 파일 문제가 아닙니다. 로그의 예외를 개발 쪽에 알려 주세요"로 바꿨다. 표준 오류 줄이 첫머리 뒤에 "(감시 없이 실전·실험을 돌리지 마세요)"를 붙여서 예전에는 `)(`가 생겼다(실전 엔진은 열린 PR #165가 D-107 후속 R1로 같은 정리를 한다). runbook이 기대는 낱말 "프로그램 오류"는 그대로 첫머리에 있다. `WatchdogMainTest#진입점은_기동_실패를_표준_오류에_알리고_프로그램_오류면_로그에_예외_흐름을_남긴다`가 표준 오류 줄에 `)(`가 없는지 본다.
