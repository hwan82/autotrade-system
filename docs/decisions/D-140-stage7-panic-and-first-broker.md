## 결정

| # | 질문 | 결정 |
|---|---|---|
| ① | Q-016 재기동 직후 보유가 남은 OFF 계좌의 PANIC SELL | PANIC 2차 확인을 보호 모드 진입 확인으로도 보고 OFF → PROTECTIVE로 올린 뒤 매도한다. 조건: 매도 전 보유 대사를 먼저 하고, 전체 PANIC에서 OFF 계좌를 올리는 것은 계좌마다 확인을 받으며, **2차 확인을 통과해 PROTECTIVE로 올린 뒤** 대사·취소·매도 단계가 실패하면 PROTECTIVE에 남긴다(OFF로 되돌리지 않음). 2차 확인이 실패·잠김·비밀번호 미설정이면 OFF 계좌는 **OFF 그대로** 둔다(PANIC 1단계 보호 모드 고정은 OPEN·ACTIVATING 계좌에만 해당, 확인 없이 주문 세션을 여는 상향 금지). 합격 시험: 확인 실패 PANIC에서 OFF 계좌는 OFF, 주문 세션 허가 발급 0건(risk-ops 조건) |
| ② | Q-017 장 외 시간 PANIC SELL 때 Guard | 끄지 않는다. 보호 모드 유지(미체결 매수만 취소, 서버 측 손절 유지). 기획서 v13 RSK-13의 "장 외 시간에는 미체결 취소와 Guard OFF만" 문구를 이 결정으로 대체한다 |
| ③ | Q-018 "엔진 실행 중 run 폴더 삭제" 장애 테스트 | 장애 테스트 3번의 하위 항목 **3-R**로 넣어 실전 활성화 전 합격 조건으로 둔다. "장애 테스트 8종"이라는 수는 그대로다. 합격(모두 만족, risk-ops 조건): 두 번째 엔진 기동 거부. OS 한계로 거부하지 못하면 첫 엔진이 잠금·소켓 변경을 감지해 긴급 알림을 내고 두 번째 엔진은 어떤 계좌에도 주문 세션 허가를 받지 못하며 증권사 토큰·접속키를 발급하지 않음. 이 분기에서는 또 화면의 내리기·PANIC이 OPEN·PROTECTIVE 계좌를 가진 첫 엔진에 닿아 실제로 내려가거나, 닿지 못하면 두 번째 엔진이 명령·상태에 응답하지 않고 화면이 "실전 상태 확인 불가"를 표시함(독립 QA PR #235 발견 1). 어느 경우든 화면이 첫 엔진의 OPEN 계좌를 OFF로 보이지 않고, 중복 주문 0건, 화면이 "가상"으로 바뀌지 않음, 두 번째 엔진으로 인한 증권사(한국투자 포함) 토큰 무효화·재발급 없음(첫 엔진의 정상 선제 갱신은 해당 없음). 운영 PC OS(Windows 포함)에서 반드시 시행 |
| ④ | Q-057 PANIC에서 VI 발동 종목 | **매도 가능**으로 본다. ⑤ 체결 확인 상한에 VI 단일가 시간(2분 + 최대 30초 `[가정]`)을 더하고, 상한 안에 체결되지 않으면 남은 보유에 서버 측 손절을 다시 건다. 거래정지·서킷브레이커·장 외 시간·상태 불명은 매도 불가. 늘어난 체결 확인 상한이 매도 가능 판정 마감 시각(청산 외 주문 금지 구간 전 여유, 일괄 취소 전 서버 측 손절 재설정 시간 포함)을 넘는 VI 종목은 그 실행에서 매도 불가로 본다(risk-ops 조건). 판정 때 VI가 아니었어도 ④ 매도 제출 뒤 체결 확인 상한 안에 VI가 걸리면 그 종목 상한도 같은 만큼 늘린다(마감 시각 규칙은 그대로, 독립 QA 권고 Q1). 계좌 안 일부 종목만 매도 불가면 **그 종목만 건너뛰고**(②의 매도 취소와 ③은 매도 가능 종목에만), 건너뛴 종목이 있으면 Guard OFF는 없다 |
| ⑤ | Q-058 RSK-11 일괄 취소와 서버 측 손절 | 일괄 취소 대상에 서버 측 손절 조건주문을 **넣지 않는다**. 일괄 취소는 엔진이 낸 미체결 일반 주문만 취소한다. PANIC의 서버 측 손절 재설정은 일괄 취소 시각 전에 끝내고, 일괄 취소가 방금 건 손절을 지우지 않음을 시험으로 고정한다 |
| ⑥ | Q-061 첫 실전 증권사 | **한국투자**. 게이트웨이 시세 1순위인 키움(D-024)을 그대로 두고, 모의 도메인으로 장애 테스트를 한다. 키움·토스 실전 계좌는 게이트웨이 시세 소스 문제(7단계 준비 계획 4.1 Q-061, `GatewayMain.reservedForRealTrading`)를 푼 뒤 붙인다 |

## 대안과 버린 이유
- 각 질문의 대안과 추천 이유는 [7단계 준비 계획](../team/stage-7-readiness-plan.md) 4.1장에 있다. 요약: ① 대안(건너뛰고 보호 모드 진입을 먼저 요구)은 재기동 직후 청산이 늦어 버림. ② 대안(Guard OFF)은 개장 직후 갭 하락 때 엔진 손절이 돌지 않아 버림. ③ 대안(9번째 시험, 넣지 않음)은 "8종"을 가리키는 문서 수정 부담·실전 위험 미검증 때문에 버림. ④ 대안(매도 불가, 해제 뒤 자동 진행)은 급락 중 청산이 막히거나 시험이 많아 버림. ⑤ 대안(매일 지우고 재설정)은 매일 방어선 공백과 재설정 실패 지점이 생겨 버림. ⑥ 키움은 게이트웨이 시세가 한국투자(appkey당 41건)로 넘어가 감시 종목을 줄여야 하고, 토스는 모의 환경이 없고 선행 조건이 많아 버림.

## 되돌릴 조건
- ④: 한국거래소 규정 원문이나 한국투자 공지가 "VI 중 매도 호가 접수 불가" 또는 다른 단일가 시간을 말하면 새 결정으로 다시 연다(지금 근거는 증권사 안내 2차 자료).
- ⑤: 한국투자 조건주문의 유효 기간이 하루뿐이면 매일 재설정 규칙(S4)이 필요하며, 그 경우에도 일괄 취소가 손절을 지우지 않는다는 원칙은 유지한다. 원칙을 바꾸려면 새 결정.
- ⑥: 한국투자가 서버 측 손절을 지원하지 않으면(Q-002) 실전 활성화 화면에 "PC 장애 시 보호 수단 없음" 경고(broker-and-fault-design.md 6.1)를 띄우고, 사용자에게 첫 증권사 유지 여부를 다시 묻는다.

## 후속
- 기획서 RSK-13(①·②·④·⑤ 반영), RSK-11(⑤ 일괄 취소 대상 정의), TST-01(③ 3-R), 15장 Q-017 문구는 pm-lead가 `autotrade-spec-keeper`로 다음 기획서 변경 때, 늦어도 묶음 A·E 구현 시작 전에 반영한다. 그 전까지 구현 지시에는 "D-140을 따른다"고 적는다.
- ADR-006 2.5("매도를 낼 수 없을 때"의 VI 예시, OFF 계좌 2~6단계 건너뜀), 4장 위험 표, 7장 Q-016·Q-017과 `PanicLiquidator` 계약 주석의 VI 문구는 묶음 E 첫 PR 전에 이 결정에 맞춘다(architect·risk-ops, 독립 QA 권고 Q5).
- 묶음 A의 C6(소켓·잠금 자가 확인)은 지워진 소켓을 다시 만들어 화면 명령이 첫 엔진에 닿는 쪽을 기본으로 구현한다. 절차서(I1)에는 3-R에서 명령이 첫 엔진에 닿지 못할 때 사용자가 할 조치(감시 킬스위치 또는 엔진 프로세스 종료)와 그 조치가 실제로 듣는지 확인하는 단계를 넣는다(risk-ops 재검토 (2) 권고 1).
- 7단계 절차서(I1)는 시험마다 "모의 도메인으로 충분 / 실전 도메인 소액 필요"를 나눠 적는다. 한국투자 모의 도메인은 한도·지원 API가 실전과 다를 수 있다 `[추론]`(독립 QA 권고 Q6).
- [사실] 한국투자 실전 계좌를 설정하면 게이트웨이는 한국투자를 시세 소스에서 빼고(`GatewayMain.java:97-104`) 토스도 쓰지 않으므로(D-059) 게이트웨이 실시간 소스는 키움 하나가 된다. 장애 테스트 1번의 보유 종목 보호는 엔진 보호 폴링(계획 D10)으로만 합격할 수 있고, 실전 계좌 설정 시점은 LIVE01 기간과 조율한다(독립 QA 권고 Q2).
- ③은 [broker-and-fault-design.md](../team/broker-and-fault-design.md) 7장에 3-R로 반영했다(이 PR).
- 구현은 7단계 준비 계획 3장 묶음 A(C6·C15), E(P1~P8), D-H(한국투자 주문·잔고)에서 한다. 이 결정은 실전 활성화를 뜻하지 않는다. RealTradingGuard 기본 OFF는 그대로다.
