# D-146 실전 엔진 저장소 B1 구현: 원장 모듈, 쓰기 잠금, Guard 두 단계 올림

- 날짜: 2026-10-26
- 상태: 제안. 구현 선택은 **추천안 채택(자율, architect)**. 실전 주문 경로·RealTradingGuard·보호 테스트를 바꾸는 실전 관련 PR이라 architect·risk-ops 검토, 독립 QA 뒤 사용자 머지
- 근거: [ADR-015](../adr/ADR-015-real-engine-store.md) 2장·5장 시험 1·2·6·13·14·6장 B1 행, [D-141](D-141-real-engine-store.md), PR #239 검토 원문 [architect](../reviews/pr-239/architect.md)·[risk-ops](../reviews/pr-239/risk-ops.md)·[QA](../reviews/pr-239/qa.md)
- 선행: PR #239 머지(`c1972a03`, 2026-10-26). D-140 ① 범위는 그 머지로 "거부"로 확정됐다: (가) 전면 차단 조건에서는 OFF 계좌 PANIC의 보호 모드 상향도 거부한다
- 담당: architect(구현), risk-ops(검토)

## 결정

1. **새 모듈** `autotrade-real-store`(패키지 `com.autotrade.realstore`, 의존 risk·domain·Jackson). [사실] 외부 jar·JDK 허용 목록(D-086)은 늘리지 않았다. Jackson은 허용된 `ObjectMapper`·`JsonNode`·`ObjectNode`·`ArrayNode`만 쓰고(`TextNode`를 돌려주는 `ArrayNode.textNode`도 피함), 원장은 `java.nio`·`java.util.zip.CRC32C`·`java.util.concurrent`만 쓴다.
2. **원장 줄 형식**은 ADR-015 2.4 그대로: `{"v","stream","rseq","boot","at","type","body","crc"}` 고정 순서 한 줄, `crc`는 그 앞까지 바이트의 CRC32C. 날짜 파일의 첫 줄은 체크포인트(직전 파일 이름·마지막 `rseq`·마지막 `crc`). 계좌 감사 원장은 거래소 현지 거래일(`MarketRules.tradingDate`), 공통 명령 원장은 UTC 날짜로 나눈다.
3. **쓰기 스레드**는 계좌마다 하나, 공통 원장(기동·명령)에 하나. 쌓인 줄을 원장마다 `force(true)` 한 번으로 묶는다. 대기열 상한 계좌·공통 각 1,000줄 `[가정]`.
4. **복구 검사**(ADR-015 2.7 ③):
   - 마지막 줄만 잘렸으면 그 조각을 `.cut-<ms>` 파일로 옮기고 잘라 낸 뒤 이어 쓴다(그 계좌 메모에 남김).
   - 중간 줄 CRC 불일치·형식 오류·`rseq` 건너뜀·체크포인트가 직전 파일과 이어지지 않음은 **그 계좌 원장 손상**으로 (가) 전면 차단. 손상 원장은 지우지도 이어 쓰지도 않고 그 계좌에는 쓰기 스레드를 만들지 않는다(감사는 프로세스 로그만).
   - 블랙리스트 원장 손상, 큰 부팅 번호 뒤 작은 부팅 번호 기록(쓰기 주체 둘)은 **모든 계좌** (가) 전면 차단.
   - 기동 원장·명령 원장 손상은 막지 않는다. 손상 파일을 `.corrupt-<부팅>`으로 옮기고 새로 시작하며 경고만 낸다. 부팅 번호는 모든 원장의 `boot` 최댓값 + 1이라 기동 원장이 없어도 겹치지 않는다(시험 5 앞부분).
5. **(가) 전면 차단의 집행**은 Guard API를 바꾸지 않고 감사 어댑터(`StoreGuardAuditLog`)가 올림 감사를 거절하는 것으로 한다. 그래서 활성화 시작·OPEN·`enterProtective`·PANIC의 OFF → PROTECTIVE가 모두 "전이 미적용"으로 끝난다. 저장소가 열리기 전(엔진 기동 중)에도 올림은 모두 거절된다. 내림(킬스위치·비활성화·PANIC 1단계)은 언제나 된다.
6. **Guard 두 단계 올림**(ADR-015 2.5): ① 잠금 안 검사와 `raising` 표시, ② 잠금 밖 감사(상한 2초는 어댑터가 지킴), ③ 잠금 안에서 전이 번호가 그대로이고 끼어든 내림이 없을 때만 적용. 추가로 정한 것:
   - 올림 대기 중 같은 계좌에 내림 호출(`shutdown`·`deactivate`·`failActivation`·`holdingsCleared`)이 오면 **상태가 바뀌지 않는 호출이라도**(OFF 계좌의 킬스위치 등) 그 올림을 무효로 한다. 상태 비교만으로는 OFF 계좌에서 시작한 PANIC 상향 중 누른 킬스위치가 사라지기 때문이다(시험 중 발견).
   - 같은 계좌의 두 번째 올림은 앞 올림이 끝날 때까지 거절한다(risk-ops PR #239 N-1의 "진행 중인 올림 표시").
   - 적용하지 못한 올림은 `RaiseNotAppliedException`(이유 `AUDIT_NOT_RECORDED`·`LOWERED_FIRST`)으로 알리고, 내림이 먼저면 같은 원장에 "전이 미적용(내림이 먼저)" 보정 기록(from = to)을 남긴다. 명령 응답 문구도 둘을 구별한다(QA PR #239 Q5). 화면 표시는 묶음 H.
   - 2차 확인은 ①에서 소비하므로 적용되지 않으면 다시 받아야 한다(활성화 마지막 단계 실패는 활성화 실패로 OFF).
7. **쓰기 잠금** `engine-store/writer.lock`: `tryLock`, `NOFOLLOW_LINKS`, 내용 `boot=N pid=P`. 5초마다 내용과(POSIX에서는) `fileKey`를 확인해 지워졌거나 바뀌면 모든 계좌 (가) 전면 차단 + 긴급 알림 한 번. Windows는 `fileKey`가 없어 내용 대조가 기본이다(QA PR #239 Q2). 잠금 순서는 `engine.lock`(명령 채널) → `writer.lock`. 못 잡으면 기동 거부(종료 코드 1, "실전 엔진 저장소를 열지 못해 기동을 중단합니다").
8. **기동·종료 기록**: 기동 기록(부팅 번호, PID, 이전 종료 상태, 빈 `keyFloors` 자리)을 상한 2초 안에 못 쓰면 모든 계좌 (가) 전면 차단. 정상 종료 기록에 이번 부팅의 저장소 장애 계좌와 비우지 못한 대기열 건수를 싣는다. 쓰기 실패한 계좌에는 `degraded` 표시 파일을 만든다. 다음 기동은 표시·비정상 종료·종료 기록의 장애 계좌를 "기록이 빠졌을 수 있는 계좌"로 보고(전면 차단은 아님) 복구 결과 긴급 알림에 싣는다.
9. **비밀값 가리기**: 원장 기록 직전 문자열 칸에서 설정의 계좌번호·증권사 키·운영자 비밀번호 해시·알림 비밀값(4자 이상 `[가정]`)을 `[가림]`으로 바꾼다.
10. **엔진 배선**: `LoggingGuardAuditLog`를 지우고 `StoreGuardAuditLog`로 바꿨다. 명령 감사는 `StoreCommandAuditLog`가 기존 로그·알림 뒤에 공통 원장에도 남긴다. 저장소 알림은 새 알림 종류 `engine-store`(긴급)로 보낸다. 닫는 순서는 자가 확인 → 명령 처리기 → 명령 채널 → 저장소 → 하트비트 → 알림 큐.
11. **실측 도구**: `autotrade-engine store-probe`가 설정 폴더 디스크에서 원장 크기 줄의 강제 기록 시간을 200번 재어 중앙값·95%·99%·최대를 출력한다. [가정] 상한 값(올림 2초, 기동·종료 2초)은 운영 PC 실측 전이다. 실측은 7단계 절차서 2장 항목으로 둔다.
12. **보호 테스트 변경**(지침 11장): `ModuleOwnershipTest.OWNERS`에 `com.autotrade.realstore`, `RealPathReflectionTest`의 실전 경로 프로젝트·패키지에 이 모듈, `ArchitectureTest`에 규칙 2개(실전 엔진 밖은 저장소 의존 금지, 저장소는 `RealTradingGuard`·2차 확인에 의존 금지)와 위반 고정 예제 2개, 게이트웨이·감시·수집기·실험 명령의 `processIsolation` 금지 목록, `protected-paths.txt`·`CODEOWNERS`에 이 모듈. `RealTradingGuardTest`에 두 단계 올림 시험을 더했다. 지운 시험·약화한 단언은 없다. Guard 패키지 레코드 고정 목록(D-086)을 지키려고 대기 중 올림은 레코드가 아닌 클래스로 만들었다.

## 대안과 버린 이유

| 선택 | 대안 | 버린 이유 | 되돌릴 조건 |
|---|---|---|---|
| 차단을 감사 어댑터가 집행 | Guard에 "차단" API를 더함 | Guard 공개 API·불변식이 늘고 ADR-015 2.10(Guard 변경은 올림 감사 이동만)과 어긋남 | 차단 사유를 STATUS에 Guard 상태로 보여야 하면(묶음 H) Guard 밖 조회로 먼저 해 보고, 안 되면 다시 검토 |
| 내림 호출은 상태가 안 바뀌어도 올림을 무효로 | 상태가 바뀔 때만 무효 | OFF 계좌에서 PANIC 상향 감사를 기다리는 동안 누른 킬스위치가 무시되고 계좌가 PROTECTIVE로 올라감 | 없음(더 막는 쪽) |
| 저장소를 명령 채널 뒤에 엶 | 저장소를 먼저 엶 | ADR-015 잠금 순서(`engine.lock` → `writer.lock`)를 지키고, 두 번째 엔진이 저장소 잠금보다 명령 채널 잠금에서 먼저 막히게 함. 그 사이 올림은 모두 거절 | 감시 긴급 경로(묶음 F)가 저장소만 잡을 때 다시 봄 |
| 계좌 감사 원장 손상 = 그 계좌 전면 차단 | 감사 원장은 경고만 | ADR-015 2.7 (가) "계좌 원장 손상"에 감사 원장도 들어가며, 감사 이력을 믿을 수 없으면 쓰기 주체·일련번호도 믿을 수 없음 | B4에서 주문 원장이 따로 생기면 감사 원장 손상의 범위를 risk-ops와 다시 정함 |
| 기동·명령 원장 손상은 옮기고 경고 | 모든 계좌 차단 | 부팅 번호는 계좌 원장에서 다시 얻고 명령 감사는 Guard 감사와 겹치므로 막을 이유가 약함(ADR-015 시험 5) | 기동 기록 사본에만 있는 값이 생기면(B4 `keyFloor` 원본은 계좌 원장) 다시 봄 |

## 위험과 한계

- [가정] 상한 값과 `force(true)` 시간은 운영 PC(Windows) 실측 전이다. 99% 값이 상한의 절반을 넘으면 상한을 다시 정한다.
- [추론] Windows에서 잠긴 `writer.lock`을 지우거나 바꾸면 5초 안에 내용 대조로 감지한다고 보지만 운영 PC에서 확인하지 않았다(3-R 시행 때 확인).
- 복구 결과는 로그와 긴급 알림에만 나온다. STATUS·화면 표시는 묶음 H·B6.
- `key-floor`(B4), 블랙리스트 원장과 `blacklist/unrecorded`(B5), "기록이 빠졌을 수 있는 계좌"의 그날 신규 진입 차단(묶음 C·B4)은 이 PR에 없다. 지금은 주문 경로가 없어 실전 영향은 없다.
- 원장 자동 삭제는 없다(ADR-015 2.11). 디스크 여유는 감시가 본다.
- [추론] 기동 원장 중간이 깨지면 손상 줄 뒤의 부팅 번호는 그 원장에서 읽지 못한다. 부팅 번호는 계좌·명령 원장의 `boot`까지 보고 정하지만, 기동 기록만 남긴 부팅(그 부팅에 다른 기록이 없음)이 손상 뒤에 있으면 번호가 겹칠 수 있다. 지금은 키 발급이 없어 영향이 없고, B4에서 `key-floor`와 함께 다시 본다(PR #248 architect 권고 2).

## 검증

- `autotrade-real-store` 시험 28건: ADR-015 시험 1(원장에 OPEN이 있어도 재기동하면 OFF), 2(올림 상한 초과: 대기열 취소·보정 기록, 같은 계좌 내림은 즉시, 다른 계좌는 상한 안), 6(끝 잘린 줄, 중간 CRC, `rseq` 건너뜀, 체크포인트, 날짜 이어짐), 13(잠금 못 잡음, 두 쓰기 주체, 실행 중 잠금 내용 변경·삭제, 기동 기록 실패, 심볼릭 링크), 14(계좌번호 가리기), 기동 원장 손상, `degraded` 표시, 실측 도구.
- `RealTradingGuardTest`: 감사 실패 시 전이 미적용, 같은 계좌 내림이 올림 감사를 기다리지 않음과 그 올림 무효(종류별), OFF 출발 올림 중 킬스위치, 같은 상태로 되돌아온 경우(ABA), 두 올림 겹침 거절, 다른 계좌 킬스위치 지연 없음.
- 엔진 배선 시험 5건, `EventRoutesTest`, ArchUnit 규칙과 위반 고정 예제, `./gradlew build` 통과.
- 같은 묶음에서 뒤 줄 붙이기가 실패해 원장이 되돌려지면, 먼저 붙였던 같은 원장의 줄도 실패로 돌려준다(`LedgerWriterTest`, PR #248 architect 발견 1: 고치기 전에는 지워진 올림 감사가 "기록됨"으로 끝나 Guard가 올라갈 수 있었다).
- 운영 PC 실측과 Windows 잠금 파일 동작은 검증하지 못했다.
