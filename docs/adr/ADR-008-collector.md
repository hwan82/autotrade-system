# ADR-008 과거 데이터 수집 일괄 명령(Q-037): Java 수집기, 수집기 전용 키 파일, 일봉·재무 스냅샷

- 상태: 제안. 실전 주문 경로·Guard·블랙리스트·리스크 한도 코드는 건드리지 않지만, 실전 엔진과 같은 PC에서 도는 새 실행 단위라 프로세스 격리·자원 정지 순서(장애 대응, A 점검표 A8·A12)에 걸려 risk-ops 검토 후 **사용자 머지** 대상이다(지침 10장)
- 날짜: 2026-10-10
- 단계: 2단계 후속, 기획서 14장 배치표 1번(6단계 시작 전 완료)
- 기획서: ARC-06, MD-07·09·10·11, CFG-03
- 근거 결정: D-019(수집 경계, 되돌릴 조건), D-038(2단계 일봉 범위), D-042(재무 시점 규칙), D-050(수집 출처, ⑤ 수집기 전용 비밀 파일), D-013(상주 프로세스 4개)
- 결정 로그 번호: D-051 (Q-037 닫음)
- 영향 역할: data-engineer(구현), architect(모듈·계약), strategy-researcher·sim-engine(스냅샷 읽기), risk-ops(A 점검표: 프로세스 격리·자원 보호 2.7, Q-041)

## 1. 배경

[사실] D-019는 국내 공개 라이브러리(pykrx 등)를 쓰려고 Python 배치 수집기를 허용했다([D-019](../decisions/D-019-python-collector.md) 2번, 대안 A 버린 이유). D-050은 그 라이브러리를 모두 버리고 공식 REST API 두 개(KRX Open API, OpenDART)로 정했다(D-050 ①②). D-019 되돌릴 조건은 "Java만으로 같은 데이터를 같은 품질로 확보할 수 있게 되면 Python 수집기를 걷어내고 새 결정 번호로 기록"이다.

[사실] `secrets.json`에는 증권사 키·계좌번호·운영자 비밀번호 해시가 함께 있고 4개 프로세스가 모두 읽는다([config-keys.md](../config/config-keys.md)). 설정 로더는 모르는 키가 있으면 그 파일을 쓰지 않는다(같은 문서 7행). 그래서 D-050 ⑤가 수집기 키를 `secrets.json` 밖에 두기로 했고, PR #36 architect 검토 R3은 "수집기 전용 비밀 파일 + 증권사 키 비로딩"을 언어와 관계없이 지키라고 했다.

[사실] 열린 PR #37(ADR-007)은 실전용 선정 결과 생산자를 4개 프로세스 밖 단발 일괄 명령(`autotrade-app-selection`, `secrets.json` 미로딩)으로 정했고, 배치표 1번에 manifest의 기준일 필드(일봉 마지막 거래일, 상장주식수 기준일, 재무 마지막 수집 시각)를 요구했다(ADR-007 5장 data-engineer 행).

## 2. 결정

### 2.1 수집기는 Java 단발 일괄 명령 `autotrade-app-collector` (Q-037)

- 새 부트 모듈 `autotrade-app-collector`(패키지 `com.autotrade.app.collector`), 진입점 `CollectorMain`, 배포 이름 `autotrade-collector`(`installDist`). D-013의 상주 프로세스 4개에 넣지 않는 **단발 명령**이다. 실행이 끝나면 종료한다(`symbolMaster`, ADR-007의 선정 일괄 명령과 같은 자리).
- 명령 두 개: `krx-daily`(일봉·상장주식수·종목 이력), `dart-financials`(사업보고서 재무). 실행 수단은 사용자가 손으로 또는 OS 예약 작업(장 마감 뒤)으로. 절차는 [수집기 runbook](../runbooks/collector.md).
- 의존: domain, marketdata(스냅샷 계약·CSV·SHA-256), config(설정 폴더 위치 규칙과 `Secret` 타입만), Jackson. **런타임 금지**(`verifyProcessIsolation`): sim, app-lab, ui, risk, strategy, control, broker-api·kiwoom·kis, app-engine·gateway·watchdog, Spring.
- 부르는 곳은 KRX Open API와 OpenDART뿐이다. 증권사 API, 실시간 시세, 주문을 쓰지 않는다(D-019 3번 경계를 그대로 유지).
- `collectors/python/`에는 수집기를 두지 않는다. CI 경계 검사(`scripts/ci/check-python-collectors.sh`)는 나중에 누가 Python 스크립트를 넣을 때를 막도록 남기고, MD-11대로 `crtfc_key` 패턴을 더한다.

### 2.2 수집기 전용 키 파일 `<설정 폴더>/collector-secrets.json`

```json
{ "krx": { "auth-key": "<KRX_OPEN_API_AUTH_KEY>" }, "opendart": { "crtfc-key": "<OPENDART_CRTFC_KEY>" } }
```

- 위치: 4개 프로세스와 같은 설정 폴더(`autotrade.config-dir` → `AUTOTRADE_CONFIG_DIR` → `~/.autotrade`, `ConfigPaths.defaultLocation()`의 폴더). 저장소 밖이고 `.gitignore`에 `**/collector-secrets.json`을 더했다.
- 읽는 곳은 `CollectorSecrets` 하나다. 모르는 항목(예: 증권사 키를 잘못 넣은 경우, `crtfc_key` 같은 오타)이 있으면 **파일 전체를 거부**하고 명령이 종료 코드 1로 끝난다. 이 파일은 4개 프로세스와 무관하므로 거부해도 다른 프로세스 기동에 영향이 없다. 오류 메시지에 값을 넣지 않는다(파서 메시지도 옮기지 않음).
- 수집기는 `runtime-config.json`·`secrets.json`을 **열지 않는다**. 설정 폴더 위치만 `ConfigPaths`로 구하고 파일은 읽지 않는다. ArchUnit `COLLECTOR_READS_ONLY_ITS_SECRETS`가 수집기 패키지의 `ConfigLoader`·`RuntimeConfigStore`·`RuntimeConfigHolder`·`LoadedConfig`·`RuntimeConfig`·`ProcessStartup` 참조와 증권사·주문 패키지 참조를 막는다(위반 고정 예제로 규칙이 실제로 잡는지 확인).
- 일반 설정(기간, 호출 상한, 폴더)은 설정 파일 키를 만들지 않고 **명령줄 옵션**으로 받는다. 단발 명령이라 실시간 변경이 필요 없고, 설정 파일 하나를 더 만들면 키 문서·검증이 하나 더 생긴다. 그래서 config-keys.md에 새 키는 없고 파일 하나(위)만 추가한다.
- 값은 `Secret`으로만 들고 다닌다. 요청 URL·헤더를 오류 메시지에 남길 때는 `Redaction`이 `crtfc_key=`와 알려진 키 값을 `****`로 바꾼다. JDK HTTP 예외 메시지는 URL을 담을 수 있어 원인 메시지를 옮기지 않고 예외 종류만 남긴다.

### 2.3 KRX 일봉 수집(`krx-daily`, MD-07)

- 요청: `GET https://data-dbg.krx.co.kr/svc/apis/sto/{stk|ksq|knx}_bydd_trd?basDd=yyyyMMdd`, 헤더 `AUTH_KEY`. 응답 `OutBlock_1` 목록. 주소·헤더·필드 이름은 `[가정]`(공개 클라이언트 예제 기준, 이 환경에서 KRX 사이트 접속이 막혀 원문 미확인). 응답 모양이 다르거나 응답 날짜가 요청과 다르면 조용히 넘기지 않고 멈춘다. 첫 실호출로 확인한다(runbook 2장).
- **증분**: 날짜·시장별 응답 원문을 `<설정 폴더>/collector-cache/krx/<시장>/<연도>/<yyyyMMdd>.json`에 두고 캐시가 있는 날은 다시 부르지 않는다. 주말은 부르지 않고, 휴장일은 빈 응답을 캐시해 다시 부르지 않는다. 단 최근 7일 안의 평일 빈 응답은 자료 게시 전일 수 있어 캐시하지 않고 다음 실행에서 다시 부른다 `[가정]`. 오늘(서울 날짜) 응답은 캐시하지 않는다. 기본 `--to`는 서울 18:00 `[가정]` 전이면 어제, 뒤면 오늘.
- **호출 상한**: 하루(서울 날짜) 9,000회 기본(약관 10,000회의 90%, `--max-calls`는 10,000 이하만 받음). 호출마다 `<설정 폴더>/collector-state/budget/krx-<날짜>.json`에 기록해 같은 날 여러 번 실행해도, `--cache-dir`를 바꿔도 합산한다(같은 키의 하루 한도라서). 재시도도 센다. 상한에 닿으면 종료 코드 3으로 멈추고, 받은 날은 캐시에 남아 다음 날 이어 받는다. 2010-01-04부터 전체를 받으면 약 4,100거래일 × 3시장이라 첫 수집은 이틀 정도 걸린다 `[추론]`.
- **수정 계수**: 기준가 = 종가 − 전일 대비(`CMPPREVDD_PRC`). 기준가가 전일 종가와 다르면 그날 권리 변동(분할·병합·무상·유상 권리락 등)으로 보고 비율 f = 기준가 ÷ 전일 종가(유효숫자 16자리)를 이벤트로 둔다. 날짜 D의 누적 계수 = D 뒤 이벤트 비율의 곱, 마지막 날 1(`DailyBar.adjFactor` 계약 그대로). 상장주식수만 바뀐 날(유상증자 상장 등, 기준가 불변)은 이벤트가 아니다. 증권사 수정주가와 같은 방식 `[추론]`이며 표본 대조는 runbook 3장.
- **거래정지·빈 가격**: 시가·고가·저가가 없거나 0이면 종가로 채운다. 거래량 0이면 거래정지일(품질 검사 ZERO_VOLUME 경고), 거래량이 있으면 원자료 이상으로 따로 센다. 종가가 없으면 그날 일봉을 쓰지 않는다.
- **종목 이력**: (시장, 소속부 `SECT_TP_NM`, 종목명)이 바뀌면 새 구간(Q-012 형식). 수집 마지막 거래일까지 나오는 종목은 끝 날짜가 비고, 그 전에 사라진 종목은 마지막으로 나온 날이 끝 날짜다(상장폐지 포함). `kind`는 `STOCK`(일별매매정보는 주식 시장 서비스라서). 소속부는 `KOSPI`, `KOSDAQ/우량기업부` 형식.
- **상장주식수**: 새 선택 파일 `listed_shares.csv`(`market,code,date,listed_shares`), 값이 바뀐 날(첫 날 포함)만. 날짜 D 값은 D 장 마감 시점 상장주식수. 읽기는 `SnapshotListedShares.asOf(symbol, date)`(직전 행 값). MD-07 "선정 기준일 시가총액 = 직전 거래일 종가 × 직전 거래일 상장주식수"는 읽는 쪽이 `previousTradingDay`로 부른다.
- 같은 날 두 시장에 같은 코드가 나오면 어느 쪽이 맞는지 근거가 없어 멈춘다.

### 2.4 스냅샷 쓰기와 ID (ARC-06 계약 확장, 스키마 버전 1 유지)

- 폴더: `<설정 폴더>/snapshots/krx-daily/<ID>/`, `<설정 폴더>/snapshots/dart-financials/<ID>/`. 저장소 밖이다(D-019, D-050 조건 3 "원자료 재배포 없음").
- 쓰기: 임시 폴더에 CSV를 한 줄씩 쓰고(UTF-8, BOM 없음, `\n`), 파일별 SHA-256·행 수로 manifest를 만든 뒤 폴더째 `ATOMIC_MOVE`. 같은 ID 폴더가 있으면 덮어쓰지 않는다.
- **ID**: `krx-daily-<마지막 거래일>-<daily_bars.csv SHA-256 앞 8자리>`, `dart-financials-<다 훑은 날>-<financial_filings.csv SHA-256 앞 8자리>`. 같은 캐시면 같은 ID(같은 날 다시 돌려도 새 폴더가 생기지 않는다, 테스트 있음).
- **manifest `coverage`**(새 선택 칸): `firstDate`, `lastTradingDate`, `sharesAsOf`, `lastCollectedAt`. ADR-007 2.6 `inputs`의 기준일(일봉 마지막 거래일, 상장주식수 기준일, 재무 마지막 수집 시각)은 이 칸을 옮긴다. 칸이 없는 예전 스냅샷은 `null`이다. Jackson이 모르는 칸을 무시하므로 스키마 버전을 올리지 않았다.
- `manifest.sources[].license`에 D-050 약관 조건을 적는다. KRX: "KRX Open API 이용약관(2025-12-26 시행): 비상업 목적, 제3자 제공 금지, 출처 '한국거래소 통계정보'". OpenDART: "OpenDART 이용약관(2020-01-21 시행), 개인 실험용 로컬 저장".
- 일봉 스냅샷은 기존 `SnapshotDailyBarSource`가 그대로 읽는다(헤더 불변). manifest·해시 확인은 `SnapshotFiles`로 묶어 일봉·상장주식수·재무 읽기가 같이 쓴다.

### 2.5 OpenDART 재무 수집(`dart-financials`, MD-10·11, 증분)

- [사실] 공시검색 `list.json`은 회사 코드 없이 부르면 기간이 3개월까지, 한 쪽 최대 100건, `last_reprt_at=N`이면 정정 공시를 포함한다. 단일회사 주요계정 `fnlttSinglAcnt.json`은 `corp_code`·`bsns_year`·`reprt_code`(11011 사업보고서)를 받고 항목마다 `rcept_no`·`fs_div`(CFS/OFS)·`account_nm`·`thstrm_amount`를 준다. 상태 020은 요청 제한 초과, 013은 자료 없음(OpenDART 개발가이드 DS001 2019001·DS003 2019016, 2026-10-10 확인).
- **공시 훑기(증분)**: 사업보고서(`pblntf_detail_ty=A001`, 정정 포함)를 3개월 창씩 접수일 오름차순으로 훑어 `<cache>/dart/filings/<접수번호>.json`에 둔다. 유가·코스닥·코넥스(`corp_cls` Y·K·N)이고 6자리 종목 코드와 보고서명 괄호의 사업연도가 있는 것만. 창 하나를 끝낼 때마다 훑은 구간을 `state.json`의 `scanned`(`[{from,to}]`, 겹치거나 이어지면 합침)에 더한다. 다음 실행은 요청 범위(`--from`~`--to`) 중 **아직 훑지 않은 구간만** 훑는다. 그래서 짧은 기간으로 먼저 돌린 뒤 `--from`을 앞당겨도 앞 구간을 빠뜨리지 않는다. 오늘 공시는 더 들어올 수 있어 어제까지만 훑는다.
- **계정 받기**: 계정 응답이 없는 공시마다 주요계정을 불러 `<cache>/dart/accounts/<접수번호>.json`에 둔다. 응답의 `rcept_no`가 그 공시와 **같을 때만** 그 공시의 값으로 인정한다(`valuesFor`). 매일 증분으로 돌리면 정정 공시가 나오기 전에 원 공시 값을 받아 두게 되므로 MD-10 **기본 규칙**(원 공시 값 → 정정 접수일 다음 거래일부터 정정 값)을 쓸 수 있다.
  - 응답이 이미 뒤 정정 값을 담고 있으면(과거 기간을 처음 받을 때) 그 공시는 **값 모름**으로 남는다. 읽는 쪽은 MD-10 **대체 규칙**을 적용하고 편향 표시를 남긴다.
  - 응답이 아직 앞 공시를 가리키거나 자료 없음(013, 그 회사·사업연도의 첫 공시가 아직 반영 안 됨)이면(반영 지연 `[가정]`) 접수 뒤 14일 동안 다음 실행에서 다시 부르고, 그 뒤엔 값 모름으로 둔다. 대기 중인 공시는 스냅샷에서 뺀다.
- **호출 상한**: 하루 10,000회 기본(가이드의 "일반적으로 20,000건"의 절반 `[가정]`, 하루 단위도 `[가정]`). 상태 020을 받으면 그날 기록에 `stopped`를 남기고 종료 코드 3. 010·011·012·901(키 문제)은 오류로 멈춘다.
- **재무 스냅샷 파일** `financial_filings.csv`: `market,code,corp_code,bsns_year,reprt_code,rcept_no,rcept_dt,correction,values_known,fs_div,revenue,operating_income,total_assets,total_liabilities,total_equity`. 한 행 = 공시 한 건(원 공시와 각 정정이 따로). `correction`은 보고서명이 `[`로 시작(`[기재정정]` 등). 금액은 원 단위 정수, 계정이 없으면 빈 칸. `values_known=N`이면 금액이 모두 비어야 한다(읽는 쪽이 거부). 연결(CFS) 항목이 있으면 연결, 없으면 개별(OFS). 계정명 표는 `DartSnapshotBuilder.ACCOUNTS`(`[가정]`, 업종별 변형은 첫 실수집 품질 리포트의 결측 건수로 보강).
- 읽기: `com.autotrade.marketdata.financial.SnapshotFinancials`(해시·행 수 확인, 정렬: 종목·사업연도·보고서·접수일·접수번호). **접수일이 없거나 형식이 틀린 행이 하나라도 있으면 스냅샷 전체를 거부**한다(MD-11 "접수일 없는 행 0건"). 시점 규칙 적용(접수일 다음 거래일부터, 정정 처리)은 선정 계산(배치표 2·3번, ADR-007 `selection.calc`) 몫이다. 이 스냅샷은 그 규칙에 필요한 원재료(접수일, 정정 여부, 값을 아는지)를 모두 담는다.

### 2.6 품질 리포트 (MD-09)

- 일봉: 기존 `QualityReport`(ADR-003 2.6 규칙)를 `experiments/_data-quality/<ID>.md`에 쓰고 끝에 "수집 요약"(원자료 행, 거래정지일, 원자료 이상, 수정 이벤트, 전일 대비 칸 결측, 호출 수, 출처 표시 문구)을 붙인다. 리포트는 `DailyBarQualityCheck.checkSnapshot`으로 만든다: 쓴 스냅샷의 해시·행 수를 읽는 쪽과 같이 확인하고, 일봉을 날짜 순으로 한 줄씩 읽으며 같은 규칙을 적용해 메모리가 행 수와 무관하다(종목 수·발견 수에 비례). `SnapshotDailyBarSource.load`(전체 적재)의 검사와 결과가 같다는 테스트가 있다(무작위 이상 자료 포함). 전체 적재 방식은 2GB 힙에서 약 300만 행부터 메모리 부족이었다(QA PR #39 실측).
- 재무: `<ID>.md`에 공시 행, 정정 행, 값 모름 행, **대체 규칙 대상 묶음**(원 공시 값 없고 정정 값만 있는 (종목, 사업연도, 보고서) 수), 값이 하나도 없는 묶음, 대기, 개별만 있는 행, 자본잠식 행, 계정별 결측, 호출 수. 집계 건수만 담고 원자료 값은 담지 않는다(D-050 조건 3).

### 2.7 실전 엔진 PC 자원 보호 (broker-and-fault-design 5.1, risk-ops 검토 PR #39 F1·F2, Q-041)

수집기는 감시 프로세스가 알지도 멈추지도 못하는 단발 명령이라(5.2 정지 순서 밖) 스스로 물러난다. 단발 명령을 5.2·장애표 #10에 넣는 것은 장애 대응 규칙 변경이라 Q-041로 사용자 결정을 받는다.

- **장 시간 보호 구간 실행 거부**(`RunGuard`): 국내(KRX)·미국 거래일 정규장의 개장 60분 전부터 폐장 30분 뒤까지는 시작하지 않고(종료 코드 4), 실행 중 그 구간에 들어서면 다음 API 호출 전, 스냅샷 쓰기 시작 전, 일봉 스냅샷을 쓰는 동안 하루 읽을 때마다 멈춘다(받은 것은 캐시에 남고 쓰던 임시 폴더는 지움). 쓰기가 끝난 뒤 품질 리포트 단계(전 기간 읽기)는 중간에 멈추지 않는다. 구간은 `autotrade-marketdata` 거래소 캘린더(휴장일·특별 운영일·서머타임)로 계산한다. 수집기는 Guard 상태를 읽을 수 없으므로(2.2) 실전 계좌가 켜졌는지와 상관없이 시간으로 막는다. 캘린더 수록 범위 밖이면 판단할 수 없어 막는다(KRX 캘린더는 2026-12-31까지라 연말 전에 갱신해야 한다). `--allow-during-session`으로만 푼다(실전 엔진을 끈 날).
  - 서울 기준 국내 보호 구간 08:00~16:00, 미국 보호 구간은 서머타임 중 21:30~05:30, 아닐 때 22:30~06:30. 매일 실행은 서울 18:30~21:30 사이가 맞다.
- **힙 상한 고정**: 설치본·`run` 모두 `-Xmx2g`(`build.gradle.kts`). 품질 리포트 단계가 모자라면 상한을 올리지 않고 `--from`으로 기간을 줄인다. 낮은 OS 우선순위로 실행한다(runbook 4장).
- **디스크 여유 확인**: 시작할 때와 스냅샷 쓰기 전에 캐시·스냅샷 폴더 디스크 여유가 `--min-free-gb`(기본 20GB `[가정]`) 미만이면 멈춘다(종료 코드 4). 실전 엔진의 상태 기록·DB 쓰기가 같은 디스크를 쓸 수 있어서다(장애표 #8 재기동 복구 전제).
- **스냅샷 보관**: `--keep-snapshots K`를 주면 소스별로 manifest 생성 시각 기준 최근 K개, 방금 만든 것, 실험 폴더(`--experiments-dir`, 기본 작업 폴더의 `experiments/`) 아래 파일(4MB 이하, 깊이 4)에 ID가 적힌 것을 남기고 나머지 스냅샷 폴더를 지운다. 수집기가 쓰는 품질 리포트 폴더(`--report-dir`)는 참조로 보지 않는다. 실험 폴더가 없으면 참조를 확인할 수 없어 지우지 않는다. 실험실 DB(`experiment.data_snapshot_version`)에만 적힌 참조는 보지 못한다(수집기는 DB를 읽지 않음, 2.2): 실험은 `experiments/<실험ID>/`에 스냅샷 ID를 남겨야 보호된다(지침 2장 실험 결과 위치). 기본은 지우지 않는다(데이터 삭제는 사용자가 정하는 일, 지침 8장 3번). **정리는 일봉(`krx-daily`)만 한다.** 지운 일봉 스냅샷은 같은 `--from`·`--to`로 다시 만들면 원문 캐시가 남아 있는 한 같은 ID로 복원된다(ID가 내용 해시, 과거 날짜 캐시는 바뀌지 않음). **재무 스냅샷(`dart-financials`)은 정리하지 않는다**: 캐시에 있는 공시 전체와 그때의 대기·확정 상태로 만들어지고 실행마다 공시·정정·확정이 늘어, 지우면 같은 내용으로 다시 만들 수 없다(QA PR #39 F2). 크기가 작아(수 MB `[추론]`) 디스크 부담도 낮다. 정리는 스냅샷을 커밋한 직후, 품질 리포트보다 먼저 한다(리포트 단계가 실패해도 정리는 끝나 있게). 원문 캐시는 지우지 않는다. 매일 예약 실행의 `krx-daily`에는 `--keep-snapshots 3`을 권한다(runbook 4장).
- **호출 기록 잠금**: `CallBudget`은 소스별 잠금 파일(`FileChannel.lock`) 안에서 읽고 써서 같은 명령을 동시에 돌려도 하루 상한 합산이 빠지지 않는다.
- **주소 옵션은 https만**: `--krx-base-url`·`--dart-base-url`은 `https://`로 시작해야 한다(키가 평문으로 나가지 않게). 리다이렉트는 따르지 않는다.
- 빌드 격리: 실전 엔진·게이트웨이·감시의 `processIsolation.forbiddenProjects`에 `:autotrade-app-collector`를 넣었다(클래스 수준은 `PROCESSES_ARE_INDEPENDENT`가 이미 막음).

## 4. 위험과 한계

- **KRX 요청 형식 미확인**: 주소·헤더·필드 이름이 `[가정]`이다. 틀리면 첫 호출에서 HTTP 오류 또는 "OutBlock_1 목록이 없습니다"로 멈추고 캐시에는 아무것도 남지 않는다. 사용자 첫 실행 결과로 고친다(runbook 2장).
- **스냅샷 읽기의 메모리**: 수집기는 쓰기(두 번 훑기)와 품질 리포트(날짜 순 검사, 2.6) 모두 행 수와 무관한 메모리로 돈다. 실제 규모 확인: 힙 128MB 자식 JVM에서 120만 행 스냅샷의 정리·리포트가 끝나고, 같은 힙에서 전체 적재 방식은 메모리 부족임을 비교 실행으로 확인한다(`CollectorScaleTest`). 그러나 **실험실이 `SnapshotDailyBarSource.load`로 읽을 때는 여전히 전 기간을 메모리에 올린다**(2GB 힙이면 약 300만 행, 약 4년 치까지). 기간별 지연 로딩은 sim-engine 변경 제안으로 남긴다(6장).
- **수정 계수의 한계**: 전일 대비 칸이 없거나 거래정지 기간을 사이에 둔 권리 변동은 잡지 못할 수 있다. 수집 요약의 "전일 대비 칸이 없어 수정 판정 못 한 행"과 품질 검사 UNADJUSTED_JUMP 경고로 드러난다.
- **종목 이력은 2010년부터**: KRX Open API가 2010년 이후만 주므로 그 전 상장일은 모른다. 첫 구간 시작일이 2010-01-04면 "그 전부터 상장"으로 읽어야 한다. 다년 워크포워드는 2010년 이후로 설계한다(조사 문서 5장).
- **종목명 바뀜 = 새 구간**: 이름만 바뀐 날 구간이 둘로 나뉜다. 유니버스 재현에는 영향이 없지만 구간 수가 늘어난다. 코드 재사용(폐지 뒤 같은 코드로 다른 회사 상장)은 이름이 달라 새 구간으로 갈린다. 수정 계수는 코드가 20거래일 넘게 비었다가 다시 나오면 옛 종가를 잇지 않아(다른 회사로 봄 `[가정]`) 가짜 수정 이벤트를 만들지 않고, 다시 나온 날부터를 새 구간으로 나눠 새 회사의 수정 이벤트를 옛 회사 일봉에 곱하지 않는다. 그 건수를 품질 리포트에 센다. 20거래일 안에 다른 회사로 재사용되면 잡지 못한다.
- **OpenDART 반영 지연·사업연도**: 응답이 앞 공시를 가리키는 지연 기간(14일)과 3월 결산 등 비12월 결산의 사업연도 해석(보고서명 괄호 연도)은 `[가정]`이다. 품질 리포트의 대기·값 모름 건수로 확인한다.
- **호출 한도 단위**: OpenDART 20,000건이 하루 단위인지 `[가정]`이다. 상한을 절반으로 두어 여유를 남겼다.
- **자원 보호의 한계**: 보호 구간은 시간 기준이라 실전 엔진이 꺼진 날에도 막고(명시 옵션으로 풂), 정규장 밖 시간외 거래·미국 프리마켓 운용은 보호하지 않는다 `[가정]`(실전 운용을 정규장 기준으로 봄). 감시 프로세스가 수집기를 멈출 수단은 아직 없다(Q-041).
- **실제 서버로 검증하지 못했다.** 테스트는 가짜 HTTP로 응답 형식·증분·상한·키 가림·스냅샷 왕복을 확인한다. 이 환경에서는 두 사이트 모두 접속이 막혀 있다(프록시 403).

## 6. 다른 역할에 대한 변경 제안

- **strategy-researcher·sim-engine(배치표 2·3번)**: 재무 값은 `SnapshotFinancials`로 읽고 MD-10 규칙(접수일 다음 거래일부터, 정정 기본·대체 규칙, 대체 규칙 표시·건수)을 `selection.calc`에서 적용한다. 시가총액은 `SnapshotListedShares.asOf(symbol, previousTradingDay(T))` × 직전 거래일 종가.
- **sim-engine**: `SnapshotDailyBarSource`에 기간 지정 로딩(`load(dir, from, to)`)을 더해 다년 스냅샷의 메모리를 줄이는 방안. 계약 추가라 architect 검토.
- **ADR-007 구현(배치표 0번 후속)**: 결과 파일 `inputs`의 기준일은 manifest `coverage`(2.4)를 옮긴다. 일괄 명령 `POST_CLOSE` 실행은 `krx-daily`(와 그날 `dart-financials`) 다음 순서(runbook 4장).
