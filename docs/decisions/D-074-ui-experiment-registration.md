# D-074 실험 생성 화면은 조합 실험 등록 파일을 쓴다(실행은 실행 명령)

- 날짜: 2026-10-14
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 실전 주문 경로·Guard·블랙리스트·리스크 한도·장애 대응은 건드리지 않는다
- 담당: ui-dev. 교차 검토: architect
- 근거: 기획서 UI-02("기간·시드·조합으로 실험 생성", 5단계 완료 기준 "실험을 UI로 만들고 비교 가능", team-design.md 6장), UI-03("시장·스타일이 다른 조합은 화면에서 만들 수 없음"), STR-02·17, [D-060](D-060-selection-ui.md) 남은 일, [D-062](D-062-lab-loads-result-bundle.md)(실험실은 실험을 돌리지 않음, 대안 A 되돌릴 조건), [D-063](D-063-experiment-command-stop-gate.md)(실행 명령의 장 시간 보호), [조합 실험 절차](../strategy/combination-experiments.md) 1장(등록 파일을 먼저 쓰고 커밋), [ADR-005](../adr/ADR-005-ui-dashboard.md), PR #49 후속 과제(실험 생성 화면의 시장·스타일 필터, 조건 편집기의 의미 동일 알림, 전략 프로필 200개 한 쪽 조회)
- 범위: 실험실 화면과 REST. 실행 명령·결과 파일·결과 묶음 형식은 바꾸지 않는다

## 결정

1. **실험 생성 = 등록 파일 쓰기**: 화면 "실험 → 새 실험 등록"에서 실험 ID, 질문, 시장, 매매 스타일, 기간, 시드, 시드머니(기본 `lab.default-seed-capital-krw`), 일봉·재무 스냅샷, 비교 종목, 병렬 수, 제외 종목, 조합(선정 × 전략)을 고르면 실험실이 `experiments/<실험ID>/experiment.yaml`(조합 실험 등록 파일, `CombinationPlan` 형식)을 새 폴더에 쓰고 실행 명령을 보여 준다. 실험실은 실험을 돌리지 않는다(D-062 그대로). 사용자가 등록 파일을 커밋하고 실행 명령(`runCombinationExperiment`, D-063 정지 확인 포함)으로 돌린 뒤 "실험 폴더"에서 불러와 비교한다.
2. **쓰기 전 검사**(서버, `ExperimentRegistrations`): 실험 ID 모양(실행 명령과 같음, 경로 밖 불가), 새 폴더만(같은 ID가 있으면 409, 사전 등록은 덮어쓰지 않음), 프로필 버전이 있음, **조합마다 선정·전략 프로필의 시장·스타일이 실험의 시장·스타일과 같음**(STR-02, 한 실험 = 한 스타일), 재무 지표를 쓰는 선정이 있으면 재무 스냅샷 필수, 조합 1~128개(SIM-14), 시장은 KRX만(실행 명령이 국내만 돌림). 만든 글을 `CombinationPlan.parse`로 다시 읽어 입력과 같은지 본 뒤 임시 파일 → 원자적 이동으로 쓴다. `POST /api/experiment-folders/preview`는 같은 검사를 하고 쓰지 않는다.
3. **시장·스타일 필터**: `GET /api/profiles`, `GET /api/selections`에 선택 질의 `market`, `style`을 더한다. 실험 생성 화면은 고른 시장·스타일의 프로필만 교차표 모양(행 = 선정 프로필 + "선정 없음", 열 = 전략 프로필, 칸 = 체크, 행·열마다 버전 선택)으로 보여 준다. 선정 프로필 화면의 "조합할 수 있는 전략 프로필"도 이 질의로 끝 쪽까지 읽는다(200개 넘어도 빠지지 않음).
4. **스냅샷 고르기**: `GET /api/experiment-folders/snapshots?kind=krx-daily|dart-financials`가 `<설정 폴더>/snapshots/<종류>/<ID>/manifest.json`의 기간(coverage)을 보여 준다(실행 명령의 스냅샷 폴더 기본값과 같은 곳). 화면은 실험 기간이 스냅샷 범위 밖이면 미리 경고한다(최종 판정은 실행 명령).
5. **조건 편집기의 의미 동일 알림**: 선정 프로필 새 버전을 저장하기 전에 `POST /api/selections/{id}/versions/{version}/compare`로 원본과 비교한다. 선정 결과(갱신 주기, 최대 종목 수, 상품 유형 집합, 최소 가격·일봉 거래일, 자격 조건 집합(순서 무관, 기준값은 값 비교), 순위)가 같고 글자만 다르면(자격 조건 순서·번호, 값 표기, 가설, `notes.*`) "같은 선정이 새 해시로 따로 집계된다"고 확인을 받는다. 저장은 막지 않는다(가설 문구 수정은 정당한 새 버전일 수 있다).

## 위험과 한계

- 화면 기본 실험 ID(`EXP-<오늘>-CMB01`)와 시드(오늘 날짜)는 브라우저 시계로 채우는 제안값일 뿐이고 등록 파일에 쓰이는 값은 사용자가 확인한 값이다. 실험 결과에는 영향이 없다(결정론은 등록 파일 값으로).
- 등록 파일을 쓴 뒤 커밋하지 않고 돌리면 결과의 코드 상태가 dirty로 남는다(experiments/ 안 변경은 dirty로 치지 않는 규칙은 실행 명령 쪽). 화면은 커밋 명령을 함께 보여 주는 데서 그친다.
- 스냅샷 목록은 manifest만 읽고 파일 해시를 확인하지 않는다(실행 명령이 확인).
- 의미 동일 판정은 선정 계산이 모든 자격 조건을 평가해 AND로 묶는다는 현재 구현(`SelectionCalculator`)에 기댄다. 조건 순서에 따라 건너뛰는 평가가 생기면 판정을 고쳐야 한다(테스트가 순서 변경을 "같음"으로 고정).
- 미국 조합 실험은 실행 명령이 생길 때 시장 선택을 연다.

## 검증

- `ExperimentCreationEndToEndTest`: 스냅샷 목록 → 시장·스타일 필터 목록 → 미리 보기(쓰지 않음) → CSRF 없는 등록 403 → 등록 201 → 같은 ID 409 → 실험 폴더 "아직 실행 안 함" → 실행 명령 본체(`CombinationExperiment.runAndWrite`, 결정론 확인 같음)로 실제 저장소 프로필 `kr-vol-surge-quiet@1 x kr-ma-trend@1`, `none x kr-ma-trend@1` 실행 → "불러올 수 있음" → 불러오기 → 실험 상세 계좌 2개·교차표·자산 곡선 API 200. 스타일 불일치, 재무 스냅샷 없음, 없는 버전, 경로 밖 ID, 미국, 조합 없음은 400이고 폴더를 만들지 않음.
- `SelectionEquivalenceTest`: 글자 같음, 자격 조건 순서만 바뀜, 값 표기만 바뀜, 가설·메모만 바뀜은 "선정 같음"(차이 문구 확인), 기준값·기간·연산·순위 방향·최대 종목 수·상품 유형·조건 삭제는 "다름", 해석 불가 후보는 이유를 준다.
- 화면 JS는 빌드 도구가 없어 자동 테스트가 없다. 브라우저로 확인한 범위는 PR 본문에 적는다.
