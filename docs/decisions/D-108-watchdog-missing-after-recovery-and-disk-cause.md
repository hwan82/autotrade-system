# D-108 감시 결측 경고: 회복 직후 다시 빠지면 바로 알림, 드라이브 읽기 실패 원인 기록(PR #123 QA R1, PR #119 risk-ops K3·QA R3)

- 날짜: 2026-10-17
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 감시 모듈(`autotrade-app-watchdog`, 보호 경로)의 결측 로그·알림 정책과 시험만 바꾼다. 정지 요청 판정(D-092 3번·D-095 3번, `Watchdog.pressure`·`StopRequests`), 하트비트 판정, 감시 설정, 기동 거부 조건, 보호 테스트는 바꾸지 않는다. 보호 경로라 사용자 머지로 확정한다.
- 담당: risk-ops 결정·구현. 교차 검토: architect(코드), risk-ops(실전 관련)
- 근거: [PR #123 독립 QA](../reviews/pr-123/qa.md) R1·R3, [PR #119 risk-ops](../reviews/pr-119/risk-ops.md) K3, [PR #119 독립 QA](../reviews/pr-119/qa.md) R3, [PR #148 독립 QA](../reviews/pr-148/qa.md) Q1·Q2, [PR #148 risk-ops](../reviews/pr-148/risk-ops.md) M7, [D-096](D-096-watchdog-missing-reading-warnings.md)
- D-096 2번(오가는 결측은 간격마다 WARN 하나·INFO 하나)과 위험과 한계 첫 줄을 대체한다. D-096은 머지된 결정이라 본문을 고치지 않는다.

## 문제

1. **회복 INFO 직후 다시 빠지면 최대 10분 무로그**(PR #123 QA R1, 탐침 P3): 5초 WARN → 10초 "자원 값을 다시 읽음" INFO → 15초부터 계속 결측이면 다음 WARN이 10분 5초에 나왔다. 그동안 마지막 로그와 마지막 알림이 "다시 읽음"이라 운영자는 감시가 그 값을 다시 판단한다고 오해할 수 있다(실제로는 그 값의 위험 판정이 꺼져 정지 요청을 새로 못 만듦).
2. **드라이브 읽기 실패 원인이 남지 않음**(PR #119 risk-ops K3·QA R3): `DiskFreeSource`가 경로별 `IOException`·`RuntimeException`을 삼키고 값만 뺐다. 결측 지속 경고(D-096)는 "어느 값이 빠졌는지"는 10분마다 남기지만 "왜"는 없었다.
3. **기동 실패 출력 시험 공백**(PR #148 QA Q1·Q2, risk-ops M7): `launch`에서 표준 오류 출력을 지워도, 설정 폴더 경로 오류 문구를 바꿔도, 프로그램 오류 로그에서 예외(스택)를 빼도 시험이 통과했다.

PR #123 QA Q1(간격이 찬 뒤 다시 빠진 값 즉시 경고)·Q2(10분 값·로그 수준 고정)·R4(시계 역행)는 PR #128(D-100)에서 이미 코드와 시험이 들어가 있어 이 결정 범위가 아니다(`WatchdogTest#간격이_찬_경고_뒤에_다시_빠진_값은_바로_알린다`, `#반복_간격은_10분이다`, `#빠진_값_경고는_WARNING_회복은_INFO로_남긴다`, `#시계가_뒤로_가도_반복_경고가_밀리지_않는다`, `#하트비트를_하나도_못_본_경고도_시계가_뒤로_가면_바로_되풀이한다`).

## 결정

1. **회복 INFO 뒤 다시 빠지면 바로 WARN**: 마지막 결측 로그가 회복 INFO인 상태에서 값이 빠지면 간격과 상관없이 WARN을 남기고 "자원 값을 읽지 못함" 알림(긴급)도 넣는다. 그래서 값이 빠진 점검 뒤의 마지막 결측 로그는 늘 "읽지 못함"이다.
2. **회복 INFO는 간격마다 한 번**: 위 1번이 점검마다 오가는 값에서 WARN·INFO를 점검마다 쌓지 않도록(PR #122 QA R4), 회복 INFO는 마지막 회복 INFO에서 `MISSING_REPEAT`(10분) 안이면 미룬다. 미룬 회복은 간격이 찬 뒤 값이 다 있는 첫 점검에 남긴다. 미루는 동안 마지막 로그는 "읽지 못함"이라 틀려도 안전한 쪽(판단 못 한다고 보임)이다. 결과: 같은 값이 점검마다 오가도 간격마다 WARN 둘(새 값·회복 뒤 재결측 하나, 간격 반복 하나)과 INFO 하나를 넘지 않는다. 알림은 회복 뒤 재결측 WARN에 하나 더 붙어 간격마다 긴급 하나·정보 하나 수준이다(알림 큐의 같은 대상·종류 10분 억제와 전체 상한은 그대로, D-100).
3. **드라이브 읽기 실패 원인 기록**: `DiskFreeSource`가 마지막 읽기에서 실패한 경로마다 원인(예외 종류와 메시지 한 줄, 160자까지)을 갖고, 감시의 결측 WARN에 `(원인: disk.free-gb:<경로> ← IOException: …)`로 붙인다. 원인은 OS가 준 경로 문구라 비밀값이 없다. 결측 지속 주기 경고(PR #119 QA R3, risk-ops K3의 "판단 못 함이 상태로 바뀔 때 WARN")는 D-096으로 이미 있으므로 새 주기를 만들지 않는다.
4. **기동 실패 출력 시험**: `WatchdogMainTest`가 진입점 `launch`의 표준 오류 첫머리(프로그램 오류·설정 오류), 설정 폴더 경로 오류 문구 "설정 폴더 경로가 틀렸습니다(autotrade.config-dir 또는 AUTOTRADE_CONFIG_DIR)", 프로그램 오류 로그에 예외가 붙고 설정 오류 로그에는 안 붙는 것을 확인한다. 운영 코드는 바꾸지 않는다.

## 대안

| 대안 | 판단 |
|---|---|
| ① 회복 뒤 재결측 즉시 WARN + 회복 INFO 간격마다 한 번(채택) | 마지막 로그가 거짓 "회복"인 시간을 없애고, 틀려도 "판단 못 함" 쪽으로만 틀린다. 오가는 결측의 로그 상한은 간격당 WARN 둘·INFO 하나로 D-096보다 WARN 하나 늘 뿐이다 |
| ② 회복 INFO 때 경고 값을 잊음(간격 초기화) | 점검마다 오가면 5초마다 WARN·INFO가 쌓인다(PR #122 QA R4, PR #123 QA 변이 W6). 버림 |
| ③ 회복을 일정 시간(예: 1분) 이어진 뒤에만 INFO | 정상 회복도 늘 늦게 보이고, 그 시간보다 길게 오가면 R1이 그대로 남는다. 버림 |
| ④ 그대로 두고 알림 화면의 상태 값으로 해결(QA R1 제안) | 상태 화면은 감시에 아직 없다(D-092 범위 밖). 로그만 보는 지금 운영에서 10분 오해가 남는다. 화면이 생겨도 ①과 충돌하지 않는다. 버림 |
| 드라이브 원인: 수집원에서 실패마다 WARN | 감시 결측 WARN과 같은 사건을 두 줄로 남기고 주기 정책이 둘이 된다. 버림 |

되돌릴 조건: 6단계 운용에서 회복 뒤 재결측 알림이 잦아 소음이 되면 알림만 새 값일 때로 되돌리고(로그는 유지) 간격을 `watchdog.properties` 키로 올리는 것을 검토한다.

## 위험과 한계

- 값이 오가는 동안 회복 INFO가 최대 10분 늦게 나온다. 그동안은 실제로 값이 있어도 마지막 로그가 "읽지 못함"이다(안전한 쪽). 정지 요청 판정은 점검마다 실제 값으로 하므로 이 지연과 무관하다.
- 원인 문구는 마지막 읽기의 것이다. 경로마다 원인이 바뀌어도 WARN은 간격 규칙대로만 나오므로 중간 원인은 남지 않을 수 있다.
- CPU·메모리 결측(JDK가 음수·범위 밖 값을 줌)은 원인이 "값 없음"뿐이라 원인을 붙이지 않는다.
- Windows 드라이브 오류 문구(로컬라이즈된 OS 메시지)의 실제 모양은 확인하지 못함 `[추론]`. 6단계 첫 주 점검의 로그 한글 표시 확인(PR #116 QA R2)과 함께 본다.

## 검증

- `WatchdogTest#회복_알림_뒤_다시_빠지면_간격을_기다리지_않고_바로_알린다`: 5초 WARN·10초 INFO·15초 재결측 WARN과 알림 세 건, 그 뒤 15초 경고에서 10분까지 조용, 10분에 반복 WARN(알림 없음).
- `WatchdogTest#간격_안에_두_번째_회복은_미뤘다가_간격이_찬_뒤_값이_다_있으면_남긴다`: 두 번째 회복 INFO가 첫 INFO에서 정확히 10분에 나오고 직전에는 없음.
- `WatchdogTest#점검마다_오가도_간격마다_WARN_둘_INFO_하나를_넘지_않고_마지막_로그가_틀린_회복이_아니다`: 60분 동안 5초마다 오가도 WARN ≤ 12·INFO ≤ 6, 빠진 점검마다 마지막 결측 로그가 "읽지 못함".
- `WatchdogTest#같은_값이_빠졌다_돌아오기를_되풀이해도_간격마다_정해진_횟수만_알린다`(옛 이름 `..._간격마다_한_번만_알린다`, architect N1): 기대값을 새 규칙(5분 오감 WARN 2·INFO 1, 끝 WARN 4)으로 바꿈.
- `WatchdogTest#드라이브를_읽지_못한_원인을_결측_경고에_적는다`, `DiskFreeSourceTest`(원인 기록·성공 시 지움, 읽기 중 `Error`가 나가도 이전 원인을 남기지 않음(risk-ops K1), 한 줄·160자 경계·서로게이트 쌍을 가르지 않음(architect N2)·메시지 없음·익명 예외).
- `WatchdogMainTest#진입점은_설정_폴더_경로가_틀리면_설정_오류로_거부한다`(표준 오류 문구), `#진입점은_기동_실패를_표준_오류에_알리고_프로그램_오류면_로그에_예외_흐름을_남긴다`(PR #148 QA Q1·Q2, risk-ops M7).
- 변이(개발 쪽 직접 실행, `:autotrade-app-watchdog:test`): 회복 뒤 재결측 판정 제거 4건 실패, 회복 INFO 간격 제거 3건 실패, `launch`의 `report` 삭제 2건 실패, 프로그램 오류 로그에서 예외 빼기 1건 실패. 모두 원본으로 되돌림.
