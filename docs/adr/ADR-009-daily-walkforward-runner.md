# ADR-009 일봉 워크포워드 판정 실행기: 예열(warmup)·구간 끝 정리 계약, 등록 파일 `study.yaml`, 결과 형식

- 상태: 제안(초안, sim-engine). 교차 검토: architect(모듈 경계·실험 실행기 계약 변경), strategy-researcher(판정 규칙·통계). 실전 주문 경로·RealTradingGuard·블랙리스트·리스크 한도 코드는 건드리지 않는다. 가상 계좌가 실전과 같은 리스크 체인·주문 상태머신·블랙리스트를 지나는 규칙(지침 5장)은 그대로이고, 실험 실행기에 선택 인자 두 개를 더한다.
- 날짜: 2026-10-13
- 단계: 4단계(전략 탐색), 계획 3·4장 `runWalkForwardStudy`
- 근거 결정: [D-071](../decisions/D-071-stage-4-plan.md)(범위·순서·선발 기준표), D-066(중기 워크포워드 학습 3년 + 검증 1년, 최소 3구간, 검증 합 30건), D-061(일봉 리플레이 조합 실험), D-063(실행 명령 정지 확인), D-027(선발 기준 수치)
- 결정 로그 번호: 없음(D 번호는 코디네이터가 매긴다). 이 ADR이 새로 정하는 것은 실행 계약이며 D-071 5번의 판정 규칙은 바꾸지 않는다.
- 영향 역할: sim-engine(구현), architect(`MarketDataSet`·`SimulationExperimentRunner` 계약), strategy-researcher(판정·대조군 해석), data-engineer(`listed_shares.csv` 필수화), risk-ops(실험 프로세스 정지 순서는 D-063 그대로)

## 1. 배경

[사실] 조합 실험(D-061)은 한 기간에 후보를 줄 세운다. D-071 5번은 일봉 후보를 학습 3년 + 검증 1년, 최소 3구간 워크포워드로 돌려 통과·탈락·보류로 가르는 판정(C1, C1w, C2..C10, C9d)을 정했다. 이를 위해 기존 실행기에 없던 세 가지가 필요하다.

1. 전략이 이동평균·20일 수익률을 쓰려면 구간 시작 전 시세를 봐야 하는데, 기존 실행기는 `spec.from` 앞 이벤트를 버린다.
2. 구간이 끝날 때 열려 있는 포지션이 PF·왕복 수·C10에서 빠지면 보유 중 평가손익이 판정에서 사라진다.
3. 후보마다 구간 × (학습 + 변형 2 + 검증 + 슬리피지 2배 + 대조군 시드 수)번 실행하므로 Run마다 전체 이벤트 선형 탐색을 하면 못 돈다.

## 2. 결정

### 2.1 예열(warmup) 계약: `SimulationExperimentRunner(..., warmupDays)`

- `warmupDays = 0`(기본)이면 기존 동작과 바이트까지 같다(기존 골든 테스트가 증거).
- `warmupDays = N > 0`이면 `spec.from` 직전 N개 거래일의 이벤트를 **전략에만** 준다. 이 이벤트는 거래소 모델·가상 계좌·평가금액·선정·자산 곡선에 가지 않는다. 전략 컨텍스트는 현금 0, 포지션·미체결 없음의 빈 `AccountSnapshot`이라 예열 중 나온 신호는 수량 0이 되고 모두 버린다(진입·체결·평가 금지).
- 예열이 필요한 만큼 앞선 거래일이 데이터셋에 없으면 `IllegalArgumentException`("예열 거래일이 모자랍니다")으로 시작하지 않는다.
- 비용 표 범위 검사(SIM-07)는 거래 구간(`spec.from` ~ `spec.to`)만 받는다. 예열 시세는 비용을 쓰지 않는다.
- 미래 정보 금지: `spec.to` 뒤 이벤트는 전략에 가지 않는다.
- 대안: ① 구간 앞에 전략 상태를 따로 "달궈" 직렬화하기(전략 인터페이스를 바꿔야 해 버림) ② 예열 일수만큼 `spec.from`을 당기고 결과에서 앞부분을 자르기(예열 중 진입이 막히지 않고 비용·체결이 생겨 버림). 되돌릴 조건: 전략이 시세 이력을 스스로 조회하는 인터페이스가 생기면 이 계약을 닫는다.

### 2.2 구간 끝 정리 `settleAtWindowEnd`

- true이면 마지막 거래일 마감 직전 남은 포지션을 그날 마지막 체결가 × (1 − 슬리피지)를 호가 단위로 내림한 가격으로 팔고, `cost.fees(SELL, ...)`로 수수료·거래세를 뺀 `OrderIntent.EXIT` 체결을 `VirtualAccount.apply`로 적용한다(실전과 같은 비용 모델, 가상 전용 우회 없음). 왕복 원장의 해당 lot id는 `RunReport.windowEndLots`에 남고 보고서에서 `window-end`로 표시된다. 기본값 false이면 기존 출력은 그대로다.
- 구간 중간에 상장폐지된 종목도 구간 끝에 같은 방식으로 정리한다(현금에 이자가 없어 최종 평가는 같고, 중간 평가 곡선은 정리 비용만큼 다르다). 폐지 뒤 손실은 일봉에 없어 반영하지 못한다.
- 결과 파일에 후보·구간별 정리 왕복 수와 손익 합을 따로 적는다(정리 왕복이 성과의 큰 몫이면 판정 해석에서 의심하도록).
- 대안: 구간 끝 평가손익만 남기고 왕복에서 빼기(PF·C5·C10이 보유 중 손익을 못 보고, 청산 비용을 숨김). 구간을 넘어 포지션을 이월(계좌를 새로 만들지 않으면 구간 간 상태가 섞여 구간 독립성이 깨짐).

### 2.3 `MarketDataSet` 일 인덱스

- `MarketDataSet`에 기본 메서드 `tradingDays()`(기본 빈 목록)와 `firstEventIndex(int dayIndex)`(기본 `UnsupportedOperationException`)를 더한다. `DailyBarMarketDataSet`이 구현하고, 실행기는 이를 있으면 구간 이벤트를 이분 탐색으로 자른다(없으면 기존 선형 경로). 같은 입력에서 두 경로의 결과는 같다.
- `DailyBarMarketDataSet.warmupStart(allTradingDays, from, warmupDays)`가 예열 시작일을 계산한다. 구간·단계마다 데이터셋을 따로 만든다(전체 기간을 한 데이터셋으로 만들면 이벤트 3천만 개 이상이라 메모리가 크다). 따라서 가격 기준(첫 일봉)이 데이터셋마다 다르다(D-061과 같은 한계).

### 2.4 등록 파일 `experiments/<실험ID>/study.yaml`

- 형식은 `WalkForwardPlan` 주석이 원본이다. 키: `id`, `question`, `market`, `bars-snapshot`, `financials-snapshot`(선택), `seed`, `seed-capital`, `parallelism`, `first-test-from`, `train-years`, `test-years`, `windows`(3~20), `warmup-days`, `null-seeds`(1~5000), 목록 `combinations`, `controls`("STYLE id@버전"), `blacklist`(선택). 읽는 모양은 `RegistrationYaml`(모르는 키·같은 키 두 번 거절)이고, 같은 조합·같은 스타일 대조군 두 번과 스타일 불일치(조합 실험의 스타일 검증 재사용)도 시작 전에 거절한다.
- 구간 계산: `t_k = first-test-from + k × test-years`(달력, 윤일은 `LocalDate.plusYears` 규칙), 학습 `[t_k − train-years, t_k − 1일]`, 검증 `[t_k, t_(k+1) − 1일]`. 휴장일에 걸려도 빠짐·겹침이 없고 실제 거래일 경계는 데이터셋이 정한다. 스냅샷 범위 밖 구간·`windows < 3`은 시작하지 않는다.
- 실험 ID 상한 30자(구간·시드별 하위 ID 접미어 때문에 `ExperimentId` 48자 제한 안에 들어야 함).
- 등록 파일은 실행 전에 커밋하고 결과를 본 뒤 고치지 않는다. 바꾸려면 새 실험 ID.

### 2.5 실행 단계와 판정 입력

구간 k마다 새 계좌로 ① 학습(후보 + 핵심 파라미터 ±20% 변형 2개) ② 검증(후보 + 슬리피지 2배 + 같은 선정 × 스타일 무작위 대조군 × 시드 수) ③ `-PverifyDeterminism`이면 전체를 병렬 1로 다시 돌려 결과 파일을 바이트 비교한다. 대조군 시드 i의 시드는 실험 시드 + i. 모든 계좌는 같은 시세를 공유하되 상태는 격리되고(공유 가변 상태 없음) 리스크 체인·주문 상태머신·블랙리스트는 실전과 같은 코드를 지난다.

판정은 구간별 검증 자산 곡선을 구간 시드로 나눠 이은 곡선(chained)에서 계산한다(C3·C4·C8이 같은 대상을 본다). 규칙 전체는 [조합 실험 절차 6장](../strategy/combination-experiments.md)이 원본이며 이 ADR은 복사하지 않는다. 판정 합성 순서: C5 미달 → 보류, 탈락 하나라도 → 탈락, 판정 불가 하나라도 → 보류, 전부 통과 → 통과.

### 2.6 벤치마크

시총 가중 지수(전일 원종가 × 전일 장 마감 상장주식수 가중, 수정 종가 비율로 이은 일수익률, 가격 지수, 비용 없음, 상장폐지 종목은 마지막 일봉일까지 포함)와 동일가중 참고 열. 상장주식수가 없는 (종목, 거래일)은 시총 가중에서 빼고 건수를 기록한다. 스냅샷에 `listed_shares.csv`가 없으면 시작하지 않는다.

### 2.7 결과 형식

`results.md`, `runs.tsv`, `windows.tsv`, `inputs.yaml`, `detail.txt`. 타임스탬프를 쓰지 않고 정렬을 고정해 같은 입력이면 바이트까지 같다. `inputs.yaml`에 데이터 버전(스냅샷 ID·해시·구간별 데이터셋 ID), 후보 조합·변형 해시, 비용 모델과 비용 표 해시, 체결 모델, 블랙리스트 지문, 시드, 코드 커밋, 결정론 확인 결과를 남긴다. 결과 묶음(`result-bundle.jsonl.gz`)은 만들지 않는다(실험실 화면 연동은 후속).

### 2.8 명령과 종료 코드

`./gradlew :autotrade-app-experiment:runWalkForwardStudy -Pexperiment=<ID> [-PverifyDeterminism] [-PallowDuringSession] [-PsnapshotsDir=...]`, 별칭 `:autotrade-sim:runWalkForwardStudy`. `ExperimentMain walkforward`가 D-063 정지 확인(장 시간 보호, 정지 요청 파일)을 넣는다. 종료 코드 0 완료, 1 입력 오류, 2 Run 실패나 결정론 불일치, 4 정지(결과 파일 없음). `WalkForwardMain`에는 `main`이 없어 정지 확인 없이 돌릴 길이 없다. 자원 부족 시 가장 먼저 멈추는 실험실 계열이며 실전 엔진 자원을 쓰지 않는다.

## 3. 대안 검토

| 선택 | 고른 것 | 버린 것과 이유 |
|---|---|---|
| Run 분리 | 구간·단계별 데이터셋과 새 계좌 | 한 데이터셋 전체 기간(메모리 큼), 계좌 이월(구간 독립성 깨짐) |
| 판정 곡선 | 시드로 나눠 이은 곡선 | 구간 평균만(MDD·샤프 정의 불가), 단순 합(시드 크기 의존) |
| C10 | 경험적 p, 표본 N + 1 ≥ 20m이어야 판정 | 정규 근사 p(왕복당 손익 분포가 꼬리가 두꺼움), 표본 부족을 통과로 처리(위험) |
| 대조군 0 왕복 | 분포에서 제외하고 개수 기록 | 0으로 포함(분포를 0 쪽으로 눌러 후보에 유리) |

## 4. 위험과 한계

- [가정] 계산량: 대조군 400 × 조합 10 × 4구간 규모는 Run 수천 개다. 초당 100만 이벤트 가정의 추정치이며 실측하지 않았다(`results.md` "계산량 추정"). 실제 규모 실험 전에 한 번 재서 보정한다.
- 상장폐지 뒤 손실 미반영(지수·계좌 모두 낙관), 가격 지수(배당 없음), 구간 경계 전량 현금화, 데이터셋마다 다른 가격 기준, 종목 이력 소속부를 마지막 일봉일 기준 한 구간으로 단순화(Q-012).
- 번들 거래소 캘린더는 2026~2027년만 수록한다. 스냅샷 날짜가 그보다 앞서면 거래일은 일봉 날짜로 정하고(대조는 겹치는 기간만) 합성 테스트로 2022~2025 구간이 도는 것은 확인했지만 실제 수집 스냅샷(2010~)으로는 검증하지 못했다.
- `random-daily` 대조군은 예열 구간에서도 난수를 쓰므로 `warmup-days`가 바뀌면 같은 시드의 진입일이 달라진다(결정론에는 영향 없음).
- 검증하지 못한 것: 실제 KRX 스냅샷 전체 규모 실행(메모리·시간), 대조군 400 규모의 C10 통과 가능성.

## 5. 검증

- 단위: 파서(모르는 키·중복·구간 수 하한), 구간 계산(윤년·휴장 경계·범위 밖), 예열(전략만 봄, 체결·평가 없음, 미래 누출 없음, 0이면 동일, 부족하면 거부), 구간 끝 정리 손 계산, 벤치마크 손 계산, 판정 경계값(3/4 올림, C3 20% 경계, C5 29·30건, C10 N + 1 = 20m, p 경계).
- 통합: 합성 스냅샷(2021-10~2025-12, 3종목)으로 등록 파일 → 결과 파일, 병렬 1과 N의 결과 바이트 일치, 같은 입력 두 번 실행 일치, 정지 확인 시 결과 파일 없음, 범위 밖 구간 거부.
- 기존 골든·조합 실험·합성 실험 테스트와 ArchUnit 통과(패키지 `com.autotrade.sim.walkforward`는 `autotrade-sim` 소유).

## 6. 결정 필요 항목(코디네이터에게)

1. 결정 로그 번호 부여(이 ADR은 D-071의 실행 계약이며 새 D 번호가 필요한지).
2. 번들 캘린더 수록 범위(2026~2027) 밖 과거 구간에서 `KrxMarketRules`가 쓰는 장 시간·휴장 정보를 어떻게 다룰지(data-engineer, 현재는 일봉 날짜로 거래일을 정함).
3. 결과 묶음과 실험실 화면 연동 범위.
