# D-027 4단계 전략 탐색의 프로필 형식, 공통 매매 골격, 1차 선별 기준

- 날짜: 2026-10-08
- 상태: 확정, **추천안 채택(자율)** (project-instructions.md 8장). 모의 실험 규칙이며 실전 주문 경로·RealTradingGuard·실전 리스크 한도와 무관하다. 승격 기준 수치 확정은 Q-013으로 남긴다(사용자 결정)
- 근거: 기획서 STR-01~14, SIM-05, autotrade-strategy-lab 스킬 1~5장, role-guides.md 5·8장, D-021, D-025, ADR-004
- 담당: strategy-researcher. 검토: architect(모듈 경계·결정론·미래 정보·계약 사용, 조건부 승인. 지적 M2·M3·L1~L7은 이 PR에서 반영, M1은 임시 조치 + 변경 제안)

## 결정

1. **프로필 파일 형식**: 배치와 파일 모양은 D-026(ADR-005 4장)의 `strategies/<프로필ID>/v<버전>.yaml`을 따른다(최상위 `id`·`version`·`market`·`style`과 기록용 `based-on`·`created-at`·`note`, `parameters` 아래 평평한 점 키와 문자열 값). 실험 실행기는 순수 모듈의 `ProfileYaml`로 이 모양의 부분집합(UI가 쓰는 여러 줄 큰따옴표 문자열 포함)만 읽고, UI 저장소와 같은 해시로 읽는지 app-lab 테스트가 저장소 프로필 전부로 확인한다. 로직이 쓰지 않는 키는 거절한다(`hypothesis`, `study.*`, `notes.*` 제외). 실험은 프로필을 `ID@버전`으로 고정한다. 키 목록은 [strategies/README.md](../../strategies/README.md).
2. **공통 매매 골격**: 진입 로직(주 신호)만 프로필마다 다르고, 신호 만료·확인 신호(STR-07), 비중·한도(STR-12), 청산(STR-09)은 `ManagedStrategy` 한 코드로 처리한다. 진입·청산은 시장가. 수량 = min(위험 금액 / (가격 × 손절폭), 종목당 상한, 현금 여유 / (가격 × 1.003)). 기본값 `[가정]`: 신호 만료 600초, 거래당 위험 0.5%, 종목당 20%, 동시 3종목, 현금 여유 5%, 하루 진입 6건, 재진입 금지 30분, 당일 손실 2%에서 진입 중단, 연속 손절 3회에서 진입 중단, 장중 15:10 전량 청산.
3. **첫 카탈로그**(STR-06): ORB, VWAP 회복, 전일 고점 돌파, 거래량 폭증, 호가 불균형, 눌림목(장중 6), 이동평균 추세(스윙 1), 매수 후 보유(기준선), 무작위 진입(대조군). 장전 후보 풀·스크리너 점수화(STR-03·08·10·11)는 일봉 스냅샷(PR #10) 뒤로 미룬다.
4. **실험 절차**: 학습·검증(표본 외) 구간 분리, 같은 시드·비용·체결 모델, 지연 0·0.5·1.5·2초 전부 실행(STR-13), 핵심 파라미터 ±20% 변형은 학습 구간에서만, 무작위 진입 대조군을 시드만 바꿔 20번, 같은 실험을 병렬 수만 바꿔 다시 돌려 결과 바이트 일치 확인.
5. **1차 선별 기준**(검증 구간, 지연 0.5초, 모두 통과해야 후보): C1 매수 후 보유 대비 초과수익 > 0, C2 PF ≥ 1.3, C3 MDD ≤ 20%, C4 샤프 ≥ 1.0, C5 왕복 ≥ 30, C6 검증 하루 수익률 ≥ 학습의 60%, C7 ±20% 변형이 원래 수익률의 50% 이상·PF ≥ 1.0 `[가정]`, C8 최고 1주 제외 후에도 수익, C9 지연 2초에서 수익·PF ≥ 1.0 `[가정]`, C10 왕복당 순손익이 대조군 분포 95분위 초과 `[가정]`. C1~C6·C8은 스킬 5장 기본값, C7·C9·C10의 수치는 이번에 정한 가정값이다.
6. **합성 시세는 파이프라인 검증용**: 녹화 데이터(PR #10)가 쌓이기 전에는 `SyntheticMarket`(모형 `SYNTH-KRX-V1`) 데이터로 절차를 끝까지 돌린다. 합성 데이터 결과로는 후보를 고르지 않고, 승격 제안서의 근거로 쓰지 않는다.

## 대안 비교

| 선택 | 대안 | 판단 |
|---|---|---|
| 순수 모듈에서 UI 파일 모양의 부분집합 직접 읽기 | A. 순수 모듈에 Jackson YAML(jackson-dataformat-yaml) | 버림. 순수 모듈 의존이 늘고, 손으로 쓴 따옴표 없는 값의 타입 추론(`on` → true)으로 해시가 흔들릴 수 있다. 두 읽기의 일치는 호환 테스트로 묶는다. 목록이 꼭 필요해지면 되돌린다 |
| D-026 배치(ID 폴더 + 불변 버전 파일)를 따름 | A'. 처음 쓴 `strategies/<ID>.yaml` 중첩 맵 유지 | 버림. UI가 먼저 머지됐고, 불변 버전 파일이 실험 추적(해시)에 더 맞다. 옮겨도 파라미터가 같아 9개 프로필 해시는 그대로다 |
| 공통 골격 + 진입 로직만 교체 | B. 로직마다 청산·비중을 따로 구현 | 버림. 성과 차이가 진입 로직이 아니라 청산 구현 차이에서 나올 수 있어 비교가 오염된다 |
| C10 왕복당 순손익 비교 | C. 총수익률을 대조군과 비교 | 버림. 대조군(96건)과 후보(7~40건)의 거래 수가 달라 비용 부담 차이가 섞인다(첫 시험 실행에서 확인) |
| 대조군 = 무작위 진입, 청산 같음 | D. 다중 비교 보정(Bonferroni 등)만 | 보완 관계. 표본이 작아 p값 근사가 불안정하므로 같은 청산 규칙의 무작위 진입 분포를 경험적 기준으로 쓰고, 비교한 프로필 수는 리포트에 적는다 |
| 합성 데이터로 먼저 절차 검증 | E. PR #10 머지까지 대기 | 버림. 실험 절차·선별 기준·리포트 형식은 데이터와 무관하게 만들고 검증할 수 있다 |

## 위험과 한계

- 기본 파라미터와 C7·C9·C10 수치는 근거 없는 가정이다. 너무 엄격하면 쓸 만한 기법을 버리고, 너무 느슨하면 우연을 고른다. 녹화 데이터 실험 결과로 Q-013에서 다시 정한다.
- 합성 데이터의 성질(추세일 모멘텀, 횡보일 평균 회귀, 3초 간격)은 생성기가 정한 것이라 그 위의 성과는 실제 시장 정보가 아니다.
- 시장가 진입만 쓰므로 지정가 진입(체결 대기·앞선 잔량)이 유리한 기법은 지금 비교에서 불리하다. 신호 취소 계약이 없어(TradeSignal에 취소 없음) 지정가 진입은 sim-engine 변경 후로 미룬다.
- 실행기는 구간마다 전략을 새로 만들고 구간 밖 시세를 주지 않는다. 지난 거래일이 필요한 프로필(이동평균 8일, 전일 고점 1일)은 구간 앞부분에 신호가 없다. 지금은 프로필의 `study.warmup-days`(사전 등록)만큼 C6 하루 평균에서 빼는 임시 조치이고, 예열 구간 계약은 sim-engine 변경 제안이다(architect 검토 M1).
- `exit.eod-time`이 실제 마지막 시세보다 늦으면 장중 포지션이 이월된다. `MarketRules`에 정규장 끝 시각 조회가 없어 검증하지 못한다(architect 검토 L8, 변경 제안).
- 리스크·거래소에서 거절된 진입도 하루 진입 수에 센다(보수적, architect 검토 L9).
- 청산 사유는 손절 의도 여부만 원장에 남는다. 사유 코드(STR-09 인수 조건)는 실행기 변경이 필요하다(변경 제안, 아래).

## 되돌릴 조건

- 녹화 데이터 첫 실험에서 장중 프로필 대부분이 C5(왕복 30건)에 못 미치면, 장중 기준을 Q-013에서 따로 정한다(STR-14 "장중 프로필은 녹화 기간이 짧아 별도 기준").
- 대조군 분포가 시드에 따라 크게 흔들리면(20개로 95분위가 불안정) 대조군 횟수를 늘린다.
