# D-020 UI 형태: 로컬 웹 대시보드 (Spring Boot + 경량 프런트, SSE) (D5)

- 날짜: 2026-10-08
- 상태: 확정, **추천안 채택(자율)** (project-instructions.md 8장). Q-005 닫음
- 근거: team-design.md 8장 D5, team-design.md 2.1(v5 UI: SSE + 페이징, v6 모니터링 웹), broker-and-fault-design.md 5.1(UI는 읽기 전용 경로)
- 담당: ui-dev, architect(모듈 경계), risk-ops(실전 제어 화면 검토)

## 결정
1. UI는 개인 PC에서 띄우는 **웹 대시보드**다. 서버는 Spring Boot(`autotrade-app`), 화면은 `autotrade-ui` 모듈의 경량 프런트(빌드 산출물을 정적 리소스로 서빙).
2. 실시간 갱신은 **SSE**(서버 → 브라우저 단방향), 목록 조회는 페이징 REST.
3. 기본 바인딩은 `127.0.0.1`(로컬 전용). 외부 접근은 범위 밖이며, 필요해지면 인증 설계와 함께 새 결정으로 다룬다.
4. 조회는 실전 엔진의 스냅샷만 읽는다. 실전 제어 명령(활성화, PANIC SELL)은 별도 명령 채널로 검증 후 반영한다(broker-and-fault-design.md 5.1, 기획서 10장). UI가 죽어도 실전 엔진은 영향받지 않는다.
5. 프런트 프레임워크 선택(예: 서버 렌더링 템플릿 + htmx, 또는 경량 SPA)은 ui-dev와 architect가 ADR로 정한다. 유료 라이브러리는 쓰지 않는다(쓰려면 과금 항목으로 사용자에게 묻는다).

## 대안 비교
| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **A. 로컬 웹 대시보드** | 기존 설계(SSE, 웹 모니터링)와 일치, 같은 JVM 생태계, 브라우저만 있으면 됨 | 브라우저 탭 관리 필요 | **채택** |
| B. 데스크톱 앱(JavaFX 등) | 단일 창, 오프라인 친화 | 기존 웹 설계 재작성, 모니터링 웹과 이중화 | 버림 |
| C. 별도 SPA 서버(Node) | 프런트 생태계 풍부 | 런타임 추가, 개인 PC 자원 소모, 프로세스 늘어남 | 버림 |

## 위험과 한계
- 로컬 웹이라도 같은 PC의 다른 프로그램이 접근할 수 있다 `[추론]`. 완화: 루프백 바인딩, 실전 제어 명령은 2차 확인과 명령 채널 검증, 비밀값 마스킹(role-guides.md 7장).
- SSE 스트림이 자원을 쓰므로 자원 부족 시 갱신 주기를 1초 → 5초로 늦춘다(broker-and-fault-design.md 5.2 4번).

## 되돌릴 조건
- 모바일·원격 확인이 필수 요구가 되면(인증·네트워크 노출 필요) 새 결정으로 다룬다. 이는 범위 변경이므로 사용자에게 묻는다.
