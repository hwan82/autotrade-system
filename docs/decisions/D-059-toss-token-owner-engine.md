# D-059 토스 토큰은 실전 엔진만 갖는다 (Q-042 ②)

- 날짜: 2026-10-11
- 상태: 확정 · **사용자 결정**(2026-10-11T09:23:38Z, 결정 카드에서 "실전 엔진만" 선택)
- 담당: architect(문서), risk-ops(검토)
- 근거: [D-053](D-053-toss-rest-read-only-client.md) ③·④, [토스 명세 요약](../research/toss-openapi-spec.md), [ADR-003](../adr/ADR-003-market-data.md) 4장과 "risk-ops 7단계 요구 사항", 지침 4장 절대 규칙 6
- 범위: 결정과 문서만. 코드·설정 기본값 변경과 강제는 토스 연결 PR(실전 관련, 사용자 머지)에서

## 배경

[사실] 토스 토큰은 Client ID당 하나만 유효하고, 새로 발급하면 이전 토큰은 즉시 `token-revoked`(401)가 된다(D-053, 토스 명세 요약). 호출 한도도 Client ID × Rate Limits Group 단위다.
[사실] 게이트웨이와 실전 엔진이 같은 Client ID로 각자 토큰을 받으면 서로의 토큰을 끊는다. 토큰을 프로세스끼리 나눠 쓰면 실전 엔진이 다른 프로세스에 기대게 되어 절대 규칙 6과 부딪힌다.
[사실, 사용자 확인 2026-10-11T09:37:41Z] 토스 WTS의 Open API 설정 화면에서 Client ID를 하나 더 만들 수 없다(Q-042 ①). 그래서 토큰을 쓸 프로세스는 하나뿐이다.

## 결정

1. **토큰 소유**: 토스 토큰은 실전 엔진 한 프로세스만 발급받고 쓴다. 보호 폴링(현재가 `TOSS-POLL`)과 7단계 주문·잔고 조회는 같은 토큰 캐시를 쓴다(ADR-003 4장).
2. **게이트웨이·실험실**: 토스 API를 호출하지 않는다. 감시 프로세스도 평상시에는 토스를 호출하지 않는다. 다만 실전 엔진이 멈췄을 때 감시가 토스 계좌에 긴급 청산을 보내는 경로(MON-02, [broker-and-fault-design.md](../team/broker-and-fault-design.md) 5.1)는 결정 카드가 묻지 않았으므로 이 결정에 넣지 않고 Q-048로 사용자 결정을 받는다. 실시간·REST 보정 시세는 키움·한국투자로만 받는다. 이 범위에서 D-024·D-039의 "토스 실시간 2순위"와 `market-data.priority` 기본값 중 `TOSS` 항목은 쓰지 않는다(D-024·D-039의 다른 내용은 그대로).
3. **강제**(토스 연결 PR에서 구현): 실전 엔진 밖에서 토스 호출기(`TossRestClient`·`TossTokenClient`)를 만들 수 없게 설정 검사나 테스트로 막는다(PR #41 architect N7). 게이트웨이 `market-data.priority`에 `TOSS`가 있으면 기동 시 경고하고 건너뛴다. 기본값을 `["KIWOOM","KIS"]`로 바꿀지는 그 PR에서 config-keys.md와 함께 정한다.
4. **연결 전 조건**은 그대로다: ADR-003의 토스 연결 PR 전 조건(risk-ops R1~R10, QA N1·N2). R1의 "다른 프로세스는 재발급 금지"는 이 결정으로 "다른 프로세스는 토스를 호출하지 않음"이 된다.

## 대안과 되돌릴 조건

| 선택 | 버린 대안 | 이유 |
|---|---|---|
| 실전 엔진만 | 게이트웨이만 | 실전 엔진의 토스 보호 폴링(D-024)이 사라져 손절 감시용 보호 경로를 따로 만들어야 함 |
| 실전 엔진만 | 토큰 공유(한 프로세스가 받아 나눠 줌) | 실전 엔진이 다른 프로세스의 생존·응답에 기대게 됨(절대 규칙 6) |
| 실전 엔진만 | 아직 안 정함 | 토스 연결 작업(R1·R4·N7)의 기준이 없어 진행 불가 |

- **되돌릴 조건**: 토스가 Client ID를 두 개 이상 발급하도록 바뀌면(2026-10-11 확인 때는 불가), 게이트웨이용 Client ID로 토스 실시간 2순위를 되살릴지 새 D 번호로 사용자에게 묻는다. 이때도 실전 엔진의 Client ID·토큰은 게이트웨이와 나누지 않는다.

## 위험과 한계

- 실시간 소스가 키움·한국투자 둘뿐이라, 두 곳이 모두 DEGRADED면 실험실·녹화의 실시간 시세가 끊긴다. 토스가 설정되고 ACTIVE일 때는 실전 엔진의 토스 보호 폴링이 보유 종목을 지킨다. 토스가 설정되지 않았거나 DEGRADED(`token-revoked` 뒤 10분 정지 포함)일 때는 키움·한국투자 폴링이 추가될 때까지(ADR-003 7단계 전 필수) 보호 시세 경로가 없다.
- 실전 엔진이 멈춘 동안 토스 계좌 보호는 서버 측 손절(D-012)과, Q-048이 정해지면 감시 긴급 경로뿐이다.
- 토스 보유 종목도 게이트웨이 실시간에서는 키움·한국투자 구독 한도 안에서만 받는다. 한도 초과 시 `unservedHeld` 알림(ADR-003 risk-ops 확인 요청)과 보호 폴링에 기댄다.
- **장애 테스트 1-T와 부딪힘**: [broker-and-fault-design.md](../team/broker-and-fault-design.md) 7.1의 1-T(토스 단독)는 게이트웨이 토스 실시간을 전제로 해서, 그대로 두면 토스 실전 계좌가 실전 활성화 조건을 채울 수 없었다. 이 PR에서 1-T를 "D-059 동안 해당 없음"으로 바꾸고 기존 조건은 D-059가 아닐 때로 한정했다. 대신 엔진 토큰을 끊을 수 있는 위험(엔진 밖 프로세스의 토큰 발급, 같은 Client ID를 쓰는 외부 도구, 두 번째 엔진)을 두 가지로 막는다: 1-0에서 실전 엔진 밖 모든 프로세스의 토스 미사용 확인, 새 1-TR(같은 Client ID로 토큰을 새로 받아 엔진 토큰을 끊는 주입) 합격. 장애 대응 기준 변경이므로 Q-047로 기록하고 사용자 머지로 확정한다(PR #47 architect B7, risk-ops A12, 독립 QA F2).
- 토스를 빼면 미국 프리·애프터·데이마켓 실시간 범위가 줄 수 있다 `[추론]`. 키움·한국투자의 미국 장외 세션 실시간 지원 여부는 확인하지 않았다(확인 방법: 각 사 미국 실시간 명세의 세션 구분, 2단계 실측). 확인 전까지 장외 세션 전략의 실시간 실험은 수신 범위를 결과에 표시한다([overseas-design.md](../team/overseas-design.md) 6장, 독립 QA F1).
- 두 번째 실전 엔진이 같은 설정 폴더로 뜨면(`run/engine.lock` 삭제, ADR-006, Q-018 미결) 두 엔진이 토스 토큰을 서로 끊는다. Q-018의 중요도가 D-059로 올라갔다(독립 QA R2).
- 토스를 뺀 게이트웨이 실시간 수용량은 키움 세션당 200종목과 한국투자 appkey당 41건이다([시세 조사](../research/market-data-limits.md) 1장, 계정 수에 따라 달라짐).
- 실전 엔진 한 프로세스가 토스 Client ID의 호출 한도를 혼자 쓰므로 프로세스 간 한도 배분(R4)은 "실전 엔진 안의 보호 폴링 우선(R8)"으로 좁혀진다.
