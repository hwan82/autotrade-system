# D-139 선정 지표 `turnover`: 실제 거래대금(`ACC_TRDVAL`) w거래일 평균(D-133 6번)

- 날짜: 2026-10-24
- 상태: 확정 · **추천안 채택(자율)**(지침 8장). 지표 정의와 결측 규칙은 D-133 6번에서 strategy-researcher와 상담해 적어 둔 제안 그대로다.
- 담당: sim-engine(구현), strategy-researcher(정의). 교차 검토: architect(코드·결과 형식), strategy-researcher(지표 정의)
- 근거: [D-133](D-133-krx-actual-turnover.md) 6번, [ADR-012](../adr/ADR-012-intraday-selection.md) 3.2(49행)·6장 후속 F1, PR #193 strategy-researcher R2(근사 c 종가 × 거래량은 고가 마감 쪽으로 기운다), [ADR-007](../adr/ADR-007-selection-combination.md) 2.6
- 선행 조건 확인 `[사실, 사용자 PC]`: 2026-10-22 첫 실행 스냅샷 `krx-daily-2026-10-21-6e06b0ff`에 `ACC_TRDVAL` 9,701,603행, 값 없는 일봉 0건, 범위 밖 18,625행(0.19%, 경고만), 오류 0(runbook collector.md 3.8).
- 번호: main 최신은 D-138(PR #231)이고 열린 PR #232는 새 D 번호를 쓰지 않아 D-139를 쓴다.
- 바꾸는 코드: `autotrade-selection`(지표·읽기·결과 칸), `autotrade-sim`(입력 잇기·결과 파일 읽기), `autotrade-app-lab`(결과 묶음 읽기·카탈로그 설명), 화면 이름표 한 줄. 실전 경로, RealTradingGuard, 블랙리스트, 리스크 한도, 게이트웨이, 수집기, 보호 경로(`autotrade-marketdata` 포함)는 바꾸지 않는다.

## 결정

1. **정의**: `turnover`(Kind `TURNOVER`, 기간 `window` w, 1~250) = c에서 끝나는 w거래일의 그 종목 `ACC_TRDVAL` 합 ÷ w. 원 단위, 수정 계수를 곱하지 않는다(금액은 분할에 불변). 계산은 다른 지표처럼 합·나눗셈을 `DECIMAL128`로, 값만 `DECIMAL64`로 한 번 줄인다. 자격 조건과 점수 둘 다 쓸 수 있고, KRX 선정만 받는다(미국 선정이면 해석 단계에서 거부).
2. **입력**: 일봉 스냅샷 폴더의 선택 파일 `daily_turnover.csv`(D-133). 새 읽기 클래스 `SnapshotTurnover`(selection 모듈)가 manifest의 SHA-256·행 수와 맞춰 보고, 한 행이라도 형식이 틀리면(시장·코드·날짜·0 이상 정수 금액) 또는 같은 종목·날짜가 두 번 있으면 스냅샷 전체를 거부한다.
3. **결측 규칙**(D-133 6번 제안 그대로):
   - 스냅샷에 파일이 없음(D-133 전 스냅샷, `--without-turnover`) → 그 선정 계산 전체 실패. 근사 `avg-turnover`로 조용히 바꾸지 않는다. 메시지에 `daily_turnover.csv가 없습니다`(실시간 모의 준비는 `PRODUCER_FAILED`로 남김).
   - 파일의 가장 늦은 날짜가 c보다 이르면(또는 행이 없으면) → `STALE_INPUT:`으로 시작하는 메시지로 계산 실패(실시간 모의 준비는 `STALE_INPUT`으로 남김, `SelectionPreparer`).
   - w거래일 중 하루라도 그 종목 행이 없음 → 그 종목만 `GATE_<nn>_NO_DATA`(점수면 `SCORE_NO_DATA`). 0으로 채우지 않는다.
   - 거래정지일 0원 행은 0으로 평균에 넣는다. 일봉 행이 있는지는 보지 않는다(거래대금 파일만으로 계산).
4. **결과 칸**: 실제 거래대금 조건이 있는 선정만 결과 `inputs.turnover = {"sha256": <daily_turnover.csv SHA-256>, "last_date": <파일 가장 늦은 날짜>}`를 쓴다. 스냅샷 ID는 일봉과 같아(D-133 3번, ID 해시가 두 파일을 덮음) 따로 두지 않는다. 조건이 없으면 키를 **아예 쓰지 않아** D-139 전 결과의 내용 해시는 그대로다(공시 칸 D-123과 같은 규칙). 결과 파일 읽기(`SelectionResultFile`)와 결과 묶음 읽기(`ResultBundleReader`)가 이 칸을 되살린다.
5. **읽는 시점**: 실험 입력(`SnapshotInputs`)은 manifest에 거래대금 파일이 있으면 읽는 함수만 넘기고, `turnover` 조건이 있는 선정이 처음 계산될 때 한 번 읽는다(로그 `실제 거래대금 읽기: …`). 쓰지 않는 실험·준비 작업은 970만 행을 읽지 않는다. 읽은 값은 일봉과 스냅샷 ID가 같아야 받는다.
6. **바꾸지 않는 것**: 기존 지표 `avg-turnover`(정의·값·해시), 기존 프로필 전부(`kr-watchlist-turnover@1`, (다)(라)와 그 하루 늦춘 판), 등록된 실험(EDGE01·EDGE04·LIVE01, D-138)과 그 결과, 감시 종목 목록(D-122, LIVE01·LIVE02 동안 불변). `turnover`를 쓰는 프로필 v2는 LIVE02 등록 뒤 새 EDGE 실험(새 ID)에서 만들고 v1과의 선정 겹침을 기술 통계로 남긴다(D-133 6번).

## 대안

| 안 | 내용 | 판단 |
|---|---|---|
| A. `avg-turnover` 정의를 실제 거래대금으로 바꿈 | 지표 하나 | 버림. 같은 프로필의 해시·결과가 바뀌어 EDGE01·EDGE04·LIVE01 고정 결과와 비교할 수 없다(D-133 6번) |
| **B. 새 지표 `turnover`, 정지일 0원 포함, 행 없음은 NO_DATA** | 이번 결정 | 채택. 근사와 실제를 같은 스냅샷에서 나란히 계산할 수 있고 기존 결과 불변 |
| C. 정지일(0원)을 빼고 나머지 날로 평균 | 정지 영향 제거 | 버림. 오래 정지했던 종목의 평균이 부풀어 유동성 조건을 잘못 통과한다. `volume-spike`가 정지일을 `NO_DATA`로 두는 것은 비율 지표라 분모가 줄면 배율이 커지기 때문이고(PR #193 M1), 금액 평균은 0을 넣는 쪽이 "그 기간 실제로 거래된 금액"에 맞다 |
| D. 행 없는 날을 0원으로 채움 | 결측 없음 | 버림. 상장 전·KRX 미제공과 실제 0원을 구분하지 못한다 |
| E. 실험 입력을 읽을 때 늘 거래대금 파일을 같이 읽음 | 단순 | 버림. 쓰지 않는 실험도 970만 행을 읽는다(지금 등록된 실험은 모두 쓰지 않음). 필요할 때 읽어도 계산 결과는 같다 |
| F. 결과 칸에 `snapshot_id`도 둠 | 명시적 | 버림. 일봉 `snapshot_id`와 늘 같아 두 값이 어긋나는 경우만 새로 생긴다 |

**되돌릴 조건**: 실제 거래대금이 근사보다 선정을 나쁘게 만든다는 근거가 v2 EDGE 실험에서 나와도 지표는 그대로 두고 프로필만 고르지 않는다. 파일 형식이 바뀌면(D-133 되돌림) 이 지표를 쓰는 선정은 1번 결측 규칙대로 계산이 멈추므로 새 결정으로 읽는 쪽을 맞춘다.

## 위험과 한계

- KRX `ACC_TRDVAL`에는 시간외 거래·대량매매가 들어갈 수 있다 `[추론]`(D-133 5번). 장중 단타 유동성의 근사로는 근사 `avg-turnover`보다 나을 수도 못할 수도 있다. 판단은 v2 EDGE 실험으로 한다.
- 파일의 첫 날짜는 따로 확인하지 않는다(일봉과 같이 수집 시작일부터 있음). 수집 구간보다 앞선 날이 창에 들어가면 그 종목들이 `NO_DATA`로 빠진다. 일봉 지표(`avg-turnover`)도 같다.
- 힙: 종목별 날짜(int)·금액(long) 배열로 행당 약 12바이트 + 종목당 배열 머리. 970만 행이면 약 120MB `[추론]`로, 일봉 행당 1KB 추정(`SnapshotHeap`, 970만 행이면 약 9.7GB)에 견주어 작아 따로 힙 검사를 두지 않는다. 읽는 중에는 배열 확장 여유·복사본·종목 키가 함께 살아 순간 최대는 그 2~3배일 수 있다 `[추론]`(PR #233 architect F3). 실측(순간 최대 포함)은 v2 EDGE 실험 때 한다.
- 읽기 시간: 970만 행 한 번 훑기(SHA-256 포함). 사용자 PC에서 첫 v2 실험 때 로그 시각으로 확인한다(미측정).
