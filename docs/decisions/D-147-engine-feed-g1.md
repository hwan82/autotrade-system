# D-147 실전 엔진 시세 통로 G1 구현(엔진 전달 서버·받는 쪽·줄 형식·ArchUnit)

- 날짜: 2026-10-27
- 상태: 제안. 아래 결정 1~9는 **추천안 채택(자율)**(지침 8장, architect 추천안). `autotrade-marketdata`(보호 경로)와 보호 테스트(`autotrade-architecture-test`)를 바꾸므로 실전 관련 PR이다: architect·risk-ops 검토 → 독립 QA → **사용자 직접 머지**(지침 10·11장). 머지가 이 기록의 최종 확인이다
- 근거: [ADR-016](../adr/ADR-016-real-engine-market-feed.md)(D-143) 2.2~2.5·5장 G1, architect PR #245 검토 [N6·N7](../reviews/pr-245/architect.md), risk-ops PR #245 R5, QA PR #245 Q4, QA PR #87 R1
- 담당: architect(주관). 검토 risk-ops(실전 입력 경로·보호 테스트)
- 범위: `com.autotrade.marketdata.enginefeed`(줄 형식·받는 쪽·소켓 위치), `com.autotrade.marketdata.enginefeed.server`(서버), 경계 규칙 `EngineFeedBoundaryTest`. **게이트웨이·엔진 실행부에는 아직 연결하지 않는다.** 게이트웨이·녹화·실험실 전달 동작은 바이트 하나 바뀌지 않는다(LIVE01 진행 중). 연결은 G2(게이트웨이, 구독 계획)·G4(엔진)

## 결정(추천안 채택(자율))

## 검증

- [사실] 컨테이너(4코어) `./gradlew :autotrade-marketdata:test`·`:autotrade-architecture-test:test` 통과. 엔진 전달 시험 29건(줄 형식 5, 서버 18, 받는 쪽 5, 지연 1)은 세 번 연속 통과.
- [사실] 지연 시험(읽지 않는 실험실 받는 쪽 4개 + 녹화 + 엔진, 초당 약 5,000건, 관심 128/200종목, 측정 40,000건): `publish` p99.9 17~32µs(기준 50µs), 콜백 → 엔진 줄 해석 p99 1.3~4.1ms(기준 10ms), 최대 16~32ms(기준 200ms), 엔진 큐 버림 0. 실험실 받는 쪽은 읽지 않아 버림(조건 확인).
- 검증하지 못한 것: 사용자 PC(Windows) 소켓·권한·타이머 해상도와 지연 기준(7단계 절차서 I1), 실제 게이트웨이 수신 콜백에서의 지연(G2), 엔진 쪽 판단(G4). ADR-016 5장 9번(엔진 없음 바이트 동일)과 17번의 게이트웨이 콜백 부분은 게이트웨이를 바꾸는 G2에서 한다.

## 위험과 한계

- 쓰기 스레드가 비었을 때 0.5ms마다 깨어난다(Linux 초당 약 2,000번, CPU는 적음). Windows에서 0.5ms 쉬기가 실제로는 1~16ms로 늘 수 있다 `[가정]`. 그러면 엔진 전달 지연이 그만큼 늘고 기준 ②를 넘을 수 있다(되돌릴 조건 2번).
- 컨테이너 지연 측정은 CI 러너 성능에 따라 흔들릴 수 있다. CI에서 기준을 넘으면 G5 판단 근거로 다루고, 시험을 느슨하게 고치지 않는다.
- 같은 OS 사용자 프로세스의 선점·거짓 서버 위험은 ADR-016 4장 그대로다(이 PR이 줄이거나 늘리지 않는다).
