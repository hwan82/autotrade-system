## 결정

| # | 질문 | 결정 |
|---|---|---|
| ① | Q-016 재기동 직후 보유가 남은 OFF 계좌의 PANIC SELL | PANIC 2차 확인을 보호 모드 진입 확인으로도 보고 OFF → PROTECTIVE로 올린 뒤 매도한다. 조건: 매도 전 보유 대사를 먼저 하고, 전체 PANIC에서 OFF 계좌를 올리는 것은 계좌마다 확인을 받으며, 어느 단계든 실패하면 PROTECTIVE에 남긴다(OFF로 되돌리지 않음) |
| ② | Q-017 장 외 시간 PANIC SELL 때 Guard | 끄지 않는다. 보호 모드 유지(미체결 매수만 취소, 서버 측 손절 유지). 기획서 v13 RSK-13의 "장 외 시간에는 미체결 취소와 Guard OFF만" 문구를 이 결정으로 대체한다 |
| ③ | Q-018 "엔진 실행 중 run 폴더 삭제" 장애 테스트 | 장애 테스트 3번의 하위 항목 **3-R**로 넣어 실전 활성화 전 합격 조건으로 둔다. "장애 테스트 8종"이라는 수는 그대로다. 합격: 두 번째 엔진 기동이 막히거나 첫 엔진이 잠금·소켓 변경을 감지해 긴급 알림, 화면이 "가상"으로 바뀌지 않음, 토스 토큰 무효화 없음 |
| ④ | Q-057 PANIC에서 VI 발동 종목 | **매도 가능**으로 본다. ⑤ 체결 확인 상한에 VI 단일가 시간(2분 + 최대 30초 `[가정]`)을 더하고, 상한 안에 체결되지 않으면 남은 보유에 서버 측 손절을 다시 건다. 거래정지·서킷브레이커·장 외 시간·상태 불명은 매도 불가. 계좌 안 일부 종목만 매도 불가면 **그 종목만 건너뛰고**(②의 매도 취소와 ③은 매도 가능 종목에만), 건너뛴 종목이 있으면 Guard OFF는 없다 |
| ⑤ | Q-058 RSK-11 일괄 취소와 서버 측 손절 | 일괄 취소 대상에 서버 측 손절 조건주문을 **넣지 않는다**. 일괄 취소는 엔진이 낸 미체결 일반 주문만 취소한다. PANIC의 서버 측 손절 재설정은 일괄 취소 시각 전에 끝내고, 일괄 취소가 방금 건 손절을 지우지 않음을 시험으로 고정한다 |
| ⑥ | Q-061 첫 실전 증권사 | **한국투자**. 게이트웨이 시세 1순위인 키움(D-024)을 그대로 두고, 모의 도메인으로 장애 테스트를 한다. 키움·토스 실전 계좌는 게이트웨이 시세 소스 문제(7단계 준비 계획 4.1 Q-061, `GatewayMain.reservedForRealTrading`)를 푼 뒤 붙인다 |

## 대안과 버린 이유
- 각 질문의 대안과 추천 이유는 [7단계 준비 계획](../team/stage-7-readiness-plan.md) 4.1장에 있다. 요약: ① 대안(건너뛰고 보호 모드 진입을 먼저 요구)은 재기동 직후 청산이 늦어 버림. ② 대안(Guard OFF)은 개장 직후 갭 하락 때 엔진 손절이 돌지 않아 버림. ③ 대안(9번째 시험, 넣지 않음)은 "8종"을 가리키는 문서 수정 부담·실전 위험 미검증 때문에 버림. ④ 대안(매도 불가, 해제 뒤 자동 진행)은 급락 중 청산이 막히거나 시험이 많아 버림. ⑤ 대안(매일 지우고 재설정)은 매일 방어선 공백과 재설정 실패 지점이 생겨 버림. ⑥ 키움은 게이트웨이 시세가 한국투자(appkey당 41건)로 넘어가 감시 종목을 줄여야 하고, 토스는 모의 환경이 없고 선행 조건이 많아 버림.

## 되돌릴 조건
- ④: 한국거래소 규정 원문이나 한국투자 공지가 "VI 중 매도 호가 접수 불가" 또는 다른 단일가 시간을 말하면 새 결정으로 다시 연다(지금 근거는 증권사 안내 2차 자료).
- ⑤: 한국투자 조건주문의 유효 기간이 하루뿐이면 매일 재설정 규칙(S4)이 필요하며, 그 경우에도 일괄 취소가 손절을 지우지 않는다는 원칙은 유지한다. 원칙을 바꾸려면 새 결정.
- ⑥: 한국투자가 서버 측 손절을 지원하지 않으면(Q-002) 실전 활성화 화면에 "PC 장애 시 보호 수단 없음" 경고(broker-and-fault-design.md 6.1)를 띄우고, 사용자에게 첫 증권사 유지 여부를 다시 묻는다.
