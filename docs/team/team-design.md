# 자동매매 프로그램 개발팀(프로젝트) 구성안

작성일: 2026-10-08 (같은 날 개정: 시세 소스 정정) · 근거: 업로드된 기획 문서 15개(v1.0~v11.0, ChatGPT 설계서 2종)와 2026-10-08 요청

---

## 1. 요약

- 이번 요청의 핵심은 **증권사 모의투자 API 없이, 실전 API로 받은 실시간 시세 위에서 자체 시드머니 모의 계좌로 돌아가는 "다중 전략 시뮬레이션 실험실"** 입니다. 주문은 증권사로 나가지 않고 자체 가상 거래소에서 실전처럼 체결합니다. 기존 기획안 v8~v11은 가상매매 엔진을 "실전 주문의 우회 경로" 하나로만 다뤘고, **여러 전략 유형을 같은 기간에 병렬로 돌려 비교·선발하는 구조**는 없었습니다. 이 부분을 시스템의 중심으로 다시 세웁니다.
- 팀은 **Claude 프로젝트 1개 + 역할 7개**로 구성합니다. 역할은 스레드 단위로 일하고, 공통 지침(프로젝트 지침)과 역할별 지침, 스킬 3개로 움직입니다.
- 개발 착수 전에 확정해야 할 결정이 남아 있습니다(8장). 시세 소스는 실전 API로 확정되었으므로, 가장 중요한 것은 **시세를 받을 증권사와 실시간 구독 한도**입니다.

| 8 | 거래세 0.18% 가정 | `[가정]` 현행 세율 확인 후 설정값으로 관리 |
| 9 | 3단 모드 REAL / MOCK_BROKER / VIRTUAL_ENGINE | VIRTUAL_ENGINE을 기본 모드이자 실험 플랫폼으로 승격, MOCK_BROKER는 선택 사항 |

## 3. 시뮬레이션 실험실 핵심 개념 (새로 정의)

```
[실전 API 실시간 시세]  ── 체결·호가 WebSocket (주문 API는 호출하지 않음)
        │ 같은 시세를 모든 실험 계좌가 공유 + 전량 녹화(틱/호가/분봉)
        │                                         └─▶ [녹화 리플레이] 같은 날을 새 전략으로 다시 돌림
        ▼
[가상 거래소 VirtualExchange] ── 체결 규칙 + 비용 모델(수수료·세금·슬리피지)
        │
        ├─ 가상 계좌 A  ← 전략 프로필 "ORB돌파_ATR1.5_비중10%"
        ├─ 가상 계좌 B  ← 전략 프로필 "VWAP회복_고정손절3%"
        ├─ 가상 계좌 C  ← 전략 프로필 "스윙_점수상위20_2xATR"
        └─ ...           (각 계좌는 같은 시드머니로 독립 운용)
        ▼
[성과 분석] ── 수익률, MDD, 샤프, 승률, 손익비, 거래 수, 비용 비중
        ▼
[비교·선발] ── 리더보드 → 과최적화 검사 → 승격 후보
        ▼
[승격 단계] 실시간 모의(다중 계좌) → 녹화 리플레이로 재검증 → 실전 소액(RealTradingGuard ON)
```

| 개념 | 정의 |
|---|---|
| 전략 프로필 (StrategyProfile) | 종목 선정 + 매수 선별 + 진입 타이밍 + 비중 + 거래 건수 제한 + 청산 규칙 + 리스크 한도를 묶은 하나의 매매 기법. 버전과 해시를 갖고, 모든 거래에 스냅샷이 남음 |
| 실험 (Experiment) | 기간 × 시드머니 × 전략 프로필 N개 × 비용 모델. 같은 입력이면 항상 같은 결과(결정론) |
| 실험 실행 (Run) | 실험 1회 수행 결과. 계좌별 거래 내역, 자산 곡선, 성과 지표 |
| 체결 규칙 | 실시간: 실제 호가 잔량 기반(지정가는 앞선 잔량 소멸 후 체결, 시장가는 최우선 호가부터 잔량만큼 소진) + 지연 반영. 일봉 전략은 다음 날 시가 기준 |
| 녹화 | 실시간으로 받은 체결·호가를 날짜별로 저장. 새 전략을 과거 녹화일에 돌려 실시간 모의와 같은 조건으로 비교 |
| 구독 한도 | 모든 계좌의 감시 종목 합집합이 증권사 실시간 구독 한도 안에 들어가야 함. 장전 후보 풀(Stage 0)을 전략 공통으로 운용 |
| 선발 기준 | 비용 차감 후 성과, 최소 거래 수, 표본 외 구간 성과가 학습 구간의 60% 이상, 파라미터 ±20% 민감도 통과 |
| 승격 게이트 | 실시간 모의 최소 8주(선발 기준 통과, 주문 처리 오류 0건) → 녹화 리플레이로 표본 외 재검증 → 실전 소액(자산 10% 이하) |

## 4. Claude 프로젝트 구성

### 4.1 권장 구조: 프로젝트 1개, 역할 7개
| 구성 요소 | 내용 |
|---|---|
| 프로젝트 | "자동매매 시스템" 1개. 기획서, 결정 로그, 실험 결과를 한 곳에서 공유 |
| 프로젝트 지침 | [project-instructions.md](project-instructions.md)를 프로젝트 설정의 지침에 붙여 넣음 |
| 저장소 | GitHub 저장소 1개(Java 멀티 모듈)를 프로젝트에 연결 |
| 역할 | 스레드를 열 때 "역할: 시뮬레이션 엔진" 처럼 역할을 지정하면 해당 역할 지침([role-guides.md](role-guides.md))을 따름 |
| 스킬 | 기존 3개 + 이번에 만든 3개(5장) |
| 공유 파일 | `docs/spec/`(기획서), `docs/decisions/`(결정 로그), `experiments/`(실험 결과) |

프로젝트를 역할마다 나누지 않는 이유: 이 시스템은 모듈 간 계약(인터페이스, DB 스키마, 설정 키)이 촘촘해서, 프로젝트를 나누면 기획서와 결정 로그가 갈라집니다. 나중에 모니터링 agent처럼 다른 프로젝트에서도 쓰는 모듈이 커지면 그때 분리합니다.

### 4.3 협업 흐름
```
PM ──요구사항/결정──▶ 아키텍트 ──인터페이스/스키마──▶ 데이터 · 시뮬레이션 · 리스크 · UI
                                                         │
전략 연구 ◀──실험 플랫폼── 시뮬레이션 엔진 ◀──시세── 데이터
    │
    └─실험 리포트·승격 제안──▶ PM(결정 로그) ──▶ 리스크·운영(실전 가드 조건 반영)
```
- 모듈 간 계약(인터페이스, 테이블, 설정 키)이 바뀌면 아키텍트가 ADR을 쓰고 PM이 기획서에 반영합니다.
- 실전 매매 활성화와 관련된 변경은 리스크·운영 역할의 검토 없이는 병합하지 않습니다.

## 7. 이미 있는 자산 재사용
- ChatGPT 스크리너 기획서의 지표 카탈로그·가중치·리스크 기본값은 **전략 프로필의 첫 기본 세트**로 그대로 씁니다.
- ChatGPT 장중 설계서의 신호 카탈로그(ORB, VWAP 회복, 눌림목, 거래량 폭증, 전일 고점 돌파, 호가 불균형)는 **장중 전략 프로필 후보**로 씁니다.
- v9의 `virtual_trade_log.parameters_snapshot`(JSONB)은 그대로 두고, `experiment_id`, `run_id`, `account_id`, `profile_hash`를 추가합니다.
- 주문 무결성 9대 원칙은 가상 엔진에도 같은 코드 경로로 적용해, 실전 전환 때 동작이 달라지지 않게 합니다.
