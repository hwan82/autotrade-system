# D-113 6단계 실시간 모의 운영 등록(LIVE00 시험·LIVE01 8주)과 무사고·승격 판정 기준

- 날짜: 2026-10-19
- 상태: 1~5번 확정 · **추천안 채택(자율)**(지침 8장). 6번(장중 승격 후보 기준)은 승격 기준이라 사용자 결정으로 넘겼고(지침 8장 5번), 2026-10-19 사용자가 추천안 그대로 확정했다([D-114](D-114-intraday-live-promotion-criteria.md)). 실전 주문 경로·RealTradingGuard·블랙리스트 코드·리스크 한도·장애 대응·감시·게이트웨이 코드는 바꾸지 않는다
- 담당: strategy-researcher(등록·기준), sim-engine(점검 명령 후속 T1·T2), data-engineer(게이트웨이 감시 종목)
- 근거: 사용자 결정 "6단계 실시간 모의 운영(8주)을 4단계와 나란히 지금 준비"(PM 스레드 결정 카드, 2026-10-19), 로드맵 6단계, STR-05·13·14, D-023(사고 정의), D-027, D-066, D-071 1번, D-076, D-088
- 상세: [6단계 계획](../strategy/stage-6-plan.md), [시작 점검표](../runbooks/stage-6-start-checklist.md)

## 결정

1. **두 등록**: 시험 운용 `EXP-20261020-LIVE00`(2026-10-20~10-23, 성과 판정에 쓰지 않음)과 본 운용 `EXP-20261026-LIVE01`(2026-10-26~12-18, 40거래일). 프로필·종목·블랙리스트가 같아 LIVE00에서 사용자 PC의 소켓·되살리기·주간 점검·끝내기·리플레이 확인과 하루 디스크·점검 메모리를 미리 잰다.
2. **프로필 8개**: 대조군 `kr-bh-baseline@2`(A01, v1에서 `sizing.slots` 4 → 10만 바꿈. v1은 먼저 호가가 온 4종목만 사서 기준선 바구니가 세션을 연 시각에 달렸다, PR #175 strategy-researcher M1)·`kr-random-control@1`(A02)과 장중 6개(`kr-orb-30`, `kr-vwap-reclaim`, `kr-pdh-breakout`, `kr-volume-surge`, `kr-book-imbalance`, `kr-pullback`, 모두 v1). 스윙 `kr-ma-trend`는 빼고 4단계 일봉 판정에 맡긴다.
3. **boards 10종목**: KOSPI 8(005930 벤치마크, 000660, 035420, 005380, 373220, 068270, 105560, 035720) + KOSDAQ 2(247540, 028300). 게이트웨이 `watchlist.json` 후보를 같은 10종목으로 바꾼다(키움 한도 200의 5%).
4. **블랙리스트 확인 종목**: 035720을 등록 파일 `blacklist`에 둔다. 이 종목 체결이 하나라도 있으면 블랙리스트 우회 사고다(기존에는 6단계에서 잴 방법이 없었음).
5. **무사고(단계 완료 조건)**: 사고 정의는 D-023(Q-014 12번) 그대로 "주문 경로의 무결성 오류(중복 주문, 금지 전이, 미해소 대사 불일치, 블랙리스트 우회), 인프라 장애는 공백". 실험실 측정: I1 계좌 실패 0, I2 블랙리스트 종목 체결 0, I3 `runLiveReplayCheck` 종료 코드 0(대사 대신), I4 주간 점검 8회 종료 코드 0, I5 유효 운용일(그날 받음 ÷ 녹화 boards ≥ 95%) 40일 중 36일 이상 `[가정]`. I1~I4가 깨지면 사고(그 프로필 버전 8주 재시작, 새 ID), I5가 모자라면 판정 보류(새 ID로 이어 운용).
6. **장중 승격 후보 기준(사용자 확정, D-114)**: D-027 C1~C10을 실시간 8주에 옮긴 L1~L11. 수치는 C1~C5·C7~C9 그대로, C10은 4단계와 같은 본페로니 보정판(p ≤ 0.05/m, N + 1 < 20m이면 판정 불가, D-071 5번), C6은 학습 구간이 없어 "앞 4주·뒤 4주 각각 비용 차감 순손익 > 0"으로, D-066 4번의 장중판으로 L11 "실시간 대 같은 날 녹화 리플레이 총수익률 차 ≤ 2%p, 체결 수 차 ≤ 10%"를 더한다. 후보 0개여도 판정 리포트로 단계는 끝난다(기준을 낮추지 않음).
7. **주간 점검 운영**: 사용자가 금요일 장 마감 뒤 `runLiveWeeklyCheck`를 돌려 결과를 올리고, Claude 예약 작업이 토요일마다 요약한다(지침 10장 "6단계 주간 점검 일정").
