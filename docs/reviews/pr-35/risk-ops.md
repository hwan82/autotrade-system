## 수정 요청 (머지 전)
1. **포지션별 조합 해시의 영속·복구와 실패 시 손절 규칙 (A9, A12-2)**: STR-19 본문과 인수 조건에 다음을 넣는다.
   - 진입 조합(선정 프로필 해시, 전략 프로필 해시)은 주문 원장·포지션 기록에 진입 주문 단위로 영속하고, #8·#12 복구(DB 상태 복구 → 대사)에서 포지션마다 되살린다.
   - 이전 조합 포지션이 남아 있는 동안 그 전략 프로필 버전 파일은 실전 엔진이 읽을 수 있어야 하고(불변 버전, 해시 검증), 계좌 조합 교체가 그 파일 로드를 막지 않는다.
   - 해시를 되살리지 못하거나 프로필 파일이 없거나 해시가 맞지 않는 포지션: **현재 계좌 조합으로 넘기지 않는다.** 그 포지션은 보호 모드와 같은 취급(신규 추가 매수 없음, 서버 측 손절 유지, 자체 손절은 진입 기록에 남은 손절 기준가로 감시) + 긴급 알림 + 사용자 결정. 그 계좌 신규 진입은 사용자 확인 전까지 중단.
   - 테스트: 교체 뒤 실전 엔진 강제 종료·재기동 시 이전 조합 포지션이 이전 조합 손절 규칙으로 복구되는 테스트, 해시 유실·프로필 파일 없음 주입 시 현재 조합으로 넘어가지 않고 위 보호 동작·알림이 나는 실패 테스트.
   - 장애표 #8 행의 "DB 상태 복구"에 포지션별 조합 복구를 포함한다는 변경 제안을 배치표 5번에 적는다(행 수정은 7단계 구현 PR과 함께 해도 됨).
2. **계좌 안 같은 종목 중복 진입 금지와 이전 조합 포지션의 하드 필터 감시 (A9, A12-1)**: STR-19에 "한 실전 계좌 안에서 다른 조합의 포지션이 보유 중인 종목은 새 조합이 신규 진입하지 않는다(RSK-05의 계좌 안 확장, 대사 귀속과 서버 측 손절 수량의 단일성 유지)"와 그 차단 테스트를 넣는다. 그리고 "하드 필터 탈락 긴급 알림·신규 진입 차단(STR-15)은 조합과 무관하게 계좌의 모든 보유 종목에 매 거래일 적용한다(이전 조합 포지션 포함)"를 넣고 테스트를 단다. 둘 다 신규 진입을 더 막는 보수 쪽이라 사용자 결정을 약화하지 않는다. 사용자에게는 결과로 알린다.

## 수정 요청 (머지 전)
1. **병행 모의 중단 시 대응을 실험실 장애와 분리 (A8, A12-1, A14)**: STR-05·D-047 ①의 "병행 모의가 없거나 멈추면 … 신규 진입을 멈춘다"를 바꾼다. risk-ops 추천안:
   - 예외 **지정 시점**에 같은 조합의 병행 모의 계좌가 만들어지지 않으면 지정을 거부한다(지정 시점의 조건이라 실험실 장애와 실전 운용이 묶이지 않음).
   - 운용 중 병행 모의가 멈추면(실험실 크래시, 5.2 1·2번 정지, SIM-14) 실전 계좌는 **알림만** 보내고 그대로 운용한다. 멈춘 구간은 병행 모의의 공백 구간(장애표 #9 "재기동 후 공백 표시")으로 기록하고, 사고 연동(D-046 ③)이 그 구간에 동작하지 않았다는 사실을 UI와 승격 제안서에 표시한다.
   - 공백이 길어질 때의 처리(예: 병행 모의 공백 N거래일 넘으면 사용자 확인 요청)는 신규 진입을 자동으로 멈추지 않는 범위에서 정한다.
   - 대안(지금 문구: 병행 모의 중단 시 신규 진입 중단)은 사고 감지 공백을 없애지만 지침 4장 6번·장애표 #9·5.2 정지 순서의 예외가 되므로, 사용자가 이 대안을 원하면 **사용자 결정**으로 기록하고 장애표 #9·5.2에 예외 계좌 행을 함께 고치는 변경 제안을 배치표 5번에 넣는다. 어느 쪽이든 자율 채택이 아니라 사용자 확인 항목(Q 번호)으로 올린다.
   - 인수 조건에 "실험실 프로세스 강제 종료 시 예외 계좌의 신규 진입·손절 정상, 알림·공백 표시 발생"(장애표 #9) 테스트를 둔다.
2. **외부 매도 감지 처리의 범위 (A12-2)**: STR-19·D-047 ③의 "다른 주문"을 "**그 종목의** 다른 주문(매수·매도)"으로 고치고, "같은 계좌 다른 종목의 손절·청산·서버 측 손절은 이 처리와 무관하게 계속한다"를 넣는다. 조정 주문(서버 측 손절 취소·수량 변경)이 타임아웃이면 UNKNOWN → 조회(장애표 #4)이고, 확정 전까지 그 종목 새 주문만 막는다. 인수 조건에 "조정 주문 UNKNOWN 동안 다른 종목 손절 실행" 테스트를 더한다.

## 권고 (판정 밖)
1. D-047 ②·③은 장애 대응 #6 규칙을 바꾸는 실전 영향 결정이다. 보호를 더하는 쪽이라 내용에는 동의하지만, 결정 로그 표기를 "추천안 채택(자율), 사용자 확인 대상(실전 영향, PR #35 사용자 머지로 확인)"처럼 남겨 사용자가 한눈에 보게 한다.
2. 수동 청산은 UI(실험실 프로세스)에서 시작해 실전 엔진으로 가므로 ADR-006 실전 제어 채널(D-037)을 거친다고 STR-19에 한 줄 적고, UI-05(:244) "실전 관련 버튼은 확인 절차 없이 동작하지 않음"에 따라 포지션·수량 확인 단계를 둔다. 실험실이 죽어도 PANIC SELL·긴급 청산 같은 기존 경로가 남는지는 ADR-006 기준을 따른다.
3. 외부 매도 감지는 대사 주기(BRK-05, 5분) 뒤에 일어나므로, 그 사이 사용자가 같은 종목을 다시 사면 남은 서버 측 손절이 재매수분을 팔 수 있는 창이 남는다. 이 창은 UI 경고(증권사 앱으로 팔 때 서버 측 손절 직접 취소)로만 줄어든다. 체결 통보(증권사 실시간 체결 이벤트)로 외부 매도를 대사보다 빨리 알 수 있는 증권사는 그것을 쓰도록 7단계에서 정하기를 권한다(증권사별 가능 여부 `[가정]`, 확인 필요).
4. (정보) QA 점검표 밖 4(D2와 예외 계좌 충돌)는 배치표 5번의 D2 보강 제안으로 남아 있고, 그 전에는 D2를 지금 문구대로 적용(안전 쪽)한다는 QA 의견에 동의한다.
5. (정보) 커밋 메시지·QA 보고서의 "해소" 주장은 사실로 받지 않고 문서 위치를 직접 읽어 판정했다.
